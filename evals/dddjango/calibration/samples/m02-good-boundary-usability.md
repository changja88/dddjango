# 주문/결제 애그리거트 경계 판정

## 결론

주문과 결제는 하나의 거대한 모델이 아니라 별도 애그리거트로 둔다. 주문
애그리거트는 주문 항목, 배송지, 주문 상태 같은 주문 불변식을 지키고, 결제
애그리거트는 승인 금액, 승인 번호, 결제 상태 같은 결제 불변식을 지킨다.
배송지와 금액은 값 객체 후보로 두고, 두 애그리거트 사이 조정은 유스케이스 또는
도메인 서비스가 담당한다.

## 근거

- 주문은 결제 객체 전체를 소유하지 않고 결제 ID를 참조한다.
- 결제 성공/실패는 도메인 이벤트로 주문 쪽에 전달하고 최종 일관성으로 맞춘다.
- 작은 애그리거트를 유지하면 결제 재시도, 부분 취소, 주문 취소 정책을 각각의
  경계 안에서 테스트할 수 있다.

## 점검표

- 주문 상태 전이는 `Order.confirm()` 같은 애그리거트 메서드에서만 일어난다.
- 결제 승인 실패가 주문 금액 불변식을 깨지 않는지 테스트한다.
- 검색식은 `Order`가 `Payment` 엔티티를 직접 보유하는 코드,
  `payment.status`를 주문 서비스가 직접 바꾸는 코드를 우선 찾는다.

판단은 주문-결제 분리, ID 참조, 도메인 이벤트 연동이다. 최종 권고는
권장 경계를 유지하면서 결제 완료 이벤트를 주문 상태 전이에 반영하는 것이다.
