## 반박 과제 (4건 — 각각 독립)

1. **부분 채택 ①의 반박** — 중재는 AM#11의 `pre_gate_repair_cycles` 신설을 «회전 레코드로 갈음»하고 «A암도 회전 0 레코드를 남긴다»로 처분했다. 공격하라: A암에 회전 개념이 없는데 0 레코드를 남기는 것이 의미 있는 관측인가? 세 암의 «수리 노력»을 비교 가능하게 만드는 다른 관측량이 실제로 존재하는가, 아니면 이 갈음이 관측 공백을 감추는가? **A암이 게이트 red 시 실제로 무엇을 하는지**를 `dddjango/commands/dddjango.md` 실물로 확정한 뒤 답하라(추측 금지).

2. **부분 채택 ②의 반박** — 중재는 AN#7을 «실런에서는 `no_progress`를 진단 플래그로만, 셸 A에서는 조기 종료 허용»으로 처분했다. 공격하라: harness(셸 A)와 처치(셸 B)의 상태기계가 갈라지면 셸 A의 회귀 검출력이 무엇을 놓치는가? 구체적 실패 시나리오(입력·상태 → 놓치는 결함)를 제시하라. 또 「진단 플래그만」이 정말 동결 §6·사전 등록과 정합인지 문면으로 확인하라.

3. **부분 채택 ③의 반박** — 중재는 AN#13(설치 cache 신선도)을 «T2-3에서는 probe를 설계만 하고 실행은 T2-0b에서 사용자 요청»으로 이연했다. 공격하라: 이것이 blocker의 실질 해소인가, 검증되지 않은 설계를 미루는 것인가? **설치본 갱신 없이 T2-3에서 실행 가능한 검증**이 실제로 있는지 실물로 확인하라(`workspace/DEVLOG.md`의 plugin 설치 cache 실측 기록·`Makefile`·미러 검사 포함). 있다면 그것을 T2-3 exit 조건으로 요구하라.

4. **사용자 상정 권고안의 반박(가장 중요)** — 중재는 AN#1(A암이 귀속 red로 G2에 도달하지 못해 판정 실패로 탈락)의 처분으로 **안 «가»**(A암의 측정 종료점을 «게이트 실행·결과 기록»으로 재정의하고 G2 승인을 채점 요건에서 제외)를 사용자에게 권고한다. 공격하라:
   - 이 재정의가 사전 등록의 **인수 게이트**(`t2-plan` §2 T2-0a «발주 인수 게이트» — arm-independent 블랙박스 인수 테스트 통과본만 채점)와 충돌하는가? 게이트 시점에는 인수 테스트가 통과했는지 확정되는가?
   - 세 암의 종료점이 달라지는 것이 «B/C에는 루프 후 최종 상태, A에는 루프 전 상태»라는 **비대칭 측정**을 만들지 않는가?
