## 검증 과제 (전부 실측·인용으로)

1. **L1(코어 1 + 셸 2)의 반증**: 이 구조가 정말 «처치 1벌»을 보장하는가. 셸 A(`claude -p`)와 셸 B(coder 재호출)는 **모델·시스템 프롬프트·도구 집합·권한·컨텍스트가 전부 다르다** — 프롬프트 byte가 같다는 불변식이 «같은 처치»의 증거가 되는지 공격하라. 셸 A가 A/B의 어떤 주장도 지지하지 못한다면 그 사실을 실증하고, 셸 A의 존재 이유를 다시 규정하라.

2. **C1~C4(coder 편입)의 실물 정합**: `dddjango/commands/dddjango.md`를 실독해 **게이트가 실제로 어디서 어떻게 실행되는지** 확인하고, «게이트 red 직후 coder 재호출»이 그 절차에 삽입 가능한지 검증하라. 특히 ⓐ `registry_gate --anchor`의 **공허 차분 사용 오류**(앵커=HEAD ∧ clean → exit 1)가 루프 회전 중에 발동하는 시나리오 ⓑ 회전 중 커밋이 일어나면 앵커가 어떻게 되는가 ⓒ G2 게이트와 슬라이스 래칫 중 어디가 편입점인지 문서가 확정했는가 — 셋 다 실물로 답하라.

3. **B2(게이트 식별)의 검출력**: 배너 앵커 정규식 `^dddjango · (G0 스코프|G1 설계|G2 구현) 승인$`가 실제 배너와 맞는가. `dddjango.md` 42행의 배너 블록을 문자 단위로 대조하라(가운뎃점·공백·`{…}` 치환 후 실제 출력 문면). **assistant 텍스트가 jsonl에 어떤 모양으로 저장되는지**(`message.content[]`의 text 블록 분할·부분 스트리밍)를 이 저장소 세션 jsonl로 실측해, 「앞선 가장 가까운 assistant 텍스트」라는 앵커 규칙이 기계적으로 성립하는지 검증하라. 성립하지 않는 반례를 만들어라.

4. **B3(승인/반송 판정)의 처분 반증**: 「label 정확 일치만 결정적, 자유 입력은 `freeform`」이 실런에서 무엇을 낳는지 계산하라. 실런 판형이 «무수정 승인 고정»(t2-plan §2 T2-0a)일 때 **게이트 반송이 구조상 0**이라면, 이 계수기가 산출하는 값이 동결 §1 ②·§8의 «의무 산출물» 요건을 실제로 충족하는가 — 아니면 «항상 0을 세는 도구»를 만드는 것인가. 충족하지 못한다면 무엇을 세야 요건이 충족되는지 대안을 제시하라.

5. **L3~L5(회전 계상·수렴·범위 밖 불변)의 결함**: ⓐ `no_progress` 판정이 쓰는 «위반 집합 동일»의 동일성 키가 T2-2 어댑터 키(Work×파일×심볼)와 정말 같은 것인지 `findings.py`의 실제 레코드 필드로 대조하라 — 루프는 rule «#N» 문자열을 쓰고 어댑터는 Work IRI를 쓴다 ⓑ 범위 밖 불변 검증이 «같은 검사기 집합 안»에서만 성립한다는 자인(W2)의 실제 노출 크기를 27종 로스터로 추정하라 ⓒ 회전 레코드 필드 집합에 빠진 것이 있는가(재현·감사에 필요한데 없는 필드).

6. **B7~B9(사람 메시지·세션 경계)의 취약성 실증**: 배제 태그 목록이 이 저장소 세션 3파일에서 실제로 충분한지 **전수 대조**하라(문자열 content를 가진 `user` 레코드 전량을 분류해 배제 목록 밖 시스템 주입이 있는지). `sessionId`가 null인 레코드(실측 170·137건)의 정체를 확인하고, B9의 «파일 1 = 세션 1» 판단이 그 null 레코드 때문에 깨지는지 검증하라.

7. **범위·순서의 결함**: T2-3 산출물이 T2-0b manifest 봉인 대상(scorer·파이프라인 SHA·주입 팩 해시)과 어떻게 맞물리는지 대조하라. **T2-3에서 만든 것 중 T2-0b가 봉인해야 하는데 문서가 봉인 목록에 넣지 않은 것**을 찾아라. 또한 §5 구현 순서가 만드는 되돌릴 수 없는 지점(코퍼스 정본 개작·원장 재기준선)이 리뷰 전에 실행되도록 배치돼 있지 않은지 확인하라.
