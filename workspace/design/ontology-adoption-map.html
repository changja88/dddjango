① C암이 무엇을 받는가 = 규칙 번호·명칭까지. 문제의 뿌리는 동결 문서 두 곳이 서로 충돌한 것이었습니다 — 한쪽은 C암을 «그래프가 골라낸 규칙 팩»으로 정의하는데, 다른 쪽(주입 규약·양 런타임 절차서)은 재생성에 넘길 재료를 «위반의 번호·파일·메시지 뿐»으로 닫아 뒀습니다. 위반이 안 난 규칙은 파일도 메시지도 없으니 실을 방법이 없었던 겁니다. 확인해 주신 대로 규칙 번호와 명칭까지만 싣고 규범 본문은 계속 안 싣는 것으로 확정했습니다 — 주입 금지 규약은 손대지 않고, 절차서 문면 한 곳만 고치며, B암 프롬프트는 한 byte도 바뀌지 않습니다. ② 계약형 위반이 섞인 실행 = 계수만 하고 유효 유지. 일부 검사기는 규칙 번호 없이 «계약 위반»만 뱉는데(해당 검사기 기준 규칙 범주 23개 중 11개), 이런 항목은 구조상 C암 처치에 도달하지 못합니다. 그런 실행을 통계에서 빼지 않고 비율만 기록해 리포트에 병기합니다 — 세 암이 같은 조건이라 편향이 없고, 표본이 작아 제외 규칙은 유효 표본만 깎기 때문입니다.

앞서 확인해 주신 결정(모두 반영 완료): 개정 7 — A암 측정 종료점을 «승인 화면»이 아니라 «처치가 끝난 공통 시점»으로 이동(A가 나쁠수록 측정에서 탈락하던 문제 해소, 처치 정의는 불변) · 설치본 갱신 = T2-0b(실런 직전) 때 한 번에(지금 설치된 플러그인은 2.11.0 구판이라 T2-1·T2-3 산출물이 빠져 있고, 갱신·동일성 검증·probe 재실행이 실런 진입의 필수 선행조건으로 등재됨).

돌린 것: 같은 발주(«재고 부족하면 409로 거절, 충분하면 차감하고 주문 생성»)를 세 가지 방식으로 동시에 돌렸습니다. ⓐ 새 기능 끔 ⓑ 켬(미리 만든 파일에서 규칙을 꺼냄) ⓒ 켬(그래프에 물어봐서 꺼냄). 세 방식의 차이는 환경 설정 두 개뿐이고, 시작 코드·발주문·모델·권한이 전부 같습니다(글자 단위로 대조해서 확인).

가장 중요한 발견: ⓒ가 루프까지 갔는데 주입이 한 번도 안 일어났습니다. 그냥 «효과 없음»으로 보이지만, 이유를 파 보니 달랐습니다 — 고칠 거리가 없어서가 아니라, 검사기 하나가 낸 진단을 게이트가 읽지 못해서였습니다. 규정에도 이런 건 «측정 실패로 되돌려 보내라»고 적혀 있습니다. 그래서 «효과 없음» 판정을 내리지 않았습니다. 「할 말이 없었다」와 「말할 기회를 못 얻었다」는 전혀 다른 결론으로 이어집니다.

밤새 한 다른 일: 무인으로 돌리려고 감시 장치를 만들었는데 결함이 여덟 번 나왔습니다(멈춤 감지 실패·긴 명령 오분류·화면 폭에 따른 오탐 등). 전부 «과하게 멈추는» 쪽이었고 «잘못 승인하는» 쪽은 없었습니다. 마지막에는 자동 승인을 아예 빼고 제가 하나씩 판단하는 방식으로 바꿨습니다 — 감시 장치 안에 위험한 명령어 목록이 들어 있으면 그 자체가 위험하게 보이는 문제가 있었고, 그걸 숨겨서 통과시키는 건 옳지 않다고 봤습니다.

# === 빈혈 도메인 모델 (Anemic Domain Model) -- 안티패턴 ===   ← final.md 586행 실물
@dataclass
class OrderAnemic:
    """데이터만 있고 행동이 없는 빈혈 모델"""
    id: str
    customer_id: str
    items: list
    status: str
    total: int

class OrderServiceAnemic:
    """모든 비즈니스 로직이 서비스에 집중 -- 절차적 프로그래밍과 동일"""
    def place_order(self, order: OrderAnemic) -> None:
        if not order.items:
            raise ValueError("상품이 없습니다")
        order.total = sum(i["price"] * i["qty"] for i in order.items)
        order.status = "placed"

# === 풍부한 도메인 모델 (Rich Domain Model) -- DDD 지향 ===
class OrderRich:
    def cancel(self) -> None:
        """비즈니스 규칙이 도메인 객체 안에 있다"""
        if self._status not in (OrderStatus.PLACED,
                                OrderStatus.PREPARING):
            raise ValueError(f"{self._status.value} 상태에서는
                              취소할 수 없습니다")
        self._status = OrderStatus.CANCELLED
