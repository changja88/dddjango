## 특이 발견

1. **쌍둥이는 개명 경로에 존재**: codex판이 `codex-dddjango/skills/discipline-cleancode/`가 아니라 `codex-dddjango/skills/dddjango-discipline-cleancode/`(접두 `dddjango-`)에 있다. 파일 구성(SKILL.md + references/final.md)은 동형. 경로 기반 쌍둥이 대응표를 만들 때 단순 이름 매칭이 실패하는 사례.
2. **백스톱 앵커가 역방향 단방향**: 문서는 어떤 검사기도 지목하지 않지만, `dddjango/scripts/check-choices-literal-consumption.py`의 docstring이 «cleancode §2.14 소비 규율»을 명시 지목한다(스크립트→문서). 커버 범위도 §2.14 전체가 아니라 소비 규율의 직접형 2종(`default=` 리터럴, 직접 `filter` 리터럴)뿐 — 의미 레인은 discipline-reviewer 몫이라고 스크립트 스스로 선언.
3. **규칙 ID 체계가 이미 존재**: §12.2가 결정 ID **#453·#454**를 인용하고, `scripts/check-naming.py`는 «rule-owner-map»(`workspace/plan/2026-08-11-rule-owner-map.md`)과 #번호 규칙 배정(#28·#30·#33 등, 총 32건)을 이미 운용한다. 온톨로지 레지스트리의 전신이 산재해 있어 P0 이후 통합 대상.
4. **규범 밀도의 극단적 편중**: 상위 3개 표면(§2.14=27, §12 블록=26, 요약 체크리스트=29)이 전체 236문장의 약 35%를 차지한다. 반대로 §7(깊은 모듈)·§15(리팩토링)·§10 대부분은 규범 문장 0 — 지시가 SKILL.md의 요약 bullet에만 존재하고 본문은 정의·예제뿐이라, 절 단위 레지스트리화 시 «규칙의 실체가 어느 파일에 있는가»가 절마다 다르다.
5. **3중 유지 표면(표류 위험)**: 같은 규칙이 (a) SKILL.md 핵심 운영 원칙 bullet, (b) final.md 본문 절, (c) final.md 말미 «핵심 요약 체크리스트» 29행에 삼중으로 존재한다. 특히 SKILL.md bullet 2는 §2.14의 ~6개 지시를 한 줄에 압축해 본문 개정 시 동기화 누락 1순위 후보.
6. **문장 단위 중복**: §3.1과 §3.2가 동일 문장(«의미 있는 이름으로 다른 함수를 추출할 수 있다면, 그 함수는 여러 작업을 하고 있다»)을 그대로 중복 수록.
7. **소유자 명시는 전부 위임 조항**: 소유자가 명시된 10개 절은 모두 타 스킬로의 판정 위임(§2.14→architecture-ddd·implementation-test·houserules, §12.3→implementation-django-ninja §6.2, §16.5→discipline-tdd §5.5 «소유한다», §4.7·§5.2·§18→implementation-python 등)이다. 이 문서 자신의 규칙(나머지 105절)을 누가 판정하는지는 문면 어디에도 없다 — check-choices 스크립트 docstring이 «의미 레인 = discipline-reviewer 몫»이라고 암시할 뿐, 문서 본문에는 부재.
