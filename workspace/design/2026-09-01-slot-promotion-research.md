  잎 칸 파일의 분해 칸(schema_in/out)을 이미 갖지만, 칸의 역할 밖 응집 단위(SSE renderer

## 1. 생태계 선례 (조사 A — 출처 원문 확보)

- **크기를 하드 트리거로 규범화한 생태계는 없다.** Go "flexible about file size" ·
  37signals "arbitrary containers로 쓰지 말라" · Django 커뮤니티 1,000줄 휴리스틱도 전부
  «고려 신호» 어조 → «크기=감사 신호» 설계와 정합.
- **캐스케이드 ②(역할 밖 응집 단위)의 방증**: Java는 public 클래스=새 파일이 언어 강제,
  Rails 37signals "cohesive unit that captures a trait of the host"가 동문.
- **`__init__.py` 재수출**: Django models는 공식 문서가 명문화한 기계적 필수
  (`models/__init__.py` import 의무 — app registry·마이그레이션), admin은 autodiscover상
  사실상 필수, views/services는 호출부 안정성 관행(HackSoft "import-export dance").
  Go는 패키지=import 단위라 분할이 호출부에 원천 불가시 — 재수출은 Python에서 그
  불가시성을 재현하는 장치로 정당화.
- **교체형(⇄) 설계의 최강 근거**: Rust RFC 2126이 «승격 시 기존 파일 이동 마찰»을
  에디션 개정 사유로 명시(2018: `foo.rs`+`foo/` 병행). 단 Python은 `foo.py`/`foo/` 형제
  공존 불가 → 본체가 폴더 안으로 들어가고 재수출로 호출부 불변을 복원하는 게 등가물.
  본체 코드를 `__init__.py`에 두는 건 mod.rs 비판(특수명 파일 혼동)과 동형 안티패턴 —
  **동명 본체 `<이름>.py` + 재수출 전용 `__init__.py`** 형태가 옳다.
- **본체 파일=공개면 + 동명 폴더=부품**의 안정 운용 실증: Phoenix context(공식 표준),
  Rails Zeitwerk(`recording.rb`+`recording/`).
- 함정 3: ⓐ `app_label` 필수 서술은 Django 1.7 이후 낡은 지식 — 규범에 넣지 말 것
  ⓑ 형태 검사기는 전체 경로 기준 비교(clippy `mod_module_files` 반복 버그 반면교사)
  ⓒ 승격 시 `git mv` 이력 보존 지침 병기 가치.

## 2. 자매 플러그인 대조 (조사 C)

- **같은 낱말, 다른 기하**: dddart·dddjango-web의 «승격»은 계약이 바뀌는 **단(tier)
  이동**(section→widget·view 삼총사·design_system). 우리 것은 같은 칸 안의 **형태
  전환** — 무수식 «승격» 단독 사용은 의미 충돌 → **«동명 폴더 승격»** 고정 수식어 권고.
  캐스케이드 ①=«이동»·②=«승격» 구분은 자매의 "승격·이동 규칙" 표제와 정확히 평행.
- **트리거 철학 충돌 없음**: 양 자매 §1/§2 첫 문장이 "3단은 **크기가 아니라** …로
  가른다" — 이 공리 문형을 서두에 수입하면 ③이 예외가 아니라 공리의 귀결로 읽힘.
  성장 규칙 트리거도 "파일 수가 아니라 다른 묶음의 등장".
- **«강등» 낱말 금지**: dddart에서 판정 소유 규칙(architecture-ddd §5)의 전문 용어로
  점유. 역방향은 `⇄` 기호 또는 절제 원칙("~만으로 성립하면 승격하지 않는다")으로 서술.
- **이식할 형태 규정 4종**: ⓐ 승격 후 원 파일 동결·공개면 불변 리트머스(dddart area
  규칙 "지워 되돌려도 바뀌는 것은 경로와 import뿐" — 양방향 전환 요건으로 그대로 사용)
  ⓑ «미리 파지 않는다»(예비 폴더형 금지) ⓒ 폴더 내부 정크드로어(`utils.py`류) 금지
  ⓓ 판별 배정 판형 — 1차 결정자와 검증자가 **같은 판별 문서**를 적재("다른 기준으로
  판정하면 반송 루프").
- **실행 주체 긴장(결정 필요)**: 양 자매 모두 승격 1차 결정=설계자, coder는 «2차
  발견자 — 임의 분할 금지·보고». 우리 초안(coder 인라인 형태 결정)과 배치가 다름.
  단, 자매 승격은 계약이 바뀌므로 설계 소유가 필연이고, 우리 동명 폴더 승격은 공개면
  불변(계약 무변)이라 형태 집행으로 분류할 논거가 성립 — D1로 표면화.

## 3. 실측 표본 검증 (조사 D — 캐스케이드 소급 적용 16건)

- **골격은 작동한다**: turn_controller 기준 판정(파싱→①·renderer→②·view→③) 재현,
  `generation_service.py`의 `_PublishedGenerationStream`이 동형 ②로 일관, 단일 대형
  클래스 파일들(애그리거트 558행 등)이 전부 ③ 안착. 감사 신호(>200행) 발화율
  1.69%(28/1,657 — 신뢰도 검증 재실측 정정) — 실용적. kkebi-mirror는 후보 0건의 음성 대조군.
- **문안 보강 5건**:
  1. ② 술어 2중 조건화 — (a) "자기 상태·수명" 외에 "독자 식별자로 불리며 독립 변경
     이유를 가진 무상태 클러스터(모델군+상수+함수 쌍)"까지 확장(미발화 교정 —
     intent_generation_adapter 계약 클러스터 3개) (b) **중대성 하한**(부품 합계 ≥50행
     또는 파일의 ≥20%) 추가(과발화 교정 — 20행 `_StartConnectionCloser`).
  2. ①에 수용성 확인 단서 — "이동 후보 칸이 실제로 받을 수 있는가(의존 방향 역류
     없음 + 역할 계약 부합)를 확인한 뒤에만 이동"(conversation_item wire 사영의 의도적
     도메인 소유 사례·use_case 헬퍼의 command 의존 역류 사례).
  3. 감사 신호의 **칸 유형 조건화** — 선언 칸(bc_error_schema·schema·contract·result·
     port 자료)은 클래스 수 무관, **행위 칸**(controller·service·use_case·adapter·
     repository 구현·aggregate·wiring)만 역할 밖 검사.
  4. 프레임워크 관례 동거 예외 명문 — Model+Manager+QuerySet(+불변 예외), admin
     panel+inline, migrations.
  5. 잔여 결정: 전부 역할 내인 초대형 파일(757행 VO 등 — 실측 2건)은 캐스케이드가
     ③ 확정 — 유지 권고(승격 출구 없음이 의도).
- (부수 발견) 같은 area 형제 유스케이스 간 top-level 헬퍼 근사 중복 — 승격 규칙 밖,
  별도 감사 신호 후보로만 기록.

## 4. 코퍼스 전수 — 수요 지도·검사기 비용·등가 조항 좌표 (조사 B)

### 4.2 검사기 비용 실측 (27종 전수 — 개정의 실질 본체)

  빚 스캔이 오탐을 빚으로 계상).

## 5. 종합 — 계획으로 넘길 결정 후보

- 어휘·형태 확정치(결정 불요 — 조사 근거로 채택): «동명 폴더 승격» 수식어 · "크기가

  폴더=리프 폐쇄·내부 재량·정크드로어 금지 · 미리 파지 않는다 · «강등» 낱말 금지 ·
