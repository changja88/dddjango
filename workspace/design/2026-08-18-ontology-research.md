## 2. 수렴 지점 (레인 간 일치)

1. **D1 = YAML 자체 형식, 사실상 확정** — R2·R3·R5·R7 독립 일치. RDF/SHACL 전면 채택을 지지한 레인 0. 단 어휘(deprecated·replaced_by·severity 관례)는 표준에서 차용해 전환 비용을 낮춘다.
2. **ID는 신설이 아니라 통합·흡수** — 재번호 전면 금지, alias 간접층(R1) = P0 실측 «번호 공간 5종»의 처방.
3. **파생이 정본보다 먼저** — rule-owner-map·집행 규칙 표는 docstring 파싱 **파생 뷰**로(R3·R7), 새 정본 문서 신설 금지.
4. **미러 lint는 레지스트리와 독립으로 즉시 가능** — 실증 피해(표류 2건)의 직접 처방이자 표류율 측정 장치(R4·R7).
5. **사람 심의 부하의 상한 관리가 생존 조건** — 자동 fuzzy 판정+사람 해제(R4), 합의 의식 금지+기계 게이트(R6), triage 보조 한정 LLM(R4).

## 3. 긴장 지점 (③ 블루프린트 v2가 해소해야 할 것)

- **R7 vs 원안 블루프린트**: 원안 «레지스트리=뼈대 정본 즉시 채택»은 이중 장부 위험. → v2는 **승격 사다리**(파생 뷰→신규만 등재→실적 게이트 후 정본 승격, 일몰 조건 내장)로 재설계한다(Gall의 법칙).
- **R1(전면 ID) vs R3(ID 없이 인용 지목 가능) vs R7(신규만)**: → ID 발행은 Stage C(신규·개정분)부터, 기존 참조는 alias로, Duvet식 인용 지목은 ID 이전 단계의 다리로.
- **R4의 선행 의존(ID 필요) vs 미러 lint 즉시론(R7)**: → 미러 lint 1차분은 ID 없이 문서쌍 정규화 대조로 시작(P0 실측이 이미 증명), ID 도입 후 절 단위 조인으로 정밀화.
