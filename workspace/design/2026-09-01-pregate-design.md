## 3. 아키텍처 결정

### D1. 시뮬레이터 노선 — **archive+overlay+init 격리 사본** + registry 앵커 차분

기존 검사기 27종은 **한 줄도 수정·복제하지 않는다**. v1의 `git worktree add` 노선은 실험에서 세 부작용이 실증되어(untracked 잔재로 `worktree remove` 상시 실패 · 소비 저장소 post-checkout 훅이 비밀·대용량 자산을 복제 · 레인 트리 내 배치 시 G2 스냅숏 오염) **격리 사본 노선으로 교체**한다:

1. **사본 생성**(저장소 트리 밖 스크래치): `git -c core.hooksPath= archive <BASE_SHA> | tar -x` → **dirty overlay**(레인의 non-ignored 미커밋·미추적 실물을 겹침 — P2 중 재실행에서 미커밋 슬라이스 소실 방지) → `git init` + 전량 commit(이 커밋이 앵커).
2. **팬텀 스텁 실체화**(§3-D2 규약) — 사본 위에 겹침.
3. `registry_gate.py <사본 루트> --anchor HEAD` — N∖L 차분이 «팬텀 유발 위반»만 귀속(G2와 동일 판정 의미론 재사용·legacy 자동 격리). 팬텀이 1파일 이상이므로 공허 차분 가드(exit 1)는 비발화; 실체화 0건이면 게이트를 부르지 않고 «실체화 0 — skip» 명시 보고.
4. 산출: 예보 리포트(§3-D4) → `.dddjango/<런 폴더>/pregate-report.md` append(미결 M1 확정).
5. 청소: 사본 디렉터리 삭제(try/finally — 공유 저장소에 등록·잠금·브랜치 흔적이 애초에 없다).

모든 git 호출은 `design_pregate.py` **내부**에서만 수행한다(레인 권한 프로파일에 git 부재 — Coordinator가 bare git을 치지 않는다는 문장을 §5에 성문). 훅은 전 호출 `core.hooksPath=` 억제.

**조치 태그별 실체화 의미론**([신규 1]의 실행 측):

- `update`: **실물 보존 + append만** — ② 화이트리스트의 정형 배선 1줄류에 한정. 그 외 update 계획은 시뮬레이션하지 않고 리포트 «미시뮬레이션 목록»에 명시(침묵 금지).

- `empty`: 빈 파일 생성(골격 칸 실현 — #488 대응)만을 의미한다.

**재료↔채널 대응표**(성문): D2가 쓰는 모든 재료는 §4의 어느 블록에서 오는지 1:1 대응표를 규범에 포함한다 — 대응 채널이 없는 재료는 D2에 존재할 수 없다(리뷰 레인 4 B1 처방).

### D3. 실행 계약

- registry 기본 프로필(`auto`) 그대로 — 단 API-error 3종의 **tree 레인은 auto에서도 방출**되므로 스텁 ErrorSchema·컨트롤러에 대한 발화/침묵은 §7 발화 매트릭스로 ④에서 전수 검증한다.
- 대상 프로젝트 venv 인터프리터로 실행. venv 부재·`requires-python` 하한 미달이면 **skip 아님 — «실행 불능» red-형식 보고**(침묵 금지).
- `DJR_FINDINGS_JSON` 스크래치 격리(실 `.dddjango/violations/` 오염 금지).
- 계획 경로 선검증: 숨김 세그먼트·`.dddjango/` 외에 `build`·`dist`·`staticfiles`·`node_modules`·`site-packages`·`venv` 세그먼트도 거절(`_IGNORE_COPY` 조용 소실 방지).
- 신설 파일 명명: `design_pregate.py` — **`check-*.py` 패턴 금지**(checker_registry의 로스터↔글롭 동등 assert 즉사 방지). 보조 모듈도 동일.
- exit 매핑 성문: 형식 오류(파싱·add 충돌·경로 거절) = red-형식 / 실체화 0 = skip 보고 / 게이트 red = 예보 red / 실행 불능 = red-형식. 어느 경우도 침묵 없음.

### D4. 판정 의미론·트리거·리포트

**트리거(재정의 — 리뷰 레인 2 B1)**: «승인 지점 열거»가 아니라 **«design-spec.md 내용 변경(architect 산출 수신)마다»** 실행한다. 여기에 두 개의 무조건 실행을 못박는다: ⑴ **G1/G1′ 배너 제시 직전 최종본**(배너의 예보 1행은 항상 최종본에 대한 것 — 낡은 green 금지) ⑵ **G1 override(②/③) 반영 후 Phase 2 dispatch 전**(무배너 경로 — red면 architect 내부 루프 반송(관찰 모드: 기록), 예보는 Phase 2 진입 한 줄 상태 + pregate-report에 착지). 블록 해시 불변이면 재실행을 skip(캐시)해 직렬 비용을 없앤다(§7 성능 기준).

**앵커 의미론(성문)**: 예보의 기준선(BASE_SHA)은 «스텁 제외 현재 상태»다 — `build_anchor`를 읽지도 쓰지도 않고, 예보 실행이 build_anchor 규칙(기능 폴더 1회 기록)에 어떤 영향도 주지 않는다. **HEAD 판형 게이트 결과를 G2 증거로 유용하는 것은 차분 세탁으로 금지**(기존 step 6 규범의 문면 확장).

**대체 금지(성문)**: «예보는 Phase 2 step 6(G2 registry 게이트)의 실행·증거 요구를 어떤 형태로도 대체·축약하지 않는다» — Coordinator 절차와 리포트 헤더 상시 문구 양쪽에.

**green의 의미**: «설계 검증됨»이 아니라 «P/S/I급 결정 계약 위반 예보 0». 리포트에 사각 목록 상시 병기 — **C급 규칙 목록 + ④형 전체 + BC 내부 계층 의존 오설계(#92/#93류 유도 삽입 한계) + 앵커·상태 축(예보 기준선과 G2 build_anchor 차분의 상이) + 미시뮬레이션 목록(update·후행 remove)**.

**리포트 계약**: 예보 항목마다 **안정 ID**(경로+규칙번호 해시). Coordinator는 명세 개정 승인마다 각 red의 처분 라벨 `corrected | ignored | filtered`를 pregate-report에 append(관찰 모드의 유일한 추가 절차 의무). 기준선 SHA·프로필·커버 문면을 헤더에 병기.

## 4. 설계 명세 기계가독 형식 규범 (신규 5 + 조임 2)
