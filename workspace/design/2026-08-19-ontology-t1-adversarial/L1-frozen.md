## 상세

### L1-1 (blocker) — 발주 후보 풀 사전 등록 누락: 동결 §6이 T1에 직접 거는 유일한 순서 제약의 미착지

- **동결 근거**: `2026-08-18-ontology-blueprint-v3.md:96` — «**발주 통제**: **T1 이관 범위 확정 전에** 발주 후보 풀 사전 등록(선정-처치 독립), 층화 = 이관 클러스터 밀착 1·비밀착 1·혼합 1.» §6 서두(`:92`)는 이것이 «동결 문면으로 확정하는 하중 파라미터»임을 못박는다.
- **표적 실물**: `2026-08-19-ontology-t1-plan.md` 전문에 «발주»라는 단어 자체가 없다. 반면 §5 헤더(`:100`)는 D7(파일럿 범위)을 «T1-3 착수 전 확정»으로 규정하고, D7(`:105`)·§1(`:18`)은 이미 표적 절(ninja §6.2·tdd §5.5·architecture-ddd)의 밀도·검사기 배선까지 상세 분석해 노출했다 — 범위 확정이 사실상 진행 중인데 선행 조건이 계획에서 탈락했다.
- **왜 blocker인가**: 이 제약은 §6 3암 A/B의 선정-처치 독립을 지키는 장치다. 풀 등록 없이 범위를 확정하면 위반이 **비가역**이 된다(등록을 소급해도 «범위를 알고 뽑은 풀»이 됨). A/B는 T3 전량 이관을 정당화하는 유일한 근거 장치(§1 자인)이므로, 여기서 새면 T2 게이트의 판정 자체가 오염된다.
- **수정 방향**: T1-3 착수 전(=D7 확정 이전 또는 동시) 단계로 «발주 후보 풀 사전 등록»(실제 백로그 우선·층화 3층 표기 — §6 문면)을 T1 계획에 산출물로 신설하고, 게이트 2 검수표 또는 D7 확정 조건에 «풀 등록 선행» 행을 추가한다. 실행 순서도(§3)에도 이 선행 화살표를 넣는다.

### L1-2 (blocker) — 이관 공정 절차서(T1-2)에 Expression 생성 단계가 없다

- **동결 근거**: 개정 1(`blueprint-v3.md:174`) — 3노드형: 블록 —statesNorm→ Work, **판본은 Expression 노드**. E6(`:40`) — «판본 = Expression IRI `djr:R-NNNN@YYYY-MM-DD[.n]`», «Expression=Work+일자» 채번, 개정 ② «새 Expression+revision+1».
- **표적 실물**: T1-2 절차서(`t1-plan.md:39`) ①블록 분해 → ②Work 채번 → ③wiring → ④Section·Document → ⑤게이트 → ⑥라운드트립 → ⑦검수 — **어느 단계에도 Expression 채번·`djr:revision` 초기값·`prov:specializationOf`·`djr:currentExpression` 연결이 없다**. 그런데 T1-6 질의 ⑤(`:64`)와 게이트 2-2(`:90`)는 «규칙 Work→**현행 Expression**→(골든) 위반 왕복»의 성립을 동결 완료 기준으로 건다 — 절차서대로 저작하면 Expression이 0개라 질의 ⑤가 공집합으로 실패한다(계획 내부 모순).
- **계약 실물 대조**: `ontology/shapes/djr-shapes.ttl:73-88` — ExpressionShape는 `djr:revision`(xsd:integer, minCount 1)과 `prov:specializationOf`(→Work, minCount 1)를 의무로 건다. `djr-shapes.ttl:251-259` — WorkShape의 `djr:currentExpression`은 maxCount 1뿐(minCount 없음)이라 **SHACL은 누락을 잡아주지 못한다**: 절차서 밖에서 즉흥 저작되거나, 조용히 빠진 채 게이트 ④ green으로 통과한 뒤 T1-6에서야 터진다. `workspace/tools/ontology-authoring.md`에도 Expression 채번 절차·revision 초기값 규정이 없다(§5는 Work/ISSUED만).
- **수정 방향**: 절차서 ②를 «Work 채번+**초기 Expression 채번**(Work+이관 일자, `djr:revision` 초기값 확정 — 1 권고, E6 ②의 +1 연쇄 기점, `prov:specializationOf`·`djr:currentExpression` 연결)»으로 확장하고, authoring §13~§15 신설분에 Expression 채번 규약을 포함한다. T1 착수 전 해소 필수 — 파일럿 그래프의 형상 계약이다.

### L1-3 (major) — 게이트 2-1이 동결 완료 기준을 «또는»으로 약화

- **동결 근거**: §8 T1 완료 기준(`blueprint-v3.md:118`) — «파일럿 절 **블록 등가(원문 재구성 일치)**». §3(`:62`) — «렌더 = 블록 순서 연결이라 결정적이고 **원문 등가가 성립한다**»(블록 모델의 자인).
- **표적 실물**: 게이트 2-1 제시 자료(`t1-plan.md:89`) — «라운드트립 diff(**잔차 0 또는 등급 분류**)». T1-4(`:52`)는 «목표는 잔차 0»이라 하고 §6(`:110`)은 «잔차는 등급 분류로 가시화, 은폐 금지»라 하는데, 정작 **통과/실패 규칙이 없다**. 등급 값 공간에는 신규-표현/신규-규범(실질 내용 차이)이 포함되므로, «등급 분류 리포트 제출»이 통과로 읽히면 동결 완료 기준(일치)이 검수표에서 소리 없이 «일치 또는 분류된 불일치»로 바뀐다.
- **수정 방향**: 게이트 2-1에 통과 조건을 문면으로: «통과 = (층① 표기 정준화 한정 적용 후) 잔차 0. 등급 분류는 실패 시의 진단 리포트이며 통과 대체물이 아님 — 잔차 존치 시 블록 모델/렌더러 수리 후 재시도». §6 리스크 행의 «byte 등가 목표»와도 이 문면으로 정렬.

## overall — 자기 기각 목록 (검토했으나 지적하지 않은 것)

1. **골든 ②의 재해석**(산문 소유 절 무단 수정 = corpus lint 관할 확인의 green/red 경계 케이스): 동결 §3 골든 2건 문면(«수기 절 무단 수정·그래프 절 수기 수정»)의 red/green 배정은 명시돼 있지 않고, §7 «미이관 산문 절은 기존 corpus lint 체계 유지»와 계획의 독해가 정합 — 기각.
2. **절/블록 IRI를 djr `#` 네임스페이스(`djr: + s/…`)에 두는 선택**: E6는 절/블록 IRI의 기저를 규정하지 않았고 Work(`djr:R-NNNN`)가 이미 같은 공간이며, RFC 3987 ifragment는 `/`를 허용 — 표준·동결 양쪽 무충돌로 기각. NFC·percent-encoding 최소 집합·`<전체 IRI>` 표기·헤딩 스냅숏 불변·`djr:headingCurrent` 실재(`djr.ttl:129`)까지 전부 실물 정합 확인.
3. **동기 검증기 «[7]단» 번호 충돌 의심**: Makefile 실측 결과 verify-ontology는 [0/6]~[6/6], verify-base는 무번호 — [7]단 편입에 충돌 없음. 기각.
4. **authoring §7(어휘 개정)·§12(열린 결정)·§13~§15 신설 번호 인용 오류 의심**: 실물 헤딩 대조로 전부 정확 확인 — 기각.
5. **SPARQL «N종»을 5종으로 확정한 것**: 동결이 N을 열어 두었고(«규칙→검사기→절 왕복 등») 5종이 예시 축을 포함·상회 — 세부 계획의 정당 재량으로 기각.
6. **T1-3(파일럿)이 게이트 1(센서스 동결) 비의존인 실행 순서**: §4-1 «T1 선행 작업으로 센서스»는 센서스가 T1 내 선행 작업이라는 뜻이고, 밀집 대표는 동결이 직접 지명(ninja §6.2 또는 tdd §5.5)해 센서스 결과에 의존하지 않음 — 기각(단 T3 분모는 게이트 1 의존으로 계획이 이미 옳게 배선).
7. **표류 실증 2건의 T1 내 직접 수정 권고**: 동결 완료 기준은 «처분 확정»이므로 수정 포함은 상회 이행이고, 판별 불가 1건의 T4 진입 조건 이월도 동결 T4 행과 정합 — 기각.
