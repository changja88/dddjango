## 저자의 자인 약점 (여기서 더 나올 것이다)

1. 부속서 4항이 `PENDING` — 동결 미완결
2. seed 재계산이 파이썬 `random` 구현에 의존
3. 동결 그룹 경계가 판단 — `Makefile` 은 동결 밖
4. 부속서의 baseline 테스트 수를 도구가 재검증하지 않음
5. `--self-test` 가 다섯 변이만 봄

## 반드시 확인할 것

1. **탐지 공백**. 동결 대상 자산이 바뀌었는데 `manifest_seal.py --check --draft` 가 green 인
   경우가 있는가. 살펴볼 축: 심볼릭 링크 · 글롭이 안 덮는 파일(예: `dddjango/agents/`,
   `dddjango/skills/`, `codex-dddjango/**` 의 비-scripts 부분) · `__pycache__` 제외 규칙 ·
   대소문자 · 파일 mode/실행 비트 · 빈 디렉터리 · 그룹 사이 경계.
   **가장 값진 발견은 «처치·판정에 영향을 주는데 동결 목록 밖인 파일»이다.**
2. **`--self-test` 가 자기 자신을 시험하는지**. 변이가 사본에만 들어가고 정답이 실물에서
   오는가, 아니면 같은 함수가 양쪽을 만드는가.
3. **배정표 검증**. 3암×3발주×2 = 18 이 맞나. 각 (발주,반복) 블록에 A·B·C 가 정확히
   한 번씩인가. `--allocation` 출력과 manifest `rows` 가 같은가. seed 를 바꾸면 달라지나.
4. **인수 기준의 구멍**. P8·P9 로 인수를 느슨하게 했다 — 그 결과 «망가진 산출물»이 채점에
   들어올 수 있는가? 반대로 인수가 여전히 처치와 상관된 항목을 품고 있는가?
5. **O-5 가 실제로 돌아갈 수 있나**. 인바운드 3 중화 계획(§6)이 충분한가. 라운드 3 의 실제
   장치(`2026-08-12-bc-rebuild-protocol.md` 라운드 3 행)와 대조하라.
6. **t2-plan §2 T2-0b 의 요구 목록과 manifest 를 항목별로 대조**하라. **빠진 항목**을 찾아라
   (도구 lockfile · 모델 ID · 메모리 스냅숏 · 발주 «허용 도구» · T2-3 fragment 등).
7. **`verify-runready` 가 실제로 실런을 막는가**. 막는 것이 무엇이고 안 막는 것이 무엇인가.

실제 강도다.
