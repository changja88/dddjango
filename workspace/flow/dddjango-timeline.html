🔧 수정 모드 — 국소 변경은 풀 파이프라인을 다시 돌지 않는다

기존 파일의 작은 변경이면 영향받는 부분만 짧게. 설계 변경이 없으면 G1′도 건너뛴다. 두 경로 모두 G2 직전 백스톱 19종을 동일하게 돌린다.

discipline-reviewer 미앵커
읽는 법 — 위에서 아래로 정상 진행. 점선 배지는 되돌림 3종류: 사용자 게이트 거부(G0/G1/G2 → 해당 Phase 재실행) · 백스톱 exit2(결정적 차단 → coordinator가 발견 성격대로 설계/coder 반송) · 서브에이전트 보고(인수 Red·잘못된 명세 → 설계/사용자).
조건부·선택 단계(점선 노드) — ＊설계 경량 점검은 명세 복잡 시 coordinator 재량(생략 가능), ＊슬라이스별 감사는 슬라이스가 3개 이상일 때만 돈다(1~2개면 끝의 홀리스틱 감사 1회로 충분).
홀리스틱 감사와 백스톱은 끝에 1회만 돈다(슬라이스마다 아님 — ✅ 전체 1회 박스). 백스톱은 결정적 스크립트라 코드가 완성된 상태에서 봐야 거짓양성이 없다.
같은 지식 스킬이 여러 역할에서 재사용된다 — discipline-*·implementation-*는 감수자 전용이 아니라 작성자(acceptance-tester·coder)도 로드한다.
