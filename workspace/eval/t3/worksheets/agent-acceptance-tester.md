## 0. 배선 정책 (§16 4원 종합의 이 문서 적용판)

이 문서는 «절차 층»(command+agents) 소속이므로 §16 위임 기본값 표의 «command+agents(절차 층) → `command-dddjango`(Coordinator)»가 1차 기본값이다. 그 위에 네 갈래 이탈을 두었고 갈래마다 문면 근거를 §2 표에 남겼다.

- **P-A 절차·입출력 규범**(호출·입력 수령·보고 형식·반송) → `command-dddjango` 단독. 27종 전수 실독 결과 «에이전트 호출·입력 격리·보고 형식»을 보는 검사기가 0이다.

- **P-C 타 소유 명시** → 문면이 다른 역할을 판정 소유자로 지목한 조항만 그 Agent 병기: `agent-coder`(«coder의 몫»·«coder의 단위 테스트 영역») · `agent-design-architect`(«설계로 반송») · `agent-design-review-api`(오류 계약 12-slot 심사판).
- **P-D 기계 절반 + 의미 잔여** → 같은 축을 코드에서 집행하는 검사기가 실재하면 `enforcedBy` 를 병기하고 **미커버 범위를 basis 에 명시**한다. 이 문서의 병기 기준은 «자기 축의 일부 국면에 결정적 술어가 닿으면 병기 + 한계 명기 / 전 국면 미커버면 공란»이다(형제 문서 적대 리뷰 R2-12 처분과 동일 기준).
- **enforcedBy 절제(과잉 배선 방지)**: 축이 반대이거나 술어가 없는 검사기는 병기하지 않고 그 사실을 basis 에 적었다 — `check-mechanism-ownership`(마이그레이션 «파일» 규율이지 «그 파일을 검증하는 테스트»가 아님 · s004 b5) · `check-api-error-controller-contract` 의 helper 축(«helper 경유 매핑 구현 금지»이지 «helper 를 테스트하는가»가 아님 · s004 b15·b20) · `check-ninja-boundary-middleware`(담당 술어가 `settings.MIDDLEWARE` 자가등록 하나뿐이라 함수형 `Router` 형태에 발화 불가 — 형제 문서 R2-5 수리 판정 승계 · s004 b22) · `check-idempotency-scope-creep`(대상이 «멱등성 코드 산출물»이라 테스트 케이스의 스코프 초과에 발화 불가 · s005 b3) · `check-test-config` 의 pytest «채택 강제» 축(docstring 이 «설정이 아예 없는 것(manage.py test 관례)은 위반이 아니다»라고 자기 비커버를 선언 · s004 b23) · **`check-error-centralization` 의 preserve 자기 한정 선언**(«Positional-only, `auto`, and `preserve-established` invocations do not apply schema semantics» — 검사기가 *자기 실행에서* schema 의미를 적용하지 않는다는 **비집행 선언**이고, 실장 `_is_production_path` 가 `test`/`tests`·`test_*`·`*_test.py`·`conftest.py` 를 전수 배제해 이 규범의 위반 표면인 «테스트»에 구조적으로 발화 불가 · s004 b19 — [adv W3-2 처분: 초판은 이 선언을 «기계 실현»으로 뒤집어 읽어 병기했고 철회했다]). 반대로 문면·docstring 근거가 있는데 기본값으로 도피한 자리는 0건이다.
- **«절제 선언 = 커버» 금지선(선행 판례 승계 · W3-2 처분으로 명문화)**: 검사기 docstring 이 «나는 이 축을 보지 않는다/적용하지 않는다»고 선언한 문장은 그 축의 기계 실현이 **아니다**. 병기가 서려면 위반 표면에 실제로 닿는 **긍정 술어**가 있어야 하고, 대상 산출물(코드 ↔ 테스트 ↔ 명세)이 규범의 심사 대상과 같아야 한다 — 형제 판례 R2-7(비집행 선언 → 검사 공백 명기)·api F9(비발화 검사기의 E 병기 기각)와 같은 선이다.

## 4. 경계 판단 메모 (블록 경계·kind·계수의 애매점과 근거)

- **① (전문) 절의 프론트매터 처리**: s001 의 헤딩 라인은 `---`(YAML 여는 구분자)이고 도구가 그 한 줄을 `djr:headingSnapshot` 으로 가져간다. 나머지는 §13 자연 단위로 잘랐다 — `name:`(b1) · `description:`(b2 · 규범 4) · `tools:`(b3) · `skills:` 키+목록 5행(b4 — 한 덩이) · 닫는 `---`+빈 줄(b5) · 본문 문단+빈 줄(b6 · 규범 2). **kind=code 를 쓰지 않은 이유**: §13 은 code 리터럴을 «여는 펜스~닫는 펜스»로 한정하는데 프론트매터엔 펜스가 없다 — 웨이브 2 판례대로 행 단위 prose/norm 으로 처분했고, 형제 문서 `agent-coder`/s001 판형과 동일하다.
- **② 블록 간 구분자 귀속**: §13 대로 빈 줄은 **선행 블록의 후행 스팬**에 붙였고(s002 b1 = L16–18 등), 절 선두 구분자만 첫 블록 선두에 귀속시켰다. 절 끝 빈 줄은 마지막 블록이 삼킨다(s004 b23 = L47–48 · s001 b6 = L13–14). 도구의 «헤딩+블록 연결 == 절 스팬» 단언이 통과해 byte 등가가 기계 확인됐다.
- **③ 불릿 목록의 블록 단위**: 리스트 항은 **항목당 한 블록**(§13). s004 23항·s005 4항이 각각 한 블록이고, 한 블록 안의 여러 규범 문장은 `djr:statesNorm` 다중 연결로 각자 Work 를 가리킨다(행 중간 분할 없음 — byte 등가 불변).
- **④ 같은 문서 안 재진술 판정(spec `restates` 0건)**: 세 쌍을 심의했다. ⑴ s001 b2-4(«구현 코드는 쓰지 않는다») ↔ s003 b1-4(«코드·내부 단위 테스트는 쓰지 않는다») ↔ s005 b1-1(«구현 코드·내부 단위 테스트를 쓰지 않는다(coder의 몫)») — **동축 3각**이지만 블록 사본은 아니다(b2 는 규범 4개가 동거하는 프론트매터 한 줄, b1 은 산출 문단, s005 b1 은 독립 불릿). ⑵ s001 b2-3(«구현을 보지 않는 블랙박스») ↔ s002 b1-5(«프로덕션 구현 코드를 보지 않는다») — 부분 중첩(후자는 대체 근거 «기존 테스트와 승인 계약만»을 덧붙인 한정판). ⑶ s004 b13(L37 12-slot)의 STOP 조항(Work #47) ↔ s004 b19(L43 preserve)의 evidence 요구(Work #61) — 같은 profile 축의 다른 국면. `djr:restates` 는 블록 대 블록 관계라 세 쌍 모두 성립하지 않아 미기입하고, 대신 **일곱 꼭짓점 Work 전건(3+2+2)의 basis 에 동축 표시를 실제로 기입했다**(api 판 F8·F10 처분의 «전 꼭짓점 태그» 판형).
  - **소급 패스 통합 후보**(api 판형 승계 — 아래 좌표가 소급 패스의 유일 입력이다): ⑴ **Work #4 ↔ #15 ↔ #81**(구현 코드 금지 3각) · ⑵ **Work #3 ↔ #11**(블랙박스 ↔ 프로덕션 코드 열람 금지) · ⑶ **Work #47 ↔ #61**(shape 승인 evidence ↔ RFC 종료 evidence).

- **⑤ 무규범 prose 판정의 근거**: `tools:`·`skills:` 는 기계 설정 값(에이전트 런타임이 읽는 필드)이라 규범 문장이 아니다 — 선행 저작본 3건(`agent-coder`·`agent-design-architect`·`agent-design-review-api`)의 동일 판정을 승계했다. 본문 L13 의 1문째(역할 선언)와 4문째(«너의 블랙박스 독립성이 …»)도 술어가 «…다»의 서술이라 무규범으로 뒀고, 그 대신 같은 취지의 «구현 미열람» 의무는 b2-3·s002 b1-5 의 Work 가 진다.
- **⑥ class 판정 기준**: 조건 한정·carveout 문장은 `Exception`(s004 b2-2 충돌 예외 · b8-1 기존 migration 테스트 처분 · b14-1 별도 승인 한정 · b16-1 framework-owned smoke 한정 · b19-2 RFC 한정 · b23-1 러너 확인 조건), 금지 술어는 `Prohibition`, 허용 상한 술어는 `Permission`(s004 b16-2 field 한정 exact 단언 1건뿐), 나머지는 `Obligation`. **`Override` 는 0건**이다 — 이 문서에는 다른 규범을 우선해 무르는 문장이 없다(형제 문서 `agent-coder` 는 «예외 없음 — pytest-django가 기존 `TestCase`도 수집»류 문면이 있어 Override 4건이 섰지만, AT 판 L47 은 «만들지 않는다»는 금지형이라 Prohibition 이 맞다).
