한 줄 판정

같은 최소 스택에서 양쪽 모두 완전한 §0 4계층 구조를 생성하고 빌드도 전부 통과했다. 그러나 플러그인 표준 준수도 기준으로 claude-1이 명확히 우수하다. 격차의 본질은 구조 생성력이 아니라 리뷰·감사 깊이 — Claude 파이프라인은 ① 도메인 빈혈(죽은 코드), ② 핵심 불변식 DB 제약 누락, ③ race 잔여보고 버그를 모두 리뷰/감사 단계에서 잡았고, Codex 파이프라인은 ①②를 통과시켰다. Codex가 앞선 항목은 API Problem Details와 예외 계층화 2개뿐이다.

한계 (단정 금지)

  • 각 N=1. Claude의 감사 우위가 결정성(매 런 그러함)인지 이번 런 운인지 미확정. 단 빈혈·CHECK 누락·race 세 독립 지점에서 일관된 방향이라 시사적.
  • 다음 단계: codex 2~3회 반복으로 감사 격차의 재현성 확인(특히 빈혈·stock≥0을 매번 놓치는지).
  • 개선 과제 후보: 재현되면 codex 쪽 discipline-reviewer / design-review-ddd 스킬 본문을 보강(도메인 죽은 코드·설계-코드 제약 누락 포착). 공통 코퍼스라 Claude·Codex 양쪽에 반영된다.
  • 포트 메커니즘 충실도(spawn_agent 역할분리·게이트·설치)는 별도로 이미 입증됨 — 본 문서는 코드 품질에 한정.
