- **R0′ 폴더**: slug = `refactor-<단위 케밥>`(예: `refactor-home` · `refactor-static-images` · `refactor-web-py`) · 폴더 이름은 `<date +%Y%m%d-%H%M>-<slug>`. 후보는 slug 가 같은 폴더뿐이다 — 있으면 그것만 보이고(끝난 실행 뒤의 새 점검은 그 폴더 재사용 · 6a 재사용 폴더 규칙대로 `debt-g0.json` 교체), 없으면 새 폴더를 R1 전에 만든다.
- **새 점검의 build-state 초기화**(X2 m9): 재사용 폴더에서 새 점검을 시작하면 build-state 의 실행 필드(`phase`·`slices`·`g1_approved`·`g2_approved`·`pre_run_head`·`git_snapshot`·`check_baseline`·`test_baseline`)를 초기화하고 `mode: refactor` 로 쓴다(«복원» `:144` 가 앞 실행의 `g2_approved: true` 를 남기면 새 실행이 곧바로 «끝남»으로 읽힌다).
- **끝남**: 리팩토링 실행은 `g2_approved: true` 면 끝났다. Phase 3 합치기 도중 끊김은 기존 Phase 3 복구 규칙이 다룬다. 끝난 폴더의 새 요청은 새 점검이다.
- **잇기**: build-state `mode: refactor` 이고 G0 가 승인됐고(`## G0` 절 있음) 끝나지 않았으면 잇는다 — R2·R3 를 다시 돌리지 않고 그 audit 의 `verdict.md` 를 그대로 쓴다(M 목록 동결 · `debt-g0.json` 도 그 요청의 동결본 그대로).
- **G0 전 끊김**: `mode: refactor` · G0 절 없음 · 정지 절 없음(R1~R3 도중 세션이 죽음) → 새 점검이다.
- **표지 없는 잇기**: 표지 없는 `/dddjango-web:dddjango-web` 으로 `mode: refactor` 폴더를 «기존 폴더 이어서»로 고르면 그 순간부터 리팩토링 모드다(그때까지의 일반 모드 Phase 0 산출은 버린다). 기능이 섞였으면 G0 정지로 기록하고 기능은 따로 요청하라고 안내한다.
- **G0 정지 재개**(dddjango 대칭 · X1 B2 보정 · X2 m10 은 기각 — 부록 B): 리팩토링 실행의 `## G0 정지 <시각>` 절에 `의미 audit: <R2 시각>` 행을 적는다(§6). 같은 폴더에서 다시 시작했고 최신 기록이 이 정지이면, R1 을 다시 돈 뒤 **아래 넷이 모두 성립할 때만** `check-verdict` 를 다시 돌려 exit 0 이면 audit·verdict 를 재사용한다. 하나라도 어긋나면 새 점검이다.
  1. 그 audit `plan.md` 에 `범위 미커밋 변경 0` 이 적혀 있다.
  2. 범위 파일이 그 HEAD 이후 바뀌지 않았다(`git diff --quiet <그 HEAD> -- <범위 경로…>` — 작업 트리 포함).
  3. 범위 경로에 새 파일이 없다(`git ls-files --others --exclude-standard -- <범위 경로…>` 빈 결과).
  4. **`plan` 을 다시 돌린 결과**(범위 파일 목록 · 경계 교차 목록 · 경계 교차 소비자 목록 · 줄 편집 목록 · 참조 치환 줄 목록 · 범위 안 **키 문자열** 목록)가 그 audit `plan.md` 와 같다.
  - 재사용 거부(«새로 점검»)는 사용자 본인 직접 답만 받는다.
  - 이 재사용의 주 사용처는 «출처 없는 ⓑ 정지 → 사용자 본인 답으로 재개»다(6a W-T4 모양). R2 1회($20~65 · 30분 안팎)를 아낀다.

## 3. 대상 단위 · 점검 범위 · 스캔 단위

### 3-1. 범위 파일

- **단위 파일**: 대상 단위 아래 git 우주(6a `debt_universe` 와 같은 우주 — 바이트코드 제외).
- **전속 정적 파일**(대상이 영역 `web/<area>/` 일 때만): `web/static/**` 파일 f 의 **참조 줄**은 6a 참조 완전성의 꼬리 대조가 적중한 줄이다 — `git grep -n -F -e <f 의 꼬리> -- web '*.py' '*.html' '*.css' '*.js' ':(exclude).dddjango-web'`(꼬리 규칙 = `:211` · `static/` 접두 제거). 한 명령으로 `{% static %}` · `{% include "static/…" %}`(HTMX 선언) · CSS `url()` · 템플릿 이름 문자열이 모두 잡힌다. 참조 줄 중 **web/ 아래 파일만** 소유 판정에 쓴다(web/ 밖 줄은 §7-2 치환 후보 목록).
- **참조 파일의 소유자**: web/ 아래 참조 파일 r 의 소유자는 r 이 `web/<area>/` 아래면 그 영역, `web/static/` 아래 정적 파일이면 **r 자신의 소유자**(같은 규칙을 다시 적용 · 순환은 «정적 단위 몫»), 그 밖(base · design_system · client · 컨테이너)은 «비영역».
- **판정**(f 마다 하나 · **위에서부터 처음 맞는 행** · `plan` 이 결정적으로 매기고 규칙 이름과 참조 줄을 적는다 · X2 m1):

| 순서 | 판정 | 조건 | 몫 |
|---|---|---|---|
| 1 | 무참조 | 참조 줄 0 · 또는 참조 줄은 있으나 모든 참조 파일의 소유자가 비었음(무참조 정적 파일만 가리킴) | 정적 단위 실행 |
| 2 | 비영역 참조 | 소유자에 «비영역»이 하나라도 있음(base 전역 로드 · design_system 주석·참조 · 영역 1 + 비영역 — 현장 `wonbo.png` · `toast.js` · `choice_pair.js`) | 정적 단위 실행 |
| 3 | 경계 교차 | 소유자에 영역이 둘 이상 | 정적 단위 실행 · 영역 실행 `plan.md` 에 목록 |
| 4 | 영역 전속 | 소유자가 모두 한 영역 | 그 영역 실행 범위(에도) |

- **이중 범위**(X2 m2): 정적 단위 실행의 범위는 그 단위의 파일 **전부**이고, 영역 실행의 범위는 영역 단위 + 그 영역 전속 정적 파일이다. 영역 전속 파일은 두 실행 모두의 범위다(몫 열은 배타가 아니다).
- **이름 전속은 두지 않는다**(X1 M2): 현장 적중은 `conversation.js` 1건이었고 그 파일은 home 에서도 돈다(`home.html:13` include 사슬). base 전역 로드 파일은 모두 `web/static/js` 단위 실행의 몫이다.

### 3-2. 키의 범위 소속 (X1 M1 · X2 M2(a) · X3 M3)

키 `검사|경로`(경로는 web 기준 상대)가 범위 안이려면 다음 중 하나다:

1. 경로가 대상 단위 접두(`<단위>/`) 아래이거나 **단위 폴더 자체**(`…/` 로 끝나는 폴더 키 — WS3·WS4·WS5·WS6·WS7 발견은 폴더 경로다 · `check_structure.py:43·83·124·136·225·237·250`).
2. 경로가 **빈 문자열**(WS5 컨테이너 발견 `:215`)이고 대상이 컨테이너 단위(`web/*.py`)다.
3. 경로가 전속 정적 파일 목록에 있다(영역 실행).
4. **편집 줄의 기존 발견**(6a `:150` 묶음의 대응): `plan` 이 §3-3 줄 편집 목록과 **개명·이동 참조 치환 줄**(범위 파일 중 개명·이동 교정 대상 키 파일의 꼬리로 6a 참조 완전성 grep 을 돌린 적중 줄 — web/ 아래)을 `debt-g0.json` findings 의 `path`·`line` 과 대조해, 그 줄에 걸린 **WI·WP** 발견의 키를 범위 안 키에 더한다(«편집 줄 키» 표시). 치환한 줄은 G2 diff 게이트에서 새 줄이 되어 그 줄의 기존 WP 가 red 가 된다 — 6a 픽스처 D16b(`fixtures_debt.sh:324`)가 고정한 모양이다.
   - **키 전체 편입**(X3 M3): 편집 줄 키가 되면 그 키의 **발견 줄 전부**를 `plan.md` 줄 편집 목록에 더한다(«키 전체 줄» 표시 · 그 줄들의 **내용 교정만**). 잔존 판정(`--debt-residual`)은 키 단위(`검사|파일`)라, 편집 줄 하나만 고치면 같은 파일 다른 줄의 같은 검사 발견이 `ⓐ 잔존` 으로 남아 재상정 STOP 으로 간다 — 6a 기능 요청은 참조 파일의 단위를 스캔 단위에 넣어 키 전체를 고치므로 결과를 맞춘다. §3-4 범위 밖 편집 대조와 DR 슬라이스 0 대조도 이 목록을 쓴다.
   - «편집 줄 키는 잔존 판정에서 편집 줄만 본다» 갈래는 러너 키 계약을 바꾸므로 걷는다.

- 리팩토링 스캔이 새로 켜는 WS5 키가 폴더·빈 경로 모양이다 — 파일 목록만으로 고르면 G0 에 묻지 않고 «정리 끝»으로 닫힌다(fail-open). W6-T4 에 합성 골격 미비 단위를 둔다.
- 편집 줄 키는 C 빚이다(G0 ⓐ/ⓑ 대상). 그 줄의 발견이 개명·이동 교정이 아니라 내용 교정(WI·WP)이면 슬라이스 0 이 그 줄을 치환하면서 함께 고친다(6a 묶음과 같다). 동작 불변으로 못 고치면 그 개명·이동도 빼고 `ⓐ 재상정`(6a `:150` 끝 문장 그대로).

### 3-3. 경계 교차 소비자 · 줄 편집 범위 (X1 M2 (b) · M3 · X2 m3 · X3 M5)

- **경계 교차 소비자**: `plan` 이 범위 템플릿의 이름 문자열(꼬리)로 같은 grep 을 돌려, 범위 밖 영역 템플릿의 `{% include %}`·`{% extends %}` 줄을 «경계 교차 소비자» 목록으로 `plan.md` 에 적는다(현장: `web/home/home/view/home.html:13` → consultation `conversation_mount.html`). 그 페이지는 G2 영향 화면이다(범위는 늘지 않는다).
- **줄 편집 범위**(도9): 아래 줄은 어느 단위 파일에서든 편집 범위다 — **그 줄만**.
  - (가) 로드·include **줄**(`<script src>`·`<link>`·`{% include %}`)이 ① 범위 파일을 가리키거나 ② 범위 파일 안에 있을 때. 편집은 셋 중 하나다:
    - 그 줄을 지운다.
    - 그 줄을 옮긴다.
    - 같은 대상을 가리키는 줄을 다른 단위 페이지 템플릿의 `{% block scripts %}` 또는 `{% block styles %}` 에 더한다 — 그 블록이 없으면 **그 블록 1개를 신설**하는 틀(`{% block scripts %}{% endblock %}` 두 줄)까지 포함한다. 그 밖의 블록·구조 편집은 범위 밖이다.
  - (나) **명세 참조 줄**(X3 M5): Phase 1 명세 슬라이스 0 절의 개명·이동 쌍과 `이름:` 행이 가리키는 **web/ 아래** 참조 줄 — 옛 경로 꼬리 · 옛 모듈 점 경로 · 옛 이름(`이름:` 행의 끝 성분 · 단어 경계)으로 6a 참조 완전성 grep 을 돌린 적중 줄. 편집은 **참조 문자열 치환만**(import 줄의 모듈·이름 · 템플릿 이름 문자열 · `{% static %}` 경로). 현장 예: `web/employee_choice/…/employee_choice_view_model.py:51` 의 `redirect_if_employee_unset` 을 옮기면 6개 영역 VM 의 import 줄이 이 목록에 든다.
  - (다) §3-2 4 «키 전체 줄» — 내용 교정만.
  - `plan.md` 가 R0 시점의 (가)·(다) 목록을 적고, (나)는 G1 배너 직전 §3-4 대조가 명세로부터 계산해 `refactor-scope.md` 에 적는다(같은 6a grep 명령 · exact command·exit). 편집된 페이지는 G2 영향 화면이다.
  - (나) 줄에 걸린 WI·WP 발견은 편집 줄 키이고(§3-2 4 규칙 — 키 전체 줄 포함), R0 목록에 없던 것이라 6a `:193` 재승인 기구대로 `## G0 재승인` 빚 질문에 올린다(재스캔 없음 · `debt-g0.json` 에서 뽑음).
- **예**: 진단의 «화면 기능 JS 의 base 전역 로드»(`base.html:32-40`). `web/static/js` 실행에서 `base.html:40`(`conversation.js` 로드 줄 — 범위 파일을 가리킴)을 지우고, 그 기능을 쓰는 페이지 **모두**(consultation 페이지 · `home.html` — `home.html:13` 이 include 하는 `conversation_mount.html` 이 쓴다)의 scripts block 에 같은 로드 줄을 더한다. `record_detail.html` 처럼 scripts 블록이 없는 페이지는 블록 틀 신설까지다[X2 실측].
- **순환 없음**: (가)가 로드 줄 순환을, (나)가 정의 이동·모듈 개명의 교차 단위 import 순환(`redirect_if_employee_unset` 류 — 소비 단위 실행이 정의 쪽을 못 고치고 정의 쪽 실행이 소비 줄을 못 고치던 것)을 닫는다. 이 둘이 있어야 «두 실행이 서로를 경계 교차로 넘기는 순환이 없다»가 참이다.
- 그 줄 밖(다른 단위 템플릿·모듈의 본문 구조)을 고쳐야 하면 §4-4 «경계 교차»다.
- **확인**(새 장치 아님 · X2 m3): 5번 규율 감사(discipline-reviewer-web)의 슬라이스 0 대조에 1항 — «범위 밖 파일의 diff 는 줄 편집 목록 (가)·(나)·(다) · 참조 치환 줄 · 허용된 블록 틀 · web/ 밖 테스트 치환뿐이고, (나) 줄은 참조 문자열 치환뿐이다». 기존 감사 항목으로 싣는다.

### 3-4. 리팩토링 모드의 스캔 단위 · `:193` (X2 M2(b)(c) · X3 M5)

- **스캔 단위** = 대상 단위(+ 영역이면 전속 정적 파일). 줄 편집·참조 치환 파일의 단위(auth · design_system · 영역 페이지 · 소비 영역 VM)는 스캔 단위가 아니다 — 그 파일에서 범위 안인 것은 §3-2 4번의 편집 줄 키(와 그 키 전체 줄)뿐이다.
- **`:193` 스캔 단위 확인의 리팩토링 판**(끝 절이 앞 절을 바꾸는 곳 — §2-1 단조성): 리팩토링 모드에서 G1 배너 직전 확인은 «밖의 단위의 키를 뽑아 G0 재승인 빚 질문»을 단위 통째로 내지 않는다. 대신
  1. 명세로부터 §3-3 (나) 명세 참조 줄을 계산해 `refactor-scope.md` 에 적고,
  2. 명세의 범위 밖 편집이 모두 줄 편집 목록 (가)·(나)·(다) · 참조 치환 줄 · 허용된 블록 틀 · web/ 밖 테스트 치환 파일(§7-2) 안인지 대조해, 밖이면 architect 에 반송하고(명세에서 빼거나 «별도 요청 — 경계 교차»로),
  3. (나) 줄의 편집 줄 키만 `## G0 재승인` 빚 질문에 올린다(6a 재승인 기구 · 결정 출처·기록 정형 그대로).

## 6. G0 기록 정형 확장 — M 항목 행 (X1 M5 · X2 m4)

  - **경로 쌍**: `git diff -M --name-status <기준>..<대상> -- web/` 의 개명 쌍(6a 참조 완전성이 이미 쓰는 명령). 꼬리 규칙은 6a 와 같다(`static/` 접두 제거 · `.py` 는 점 경로도).

- **대조**(web/ 밖 변경 파일마다):
  - **`.py` 파일 — import 는 바인딩에 쌍을 적용한다**(X3 M1):
    1. 기준 파일과 대상 파일을 **원문 그대로** `ast` 로 파싱한다(파싱 실패는 exit 1).
    2. 각 블록(모듈 · 함수 본문 · `if TYPE_CHECKING:` 본문 · `try:` 본문 …)의 **연속 import 문 구간**을 바인딩으로 펼친다: `from M import a, b as c` → `M.a`·`M.b as c` · `import M` → `M` · `import M as x` → `M as x`.
    3. **대상 쪽 바인딩**마다 쌍의 역치환(새 → 옛)을 적용한다 — 점 경로 전체 쌍(`N.b → M.b`) · 경로·폴더 점 경로 쌍(접두) · 맨 이름 쌍은 `as` 별칭 없는 바인딩의 끝 성분에. 블록별 구간 바인딩의 **다중집합**이 기준과 같아야 한다(한 줄 import 가 두 줄로 갈라지거나 재정렬된 것은 green · 블록 사이 이동은 red — 현장 `test_user_info_employee_gate.py:97-98` 은 «URLconf 선적재 뒤 import» 순서에 의미가 있어 옳은 red 다).
    4. **import 문 밖**은 대상 파일의 텍스트 역치환본(모든 쌍 · 긴 것부터 동시에 · 단어 경계)을 파싱해 import 구간을 뺀 `ast.dump` 로 기준과 같아야 한다.
    - v3 의 «텍스트 역치환 먼저 → 파싱» 순서는 `from N import b` 텍스트에 `N.b` 문자열이 없어 점 경로 이름 쌍이 걸리지 않았다(정의 이동 치환이 red · X3 `x3-a`·`syn/` 실측).
    - 남는 거짓 red: `import N` 모듈 별칭 방식으로 새 모듈을 들이면 바인딩이 하나 늘어 red 다(현장 테스트에 부수효과 import 1건 `tests/web/auth/conftest.py:14` 뿐) — fail-closed 로 둔다.
  - **그 밖 파일**: 더한 줄들의 역치환 결과가 지운 줄들과 **줄 다중집합으로 같다**(6a 판 · 한 줄 다중 치환·재정렬 green).
