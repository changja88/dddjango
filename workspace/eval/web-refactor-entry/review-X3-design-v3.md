## Blocker

### B1. ⑤ «실패한 테스트 식별자» 비교가 모듈 수준 import 파손(수집 오류)과 fail-fast 명령에서 green 으로 샌다 (§7-1 :261 · :268 · W6-T13 :370)

⑤ 는 X2 B1(정의 이동이 web/ 밖 테스트를 깨도 모든 게이트가 green)을 막으려고 들인 장치다. 그런데 비교 단위가 «실패한 테스트 식별자 목록»이라, 현장에서 가장 흔한 파손 모양을 못 센다.

- **수집 오류는 식별자가 없다** [실측 — `sds` 가지 `x3-c`]
  - 테스트가 import 하는 비공개 상수 `_BG_SESSION_KEY` 를 `signup_view_model.py` 에서 개명했다(테스트는 그대로다).
  - 현장 명령의 플래그(`-rF -n0 --maxfail=1 -m "not postgresql"`)로 `tests/web/auth` 를 돌렸다.
  - 결과는 `Interrupted: 2 errors during collection` · `54 deselected, 2 errors` · exit 2 다. 실행된 테스트는 0이고 `FAILED` 행도 0이다. `-rF` 는 ERROR 요약을 내지 않는다.
  - 문면대로 «실패 식별자»를 세면 «지금 실패 − 기준선 실패 = ∅» 이 되어 green 이다.
- **이 모양이 주류다**
  - 현장 테스트의 web import 는 모듈 머리 `from web.` 가 357행이고, 함수 안 지역 import 는 1행이다(X2 가 쓴 `test_user_info_employee_gate.py:98`) [실측].
  - W6-T13 은 그 1행으로만 합격을 보므로 이 구멍을 통과시킨다. 그 경우는 호출 시점 ImportError → FAILED 식별자로 나온다.
- **fail-fast 명령은 기준선 실패가 새 실패를 가린다** [실측 — 가지 `x3-b`]
  - 현장 Makefile `testp`(:48-50)는 `-m postgresql --maxfail=1 && -m "not postgresql" --maxfail=1` 이다.
  - 실험: 기준선에 무관 실패 1건(`tests/web/auth/test_env_baseline_fail.py`)을 두고, 슬라이스 0 으로 `_render_page` 정의 이동을 넣었다(테스트 미치환).
    - `--maxfail=1` 로 돌리면 기준선·이후 모두 `FAILED …test_env_dependent_baseline_failure` 1건에서 멈춘다. 차집합은 0 이라 green 이다.
    - 같은 명령에서 `--maxfail` 만 빼면 `FAILED tests/web/intake/test_user_info_employee_gate.py::test_render_page_redirects_when_employee_choice_required` 가 새로 나온다.
  - `&&` 연쇄에서는 postgres 단계가 기준선에서 실패하면 DB 없는 단계(`tests/web` 대부분)가 아예 돌지 않는다.
  - 설계는 «기준선 실패(무관 실패)는 보고만»(:268)이라며 기준선 실패가 있는 경우를 전제한다. 바로 그 경우에 ⑤ 가 무력하다.
- **고칠 곳·고칠 말**(§7-1 :261 · :268 — 새 장치 없음, 같은 명령의 실행 규칙)
  - 두 번째 명령 규칙: «⑤ 의 두 실행은 실패를 끝까지 센다. 프로젝트 명령이 여러 단계(`&&`)면 단계마다 따로 돌리고, fail-fast 옵션(`-x`·`--maxfail`)은 떼며, 수집 오류가 나도 나머지를 돌린다(`--continue-on-collection-errors`). 쓴 명령 원문을 `test_baseline` 에 적는다.»
  - 식별 규칙: «실패 = FAILED·ERROR 노드 id(수집 오류는 그 모듈 경로) — 요약은 `-rfE` 로 받는다. 기준선 실행이 중도 정지(`Interrupted`·maxfail)로 끝났으면 기준선 불성립이다. green 이 아니라 «⑤ 판정 불가»로 보고한다.»
  - W6-T13 에 «모듈 머리 import 미치환(`_BG_SESSION_KEY` 개명) → 수집 오류 = 새 실패 → ⑤ red»와 «기준선 무관 실패 + fail-fast 명령 → 끝까지 센 실행에서 새 실패 red»를 더한다.

## Major

### M1. `--subst-check` 의 ast 정규형이 텍스트 역치환 뒤에 파싱해서, 정의 이동의 import 치환을 red 로 낸다 (§7-2 :282-283 · W6-T8 :365 · W6-T13 :370)

- **문면**: «모든 쌍의 역치환을 … 동시에 적용 → `.py`: 기준 파일과 «대상 파일의 역치환본»을 `ast` 로 파싱해 정규형을 비교». 순서는 텍스트 → 파싱 → 바인딩 펼침이다.
- **왜 깨지나**
  - 이름 쌍은 점 경로 전체(`M.a → N.a`)다. 그런데 `from N import a` 텍스트에는 `N.a` 문자열이 없어 역치환이 걸리지 않는다.
  - 끝 성분이 다르면 맨 이름 쌍(`new → old`)만 걸린다. 그러면 `from N import old` 가 되고, 바인딩 `N.old` 는 기준 `M.old` 와 다르다.
- **실험** [실측 — `subst_v3.py` 문면 모드 `text` / 대안 모드 `binding`]
  - 현장 가지 `x3-a`: `_render_page` → `user_info_page.render_user_info_page` 정의 이동에 테스트 import·호출을 치환했다(`names.txt` 에 `이름:` 1행). 결과는 `text` exit 2 · `binding` exit 0 이다.
  - 합성 `syn/`: 설계 W6-T8 사례 그대로(`from web.a.m import a, b` → `from web.a.m import a` + `from web.a.n import b`, 거기에 `TYPE_CHECKING` 블록 import 와 함수 안 지역 import 를 더함). 결과는 `text` exit 2 · `binding` exit 0 이다.
  - 대안 모드에서는 지역·`TYPE_CHECKING`·조건부 import 모두 블록별로 맞게 green 이다.
- **결과**: 문면대로 구현하면 ④ 가 정당한 치환을 막는다. M 항목의 대표 정리(정의 이동 · 테스트가 참조하는 비공개 이름 `_render_page`·`_ALL_SPIRITS`·`_Carried`)는 모두 ⓐ 재상정 STOP 으로 간다. fail-closed 지만 리팩토링 모드의 주 용도를 막는다.
- **고칠 말**(§7-2 :283): «`.py` 파일: import 문은 **원문 그대로** 파싱해 바인딩(`M.a`·`M.b as c`·`M as x`)으로 펼친 뒤 바인딩마다 경로·이름 쌍의 역치환을 적용하고, 블록별 연속 import 구간의 다중집합을 비교한다. import 문 밖은 텍스트 역치환본을 파싱해 `ast.dump` 로 비교한다.»
  - 남는 거짓 red: `import N` 모듈 별칭 방식으로 새 모듈을 들이면 바인딩이 하나 늘어 red 가 된다. 현장 테스트에는 이 방식이 부수효과 import 1건(`tests/web/auth/conftest.py:14`)뿐이라 fail-closed 로 둔다.
