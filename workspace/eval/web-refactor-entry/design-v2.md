### 2-3. R0 대상 · R0′ 폴더 · 잇기 · 끝남 · G0 정지 재개

- **R0 대상**: `대상:` 인자에서 단위를 정확히 1개 읽는다. 표기는 `web/` 기준 경로(`web/home` · `web/static/images` · `web/design_system` · `web/base` · `web/client/orders` · 컨테이너는 `web/*.py`) · 끝 `/` 무시 · 6a 단위 목록(`:148`)에 맞고 실재해야 한다. 없음 · 2개 이상 · 단위 안쪽 경로 · 불편 서술이 새 동작·새 계약을 요구함(기능 혼입)이면 폴더·기록 없이 입구에서 멈추고 사용법을 안내한다.
- **R0′ 폴더**: slug = `refactor-<단위 케밥>`(예: `refactor-home` · `refactor-static-images` · `refactor-web-py`) · 폴더 이름은 `<date +%Y%m%d-%H%M>-<slug>`. 후보는 slug 가 같은 폴더뿐이다 — 있으면 그것만 보이고(끝난 실행 뒤의 새 점검은 그 폴더 재사용 · 6a 재사용 폴더 규칙대로 `debt-g0.json` 교체), 없으면 새 폴더를 R1 전에 만든다.
- **끝남**(X1 m2): 리팩토링 실행은 `g2_approved: true` 면 끝났다. Phase 3 합치기 도중 끊김은 기존 Phase 3 복구 규칙이 다룬다. 끝난 폴더의 새 요청은 새 점검이다.
- **잇기**: build-state `mode: refactor` 이고 G0 가 승인됐고(`## G0` 절 있음) 끝나지 않았으면 잇는다 — R2·R3 를 다시 돌리지 않고 그 audit 의 `verdict.md` 를 그대로 쓴다(M 목록 동결).
- **G0 전 끊김**(X1 m2): `mode: refactor` · G0 절 없음 · 정지 절 없음(R1~R3 도중 세션이 죽음) → 새 점검이다(audit 재사용은 G0 정지 재개에만 있다).
- **표지 없는 잇기**: 표지 없는 `/dddjango-web:dddjango-web` 으로 `mode: refactor` 폴더를 «기존 폴더 이어서»로 고르면 그 순간부터 리팩토링 모드다(그때까지의 일반 모드 Phase 0 산출은 버린다). 기능이 섞였으면 G0 정지로 기록하고 기능은 따로 요청하라고 안내한다.
- **G0 정지 재개**(dddjango 대칭 · X1 B2 보정): 리팩토링 실행의 `## G0 정지 <시각>` 절에 `의미 audit: <R2 시각>` 행을 적는다(§6). 같은 폴더에서 다시 시작했고 최신 기록이 이 정지이면, R1 을 다시 돈 뒤 **아래 넷이 모두 성립할 때만** `check-verdict` 를 다시 돌려 exit 0 이면 audit·verdict 를 재사용한다. 하나라도 어긋나면 새 점검이다.
  1. 그 audit `plan.md` 에 `범위 미커밋 변경 0` 이 적혀 있다.
  2. 범위 파일이 그 HEAD 이후 바뀌지 않았다(`git diff --quiet <그 HEAD> -- <범위 경로…>` — 작업 트리 포함).
  3. 범위 경로에 새 파일이 없다(`git ls-files --others --exclude-standard -- <범위 경로…>` 빈 결과).
  4. **`plan` 을 다시 돌린 결과**(범위 파일 목록 · 경계 교차 목록 · 경계 교차 소비자 목록 · 줄 편집 목록 · 범위 안 **키 문자열** 목록)가 그 audit `plan.md` 와 같다 — 범위 파일의 diff 없이도 다른 영역 템플릿의 참조 추가로 소속이 바뀔 수 있고, 새 `debt-g0.json` 의 번호는 web/ 전체 정렬이라 밀릴 수 있다[X1 실측].
  - 재사용 거부(«새로 점검»)는 사용자 본인 직접 답만 받는다.

## 3. 대상 단위 · 점검 범위

### 3-1. 범위 파일

- **단위 파일**: 대상 단위 아래 git 우주(6a `debt_universe` 와 같은 우주 — 바이트코드 제외).
- **전속 정적 파일**(대상이 영역 `web/<area>/` 일 때만): `web/static/**` 파일 f 의 **참조 줄**은 6a 참조 완전성의 꼬리 대조가 적중한 줄이다 — `git grep -n -F -e <f 의 꼬리> -- web '*.py' '*.html' '*.css' '*.js' ':(exclude).dddjango-web'`(꼬리 규칙 = `:211` · `static/` 접두 제거). 한 명령으로 `{% static %}` · `{% include "static/…" %}`(HTMX 선언) · CSS `url()` · 템플릿 이름 문자열이 모두 잡힌다. 참조 줄 중 **web/ 아래 파일만** 소유 판정에 쓴다(web/ 밖 줄은 §7-2 치환 후보 목록).
- **참조 파일의 소유자**: web/ 아래 참조 파일 r 의 소유자는 r 이 `web/<area>/` 아래면 그 영역, `web/static/` 아래 정적 파일이면 **r 자신의 소유자**(같은 규칙을 다시 적용 · 순환은 «정적 단위 몫»), 그 밖(base · design_system · client · 컨테이너)은 «비영역».
- **판정**(f 마다 하나 · `plan` 이 결정적으로 매기고 규칙 이름과 참조 줄을 적는다):

| 판정 | 조건 | 몫 |
|---|---|---|
| 영역 전속 | 소유자가 모두 한 영역 | 그 영역 실행 범위 |
| 경계 교차 | 소유자에 영역이 둘 이상 | 정적 단위 실행 몫 · 영역 실행 `plan.md` 에 목록 |
| 비영역 참조 | 소유자에 «비영역»이 하나라도 있음(base 전역 로드 · design_system · 영역 1 + 비영역 — 현장 `wonbo.png`) | 정적 단위 실행 몫 |
| 무참조 | 참조 줄 0(분해된 Python 경로 조립 — 현장 `korea_places.txt` — 포함) | 정적 단위 실행 몫 |

- **이름 전속은 걷는다**(X1 M2): 현장 적중은 `conversation.js` 1건이었고 그 파일은 home 에서도 돈다(`home.html:13` include 사슬). 같은 모양의 auth 전용 `terms_agreement.js`·`verification_timer.js` 는 이름이 달라 빠졌다 — 우연한 명명에 기대는 규칙이다. base 전역 로드 파일은 모두 `web/static/js` 단위 실행의 몫이다.

### 3-2. 키의 범위 소속 (X1 M1)

- 키 `검사|경로`(경로는 web 기준 상대)가 범위 안이려면 다음 중 하나다:
  - 경로가 대상 단위 접두(`<단위>/`) 아래이거나 **단위 폴더 자체**(`…/` 로 끝나는 폴더 키 — WS3·WS4·WS5·WS6·WS7 발견은 폴더 경로다 · `check_structure.py:43·83·124·136·225·237·250`).
  - 경로가 **빈 문자열**(WS5 컨테이너 발견 `:215`)이고 대상이 컨테이너 단위(`web/*.py`)다.
  - 경로가 전속 정적 파일 목록에 있다.
- 리팩토링 스캔이 새로 켜는 WS5 키가 바로 폴더·빈 경로 모양이다 — 파일 목록만으로 고르면 G0 에 묻지 않고 «정리 끝»으로 닫힌다(fail-open). W6-T4 에 합성 골격 미비 단위를 둔다.

### 3-3. 경계 교차 소비자 · 줄 편집 범위 (X1 M2 (b) · M3)

- **경계 교차 소비자**: `plan` 이 범위 템플릿의 이름 문자열(꼬리)로 같은 grep 을 돌려, 범위 밖 영역 템플릿의 `{% include %}`·`{% extends %}` 줄을 «경계 교차 소비자» 목록으로 `plan.md` 에 적는다(현장: `web/home/home/view/home.html:13` → consultation `conversation_mount.html`). 그 페이지는 G2 영향 화면이다(범위는 늘지 않는다).
- **줄 편집 범위**(6a «참조 파일 단위는 스캔 단위에 넣는다» `:150` 의 대응 · 도9): 로드·include **줄**(`<script src>`·`<link>`·`{% include %}`)이 ① 범위 파일을 가리키거나 ② 범위 파일 안에 있으면, 그 줄의 편집(지움·옮김·같은 대상을 가리키는 줄을 다른 단위 템플릿의 `{% block scripts %}` 등에 추가)은 어느 단위 템플릿에서든 편집 범위다 — **그 줄만**. `plan.md` 가 현재 해당 줄 목록을 적고, 편집된 페이지는 G2 영향 화면이다.
  - 예: 진단의 «화면 기능 JS 의 base 전역 로드»(`base.html:32-40` — 기능 JS 8개). `web/base` 실행에서 `base.html:40`(범위 안 줄)을 지우고 consultation 페이지 scripts block 에 같은 로드 줄을 더하는 것 · `web/static/js` 실행에서 `conversation.js` 를 가리키는 줄을 옮기는 것 모두 성립한다. 두 실행이 서로를 «경계 교차»로 넘기는 순환이 없다.
  - 그 줄 밖(다른 단위 템플릿의 본문 구조)을 고쳐야 하면 §4-4 «경계 교차»다.

## 6. G0 기록 정형 확장 — M 항목 행 (X1 M5)

- 6a 러너 파서(`src/debt.py` `_ROW_RE`)는 `ⓐ 키`·`요구 키`·`재상정 키` 만 읽고 값은 `C<n>` 만 받는다. M 항목은 **별도 행**이다:

  - **경로 쌍**: `git diff -M --name-status <기준>..<대상> -- web/` 의 개명 쌍(6a 참조 완전성이 이미 쓰는 명령). 폴더 이동은 옛·새 경로의 공통 접두 차이로 폴더 쌍을 뽑는다. 꼬리 규칙은 6a 와 같다(`static/` 접두 제거 · `.py` 는 점 경로도 · 폴더 쌍은 패키지 점 경로도).
  - **이름 쌍**(결정 9): `--names` 파일의 정형 행 `이름: <옛> → <새>` 를 단어 경계 치환으로 더한다. 결정 9 의 «정의 본문이 이름 말고 같을 때만» 조건은 새 AST 검사를 만들지 않고 5번 감사(DR)의 슬라이스 0 대조 항목으로 싣는다.
  - **대조**: `git diff -U0 <기준>..<대상>` 의 web/ 밖 변경 파일마다 — 더한 줄들에 역치환(새 → 옛)을 **긴 꼬리부터 한 번에(동시 치환)** 적용한 결과가 지운 줄들과 **줄 다중집합으로 같다**. import 재정렬·교환 쌍·한 줄 다중 치환은 green 이다[X1 실측 · 한 줄 다중 치환은 원래 green].
  - web/ 밖 변경 파일은 모두 테스트 파일이어야 한다. `.dddjango-web/` 은 대조에서 뺀다.
  - exit 0 = 치환만 · 2 = 어긋난 줄(파일:줄 출력) · 1 = 실행 불능.
- **기능 요청 슬라이스 0 에도 같다 + G0 가시화**(X1 M7): 6a 개명·이동 묶음의 참조 줄 grep(`:150` «`web/`을 grep»)을 참조 완전성과 **같은 pathspec**(`web '*.py' '*.html' '*.css' '*.js' ':(exclude).dddjango-web'`)으로 바꾼다. 그러면 web/ 밖 테스트 파일이 G0 «슬라이스 0 규모»와 «충돌»(발주 쓰기 경계 — `:153` · 현장 발주 허용 경로 `tests/web/**` 밖인 `tests/test_settings_profiles.py` 는 충돌로 G0 질문) 판정에 오른다. `:193` «스캔 단위 확인»에 «web/ 밖 테스트 치환 파일은 단위 판정 대상이 아니다» 1구. 기능 요청 확장을 걷는 갈래는 고르지 않는다 — 지금 6a 문면대로면 현장 빚 3키의 정리가 참조 완전성 red(`tests/test_settings_profiles.py:131·148`) → 재상정 STOP 이 되어 ⓐ 가 한 번도 끝나지 않는다(6a W-T1r2 가 찾은 사례).
