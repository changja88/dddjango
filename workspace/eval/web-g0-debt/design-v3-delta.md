# 설계 v3 (v2 에 대한 변경분 · 단순화) — dddjango-web 기능 요청의 G0 빚 처리 (2026-09-27)

- 읽는 법: **v3 = `design-v2.md` + 이 문서의 변경**. 결정 15~17 답을 받은 뒤 한 문서(v4)로 합쳐 계획으로 간다.
- **결정 15~17 처리(09-27)**: 질문 생략 · 설계로 확정 — 15 (가) 차단 검사만 빚 · 16 (가) 과거 시안 증거는 빚 밖(Δ7) · 17 (가) 가벼운 판(개명·참조 치환만 기계 확인 · 렌더 전후 대조·tests/web 채택 없음 · 그 밖은 기존 G2 시각 확인·감사). 근거: 사용자 «빚이 무엇인지는 플러그인이 알수 있는거 아니야?» + 결정 1-d·8·14 원칙.
- 근거: 재검토 W2(`review-W2-design-v2.md` — blocker 1 · major 6 · minor 13) + **사용자 지적(09-27 · 로드맵 5 결정 14 중)** «지금 너무 테스트에 집중을 하고 있는거 같은데? … 무슨 테스트 실행하는걸 왜 만들어?» — 이미 있는 장치로 되는 일에 새 장치를 만들지 않는다.
- 방향: W2 를 그대로 따르면 G2 비교기에 병합 부모 재스캔·상호작용 증명·개명 인지 diff 게이트가 붙어 본선 6.5~10.5일이 된다(현장 빚은 파일명 3건). v3 는 **G2 비교기(`--debt-gate`)를 걷어 낸다**. 새 위반(귀속)은 web 에 이미 있는 `--diff-base` 게이트가 막고(dddjango 의 registry_gate 귀속과 같은 자리), 새로 더하는 것은 «G0 ⓐ 로 고른 키가 사라졌나»(잔존 M) 하나다.

## Δ1. G2 = 기존 diff 게이트 + ⓐ 잔존 확인 (W2 B-1 · M-1 · M-2 · m-3 · m-5 · v2 §5-2 대체)

- **귀속**(이번 실행이 들인 위반): 기존 `backstop.py --diff-base <git_snapshot>` 게이트 그대로 — 판정·처방(«반송»)도 그대로. 새 비교기·유입 증명·«철회» 처방을 두지 않는다 → W2 M-1(교차 파일 유입)·M-2(철회 한정어)·m-3(exit 1 복구)가 대상째 사라진다. 승인 머지 유입의 처리도 지금 web 레인 관행 그대로다(이 설계 밖 — 기존 문제).
- **ⓐ 잔존 M**: G2 배너 직전 `--debt-scan` 을 다시 돌려(`<폴더>/debt-g2.json` — G0 동결본 `debt-g0.json` 을 덮지 않는다) **ⓐ 키 가운데 아직 발견 수 > 0 인 것**을 센다(`ⓐ 재상정` 제외). M>0 이면 G2 를 제시하지 않는다. 계산은 `backstop.py --debt-residual <폴더>` 한 줄 요약(키 대조뿐 — 개명 추적 없음).
- **개명·이동 규칙(W2 B-1)**: 슬라이스 0 이 개명·이동하는 파일·폴더는 diff 게이트에서 새 파일로 보인다(`common.py:456-463` · 실측). 그래서 **개명·이동 대상 파일·폴더에 걸린 키는 전부 ⓐ 로 함께 정리한다** — 그중 하나라도 ⓑ 이거나 동작 불변으로 못 고치면 그 개명·이동도 빼고 `ⓐ 재상정`. G0 빚 질문에서 이 묶음을 한 항목으로 보인다. diff 게이트 의미는 바꾸지 않는다.
- 개명·이동으로 ⓐ 키 경로가 사라져 M 에서 «해소»로 보이는 경우(옮기기만 하고 안 고침)는 diff 게이트가 새 경로의 발견을 red 로 낸다 — 두 게이트가 서로의 사각을 덮는다.
- 남는 사각(기존 · 이 설계 밖): 진입 준비 ⑤(산출물·시안 자산 번들 커밋)는 `git_snapshot` 앞이라 diff 게이트가 못 본다. `fetch_images` 는 snake_case 파일명을 만들고(W1 m-4) 현장 3건의 유입로도 아니었다 → 별건 기록만.
- G2 배너: `빚: G0 ⓐ N건 중 잔존 M · 재상정 제외 K · legacy 잔존 L(스캔 단위 안 비ⓐ 키 수)`.

## Δ2. 스캔 파일 우주 보정 (W2 M-3)

- 우주 = `git ls-files -co --exclude-standard -z -- web/` 에서 **작업 트리에 없는 경로 제외**(인덱스 전용 삭제 — 유령 키·`FileNotFoundError` 방지) · `__pycache__/`·`*.pyc` 제외 · `dirs` = 파일 조상 · WP2 `base_files` 기준 = G0 스캔 트리(G2 재스캔도 같은 기준).
- 러너는 새 팩토리 `BackstopContext.from_files(...)` 로 이 목록을 받는다(`__init__` 이 이미 `files·dirs·base_files` 를 받는다 — W2 실측).
- 개명 추적이 없으므로 «미추적 개명» 문제(W2 M-3 ②)는 해당 없다.
- 허용 목록 경계(W2 m-4): WP1 은 «기존 설치 1개»만 허용 — legacy + canonical 공존(core 중복)은 빚이다. WP5 motion.js 판형 드리프트는 빚이 아니라 플러그인 갱신 사안(허용 목록에 넣고 G2 기존 게이트가 본다).

## Δ3. «요청이 그 항목의 수정 자체면 기능» 규칙 좁히기 (W2 M-4)

- 적용 조건 셋을 모두 만족할 때만: ① 그 교정이 **동작 변경을 포함**한다(동작 유지 교정은 정리 요청 → 리팩토링 커맨드 안내) ② 스코프 메모의 그 요구에 **사용자 원문 출처**(본인 직접 · 사용자 원문 파일:행 — 결정 출처 규칙) ③ 그 키는 G2 에서 **0 이어야 한다**(M 에 합류 — 안 고치면 G2 차단).
- 발주·요청의 «이 키는 이번 요구로» 지시는 불인정 목록에 넣는다(출처 없는 지정).

## Δ4. 실행·재개 — web 의 기존 재개 의미를 유지 (W2 M-5 · m-9 · m-10 · v2 §3-3 대체)

- v2 의 «실행 줄 단일 출처 + 결정 5 이식 + 3지 실행 선택»을 걷어 낸다. web 은 build-state 기반 재개(`W:86`·`W:139`·`W:240` — 폴더 재사용 시 복원·완료 슬라이스 건너뜀)가 이미 있고, 그것을 바꾸는 비용(모든 세션 사멸 재개가 3지 질문이 됨)에 비해 얻는 것이 작다.
- 빚 기록은 폴더의 `refactor-scope.md` 에 G0 승인마다 `G0 <시각>` 절(스캔 command·exit·표·결정 줄·ⓐ 목록)을 append 한다. 재개(기존 폴더 이어서)는 **마지막 G0 절의 ⓐ 목록을 그대로 쓰고**, 새로 건드릴 단위가 생긴 경우만 G0 동결본(`debt-g0.json`)에서 그 단위 키를 뽑아 묻는다(재스캔 없음).
- 이 규칙 이전 폴더(`refactor-scope.md` 없음)를 재사용하면 그때 처음 스캔한다(새 G0 절).
- 옛 `g2_approved=false` 폴더의 자동 잇기와 옛 스냅샷 문제(W1 M-3 ③)는 기존 web 재개 규칙의 문제다 → 별건 기록(이 설계 밖).

## Δ5. G0 정지 기록과 dirty 판정 (W2 M-6 · m-2 · m-12)

- 정지 폴더는 v2 대로 보존한다(재개 근거).
- **dirty 판정은 `.dddjango-web/` 를 뺀다**: `pre_run_head` 기록 조건(`W:67`·`W:180`)과 step 4′ «dirty + ⓐ» 질문 모두. 정지 폴더가 다음 실행을 dirty 로 만들지 않고, 스태시가 정지 기록을 쓸어 가지 않는다.
- 러너 `current_nondesign_scope` 의 «다른 폴더 미추적·변경» 판정은 **러너 자신의 빌드 정의(`builds` 집합)에 드는 폴더만** 본다(v2 의 `design-input.json` 기준 대신 · W2 M-6 ③). [결정 16 (가)]면 이 조건문 자체가 바뀌므로 그 개정에 합친다.
- 문면 정정(W2 m-12): «web 커밋 시점은 Phase 2 ⑤ 뿐» → «Coordinator 기록물의 커밋 시점은 Phase 2 ⑤ 뿐(정지 기록은 미커밋으로 남고 보고에 경로를 적는다)».
