## 2. 빚 스캔 — `backstop.py <루트> --debt-scan --json <폴더>/debt-g0.json` (W1 B-2 · M-1)

### 2-1. 의미론

- **파일 우주**: `git ls-files -co --exclude-standard -- web/`(추적 + 미추적·비무시). `os.walk` 를 쓰지 않는다 — `.DS_Store` 등 무시 파일의 거짓 빚(W1 실측: WN8 + WS1/WS2)이 사라진다.
- **범위**: web/ 전체 1회(`J:79` «루트 전체 실행 후 경로 선별»의 대응). `--scope` 로 러너를 좁히지 않는다 — «미룰 수 없음» 경로 무관 잔류와 단위 교차 검사(WN3 — 모든 영역 view 이름으로 design_system component 판정)를 지킨다.
- **검사**: 구조 4패밀리. **시안 증거 검사는 돌리지 않는다.** 각 검사를 «모든 파일이 added 인 것처럼» 적용하되 **브라운필드 허용 규범은 빚이 아니다**(허용 = 비위반 — dddjango 제외 원칙과 같다):
  - WP1 — 기존 HTMX core 설치(`static/js/htmx.min.js`·`htmx.js`)는 «그대로 소비·조용한 이동 금지»(`:131`) → 빚 아님.
  - WP2 — 기존 base 의 legacy 로드 태그는 gated 모드와 같은 `base_files` 판정으로 본다(all_mode 의 빈 `base_files` 거짓 red 제거).
  - WS5 — «레거시 화면 내부 추가에 표준 폴더 신설을 강제하지 않는다»(houserules SKILL `:29`) → 기존 단위의 골격 미비는 빚 아님(신규 단위만 G2 게이트가 본다 · 지금 그대로).
  - 목록은 러너 코드 한 곳(`DEBT_EXEMPT` · 규범 인용 주석)에 두고 픽스처로 고정한다.
- **키**: `(검사 ID, 경로) → 발견 수`. 행·메시지를 키에서 뺀다 — 행 이동·WP2 메시지 가변(W1 B-1 ④)에 흔들리지 않고, 같은 파일 다건이 한 키로 뭉쳐도 **수**가 늘면 보인다(W1 B-1 거짓 green ①). 발견 원문(행·메시지)은 JSON 에 함께 싣는다(보고용).
- **JSON**: `{schema, head: <HEAD SHA>, dirty: <bool>, files: [...], findings: [{key, check, path, line, message}], counts: {key: n}}` · exit 0 = 발견 0 · 2 = 발견 ≥1 · 1 = 실행 불능.
- **[결정 15]** (가) 구조 4패밀리만 / (나) + `check_clip_clearance`·`check_focus_ring` 합류 — 두 도구는 web 루트 전체만 받고 JSON 이 없어 개조가 필요하다 · 키에 선택자·등급 중 무엇을 넣을지 · clip·focus 교정은 외형이 바뀌어 슬라이스 0 «동작 불변»과 부딪힐 수 있다(W1 결정 15 (나) 빈틈).

### 2-2. 스코프 단위와 빚 목록

- 단위(하나로 고정): 영역 `web/<screen_area>/` · `web/static/<하위 폴더>/`(css · js · images · fonts · htmx …) · `web/design_system/` · `web/base/` · web 컨테이너 파일(`web/*.py`·`web/urls.py`) · `web/client/<bc>/`.
- 스캔 단위 = ① 스코프 메모가 파일을 추가·변경할 단위 ② **Coordinator 가 이번 실행에서 직접 쓸 단위**(배선 → `web/base/`·컨테이너 · 시안 대상이면 자산 번들 `web/static/images/`(필요 시 fonts·files) · motion.js → `web/static/js/`)(W1 M-1 ④).
- 빚 목록 = 스캔 단위 안의 키 + 경로 무관 «미룰 수 없음» 키. `C<n>` 을 붙여 `refactor-scope.md` 스캔 표(`C<n> | key | 발견 수 | 검사 | 경로 | 미룰 수 있나`)와 exact command·exit 를 기록한다. **증거 없는 «빚 0»은 G0 blocker** · 실행 불능 정의 · `--diff-base` 게이트로 대체 금지.
- 설계(G1/G1′)나 Phase 2 가 스캔 단위 밖 단위를 건드리게 되면 **G0 JSON 에서 그 단위의 키를 뽑아** G0 재승인 빚 질문을 낸다(재스캔 불필요 — web/ 전체가 이미 동결돼 있다). G1 배너 직전 확인.
- «미룰 수 없음» 판정 물음(손대지 않아도 해로운가) 그대로.
- **요청이 그 항목의 수정 자체면 빚이 아니라 이번 기능이다**(W1 M-7): 스코프 메모가 그 키의 교정을 요구로 적으면 ⓐ 목록에서 빼고 기능 슬라이스로 간다 — «미룰 수 없음 × 동작 불변 불가»의 순환을 끊는다(dddjango 로드맵 5 v3 에도 같은 규칙을 검토 항목으로 넘긴다).

### 5-2. G2 판정기 — `backstop.py <루트> --debt-gate <폴더>` (W1 B-1)

- 입력: `debt-g0.json`(G0 동결) · `refactor-scope.md` ⓐ 키·재상정 제외 · (있으면) `approved-merges.txt`.
- 절차(결정적 · JSON 출력 `debt-g2.json` + 요약 1행):
  1. 현재 web/ 전체를 2-1 의미론으로 스캔.
  2. **개명 대응**: `git diff -M <G0 head>` + 작업 트리의 개명 쌍으로 G0 키의 경로를 새 경로로 옮긴다(W1 B-1 거짓 red ③).
  3. **승인 머지 유입**: 목록의 머지가 들인 파일(`merge-base..P2` 변경 경로)의 키 증가는 «승인 유입»으로 따로 센다. 레인도 같은 파일을 바꿨으면 가를 수 없다 → 귀속 유지 + `이중 원인` 표기(1차 처방 STOP · `J:123` 동형).
  4. **귀속** = 키별 발견 수가 G0 보다 늘어난 몫(유입 제외) — 1차 처방은 **철회**(W1 m-11 · 라운드 2 교훈). G0 동결이 web/ 전체라 스코프가 넓어져도 legacy 는 귀속이 되지 않는다(W1 B-1 거짓 red ②). step 5 자산 번들·G0 직후 배선처럼 `git_snapshot` 앞 변경도 G0 기준 뒤라 잡힌다(W1 B-1 거짓 green ① 후반).
  5. **ⓐ 잔존 M** = ⓐ 키(개명 대응 뒤) 가운데 발견 수 > 0(재상정 제외 빼고). **legacy 잔존** = 스캔 단위 안 ⓑ·비ⓐ 키.
- exit: 0 = 귀속 0 ∧ M 0 · 2 = 귀속 또는 M > 0 · 1 = 판정 불가(G0 JSON 부재·head 가 HEAD 의 조상 아님 등).
- 호출 지점: G2 배너 직전 · Phase 3 재실행(감사 반영 뒤 — W1 m-12) · 잇기 재개 G0(새 빚 산출).
- G2 배너: `빚: G0 ⓐ N건 중 잔존 M · 귀속 A · 승인 유입 I · legacy 잔존 L · 재상정 제외 K` · `동작 보존: …`. 기존 `--diff-base` 게이트는 그대로 돈다(새 줄 단위 판정 — 두 게이트의 역할은 다르다).
- 남는 사각(문서화): 같은 (검사, 경로)에서 하나 고치고 하나 새로 들이면 수가 같아 귀속 0 — 스냅샷 뒤 줄이면 `--diff-base` 게이트가 잡는다.
- **[결정 16]** (W1 결정 16 빈틈 반영): (가) 빚 밖 — G2 는 과거 시안 빌드 증거를 판정 입력으로 쓰지 않는다: 러너의 과거 빌드 검사는 **현재 빌드만**(시안 레인 `--design-build <현재>`) · 비시안 레인은 과거 빌드 검사를 돌리지 않고 상태만 보고(지금의 `current_nondesign_scope` 전건 조건을 이 규칙으로 바꾼다 · `design-evidence.md` 개정) / (나) 빚 안 — 증거 갱신은 코드가 아니라 관찰이라 슬라이스 0(coder)에 담을 자리가 없고 · 다른 빌드 폴더 `visual-evidence.json` 의 작성 주체가 없고 · digest 가 web/ 전체라 이 레인 기능 슬라이스가 다시 만료시킨다 · NFC 결함 8건은 재관찰로 못 고친다.
