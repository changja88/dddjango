## Major

### P-M1 `DEBT_EXEMPT` 의 로드 태그 면제는 WP2 발견이고, 그 메시지로는 판정되지 않는다

- **요지**: 계획은 «WP1 = legacy core 1개와 그 base 로드 태그»를 한 행으로 두고 «면제 판정은 `check_id`·`path`·`message` 만 본다»고 한다(`P:28·31`). 그러나 로드 태그의 발견은 **WP2** 다(`PU:229-230` «classic 외부 스크립트는 defer가 필요하다»). 이 사유 문자열에는 script 경로가 없어서(`PU:217-232` 중 경로를 싣는 것은 «파일 없음»·«경로 불허»·«중복 로드» 셋뿐 — src 형식·위치·async·defer 사유에는 없다) 어느 script 의 태그인지 발견 문자열로 알 수 없다.
- **근거**:
  - [실측] `planproto.py lhx`(계획 목록 그대로) → `C1 = WP2|base/base.html` · 메시지 `classic 외부 스크립트는 defer가 필요하다`. 계획 픽스처 3(«legacy htmx core 1개 + base 로드 태그(defer 없음) → 키 0», `P:75`)이 red 가 된다.
  - [실측] `planproto2.py`(WP2 행 추가 · 그 행의 script src 를 ctx 마스크 캐시에서 해소) → `lhx` 키 0 · `lhx2`(canonical 공존) → `WP1|static/htmx/htmx.min.js`·`WP1|static/js/htmx.min.js`·`WP2|base/base.html` 3키. 설계 의미대로 선다.
  - [설계 사실] `D5:50` 이 이 허용을 «WP1 —» 항목 아래 적었다. 설계의 표기 결함이 계획으로 넘어왔다(의미는 맞다).
  - WP1 쪽은 발견만으로 선다: legacy 경로 + «예약 이름» 메시지 발견을, 같은 스캔에 WP1 «core 중복» 발견이 **없을 때** 뺀다. 단일 발견이 아니라 발견 목록 전체를 본다.
- **고칠 것(최소)**: `P:27-31` 을 다음으로 바꾼다.
  - `DEBT_EXEMPT` 행 = WP1(legacy core 파일 · 중복 발견 없음) · **WP2(`base/base.html` 의 defer 사유 · 그 태그의 src 가 `HTMX_LEGACY` · 중복 발견 없음)** · WP5(motion.js).
  - WP2 행의 src 판정 수단을 하나로 정한다 — ⓐ 발견 행의 script 를 `ctx.mask_of` 캐시에서 `check_purity` 의 `_script_openers`·`_attrs_of`·`_local_static_path` 로 푼다(파일 재독 없음 · 원형으로 확인) 또는 ⓑ `PU:230`·`PU:226` 사유 끝에 `— %s` % path 를 붙여 문자열만으로 판정한다(기존 픽스처는 이 문자열을 grep 하지 않는다 — `grep 'defer가 필요'` 0건 확인). ⓑ 가 «문자열만» 원칙을 지키고 모듈 결합이 없다.
  - `P:31` «파일을 새로 읽지 않는다»는 ⓐ 를 고르면 «검사기 마스크 캐시만 쓴다»로 고친다.
- **원칙 필터**: 새 장치 없음 — 계획이 이미 둔 목록의 행 하나와 판정 수단을 바로잡는다. 설계 결함은 사실로 적고 의미는 그대로 둔다.
