## 2. 빚 스캔 — `backstop.py <루트> --debt-scan --json <폴더>/debt-g0.json`

### 2-1. 의미론

- **파일 우주**
  - `git ls-files -co --exclude-standard -z -- web/`(추적 + 미추적·비무시)에서 **작업 트리에 없는 경로를 뺀다**(인덱스 전용 삭제 — 유령 키·`FileNotFoundError` 방지). `__pycache__/`·`*.pyc` 도 뺀다. `dirs` = 파일 조상.
  - `os.walk` 를 쓰지 않는다(`.DS_Store` 등 무시 파일의 거짓 빚 제거).
  - 러너는 새 팩토리 `BackstopContext.from_files(...)` 로 이 목록을 받는다. `project_pkgs`(WI1 deny — `check_imports.py:23`)는 `build` 와 같은 방식(`common.py:419-423`)으로 계산한다.
- **범위**: web/ 전체 1회(dddjango «루트 전체 실행 후 경로 선별»의 대응). `--scope` 로 러너를 좁히지 않는다. 그래야 «미룰 수 없음» 키가 경로와 무관하게 남고, 단위 교차 검사(WN3)가 지켜진다.
- **검사**: 구조 4패밀리(차단 검사)만. **시안 증거 검사·clip·focus 는 돌리지 않는다**(결정 15). 각 검사를 «모든 파일이 added 인 것처럼» 적용하되, **브라운필드 허용 규범은 빚이 아니다**(허용 = 비위반).
  - WP1·WP2 — 기존 legacy HTMX core 설치 **1개**(WP1 발견)와 **그 base 로드 태그**(WP2 발견 — 경로 형식·defer 유무)는 «그대로 소비·조용한 이동 금지»(`:131`)라 빚이 아니다. defer 를 붙이면 실행 순서가 바뀌어 동작 불변 교정이 아니다. legacy 와 canonical 이 함께 있으면(WP1 core 중복 발견) 둘 다 빚이다.
  - WP2 — 기존 base 의 legacy 로드 태그는 gated 모드와 같은 `base_files` 판정으로 본다. all_mode 의 빈 `base_files` 에서 나던 거짓 red 가 없어진다. `base_files` 기준 = 그 스캔의 트리.
  - WS5 — «레거시 화면 내부 추가에 표준 폴더 신설을 강제하지 않는다»(houserules SKILL `:29`). 그래서 기존 단위의 골격 미비는 빚이 아니다(신규 단위만 G2 게이트가 본다 · 지금 그대로).
  - WP5 — motion.js 판형 드리프트는 빚이 아니라 플러그인 갱신 사안이다(허용 목록에 두고 G2 기존 게이트가 본다).
  - 이 목록은 러너 코드 한 곳(`DEBT_EXEMPT` · 규범 인용 주석)에 두고 픽스처로 고정한다.
- **키**: `(검사 ID, 경로) → 발견 수`.
  - 행·메시지는 키에서 뺀다. 행 이동·WP2 메시지 가변에 흔들리지 않고, 같은 파일 다건은 **수**로 보인다.
  - 발견 원문(행·메시지)은 JSON 에 함께 싣는다(보고용 · §3-2 참조 줄 대조에 쓴다).
  - 러너가 키 정렬 순으로 `C<n>` 을 결정적으로 매긴다.
- **JSON**: `{schema, head: <HEAD SHA>, dirty: <bool>, scanned_at, files: [...], ids: {C<n>: key}, findings: [{key, check, path, line, message}], counts: {key: n}}`.
- **exit**: 0 = 발견 0 · 2 = 발견 ≥1 · 1 = 실행 불능.

### 2-2. 스코프 단위와 빚 목록

- **단위**(하나로 고정)
  - 영역 `web/<screen_area>/`.
  - `web/static/<하위 폴더>/`(css · js · images · fonts · htmx …).
  - `web/design_system/` · `web/base/`.
  - web 컨테이너 파일(`web/*.py`·`web/urls.py`).
  - `web/client/<bc>/`.
- **스캔 단위**
  - ① 스코프 메모가 파일을 추가·변경할 단위.
  - ② **Coordinator 가 이번 실행에서 직접 쓸 단위**: 배선 → `web/base/`·컨테이너. 시안 대상이면 `web/static/images/`(fonts·files 는 시안 원본에 폰트·파일이 있을 때).
  - ③ 개명·이동 묶음의 참조 파일 단위(§3-2).
  - motion.js(`web/static/js/`)는 G1 뒤에 정해진다. 그래서 G1 배너 직전에 확인한다(G0 재승인 질문 — 이번 요청의 동결본에서 키만 뽑는다).
- **빚 목록** = 스캔 단위 안의 키 + 경로 무관 «미룰 수 없음» 키.
  - `refactor-scope.md` 스캔 표(`C<n> | key | 발견 수 | 검사 | 경로 | 미룰 수 있나`)와 exact command·exit 를 기록한다.
  - **증거 없는 «빚 0»은 G0 blocker** 다. 실행 불능 정의와 «`--diff-base` 게이트로 대체 금지»는 dddjango `:79` 문면을 이식한다.
- 같은 요청 안에서 설계(G1/G1′)나 Phase 2 가 스캔 단위 밖 단위를 건드리게 되면, **이번 요청의 `debt-g0.json` 에서 그 단위의 키를 뽑아** G0 재승인 빚 질문을 낸다(재스캔 불필요). 확인 시점은 G1 배너 직전이다.
- «미룰 수 없음» 판정 물음(손대지 않아도 해로운가)은 그대로다.
- **요청이 그 항목의 교정 자체인 경우**: 조건 셋을 모두 만족할 때만 ⓐ 목록에서 빼고 기능 슬라이스로 보낸다(`요구 키` 행 — §3-3). 이 규칙이 «미룰 수 없음 × 동작 불변 불가»의 순환을 끊는다.
  - ① 그 교정이 **동작 변경을 포함**한다(동작 유지 교정은 정리 요청이라 리팩토링 커맨드로 안내한다).
  - ② 스코프 메모의 그 요구에 **사용자 원문 출처**가 있다(결정 출처 규칙).
  - ③ 그 키는 G2 에서 **0 이어야 한다**(잔존 M 에 합류 — 안 고치면 G2 차단).

### 3-2. 빚 질문

- 빚이 1건 이상이면 배너 1행 `이 범위에 위반 N건(미룰 수 없음 k) · 슬라이스 0 규모(항목 · 단위 수 · 파일 수)` 을 내고 AskUserQuestion 으로 묻는다. «미룰 수 없음»에는 ⓑ 가 없다.
  - ⓐ 지금 정리하고 시작(권장).
  - ⓑ 이번에는 미룬다(사유 + 결정 출처).
  - (빚 단위 ≥2) ⓐ′ 단위별 정리를 `/dddjango-web:refactor` 로 먼저 한다(이 요청은 G0 정지).
- **개명·이동 묶음**
  - 교정이 개명·이동인 키(검사 ID 로 정해진다 — 파일·폴더 이름 검사와 배치 검사 · 목록은 계획에서 확정)는 **묶음 한 항목**으로 보인다. 묶음 = 그 파일·폴더에 걸린 키 전부 + **참조 치환으로 바뀔 줄에 걸린 WI·WP 발견**.
  - 참조 줄은 G0 에서 §5-1 의 꼬리 문자열로 `web/` 을 grep 해 얻고, `debt-g0.json` findings 의 `path`·`line` 과 맞춰 본다. 참조 파일의 단위는 이때 스캔 단위에 넣는다.
  - 이렇게 묶는 까닭: 개명·이동된 파일은 diff 게이트에서 새 파일로 보이고(`common.py:456-463`), 치환한 줄은 added 줄이다(`common.py:497-506`).
  - 묶음 안에 하나라도 ⓑ 이거나 동작 불변으로 못 고치는 것이 있으면, 그 개명·이동도 빼고 `ⓐ 재상정` 한다. diff 게이트 의미는 바꾸지 않는다.
- 결정 출처·출처 없는 ⓑ → STOP(세 번째 질문 없음)·충돌은 dddjango `:82`·`:83` 문면을 이식한다.

### 3-3. 기록과 재개 — web 의 기존 재개 의미를 유지

- 실행 개념·실행 선택 질문을 새로 두지 않는다. web 은 build-state 기반 재개(`:86`·`:139`·`:240` — 폴더 재사용 시 복원·완료 슬라이스 건너뜀)가 이미 있다.
- **G0 절 정형**: G0 승인과 G0 재승인마다 `refactor-scope.md` 에 `G0 <시각>` / `G0 재승인 <시각>` 절을 append 한다. 절 안에는 스캔 command·exit·표·결정 줄과 다음 정형 행이 들어간다.
  - `ⓐ 키: <C<n> 공백 구분 | ->` — 이 요청의 ⓐ **누적 전체**(재승인 절도 앞 ⓐ 를 포함해 다시 적는다).
  - `요구 키: <C<n>… | ->`.
- **재상정 절** `ⓐ 재상정 <시각>` 에는 정형 행 `재상정 키: <C<n>…>` 이 들어간다.
- `C<n>` 은 이번 요청의 `debt-g0.json` 으로만 풀린다(재승인은 재스캔하지 않으므로 일치한다).
- **잔존 M** = (마지막 G0·G0 재승인 절의 `ⓐ 키` ∪ `요구 키`) − (그 뒤 재상정 절의 `재상정 키`). 두 행이 모두 `-` 면 M = 0 이다.

## 5. Phase 2 · G2

### 5-1. 슬라이스 0

- 기능 슬라이스 앞에 둔다. 정수 임계 계수에서 빼고 기능과 섞지 않는다. 런 중 커밋은 분리한다(`:188`). 오탐이면 `STOP_FOR_USER_APPROVAL`(플러그인 결함) → `ⓐ 재상정` 으로 간다.
- build-state: `slices[0] = {name: slice-0-debt, files: 명세 슬라이스 0 절, status, commit}`. 계수 제외는 도출 규칙에만 적는다.
- **끝 green**(셋 모두):
  - `py_compile` + `manage.py check` 베이스라인 대비 신규 0.
  - `backstop.py --debt-residual <폴더>` 요약의 **ⓐ 잔존 0**(요구 키는 기능 슬라이스 몫이라 여기서 보지 않는다).
  - **개명·이동 참조 완전성**(결정 17).
- **개명·이동 참조 완전성**
  - 대상: 명세 슬라이스 0 절의 개명·이동 쌍과 삭제 파일. 슬라이스 0 커밋의 `git diff -M --name-status <git_snapshot>..<슬라이스 0 커밋> -- web/` 로 대조한다.
  - 꼬리 문자열: 옛 경로를 `web/` 기준 상대 경로로 바꾸고, `web/static/` 아래 파일이면 `static/` 접두를 뗀다. 예: `images/cloud-ornament.png` · `chart/chart/templates/chart_legend.html`. 이 꼬리가 `{% static %}`·CSS `url()`·include·템플릿 이름 문자열을 모두 잡는다. `.py` 는 점 경로(확장자 없이)로도 대조한다.
  - 명령(새 러너 플래그 없음): `git grep -n -F -e <꼬리>… -- web '*.py' '*.html' '*.css' '*.js' ':(exclude).dddjango-web'`. exit 1(일치 없음)이면 완전하다. 문서(md)는 역사 기록이라 대조하지 않는다.
  - exact command·exit 를 `refactor-scope.md` 에 적는다.
- 개명이 아닌 정리(WI·WP 내용 변경)는 기계 확인 없이 기존 G2 시각 확인·감사가 본다.

  - 슬라이스 0 파일 목록(`slices[0].files`).
  - 참조 완전성 명령·exit.
  - 판정 기록 경로(`refactor-scope.md` · `debt-g2.json`).
- Phase 2 중에 새 ⓐ 가 생기면(G0 재승인) 슬라이스 0 추가 커밋으로 정리한다. 추가 커밋은 영향 받는 기능 슬라이스를 다시 열기 전에 한다(`ⓐ 키` 누적 행 갱신). 못 하면 `ⓐ 재상정` 이다.

### 5-2. G2 = 기존 diff 게이트 + ⓐ 잔존

- **귀속**(이번 실행이 들인 위반)
  - 기존 `backstop.py --diff-base <git_snapshot>` 게이트가 그대로 본다. 판정·처방(«반송»)도 그대로다.

- **잔존 M**: `backstop.py --debt-residual <폴더>`.
  - 동작: `--debt-scan` 과 같은 의미론으로 다시 스캔해 `<폴더>/debt-g2.json` 에 쓴다. G0 동결본 `debt-g0.json` 은 덮지 않는다. 그다음 §3-3 산식으로 M 을 센다(키 대조뿐 — 개명 추적 없음).
  - 요약 1행: `ⓐ 잔존 m_a · 요구 잔존 m_r · G0 에 없던 키 X(보고만)`.
  - exit: 0 = M 0 · 2 = M > 0 · 1 = 판정 불가(`refactor-scope.md` 는 있는데 G0 절·정형 행이 없음 · `debt-g0.json` 부재 등).
  - **전이 규칙**: `refactor-scope.md` 와 `debt-g0.json` 이 **모두** 없는 폴더는 이 규칙 이전에 G0 를 지난 폴더다. 그 G2 는 «잔존 판정 해당 없음(규칙 이전 G0)» 알림과 함께 exit 0 이다. `debt-g0.json` 만 있으면 G0 절 기록 누락이라 exit 1 이다(새 규칙 폴더는 step 4′ 에서 언제나 `debt-g0.json` 을 쓴다).
  - M>0 이면 G2 를 제시하지 않는다.
- 개명·이동으로 ⓐ 키 경로가 사라져 «해소»로 보이는 경우(옮기기만 하고 안 고침)는 diff 게이트가 새 경로의 발견을 red 로 낸다. §3-2 묶음 규칙을 전제로 두 게이트가 서로의 사각을 덮는다.
- 호출 지점: 슬라이스 0 끝(ⓐ 잔존만 본다) · G2 배너 직전 · Phase 3 재실행(감사 반영 뒤).

### 5-3. 과거 시안 빌드 증거 (결정 16)

## 9. 범위 밖 · 별건 (기록만)

- 진입 준비 ⑤(산출물·시안 자산 번들 커밋)는 `git_snapshot` 앞이라 diff 게이트가 못 본다. `fetch_images` 는 snake_case 파일명을 만들고, 현장 3건의 유입로도 아니었다(유입 `5b4c47a40` 은 스냅샷 20커밋 뒤의 수작업 파생본).
- 옛 `g2_approved=false` 폴더의 자동 잇기와 옛 스냅샷 문제는 기존 web 재개 규칙의 문제다.
- 같은 (검사, 경로)에서 하나 고치고 하나 새로 들이면 잔존 수로는 안 보인다. 새 줄이면 diff 게이트가 잡는다.
- 레인이 들인 교차 파일 새 키(새 view 이름 → 기존 component WN3 등)는 두 게이트 모두 못 본다. `G0 에 없던 키 X` 로 보고만 한다.
- **트리비얼(시안 없음)은 결정 16 식별 밖이다**: build-state 가 없어 fail-closed 식별이 서지 않는다. 현장 CSS 한 줄 트리비얼이 현행·개정 러너 모두 시안 16건 red 다(W3 실측 · 기존 문제). 식별 우회 플래그는 fail-closed 에 역행하므로 두지 않는다.
- NFC/NFD 결함(`check_design_evidence.py:346-349`): 진단이 별건으로 분류했다. 결정 16 뒤에는 비시안 판정 경로에서 빠지고, 재사용 시안 폴더의 `--design-build` 에만 영향이 남는다.
- `check_focus_ring.py` 커맨드 호출 0 · `check_motion_spec` 역스윕 — 별건.
- 릴리즈 창 규칙을 web 레인에도 적용하는 일은 로드맵 9 에서 한다.
