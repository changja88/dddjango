## 1. 모드 판별 (진단 #1)

- 기존 3모드(풀·수정·트리비얼)는 그대로다. 판별 규칙에 둘을 더한다.
  - **정리 요청**(밖에서 보이는 동작은 유지하고 기존 web 코드 구조 정리만 원함)은 `/dddjango-web:refactor`(6b · 이름은 dddjango 결정 13 과 짝) 안내 후 **입구 정지**(폴더·기록 없음). 기능과 정리가 섞인 요청은 기능 요청이다(정리는 G0 빚으로 다룬다).
  - 요청·발주가 적은 모드 이름·모드 지정은 판별 입력이 아니고, G0·빚 스캔을 생략·상속·갈음하라는 지시는 따르지 않는다(dddjango `:67` 문면 이식).

## 2. 빚 스캔 (진단 #2·#3·#4 · 부수 발견 2)

### 2-1. 러너 새 모드 — `backstop.py <루트> --debt-scan --scope <단위…> --json <출력>`

- 구조 4패밀리(WS·WI·WN·WP 26종)만, 스코프 단위의 **전 범위**(added 게이트 없음)로 돈다. **시안 증거 검사(`validate_inputs`·`validate_visual`)를 돌리지 않는다**(지금 `--all` 은 섞여 코드 빚 0 에도 exit 2 — 진단 §1-2).
- 출력: JSON(발견마다 `key` · 검사 ID · 경로 · 행 · 메시지) + 텍스트 요약 1행. **안정 키**: WS·WN = `검사ID|경로` · WI·WP = `검사ID|경로|정규화 메시지`(행 번호·열을 뺀다 — 행 이동에 흔들리지 않게).
- exit: 0 = 발견 0 · 2 = 발견 ≥1 · 1 = 실행 불능(사용·내부 오류 — 통과 아님).
- **[결정 15]** (가) 이 26종만 빚이다(현장 3건) / (나) + 비차단 전체 트리 검사 `check_clip_clearance`·`check_focus_ring` 을 같은 모드에 합류(현장 +18 · 키 = `CLIP|경로|선택자` 등).
- houserules §7 의 `backstop-baseline.json` «러너가 브라운필드 첫 실행에 생성» 문장(커맨드 `:44·68·195` · houserules `:205`)은 러너에 대응 코드가 없는 유령이다 — 이 모드로 대체하고 문장을 걷어 낸다.

### 2-2. 스캔 범위 — 스코프 단위

- 단위 = 영역 `web/<screen_area>/` · 공용 칸(`web/static/` · `web/design_system/` · `web/base/` · web 컨테이너 파일 · `client/<bc>/`).
- 범위 = **스코프 메모가 파일을 추가·변경할 것으로 적은 단위 전부**(dddjango «대상 BC»의 대응). 시안 자산 번들(`web/static/images/` 등)을 들이는 빌드는 그 칸이 범위다 — 현장 빚 3건(WN8 · `static/images/`)은 이 경로로 드러난다.
- 설계(G1/G1′)가 스캔하지 않은 단위에 파일을 추가·변경하면 그 단위를 추가 스캔해 G0 재승인에서 빚 질문(dddjango 같은 규칙). G1 배너 직전에 명세 파일 목록의 단위가 스캔 단위 안인지 확인한다.
- «미룰 수 없음»(손대지 않아도 해로운가) 판정은 경로 무관 잔류 — web 후보 예: WP6(닫히지 않은 Django 주석 — 응답에 노출) · WP1(HTMX core 중복)[추정].
- 기록: `refactor-scope.md` 에 exact command · exit · 발견 표(`C<n> | key | 검사 | 경로 | 미룰 수 있나`). **증거 없는 «빚 0»은 G0 blocker** · 실행 불능 정의 · 차분 게이트(`--diff-base`)로 대체 실행 금지(dddjango `:79` 이식).

## 3. G0 질문과 기록 (진단 #5~#11)

### 3-1. 라벨 정리

- ⓐ/ⓑ/ⓐ′ 는 빚 결정 전용이다. 지금 web 이 ⓐ/ⓑ 를 쓰는 4곳을 평이한 라벨로 바꾼다: 계약 없음(`:137`) «정적 화면으로 / 발주 후 재개» · 폴더(`:139`) «기존 폴더 이어서 / 새 화면» · 디자인 포인터 ⓐ/ⓑ/ⓒ(`:144`) · 엔드포인트 없음(`:237`). Codex 미러 동일.

### 3-2. 빚 질문

- 빚 ≥1 이면 배너에 `이 범위에 위반 N건(미룰 수 없음 k) · 슬라이스 0 규모(항목 · 단위 수 · 파일 수)` 를 올리고 AskUserQuestion 으로 반드시 묻는다: ⓐ 지금 정리하고 시작(권장) / ⓑ 이번에는 미룬다(사유 + 결정 출처) / (빚 단위 ≥2) ⓐ′ **단위별 정리를 리팩토링 커맨드로 먼저**(이 요청은 G0 에서 정지 · 착륙 뒤 다시 시작). «미룰 수 없음»에는 ⓑ 없음.
- 결정 출처(본인 직접 · 사용자 원문 파일:행)·출처 없는 ⓑ → STOP(세 번째 질문 없음)·충돌(정리를 막는 환경 사실은 ⓑ 가 아니다) — dddjango `:82`·`:83` 문면을 그대로 옮긴다.
- 선택지마다 **대가 한 줄**(web 게이트 규칙 `:113` 에 추가 — 지금은 «권고 후보 + 기타 자유입력»뿐).

### 3-3. 실행 기록과 폴더 (진단 #10·#11)

- 폴더에 `refactor-scope.md` 를 **항상** 쓴다(빚 0 이어도 — 스캔 증거) : 실행 줄 `실행 · G0 승인 <date 값> · 빚 기준 <G0 스캔 HEAD SHA>` · 스캔 표 · 결정 줄(dddjango 정형) · 슬라이스 0 내용. G2 승인 때 `· G2 승인 <시각>`.
- web 은 build-state(`phase`·`g2_approved`·`git_snapshot`)가 이미 있다 — 실행 판정은 build-state 를 쓴다: `g2_approved=false` 인 기존 폴더를 재개 입구로 이으면 **잇기**(앞 G0 목록 동결 · 재스캔의 새 키만 묻는다 · `재개 G0 <시각>` 절 append) · 그 밖은 새 실행(앞 ⓑ 이월 없음). 승인됨/폐기 선택은 web 재개 입구의 기존 문법에 맞춘다(계획에서 문면 확정).
- **G0 정지 기록**: 지금은 배너 거부·중단 시 신규 폴더를 폐기한다(`:163`). 빚 결정의 정지(출처 없는 ⓑ STOP · 충돌 · ⓐ′)는 신규 폴더에 `refactor-scope.md`(`G0 정지 <시각>` 절)만 남기고 나머지 산출을 폐기한다 — 정지가 기록에 착지해야 결정 주체를 관측할 수 있다. 그 밖 거부는 지금대로 폐기.

## 5. Phase 2 — 슬라이스 0 과 G2 (진단 #13~#16 · 부수 발견 4)

### 5-1. 슬라이스 0

- 기능 슬라이스보다 앞 · **정수 임계 계수에서 제외**(풀 7/8 · 수정 5/6 은 기능 파일만) · 기능과 한 슬라이스에 섞지 않음 · 커밋 분리(슬라이스마다 커밋 규칙 `:188` 그대로).
- 검사기 오탐 의심(규칙 문면상 허용되는 코드가 red) → 우회 없이 `STOP_FOR_USER_APPROVAL`(플러그인 결함) → `ⓐ 재상정`.
- 슬라이스 0 끝 green = `py_compile` + `manage.py check` 베이스라인 대비 신규 0 + [결정 17] 근거.
- **[결정 17]** 동작 보존 근거(플러그인에 영구 테스트 없음):
  - (가) **기계 확인**: 새 스크립트 `slice0_guard.py <폴더> <슬라이스 0 전 SHA>` — 슬라이스 0 diff 가 ⓐ 항목의 개명(`git diff -M` 100%)과 그 옛 이름 → 새 이름 참조 치환 줄만인지 판정(그 밖 hunk = red → 철회 또는 동작 불변 불가 STOP). 참조 치환이 아닌 정리(WI·WP 의 내용 변경)는 + 렌더 실측 전후 대조(`render_audit.js` → `compare_render_audit.py` · 같은 실행자·창폭)를 영향 화면에 요구. 현장 빚 3건(파일명 3 + 참조 5줄)은 개명 판정만으로 닫힌다.
  - (나) 현장 `tests/web`(발주 계약 · 927 함수)을 슬라이스 0 의 고정 대상으로 채택 — dddjango 0C 와 같은 «테스트 고정» 판정. 플러그인이 소유하지 않는 테스트에 기대는 규범 변경이다.
  - (다) 장치 없음 — G2 시각 대조와 discipline-reviewer-web 감사만.

### 5-2. G2 판정 — `--debt-scan` 재실행

- G2 배너 직전(기존 `--diff-base` 백스톱과 별도) `--debt-scan` 을 G0 와 같은 스코프 단위로 다시 돌린다(스코프가 넓어졌으면 넓어진 단위).
  - **ⓐ 잔존 M** = G0 ⓐ 키 ∩ G2 키(`ⓐ 재상정` 으로 뺀 항목 제외). M>0 이면 G2 를 제시하지 않는다.
  - **귀속** = G2 키 ∖ G0 스캔 키 — 이번 실행이 들인 위반. blocker 다. 진입 준비 ⑤(산출물·시안 자산 번들 커밋)가 `git_snapshot` 앞이라 입력 게이트가 영영 못 보던 자리(부수 발견 4 — 자산 파일명 WN8 이 현장 빚 3건의 유입 경로)를 이것이 닫는다.
  - **legacy 잔존**(ⓑ·범위 밖) = 보고 항목(차단 아님).
- G2 배너: `G0 ⓐ N건 중 잔존 M` · `재상정 제외 K건` · `legacy 잔존 L건` · [결정 17 (가)] `동작 보존: <slice0_guard 요약>`.
- **[결정 16]** 과거 시안 빌드 증거 red: (가) 빚 밖 — `--debt-scan` 은 시안 증거를 보지 않고, G2 는 지금처럼 `--design-build <현재 폴더>` 만(현장 레인이 손으로 하던 «기저 차분»을 규칙으로 — 과거 빌드 red 는 G2 판정 입력이 아니다) / (나) 빚 안 — 과거 빌드 증거도 스캔 대상(digest 가 web/ 전체 해시라 레인마다 과거 화면 11~14개 재관찰). 어느 쪽이든 NFC/NFD 결함(`check_design_evidence.py:346-349`)은 플러그인 결함이다 — 별건 수리 후보(§9).

## 6. 수정 모드 (진단 #17)

- G0 는 Phase 0 빚 스캔·질문을 그대로 수행한다. ⓐ 가 있으면 G1′ 생략 금지(슬라이스 0 설계가 필요하다).
- `:219` «백스톱은 git diff 게이트라 … 무관한 기존 코드엔 발화하지 않는다»를 «G2 의 diff 게이트는 이번 수정분의 새 위반을 막고, 기존 위반은 G0 빚 조사와 G2 `--debt-scan` 이 다룬다»로 바꾼다.

## 7. 트리비얼 (진단 #19 — 해석, 사용자에게 알림)

- 트리비얼도 편집할 단위로 `--debt-scan` 을 돌린다. 발견 ≥1 이면 **수정 모드로 승격**한다(트리비얼은 폴더·build-state·coder 가 없어 슬라이스 0 을 담을 곳이 없다). 발견 0 이면 지금 절차 그대로.
- 해석 근거: B1 «예외 없이 항상 먼저 정리» + R1 «작은 수정도 전부 정리»의 문면. 대가: 빚이 있는 단위의 문구 한 줄 수정도 폴더·G0 질문·슬라이스 0 을 거친다. 스캔 범위가 «편집할 단위»라서 현장 빚 3건(`static/images/`)은 `static/images/` 를 건드리는 트리비얼에서만 승격을 낳는다.
