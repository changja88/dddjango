## Blocker

### B-1 슬라이스 0 의 개명·이동이 기존 `--diff-base` 게이트에서 legacy 전부를 red 로 만든다 — W1 B-1 ③ 이 G2 수준에서 그대로다

| 사실 | 근거 |
|---|---|
| 러너 diff 는 `git diff --name-status`(rename 기본 탐지)이다. `R` 항목의 새 경로를 **added** 로 넣는다(`CM:456-463`). added 파일은 WN 전 검사, WI·WP 의 모든 줄(`line_is_added` → `f in added`, `CM:365`) 대상이다 | [실측] 코드 |
| `ren.sh`: legacy 템플릿 `Cart-Page.html`(WN4·WN8·WI4)을 G0 로 커밋했다. 슬라이스 0 이 WN 교정으로 `cart.html` 로 `git mv` 만 했다(R100 · WI4 는 ⓑ 로 남김). 그러자 `backstop.py --diff-base <G0>` 이 `[WI4] BLOCKER — web/shop/cart/view/cart.html:2` · blocker 1 로 끝났다 | [실측] |
| `scen.sh` C: legacy `templates/` 가 있는 화면 폴더 `cart → basket` 을 개명했다. 파일 쌍 개명 대응으로는 디렉터리 키 `WS3\|shop/cart/templates/` 가 옮겨지지 않는다 → `--debt-gate` 원형도 `WS3\|shop/basket/templates/` 를 귀속 1 로 냈다. `--diff-base` 도 added 디렉터리로 WS3 를 낸다 | [실측] |
| 결과: «ⓐ 개명 + 같은 파일·폴더의 ⓑ/비ⓐ 발견»에는 출구가 없다. ⓑ 를 고치면 ⓑ 결정과 스코프를 어긴다. 개명을 철회하면 M>0 이다. `D2:122` «기존 `--diff-base` 게이트는 그대로 돈다»와 `D2:116` «개명 대응(거짓 red ③)»이 동시에 성립하지 않는다. `J:113` «슬라이스 0 에서 빼고 진행(… 잔존은 legacy 보고)»의 web 대응도 깨진다 | [실측] 문면 |
| 범위: WN1·2·4·5·6·7·8(텍스트 파일)과 WS 이동 교정 전부가 해당한다. 현장 3건은 `.png` 라 동거 발견이 없어서 무사하다(`field.sh` — diff 게이트 구조 0) | [실측] · 브라운필드 빈도는 [추정] |

필요한 설계 결정(v3): (i) diff 게이트를 개명 인지형으로 바꿀지 — R 쌍은 added 가 아니라 touched + 쌍 diff 줄 · 디렉터리 개명 포함. 모든 레인의 기존 게이트 의미가 바뀐다. (ii) 또는 G0 동거 규칙을 둘지 — 개명·이동할 파일·폴더의 키는 전부 ⓐ, 안 되면 `ⓐ 재상정`. 어느 쪽이든 R100 + legacy 픽스처를 둔다.
