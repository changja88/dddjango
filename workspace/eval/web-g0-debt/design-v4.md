## 2. 빚 스캔 — `backstop.py <루트> --debt-scan --json <폴더>/debt-g0.json`

### 2-1. 의미론

- **파일 우주**: `git ls-files -co --exclude-standard -z -- web/`(추적 + 미추적·비무시)에서 **작업 트리에 없는 경로 제외**(인덱스 전용 삭제 — 유령 키·`FileNotFoundError` 방지) · `__pycache__/`·`*.pyc` 제외 · `dirs` = 파일 조상. `os.walk` 를 쓰지 않는다(`.DS_Store` 등 무시 파일의 거짓 빚 제거 — W1 실측 WN8 + WS1/WS2). 러너는 새 팩토리 `BackstopContext.from_files(...)` 로 이 목록을 받는다(`__init__` 이 이미 `files·dirs·base_files` 를 받는다).
- **범위**: web/ 전체 1회(dddjango «루트 전체 실행 후 경로 선별»의 대응). `--scope` 로 러너를 좁히지 않는다 — «미룰 수 없음» 경로 무관 잔류와 단위 교차 검사(WN3 — 모든 영역 view 이름으로 design_system component 판정)를 지킨다.
- **검사**: 구조 4패밀리(차단 검사)만. **시안 증거 검사·clip·focus 는 돌리지 않는다**(결정 15). 각 검사를 «모든 파일이 added 인 것처럼» 적용하되 **브라운필드 허용 규범은 빚이 아니다**(허용 = 비위반):
  - WP1 — 기존 HTMX core 설치(`static/js/htmx.min.js`·`htmx.js`) **1개**는 «그대로 소비·조용한 이동 금지»(`:131`) → 빚 아님. legacy + canonical 공존(core 중복)은 빚이다.
  - WP2 — 기존 base 의 legacy 로드 태그는 gated 모드와 같은 `base_files` 판정으로 본다(all_mode 의 빈 `base_files` 거짓 red 제거). `base_files` 기준 = 그 스캔의 트리.
  - WS5 — «레거시 화면 내부 추가에 표준 폴더 신설을 강제하지 않는다»(houserules SKILL `:29`) → 기존 단위의 골격 미비는 빚 아님(신규 단위만 G2 게이트가 본다 · 지금 그대로).
  - WP5 motion.js 판형 드리프트는 빚이 아니라 플러그인 갱신 사안(허용 목록 · G2 기존 게이트가 본다).
  - 목록은 러너 코드 한 곳(`DEBT_EXEMPT` · 규범 인용 주석)에 두고 픽스처로 고정한다.
- **키**: `(검사 ID, 경로) → 발견 수`. 행·메시지는 키에서 뺀다(행 이동·WP2 메시지 가변에 흔들리지 않고, 같은 파일 다건은 **수**로 보인다). 발견 원문(행·메시지)은 JSON 에 함께 싣는다(보고용). 러너가 키 정렬 순으로 `C<n>` 을 결정적으로 매긴다.
- **JSON**: `{schema, head: <HEAD SHA>, dirty: <bool>, files: [...], ids: {C<n>: key}, findings: [{key, check, path, line, message}], counts: {key: n}}` · exit 0 = 발견 0 · 2 = 발견 ≥1 · 1 = 실행 불능.

### 2-2. 스코프 단위와 빚 목록

- 단위(하나로 고정): 영역 `web/<screen_area>/` · `web/static/<하위 폴더>/`(css · js · images · fonts · htmx …) · `web/design_system/` · `web/base/` · web 컨테이너 파일(`web/*.py`·`web/urls.py`) · `web/client/<bc>/`.
- 스캔 단위 = ① 스코프 메모가 파일을 추가·변경할 단위 ② **Coordinator 가 이번 실행에서 직접 쓸 단위**(배선 → `web/base/`·컨테이너 · 시안 대상이면 `web/static/images/`(+ fonts·files 는 시안 원본에 폰트·파일이 있을 때)). motion.js(`web/static/js/`)는 G1 뒤에 정해지므로 G1 배너 직전에 확인한다(G0 재승인 질문 — 동결본에서 키만 뽑는다).
- 빚 목록 = 스캔 단위 안의 키 + 경로 무관 «미룰 수 없음» 키. `refactor-scope.md` 스캔 표(`C<n> | key | 발견 수 | 검사 | 경로 | 미룰 수 있나`)와 exact command·exit 를 기록한다. **증거 없는 «빚 0»은 G0 blocker** · 실행 불능 정의 · `--diff-base` 게이트로 대체 금지(dddjango `:79` 문면 이식).
- 설계(G1/G1′)나 Phase 2 가 스캔 단위 밖 단위를 건드리게 되면 **G0 JSON 에서 그 단위의 키를 뽑아** G0 재승인 빚 질문을 낸다(재스캔 불필요 — web/ 전체가 이미 동결돼 있다). G1 배너 직전 확인.
- «미룰 수 없음» 판정 물음(손대지 않아도 해로운가) 그대로.
- **요청이 그 항목의 교정 자체인 경우**: 조건 셋을 모두 만족할 때만 ⓐ 목록에서 빼고 기능 슬라이스로 보낸다 — ① 그 교정이 **동작 변경을 포함**한다(동작 유지 교정은 정리 요청 → 리팩토링 커맨드 안내) ② 스코프 메모의 그 요구에 **사용자 원문 출처**(결정 출처 규칙) ③ 그 키는 G2 에서 **0 이어야 한다**(잔존 M 에 합류 — 안 고치면 G2 차단). «미룰 수 없음 × 동작 불변 불가»의 순환을 끊는다.

### 5-1. 슬라이스 0

- 기능 슬라이스 앞 · 정수 임계 계수 제외 · 기능과 섞지 않음 · 런 중 커밋 분리(`:188`) · 오탐 → `STOP_FOR_USER_APPROVAL`(플러그인 결함) → `ⓐ 재상정`.

- **`--slice0-check`**(결정 17 · 새 스크립트 없이 러너 한 곳):
  - 입력: 슬라이스 0 커밋 범위(`git_snapshot..<슬라이스 0 커밋>`) · 명세의 개명·이동 쌍.

### 5-2. G2 = 기존 diff 게이트 + ⓐ 잔존

- **귀속**(이번 실행이 들인 위반): 기존 `backstop.py --diff-base <git_snapshot>` 게이트 그대로 — 판정·처방(«반송»)도 그대로. 새 비교기·유입 증명을 두지 않는다. 승인 머지 유입 처리도 지금 web 레인 관행 그대로다.
- **ⓐ 잔존 M**: `backstop.py --debt-residual <폴더>` — `--debt-scan` 과 같은 의미론으로 다시 스캔해 `<폴더>/debt-g2.json` 에 쓰고(G0 동결본 `debt-g0.json` 을 덮지 않는다) 마지막 G0 절의 `ⓐ 키:` 행 가운데 아직 발견 수 > 0 인 것을 센다(`ⓐ 재상정` 제외 · 키 대조뿐 — 개명 추적 없음). exit 0 = M 0 · 2 = M > 0 · 1 = 판정 불가(G0 JSON·G0 절 부재 등). M>0 이면 G2 를 제시하지 않는다.
- 개명·이동으로 ⓐ 키 경로가 사라져 «해소»로 보이는 경우(옮기기만 하고 안 고침)는 diff 게이트가 새 경로의 발견을 red 로 낸다 — 두 게이트가 서로의 사각을 덮는다(§3-2 묶음 규칙이 전제).
- 호출 지점: G2 배너 직전 · Phase 3 재실행(감사 반영 뒤).
- G2 배너: `빚: G0 ⓐ N건 중 잔존 M · 재상정 제외 K · legacy 잔존 L(스캔 단위 안 비ⓐ 키 수)` · `슬라이스 0: 개명 n쌍 참조 완전 · 영향 화면 <목록>` · `과거 시안 빌드: red n / 전체 m(판정 입력 아님)`.

### 5-3. 과거 시안 빌드 증거 (결정 16)
