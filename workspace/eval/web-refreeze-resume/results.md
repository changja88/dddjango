# 행동 시험 판정

## 실행 조건

- `run_trial.py baseline`은 runtime 수정 전에 입력을 동결하고 실행했다. source SHA를 `git show 382837c9:<file>`와 직접 대조해 전부 일치를 확인했다.
- `run_trial.py candidate`는 수정본으로 별도 실행했다. source SHA가 최종 runtime 파일과 일치한다.
- 두 실행의 scenario SHA는 같다. 각 `input.txt`의 SHA도 invocation 기록과 일치한다. 요청/응답은 각 디렉터리에 원문으로 보존했다.
- 각 실행은 CLI `claude --print --safe-mode --tools '' --no-session-persistence --output-format json`의 **도구 없는 1턴 모의 판단**이다. plugin을 실제 호출해 G0~G2를 실행한 것이 아니다. 현행 본문을 입력으로 직접 제공했다.
- 주 응답 모델은 양쪽 모두 `claude-fable-5-1`이다(결과 metadata에 보조 `claude-haiku-4-5-20251001` 사용도 기록됨). 실제 A8 당시 `claude-opus-4-8`와 다른 모델이며 같은 엔진의 재현·대조 실험이라고 하지 않는다. 모델은 CLI 기본 선택을 사용했다.
- baseline: exit 0, 1 turn, 287,126ms. candidate: exit 0, 1 turn, 362,133ms.

## 사전 핵심 판정 기준의 적용

| 상황 | baseline | candidate | 직접 확인한 반환 |
|---|---|---|---|
| R1 재개·동일 entrypoint | 충족 | 충족 | 전체 묶음·구현 일치를 미결론/미실행으로 두고 추가 수집·원본 부품 확인·현재 구현 대조로 연결한다. candidate는 새 재개 입구의 적용 경로·버전/현재 요청 기록도 명시한다. |
| R2 거짓 등가 | 충족 | 충족 | custom 원본과 native 해소 처분의 충돌을 반송하고 열린 상태의 관찰을 보완 대상으로 남긴다. 이전 승인 요약으로 닫지 않는다. |
| R3 원본 수집만 | 충족 | 충족 | bundle 차이를 보고하고 구현 대조 미실행을 명시한다. 구현 변경으로 확대하지 않는다. |
| R4A 원본 native | 충족 | 충족 | 원본 native 채택을 이탈로 취급하지 않고 구현의 상태 검증을 남긴다. |
| R4B 구체 승인 차이 | 충족 | 충족 | 해당 메뉴 외형·동작에 대한 승인을 보존하고 재승인을 요구하지 않는다. 승인 밖 필드와 닫힌 트리거의 범위는 별도로 점검한다. |

판정자: root가 두 실행의 `result`를 전부 읽고 위 고정 기준을 적용했다. 독립 구현 리뷰어도 원문으로 대조한다. 집계는 **각 1회 응답 안의 핵심 판단 5개 충족**이며, 독립 실행 5회나 전체 작업 정확도 100%가 아니다.

## 주장 범위

기존판도 핵심 기준을 충족했으므로 성공률 개선이나 인과적 재발 방지 효과를 주장하지 않는다. 실제 A8 실패 기록을 현재 역할 판단에서 다시 일으킨 RED→GREEN 시험도 아니다. 보강한 재개 절차의 판정 이해, 기존 수집/검증 분기 연결과 두 정상경로 보존을 확인한 것이다.

두 반환에는 상황에 주어지지 않은 추가 절차 가정도 있다(예: 구 폴더의 motion-notes 신규 동결, custom 재현의 실패 fallback). 따라서 출력 전체의 실행 순서·세부 설계를 정확하다고 승인하지 않는다. R4B는 사용자 직접 승인 사례이며 **위임 승인 보존은 runtime diff의 정적 리뷰 범위**다. 이번 시험은 실제 지침 파일을 도구로 다시 읽는 행동, 모든 역할 간 인계, 브라우저 조작·화면 위치·A8 앱 수정, 플러그인 미호출 대화의 자동 교정을 증명하지 않는다.

설치·reload만 한 일반 대화를 runtime 본문으로 통제할 수 없다는 한계를 유지한다. 새 가이드는 명시적인 플러그인 재호출로 기존 빌드의 작업 범위를 다시 연결하도록 안내한다.
