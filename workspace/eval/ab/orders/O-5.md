# O-5 — delivery BC 리빌드 (비밀착 · 실백로그)

> 출처: BC 리빌드 로드맵 §2 #7 — 비-test **3,848 LOC** · **인바운드 3**(accounts·lessons·
> notifications) · **HTTP ✗** · 옛 코드에 «거짓 성공» 버그 존치(`FakeAlimtalkGateway`).
>
> **층 = 비밀착**: HTTP 표면이 없어 ninja 절이 통째로 비적용이고, 파일럿 클러스터 규범이
> 주변부다. 이 발주는 **통제군** 역할을 한다 — 여기서도 효과가 크게 나오면 그건 클러스터
> 처치의 효과가 아니라 다른 무언가다.

## 1. 이 발주가 리빌드 큐의 실측 게이트 셋 중 둘을 못 넘는다 — 그리고 왜 그래도 쓰는가

프로토콜 §2 ① 실측 게이트 3(라운드 2 신설)은 «인바운드 0 · 비-test ≤5,000 · HTTP ≥1» 이다.
delivery 는 **인바운드 3** 과 **HTTP ✗** 로 둘을 못 넘는다. 그런데도 A/B 에서 쓰는 이유:

- 그 게이트는 **리빌드 큐의 순번을 정하는 기준**이다(하네스가 싸게 닫히는 BC 부터). A/B 의
  선정 기준은 **층화**이고, 비밀착 층에는 애초에 HTTP 표면이 없는 BC 밖에 없다. HTTP ✗ 를
  결격으로 보면 비밀착 층이 공집합이 되어 층화 자체가 불가능하다.
- 게이트가 막으려던 실질적 위험은 «HTTP 가 없으면 A축·오류 축 판정이 안 선다»인데, A/B 의
  **판정 스칼라는 A축이 아니라 결정적 검사기 위반 수**다. A축은 여기서 인수 밖으로 뺀다.

**그러나 인바운드 3 은 실질 위험이 그대로 남는다** — 삭제가 이웃 세 BC 를 깨면 앵커의 전역
baseline 이 죽고, 그러면 인수의 «신규 red 0» 이 성립하지 않는다. 그래서 아래 §3 을 앵커
요건으로 못 박는다.

## 2. 발주 판형

O-4 와 동일(프로토콜 §2 클린룸 리빌드). 요청문은 `templates/request-template.md` 빈칸 채움.

## 3. 인바운드 3 중화 — OHS 동결 스켈레톤 (앵커 요건)

라운드 3(parent_settings·인바운드 1)에서 실전 투입된 장치를 3소비자로 확장한다:
소비자 쪽에 **계약 dataclass + 기본값 스텁**을 식재하고 **ACL import 를 고정**해, delivery 가
사라져도 accounts·lessons·notifications 가 import 에러로 죽지 않게 한다.

앵커 preflight 에 다음을 **실행 명령+결과**로 남긴다(산문 선언 금지):

1. 인바운드 표면 grep 실측 — 세 BC 의 실제 import 지점 전수
2. 스텁 식재 후 `make test` baseline — **green/red 수를 그대로 기록**한다. 라운드 3 선례처럼
   스텁 기인 red 가 남는 것이 정상이고, 리빌드 완주 시 green 복귀가 기대값이다.
3. 그 **스텁 기인 red 목록**을 명시적으로 열거한다 — 인수의 «신규 red 0» 은 이 목록을
   기준선으로 삼는다. 열거하지 않으면 스텁 red 와 처치 기인 red 를 가를 수 없다.

## 4. 클린룸 리셋 앵커 — 실증 1회 후 봉인 (D10 조건)

O-5 는 발주 풀 등록 시 «1회성»이었고, 2026-08-19 «클린룸 리셋으로 반복 가능(A/B 한정)»으로
재판정됐다. 그 재판정은 **리셋 앵커 실증 1회를 조건으로** 유효하다(T1 order-pool append 로그).

봉인 대상 셋:

| 항목 | 내용 |
|---|---|
| baseline commit | 라운드 앵커 커밋 해시(스텁 식재 + BC 삭제가 담긴 커밋) |
| 리셋 명령 | 워크트리를 앵커 상태로 되돌리는 **정확한 명령** |
| 리셋 후 동등성 해시 | 리셋 직후 추적 파일 트리 해시 — 6회(2반복×3암) 모두 이 값이어야 한다 |

**실증**: 리셋을 1회 실제로 돌려 해시가 재현되는지 확인한다. **실증 실패 시 이 재판정은
무효**이며, 비밀착 층 처분(O-6 대체 여부)을 게이트로 재상정한다.

리셋은 **폴더 삭제 후 재클론**이 아니라 워크트리 기반이므로, 인플레이스 리셋의 잔여물
(`__pycache__`·`.dddjango/`·`.env.local`·미추적 산출물)이 다음 런에 새지 않는지가 실증의
핵심이다. 추적 파일만 같고 미추적 오염이 남으면 그건 클린룸이 아니다.

## 6. 옛 코드 버그 취급 — 오라클로 쓰지 않는다

delivery 옛 구현에는 «거짓 성공» 버그가 있다(`FakeAlimtalkGateway`). 프로토콜 ⑦-3 대로
**옛 코드 버그는 사용자 보고·판정 대상**이지 신규 구현의 기준이 아니다. 신규 구현이 그
버그를 재현하지 **않는** 것은 후퇴가 아니라 개선이며, 인수·채점 어느 쪽에서도 감점하지 않는다.
`spec.md` 는 이 버그를 요구로 옮겨 적지 않는다.
