# O-7 — 표준 스모크 발주 (밀착 · 합성)

> **합성 발주임을 명시한다**(동결 §6 합성 표기 의무). 실백로그가 아니라 확립된 벤치마크
> 판형이고, N≥5 반복 실증 이력이 있어서 A/B 적성이 가장 높다. 그 대가로 «실무 대표성»은
> 주장하지 않는다 — 리포트에서 이 발주의 결과를 실무 일반화에 쓰지 않는다.

## 1. 발주문 (토씨 그대로 · 변경 금지)

```text
재고가 부족하면 409로 거절하고, 충분하면 재고를 차감하며 주문을 생성하는 API.
```

- 런마다 `git clone` 으로 새 타깃을 뜬다 → 추적 코드 byte 동일. `setup.sh` 로 venv·DB·시드

## 4. 인수 테스트 — arm-independent 블랙박스 · **외부 스위트**

세 암 모두에 **같은 명령**을 돌린다. 구현을 읽지 않는다.

```bash
python manage.py check                              # 경고·오류 0
python manage.py makemigrations --check --dry-run   # 미반영 마이그레이션 0
# **인수의 정본은 외부 스위트다** — 산출물이 쓴 테스트가 아니다
cp workspace/eval/ab/acceptance/O-7/test_external_acceptance.py <타깃>/<앱>/tests/
python manage.py test --pattern='test_external_acceptance.py'
python manage.py test                               # 산출물 자체 스위트 = **보조 지표**
```

**왜 외부 스위트인가**: 타깃의 테스트는 **파이프라인이 직접 쓴다**. 그 스위트 green 을 인수로
삼으면 ⓐ 필요한 시나리오를 안 쓴 산출물이 통과하고 ⓑ 더 철저히 쓴 암이 자기 결함을 드러내
떨어진다 — 인수 통과가 **처치와 상관된 선택 변수**가 된다(전수 리뷰 AU 발견 6).
산출물 자체 스위트의 결과는 보조 지표로만 기록한다.

**커버 요구**(외부 스위트가 실제로 밟는다 — 산문 요구가 아니다):

| # | 시나리오 | 기대 |
|---|---|---|
| A1 | 재고 충분 + 주문 생성 | 201 · 재고가 주문 수량만큼 줄어 있다 |
| A2 | 재고 부족 | **409** · 재고 불변 |
| A3 | 없는 상품 | 404 |
| A4 | 동시 주문(경합) | **oversell 0** — 재고가 음수로 가지 않는다 |

A4 는 이 발주의 존재 이유다. 나머지 셋이 green 이어도 A4 를 밟는 테스트가 없으면 인수 실패다
(«테스트를 안 써서 통과»를 막는다).

## 5. 인수가 보지 않는 것

옛 합격 기준 (B)(빈혈 도메인·`stock__gte` 누수·§0 파일트리·§4 명명·홀리스틱 감사)는
**인수에서 뺀다**. 그건 처치가 개선하려는 대상이고, 인수에 넣으면 처치가 먹은 런만
채점되어 선택 편향이 된다. 전부 채점기(결정적 검사기 27종)와 루브릭이 본다.

## 6. 허용 도구

파이프라인 기본값 그대로. 추가·제한 없음. `--permission-mode` 는 세 암 동일
(`external_annex.runtime.permission_mode` 봉인값).

## 7. hard stop — 암별 분리

| 암 | 상한 |
|---|---|
| A | 기계 **4h** · 과금 **10M** |
| B · C | 기계 **8h** · 과금 **20M** |

세 암에 같은 값을 걸면 **초과 확률이 처치 강도와 같은 방향**으로 갈린다 — 그 값의 출처인
스모크 8런이 루프 배선 **이전의 A 판형**이기 때문이다. 자세한 근거는
`T2-0a-preregistration.md` §5. 초과 시 그 런 무효(기술 실패) → 같은 블록 triplet 재실행
1회 한도(자율). **초과 사건은 암별로 전수 보고**한다.
