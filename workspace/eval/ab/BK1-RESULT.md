## 판정 스칼라 (ab_score.py · arm-blind)

**세 암 완전 동일**: `V=1` — 전부 `#429`(config/settings.py · check-layer-skeleton) 한 건.
이는 발주가 «빚으로 격리하고 진행»으로 고정한 기존 빚이다. 즉 **B−A = 0 · C−A = 0**.

## 노출 점검의 답: **처치 발화 0 — 측정 실패**

- **B(R02)**: 루프 도달 · `regen_core --selector snapshot` → «주입 대상 0» · exit 3 · 회전 0
- **C(R03)**: 루프 도달 · exit 3 · 회전 0
- 원인은 두 런 모두 동일 — introduced.json 의 유일 귀속이
  `check-app-container.py :: [진단 미파싱 · exit 2] fail-closed 귀속` 합성 줄이고,
  이 줄은 [#N] 태그가 없어 **규칙으로 해석되지 못해 주입 대상이 만들어지지 않았다**.
- 같은 결함이 세 런의 G2 를 전부 red 로 만들어 **세 런 모두 같은 STOP** 을 올렸다
  (R01 STOP-3 · R03 STOP ④ · R02 G2 STOP — 전부 «수용·보고» 처분으로 수렴).

**«효과 없음»이 아니라 «말할 기회가 없었음»이다.** V 가 세 암 동일한 것은 처치가
발화하지 못한 상태의 자연 귀결이므로, 이 블록에서 효과 크기는 **판정 불능**.

## 바깥 인수 스위트: 판정 불능 (스위트 결함 3건 — 세 암 공통·처치 무관)

동결 스위트(`acceptance/O-7/test_external_acceptance.py`) 실측: 세 암 공히 5중 4 ERROR.

| # | 결함 | 증상 |
|---|---|---|
| ① | Django 4.2.30 × **Python 3.14**: 테스트 클라이언트 템플릿 계측(`store_rendered_templates` → `BaseContext.__copy__`)이 크래시 | 4xx/HTML 응답을 받는 순간 전 테스트 ERROR — 1차 원인 은폐 |
| ② | **고정 시드 미자급** — 스위트가 가정한 Widget/Gadget 은 개발 DB 에만 있고 테스트 DB 에는 아무도 만들지 않음 | 시드 의존 3건(a1·a2·a4) 전멸 |
| ③ | **경로 발견이 include prefix 유실** — `_candidate_paths` 가 하위 패턴(`orders`)만 취해 `/orders` 를 침. 실제는 세 암 모두 `/api/orders` | 전 요청 HTML 404 |

문면 규정(«exit 비-0 = 그 런은 채점하지 않는다»)대로면 세 런 판정 실패지만, 원인이
전부 측정 장치(러너 환경·스위트) 쪽이므로 **산출물 실패가 아니라 측정 실패**로 분류한다.
