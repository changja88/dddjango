### 감시기를 세션에서 분리했다

Monitor 로 띄우면 내 세션이 끝날 때 같이 죽는다. `nohup` 으로 떼어내 **독립 프로세스**로 돌리고,
내 세션은 이벤트 파일을 tail 만 한다. 세션이 죽어도 권한 프롬프트는 계속 풀린다.

```
watch-bk1.sh (nohup · 5초 주기)  →  bk1-events.log  →  메인 세션이 tail
```

| 상황 | 처리 |
|---|---|
| 설치본·타깃 읽기 · 무위험 bash | **즉시 자동 승인** |
| 게이트 질문(선택지 메뉴) | 전문을 `gate-questions/<런>.txt` 로 떨구고 알림 · **2분마다 재알림** |
| 게이트 **10분 무응답** | 승인형(«승인·제안대로·무수정·Recommended»)이면 **1번 폴백 제출 + 요란한 기록**. 승인형이 아니면 폴백하지 않고 사람을 기다린다 |
| 쓰기·삭제·네트워크·`sudo`·`git push` | 자동 승인 안 함 — 알림 |
| 오류·한도·컨텍스트 소진 | 알림 |
| 주입 발화 | 회전 수 변할 때마다 알림 |
| 60초 유휴 | «완주 또는 정지» 알림 |
| 15분마다 | 생존 신호 |

**폴백을 둔 이유와 그 대가**: 밤새 게이트에서 멈추면 완주가 없다. 그러나 1번이 항상 옳은 답은
아니다 — 그래서 승인형으로 한정하고, 폴백이 발동하면 **사후 검증 대상**으로 요란하게 남긴다.
G0 답(BC 배치·lens·프레임워크)은 발주문이 이미 고정했고 코디네이터가 그것을 승인 입력으로
받았음이 R01 로그로 확인됐다 — 폴백이 닿을 자리는 G1/G2 승인 계열이다.

**데이터는 세션과 무관하다**: 산출물은 전부 타깃 폴더에 있다. 감시기도 내 세션도 죽어도
이미 나온 결과는 남고, 채점은 나중에 해도 된다.

## 관측된 교락 위험 — 공유 `/tmp` (2026-08-21 02:14 · 결과 관측 전 기록)

R03 의 coder 가 검사기 조기 신호를 볼 때 **`/tmp/ls.txt`** 를 썼다(`… > /tmp/ls.txt 2>&1; grep …`).
세 런이 **동시에** 도는데 경로가 같으면 한 암이 다른 암의 출력을 읽을 수 있다.

**판단: 채점에는 닿지 않는다.** 판정 스칼라의 재료는 G2 의 `registry_gate.py --introduced-json`
출력이고, 이건 coder 가 중간에 눈으로 보는 **조기 신호 탐침**이다. 충돌해도 그 순간 coder 가
잘못된 힌트를 볼 뿐 점수 재료가 오염되지는 않는다.

**개입하지 않은 이유**: 여기서 «다른 경로를 쓰라»고 끼어들면 그 지시가 암마다 다른 시점에
들어가 처치 아닌 차이를 만든다. 위험을 기록하고 그대로 둔다.

**사후 점검 항목**: 채점 때 세 런의 G2 증거가 각자 산출물 폴더 안 파일에서 나왔는지 확인한다.
`/tmp` 경유 값이 G2 증거로 인용됐으면 그 런은 기술 실패로 본다.

2. **권고가 없으면**(«권고 불가» 표기) 아래 둘을 이 순서로 적용한다.
   - ⓐ **결정적 게이트가 실제로 검사하는 선택지**를 고른다. 판정 스칼라 V 는 게이트 출력에서
     세는 값이다 — 게이트가 아무것도 안 보는 선택지를 고르면 그 런의 측정이 무의미해진다.
   - ⓑ **스코프를 넓히지 않는 선택지**를 고른다. 한 암만 스코프가 커지면 비교가 깨진다.
3. 위 둘로도 안 갈리면 **자유 입력을 쓰지 않고** 첫 선택지를 고른 뒤 사후 검증 대상으로 남긴다.

| ③ Z-5 registrar ↔ #107 | `ⓒ` 미사용 api 인자 | **권고 불가 — 규칙 2ⓐ**(아래 상술) |

**③ 을 왜 ⓒ 로 골랐나**: 선택지 셋 중
`ⓐ`(django-ninja 도입)는 발주 배제 스택 + 스코프 폭발이라 규칙 2ⓑ 로 탈락한다.
`ⓑ`(#107 명시 수용)는 G2 «귀속 0» 계약에 승인 예외를 뚫는데, **선택지 자신이 «`--legacy-debt-file`
채널은 신규 파일에 쓰라고 만든 것이 아니다»라고 적고 있고** 커맨드 규정도 그 채널을 «미이관 표준
경로 의존»에만 허용한다(§137). 측정 장치를 규정 밖으로 오용하는 선택지다.
`ⓒ` 는 검사기가 정직하게 통과하고 예외를 만들지 않는다. 대가인 «죽은 인자»는 **루브릭이 잡아야
할 품질 비용**이지 판정 스칼라를 왜곡하지 않는다. 규칙 2ⓐ 그대로다.

**④ 의 자인**: 게이트로도 스코프로도 안 갈려 규칙 3(첫 선택지)을 적용했다. R01 은 같은 축을
**위임 처리**(기본값 503 수락)로 넘겼고 R03 은 **STOP** 으로 올렸다 — 즉 두 암의 API 가 이 지점에서
갈린다(R01 503 · R03 409). 이는 처치가 아니라 **설계가 달라진 결과**이고 그 자체가 관측 대상이지만,
내 답이 그 차이를 확정했다는 사실은 남는다. 사후 검증 대상.

**Z-6 의 `ⓐ` 를 피한 이유 하나 더**: 선택지가 자인한 위험이 «BASE_DIR 을 재계산하지 않으면
**게이트 전부 green 인 채** 개발 DB 경로가 조용히 갈린다» 였다. 측정이 못 잡는 실패는 A/B 에서
가장 나쁜 종류다.

**Z-7 은 봉인 스코프 문제였다**: 이 런의 불변 제약이 «`.venv/`·`db.sqlite3` 를 건드리지 않는다» 이고
`ⓐ` 는 그것을 «`catalog_product` 를 파괴하지 않는다» 로 **다시 읽는** 선택이다. 실험 측면 이유도
있다 — 한 암만 실 DB 를 바꾸면 **런 종료 후 타깃 트리 상태가 처치와 무관하게 갈린다**.
대가는 자인한다: 완료 기준은 전부 green 인데 개발 환경의 실제 `POST /api/orders` 는
`no such table: order_order` 로 500 이다. **«완료» 가 «동작» 을 뜻하지 않는 상태로 끝난다.**
바깥 인수 스위트는 Django 가 테스트 DB 에 마이그레이션을 적용하므로 영향받지 않는다.
