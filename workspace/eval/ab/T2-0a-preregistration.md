## 1. 판정 산식 (수식 고정)

발주 `o`, 암 `x ∈ {A,B,C}`, 반복 `r ∈ {1,2}` 의 위반 수 `V_x,o,r` 에서

- `V̄_x,o` = 반복 중앙값 (n=2 이므로 **산술평균**)
- **판정 재료** = 밀착·혼합 층의 **유효 발주** — `V̄_B,o > 0` 인 발주.
  `V̄_B,o = 0` 은 **uninformative ceiling** 으로 분리하고 **성공에 산입하지 않으며** 별도 보고한다.

**방향 조건**(유효 발주 전건): `V̄_B,o ≤ V̄_A,o` ∧ `V̄_C,o ≤ V̄_B,o`

**감소율**: `rate_o = (V̄_B,o − V̄_C,o) / V̄_B,o` — 유효 발주의 rate **중앙값 ≥ 15%**(D9)이면
운영 문턱 충족. 절대차·rate ratio 를 병기한다.

**저분모·소표본 처분**(신설 — 앞선 판은 «플래그만» 이라 규칙이 없었다):

1. **`V̄_B,o < 3` 인 발주는 rate 중앙값 계산에서 제외**하고 별도 보고한다(플래그 → **배제**로
   승격). 사유: 1→0 이 100% 로 읽히는 잡음을 계획서가 이미 자인해 놓고 그것을 걸러낼 규칙이
   없었다. 그대로 두면 «한 발주에서 위반 하나가 사라졌다»가 문턱 통과의 실체가 된다.
2. **유효 발주 < 2 이면 D9 문턱을 «충족»으로 읽지 않는다** — 판정은 자동 «조정».
   밀착·혼합 층은 O-7·O-4 **둘뿐**이므로 한쪽이 빠지면 «중앙값»은 단일 값이다.
3. **유효 발주 0건 = 판정 불가**. 원인을 세 갈래(수렴·팩 미적중·표본)로 분류해 리포트에
   등재하고 계속/조정을 게이트로 재상정한다. §10 노출 게이트와 같은 처분 경로다.

**비밀착 층**(비열화 전용): `V̄_C,o − V̄_B,o ≤ δ`, **δ = 0**.

**판정 스칼라** = 결정적 검사기 위반 수 단독(`severity=violation`).

### 1.1 계수 규약 (T2-0b 에서 확정 — 앞서 «scorer 계약»으로 전방 참조돼 있던 자리)

```
V = |{ (rule, 라인 제거 경로, symbol)
       : registry_gate 귀속 레코드 중 severity == "violation" }|
```

유일한 실행체는 `workspace/tools/ab_score.py`(`scorer` 그룹 동결). 사람이 손으로 세지 않는다 —
손으로 세는 판정 스칼라는 arm-blind 가 아니다.

| 항목 | 확정값 | 왜 |
|---|---|---|
| **축** | `registry_gate --anchor <라운드 앵커> --legacy-debt-file <봉인 빚>` 의 **귀속 차분(N∖L)** | full-tree 를 쓰면 분모가 «루프가 손댈 수 없는 질량»에 지배된다. step 6′ 자신이 legacy 즉석 수리를 금지하므로 그 질량은 **어느 암도 못 줄인다** — 문턱이 구조적 천장 위에 놓인다 |
| **집계 단위** | **라인 제거 축** `regen_core.canonical_locator` | 재생성은 줄을 계속 밀어낸다. 라인 민감 계수는 무관한 이동에 반응한다. `regen_core.py` 가 「두 축을 합칠지는 T2-0b 봉인 때 확정한다」고 미뤄 둔 결정을 여기서 내린다 |
| **`findings_count_matrix` raw 축** | **그대로 둔다** | 그쪽 목적은 stdout 골든(라인 고정)이다. 두 축은 목적이 다르므로 합치지 않는다 — EXPECTED 27종을 건드리지 않는다 |
| **severity 필터** | `violation` 만 | 진단·보고 항목은 판정 밖 |
| **exit 해석** | `registry_gate` exit **0·2 모두 정상 채점**, 1 = 재료 결손 | 0 = 귀속 0(정상적인 V=0), 2 = 귀속 존재 |
| **보조 지표** | full-tree 수·`legacy_residual`·`unmatched_lines`·raw 레코드 수 | 판정에 안 들어간다. «분모의 성질»을 리포트가 서술할 때 쓴다 |
| **arm 비노출** | 채점기는 `--arm`·`--treatment`·`--selector`·`--lane` 인자를 **거절**한다 | 실수로도 암별 계수가 갈리지 않게 기계로 막는다 |

**자인**: 이 축은 «처치가 자기 채점표를 지운다»는 성질을 갖는다 — 루프가 소비하는 재료가 정확히
`introduced.json` = N∖L 이다. 그것은 결함이 아니라 **처치의 정의**다(루프의 일이 새로 들인 위반을
지우는 것이다). 다만 B 가 수렴해 `V̄_B = 0` 이 되면 그 발주는 uninformative 로 빠지므로, 그
위험은 §10 **노출 게이트**가 별도로 다룬다.

## 2. estimand 명명 — 그리고 C 처치가 **한 성분이 아니라는** 자인

- **B − A** = «폐루프 정책 번들 효과»(루프 + 주입 + 재생성 예산)
- **C − B** = «그래프 선별 규칙 팩 효과»

두 대비 모두 **발주 사례 연구로 한정**한다. «입증» 어휘를 쓰지 않는다.

### 2.1 구성 타당도 한계 (사전 자인 — 사후 해명 금지)

C 는 B 에 **세 가지**를 더한다. `dddjango/scripts/regen_core.py` `select_graph` 는 C 에서만
불리고, 그 함수가 하는 일이 셋이다:

| 성분 | 내용 | B |
|---|---|---|
| ① 중복 제거 | 같은 `identity` 위반을 대표 하나만 | 안 함 — 라인만 다른 같은 위반이 여러 번 실림 |
| ② 재정렬 | `(순위없음, tier, 순위, identity, 자리)` 정렬 — 같은 Work 위반이 인접 | 안 함 |
| ③ `<rules>` | 규칙 번호·명칭 **+ 조인 표지(`join`) + 후보 오적용 억제 문장 3줄** | 없음 |

③ 의 실물은 «번호·명칭»보다 넓다(레인 AV 발견 13). `_RULES_NOTE` 3문장 중 「candidate 를
근거로 다른 코드를 고치지 않는다」는 **행동 지시**이고, 항목마다 `join ∈ {exact, candidate}`
표지가 붙는다. 그래서 C−B 를 「번호·명칭 효과」로 부르지 않는다.

**투여량 하한**(신설): 런의 정확 조인(`exact`) 규칙이 **0건**이면 그 런은 `uninformative` 와
같은 등급으로 분리 보고하고 C−B 유효쌍에서 뺀다. 사유: tier 2(검사기 축) 후보는 주입문 자신이
행동을 **금지**해 보내는 정보다. 팩의 alias 정확 조인은 실측 **3규칙**(`#3`·`#486`·`#488`)뿐이고
검사기 27종 중 11종이 팩 밖(tier 3 = B와 동일 재료)이라, 정확 조인 0 + 후보 다수인 런이
«정상 C 런»으로 계상되면 **투여량이 0에 가까운 런이 «효과 없음»의 증거로** 쓰인다.
용량 로그가 `exact_n`·`candidate_n`·`exact_ratio`·`candidate_ratio` 를 런마다 기록한다.

**리포트 한계 문구(의무)**: 「alias 정확 조인 3규칙 · 검사기 27종 중 11종 팩 밖」을 C−B 해석에
반드시 병기한다.

**본 설계는 이 셋을 분리하지 않는다.** 4번째 암(C′ = ①②만)이 있어야 분리되는데, 동결 §6 이
«최소 18실런»을 고정했고 24런은 예산 밖이다. 따라서 C−B 를 «규칙 이름 주입의 효과»라고 부르지
않고 **«그래프 선별 묶음의 효과»**라고 부른다.

**사전 등록 부분집합 분석**: 용량 로그의 `deduped_n == 0` 인 런에서는 성분 ①이 작동하지
않는다. 그 부분집합의 C−B 를 **별도 보고**한다 — 표본이 작아 검정은 하지 않고 **서술만** 한다.

## 3. 암 정의 — 차등은 스위치 둘

세 암 모두 **T2 개작 완료판 파이프라인**(내부 plugin·검사기·gate byte-identical).

| 암 | `DJR_LOOP_ENABLED` | `DJR_LOOP_SELECTOR` | 재생성 예산 |
|---|---|---|---|
| A | `off` | — | 0 (null treatment) |
| B | `on` | `snapshot` | N = 3 |
| C | `on` | `sparql` | N = 3 |

실런 판형 = **무수정 승인 고정**(게이트 반송 3암 공히 0). 반송 지표는 판정과 무관하며 동결 §1 ②
의무 산출물로만 기록한다.

## 4. 측정 종료점 (동결 개정 7)

런의 `measurement_complete` 와 Coordinator 의 `pipeline_complete`(G2 승인)를 **분리**한다.

1. 최초 구현·감사·관련 테스트를 마치고 동결 인수 테스트가 통과한 상태를 **`S0` 로 봉인**.
2. 첫 결정적 게이트 receipt 후 암별 처치 — A = null treatment / B·C = 동일 예산 N=3 폐루프.
   위반 0 이면 조기 종료 가능하되 `no_progress` 는 **진단 플래그로만** 기록(종료 사유 아님).
3. 처치 종료 상태를 **`S1_x` 로 봉인**.
4. **세 암 모두** `S1_x` 에서 동결 인수 테스트와 frozen scorer 를 **새로 실행**.
5. 인수 통과 + 기술 실패·scope 위반 없음일 때만 `V_x` 를 채점. **인수 실패는 판정 실패이며
   `V=0` 으로 산입하지 않는다.**
6. **G2 제시·승인은 어느 암에서도 채점 요건이 아니다.** 기록 항목:
   `measurement_complete` · `acceptance_pass` · `pipeline_complete` · `g2_blocker_count` ·
   `regen_turn_count` · `pre_gate_repair_cycles`.
7. 측정 후의 owner-remand·G1 회귀·G2 완료 작업은 **비채점 후속 처리**이며 봉인된 측정
   snapshot 과 점수를 바꾸지 못한다.
8. **`S1_x` 의 확정 시점을 못 박는다**(신설 — 앞선 판은 해석에 달려 있었다):
   `S1_x` = **마지막 회전의 coder 편집 직후** 게이트 재실행 결과. step 6′ 의 **전면 재감사**
   (규율 감사·전체 스위트·직접 selector 레인 — `dddjango.md:147`)는 **`S1_x` 이후의 비채점
   후속 처리**다.
   사유: 그 전면 재감사는 **B·C 에만 걸린다**(A 는 6′ 절을 통째로 건너뛴다). 「규율 감사」는
   결정적 검사기가 못 보는 의미 변종을 잡으라고 만든 LLM 감사이고, 그것이 `S1` 이전에 돌면
   B·C 는 A 가 받지 않는 **추가 의미 리뷰 1회**와 그로 인한 추가 수리를 받는다. 그러면
   B−A estimand 가 «폐루프 정책 번들»이 아니라 «폐루프 + 추가 규율 감사 라운드»가 되고,
   「세 암의 차이는 환경 스위치 둘뿐」이라는 주장이 그만큼 거짓이 된다.

## 5. 런 유효성 규약

런 시작 = 독립 세션 개시.

**hard stop — 암별 분리**(정정): 앞선 판은 세 암에 같은 상한(O-7/O-4 4h·10M · O-5 8h·20M)을
걸었다. 그런데 그 값의 출처는 스모크 8런(41~114분·1.58~5.60M)이고 **그 8런은 루프 배선
이전의 A 판형**이다. B·C 는 구조상 더 태운다 — coder 재호출 최대 3회 + 회전마다 게이트
재실행 + 확정용 1회 + 전면 재감사. 같은 상한을 걸면 **초과 확률이 처치 강도와 같은 방향**으로
갈리고, 초과를 «재실행»으로 처리하면 오래 걸린 B·C 런이 반복 삭제된다 — §5 가 막으려는
「불리한 표본이 지워진다」 그 자체다.

| 발주 | A | B · C |
|---|---|---|
| O-7 · O-4 | 기계 4h · 과금 10M | **기계 8h · 과금 20M** |
| O-5 | 기계 8h · 과금 20M | **기계 16h · 과금 40M** |

배수 2 의 근거: A 판형 상단(5.60M)이 A 상한의 56% 이므로, 회전 3 을 감당하려면 배수 2 가
상한을 공허하게 만들지 않으면서 A 분포를 덮는 최소값이다. hard stop 은 **예산이 아니라 이상
탐지**이며(2026-08-19 사용자 결정 «비용보다 퀄리티»), 초과 처분은 승인 문면대로 «해당 런
무효·같은 블록 triplet 재실행»을 유지한다. 다만 **초과 사건을 암별로 전수 보고**한다 —
검열이 처치와 상관됐는지 사후에 확인 가능해야 한다.

**암 영수증**(신설): 세 암 **모두** 런 시작에 한 번
`python3 <설치본 scripts>/regen_core.py --arm-receipt <산출물 폴더>/arm.json` 을 돌린다.
A암은 루프를 안 돌려 `injection.jsonl` 이 아예 생기지 않으므로, 영수증이 없으면 ⓐ A로 돌았다
ⓑ B로 돌았는데 게이트가 green 이라 발화가 없었다 ⓒ B로 돌았는데 조율자가 step 6′ 를
건너뛰었다 — 셋이 구별되지 않는다(판정 의미는 각각 정상·노출 0·프로토콜 위반으로 전혀 다르다).
**영수증 부재 = 기술 실패.** 영수증의 `DJR_LOOP_SELECTOR` 가 배정된 암과 다르거나,
`injection.jsonl` 의 어느 행이든 `selector` 가 배정과 다르면 **그 런은 기술 실패·triplet 재실행**.

| 사건 | 처분 | 재실행 |
|---|---|---|
| 기술 실패(모델 오류·인프라·scorer crash·hard stop 초과) | 같은 블록 **triplet 전체 재실행** + 최초 기록 보존·사유 등재 | **허용**(1회 한도) |
| 산출물 미완성 · `STOP_FOR_USER_APPROVAL` · 인수 불통과 | **판정 실패**(0위반 산입 금지) | **금지** |
| 클린룸 위반 실측 | 그 런 무효 | 허용 |

**가르는 선**: 처치가 원인일 수 있으면 재실행 금지(재실행은 불리한 표본을 지운다), 하네스·환경이
원인이면 재실행 허용. intention-to-treat — 유효 런 제외는 이 표의 사유만.

### 5.1 선행 계약(`rule=null`) 위반의 처분 — «계수 후 유효 유지»

`ContractFindings` 계열은 `[#N]` 표식이 없어 게이트 sidecar 에 들어가지 않으므로 **C 처치에
도달하지 않는다**(T2-4 반증 레인 AR 과제 2 실측 — `check-api-error-controller-contract.py` 기준
규칙 범주 23 중 **11** 이 이 형태).

**처분(2026-08-20 사용자 승인 — 동결 개정 9)**: companion sidecar 로 **계수만** 하고 유효 비교에
그대로 남긴다. **제외 문턱을 두지 않는다.** 사유: 세 암이 같은 조건이라 편향이 생기지 않고,
n=2 표본에서 제외 규칙은 유효 표본만 줄인다.

런마다 `uninjectable_n`(검사기별)을 기록하고 A/B 리포트에 비율을 병기한다 — **사후 해명 금지**
(사전 등록 항목).

## 9. 오탐 adjudication · 맹검의 실제 범위

오탐 심의는 arm·순서 식별자를 제거한 레코드로 **codex 독립 레인**이 수행한다(규약 R4 — 저자
비맹검 문제의 해소). 판정 기록 후 제외하며, 제외 전/후 수와 사유를 전량 공개한다.

| 층 | 성립 | 근거 |
|---|---|---|
| 채점기 | **성립** | `ab_score.py` 가 arm 인자를 **거절**한다(§1.1) |
| 오탐 심의 | **조건부 성립** | 아래 봉투 조건에서만 |
| 저자·실행자 | **불성립(자인)** | 배정표가 공개되고 실행자가 곧 저자 |

**심의 봉투 조건**(신설 — 앞선 판은 무조건 «성립»이라 적었고 그건 유지 불가였다):
`blind_label ↔ arm` 의 완전한 역매핑이 `T2-0b-manifest.json` 과 `--allocation` 출력에 **그대로
있다**. 저장소를 읽는 심의 세션은 의도적으로 조회하지 않아도 전수 탐색 중 마주친다 —
「배정표가 공개되므로 저자 맹검은 거짓 주장」이라는 논증은 **심의 레인에도 똑같이 적용된다**.

따라서 심의 레인은 **저장소 접근 없이** 돈다: 심의 대상 레코드를 파일/stdin 으로만 넘기고
작업 디렉터리를 저장소 밖에 둔다(적대 검증 레인이 쓰는 `--sandbox read-only + 저장소 루트`
판형을 **쓰지 않는다**). 이 봉투를 못 지키면 오탐 심의 행도 «불성립»으로 내려 적고, 리포트
문면 규칙에 그 사실을 함께 적는다.

**리포트 문면 규칙**: «맹검 실험»이라 쓰지 않는다. «채점기·심의 맹검, 실행자 비맹검»으로 쓴다.

## 10. 노출 게이트 (신설 — 1블록 게이트를 «비용»에서 «비용+노출»로)

루프는 **게이트가 red 일 때만** 발화한다(`dddjango/commands/dddjango.md:139`). 게이트가 green 이면
B·C 의 처치 노출이 정확히 0 이고, 그 런의 세 암은 같은 파이프라인이다.

그런데 최근 라운드 실측은 그 위험이 크다고 말한다:

| 라운드 | BC | `registry_gate` 귀속 |
|---|---|---|
| 1′ | child_settings | 23 |
| 3 | parent_settings | **0** |
| S3-r1 | child_settings | **0** |

**연속 두 라운드가 귀속 0** 이고, O-4 = child_settings 는 바로 그 발주다.

**사전 등록**:

1. 첫 블록(BK1 = O-7·Claude · R01~R03) 종료 시 **루프 발화 회전 수**와 **`V_B,O-7,1`**
   (단일 런 값 — `V̄` 가 아니다)을 함께 본다.
   **정정 근거**: `V̄_x,o` 는 반복 1·2의 평균이고 O-7 반복 2 는 BK5 에 있다. BK1 시점에
   `V̄_B,O-7` 은 **계산 불가능**하다 — 앞선 문면은 존재하지 않는 값을 보라고 적고 있었다.
   단일 런 값으로 «노출이 있었는가»는 판정할 수 있고, 게이트가 묻는 것은 그것뿐이다.
   이 게이트는 **판정이 아니라 노출 점검**이므로 `V̄` 를 쓸 이유가 없다.
2. 둘 다 0 이면 **즉시 보고**하고, 잔여 15런을 태우기 전에 처분을 정한다.
   **발주 재선정은 «방향 변경형» 개정이므로 사용자 상정 대상**이며(규약 R2·R3-2), 재선정이
   확정되면 그때까지의 런을 폐기하고 새 사전 등록으로 다시 시작한다 — 돌던 실험의 발주를
   중간에 바꾸면 앞뒤 런이 같은 실험이 아니다.
3. **노출 지표를 1급 산출물로** 등재한다 — 런마다 `injection.jsonl` 행 수(발화 회전)와
   `violations_n`. 용량 로그가 이미 둘 다 기록한다.
4. **«유효쌍 0» 처분**: 밀착·혼합에서 `V̄_B,o > 0` 인 발주가 하나도 없으면 판정은 «통과»도
   «실패»도 아닌 **«판정 불가 — 처치 미노출»**이며, §7 롤백 분기가 아니라 **발주 재선정**
   논의로 간다.
