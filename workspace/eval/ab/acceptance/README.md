# 외부 인수 스위트 — 산출물이 쓴 테스트에 의존하지 않는 인수

> 전수 리뷰 레인 AU 발견 6 의 처분. **인수 통과 여부가 처치와 상관되면 인수 게이트가 아니라
> 선택 장치다.**

## 문제

앞선 인수 판형은 세 발주 모두 «타깃의 테스트 스위트가 green 인가»를 물었다. 그런데 그 스위트는
**파이프라인이 직접 쓴다**(리빌드 프로토콜 원칙 2 — 옛 테스트를 오라클로 주지 않는 것이 설계
의도다). 그래서:

- 필요한 시나리오를 **아예 안 쓴** 산출물이 자기 스위트 green 으로 인수를 통과한다
- 더 **철저히 쓴** 암은 자기 결함을 더 드러내 인수에서 떨어진다

두 방향 모두 인수 통과를 처치와 상관시킨다. 채점 대상 집합이 처치에 따라 달라지면 그 뒤의
어떤 비교도 성립하지 않는다.

## 처분

발주별 **외부 블랙박스 스위트**를 타깃 산출물과 분리해 여기서 저작·동결한다. 산출물이 쓴
스위트 green 은 **보조 지표**로만 기록한다.

| 발주 | 외부 스위트 | 상태 |
|---|---|---|
| O-7 | [`O-7/test_external_acceptance.py`](O-7/test_external_acceptance.py) — A1~A4 + 공개 표면 존재 | **저작 완료** |
| O-4 | 공개 shape 대조(`api_shape_pre_success.json`) + 이웃 BC 테스트 | **타깃 접근 필요** |
| O-5 | 세 소비 BC(accounts·lessons·notifications) 계약 행사 | **타깃 접근 필요** |

O-4·O-5 의 외부 스위트는 타깃의 shape 파일과 소비 BC 목록을 재료로 하므로 저장소 안에서
저작할 수 없다. **부속서 `PENDING` 항목**이며, 그 상태에서 `manifest_seal.py --check` 는 red 다.

## 설계 규율 (세 스위트 공통)

1. **구현을 읽지 않는다.** HTTP 표면·공개 계약만 두드린다.
2. **이름을 강제하지 않는다.** 경로·필드명은 파이프라인의 설계 자유다. 대신 URLconf/shape 를
   훑어 표면을 **발견**하고, 발견 실패 자체를 인수 실패로 본다.
3. **발주에 없는 요구를 추가하지 않는다.** 예컨대 O-7 발주문은 조회 API 를 요구하지 않았으므로,
   조회가 없다고 떨어뜨리지 않는다(재고 확인은 DB 폴백을 둔다).
4. **메커니즘을 지시하지 않는다.** oversell 검사는 «성공 건수가 재고를 넘지 않는가»로 보고
   CAS·락·제약 중 무엇을 썼는지 묻지 않는다.
5. **거짓 red 를 만들지 않는다.** 플랫폼 의존(스레드 경합·타이밍)에 기대지 않는다 — 인수의
   거짓 red 는 그 런을 부당하게 판정 실패로 만든다.
