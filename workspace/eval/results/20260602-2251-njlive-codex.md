## 의미적 변종 / backstop-blind 메타

- **치명 의미변종 1건(SD-6)**: `check-error-centralization.py` **exit0이나 의미 FAIL** — DR-24/Goodhart 차단 규칙대로 치명 FAIL 라우팅. 백스톱이 *원리상 못 보는* 것을 의미 정독이 잡음:
  - status:int `IdempotencyClaim.response_status`가 infra store↔presentation 왕복(plain dataclass라 `JsonResponse(`/`from ninja` 텍스트 신호 0 → 백스톱 침묵).
  - operation이 비즈예외를 catch→`IdempotentProblem` 재포장 → 중앙 dedicated 핸들러 3종 죽은코드(백스톱 호출그래프 추적 안 함).
  - `_replay_response` raw `JsonResponse`(operation 내 응답 생성 — 백스톱 `response={}` 선언분만 봄).
- **backstop ⑧⑨(P-α·P-β) exit0 = 진짜 준수**(의미 정독 일치): 협상 미들웨어 0·`application/common/` 0. *이 두 축은 백스톱+의미 둘 다 PASS.*

## 조정자 노트

1. **🟢 P-α/P-β 1.0.4 예방 성공(핵심 목적 달성)**: Codex가 **3런 연속(smoke3·smoke6·final-codexB) 만들던 협상 *미들웨어*를 이번엔 안 만듦** — 415는 operation/ValidationError 핸들러서(`api_orders.py:138-148`·`orders_api_router.py:99-100`), 406은 operation Accept 검사서(`api_orders.py:122-135`) = **§6.3 "ninja 경계 안" 레시피대로**. `settings.MIDDLEWARE`=스톡 7. `application/common/` 0(problem 헬퍼가 BC presentation). **자연 재현 스트릭을 가이드가 끊은 강한 신호**(단 clean 런이라 *발화*는 미검증 — §4.3).
2. **🔴 그러나 픽스처는 치명 FAIL — 직교 미해결 축**: NJ-2(비대 operation)·SD-6(죽은핸들러+raw replay+status 왕복) 둘 다 **C3 멱등성 스코프크립**이 뿌리. 1.0.4는 P-α/P-β만 손댔고 **C3는 여전히 G1에서 안 막힘**(DR-24 P4③·C3 갭). 즉 *표적 픽스는 정확히 작동했으나, 손대지 않은 축에서 떨어졌다*.
3. **C3 라이브 토끼굴 비용 박제**: 라이브 세션서 `idempotency_store.complete`의 SQLite-lock 재시도(`sleep`)에 서브에이전트 spawn·반복 디버깅(DR-06 33분 토끼굴 계열). 결국 27/27 그린으로 수렴했으나 *요구에 없던 멱등성*이 부른 자초된 복잡도.
4. **Claude njlive와의 차이(같은 태스크·N=1)**: Claude=D7로 멱등성 명시 범위밖+G1 상정→clean(척추·NINJA 전 PASS, 60 테스트) / Codex=멱등성 필수 크립→NJ-2·SD-6 치명 FAIL(27 테스트). **§3 인과 규칙: 우열 결론 금지** — 이는 *C3 집행 갭의 비결정성 증거*지 런타임 우열이 아니다.
