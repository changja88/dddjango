## 의미적 변종 / backstop-blind 메타 (§1.3 — 측정의 주 산출물)

- **`[결정 PASS ∧ 의미 FAIL]` 칸**: **빔**(FC-2는 결정 레인=주입 실행이 직접 green을 냄 — 의미적 변종 아닌 결정+의미 동시 FAIL).
- **FC-2 ↔ backstop-blind**: 11종 백스톱 전부 exit0 ∧ `manage.py test` 15 OK인데 FC-2 ❌ — **결정 백스톱·그린바가 못 보는 테스트 커버리지 갭**(경계 회귀)을 mutation 주입이 적출. RUBRIC FC-2가 "그린바인데 회귀 방어 못함"을 치명으로 둔 취지의 실증.
- **NJ-2 ↔ SD-6 직교**: SD-6=✅(operation 성공만·중앙핸들러 7 live·app status 0). NJ-2=✅(선언적 payload·415 auth 콜백 분리). 두 축 갈림.
- **변환점 위치(SD-6 PASS·Q-1 🟡)**: 결정 레인(check-error-centralization, application_layer만)은 `config/api.py` 변환점을 *못 봄*. 의미 레인 정독: 중앙화(단일점)·app/domain status 0 확인 → SD-6 계층순수 축 PASS. 단 orders 도메인 예외 매핑이 BC presentation 밖(config)이라 응집 약화 = Q-1 노트.
- **JsonResponse idiom(NJ-1 🟡)**: §6.2 처방 형태라 치명 아님·경미 분류(c4live-codex와 동일).

## 조정자 노트

- **Serena**: skipped — 내장 도구·grep·`.venv` 직접 실행으로 닫힘.
- **FC-2 치명 FAIL = 경계 테스트 부재(런 간 비결정)**: c4live-codex 채점지 FC-2는 "M2 경계 `<`→`<=`→1 red(G3 경계 테스트 포착)"였다. nj2live-codex는 **동일 종류 mutation이 green** — 경계 테스트가 이번 런 스위트에서 빠졌다. **Codex 런 간 테스트 커버리지 비결정**(c4live 보유→nj2live 누락). 코드는 양 런 모두 경계 정확(FC-1 G3 통과). FC-2는 *테스트의 비-vacuous성*을 재므로, 코드 정확과 무관하게 경계 회귀 테스트 부재 → 치명 FAIL.
- **NJ-2 PASS(DR-35 효과)**: operation은 `payload: OrderCreateRequest` 선언적 바인딩만(`json.loads` 0). 415는 ninja `auth=create_order_preflight` 콜백이 `_run_checks`(parse_body 전)에서 처리해 400-wrap 회피 — DR-35 §6.3 view 데코레이터와 *수단은 다르나*(auth 전용) operation 얇음은 동일 충족. 단 auth를 content-negotiation에 쓴 건 의미 오용(Q-1 🟡).
- **superpowers 간섭(검증 정합성)**: discipline 감수 후 Codex가 `superpowers:receiving-code-review`(런타임 외부 플러그인) 끌어옴. 코드 직접 영향은 불명이나 dddjango 의도 산출 아님 — 향후 라이브 런은 외부 플러그인 비활성 권장(검증 순수성).
- **N=1·라이브 미검증·우열 금지**: 본 판정은 이 한 런타임·한 런 정적 기록. FC-2 경계 누락이 Codex 성향인지 timeline 1회인지 same-task N≥3 없이 단정 불가. **우열 결론 금지**(DR-34 c4live는 Codex 준수·Claude NJ-2 FAIL이었고, 이번은 반대 — P4③·N=1 분산).
