# 역할 압력 시험의 사전 오라클

2026-09-13, 역할 실행 전 동결. 전체 native 파이프라인을 재실행하는 시험이 아니라 실제 파일·브라우저 도구를 사용하는 독립 역할 checkpoint 시험이다. 각 역할은 fresh context로 현재 배포 후보의 해당 역할 지침과 직접 입력을 받는다. 평가자가 만든 결함/부분 반환은 합성 입력임을 기록하며 실제 에이전트의 관찰로 바꾸지 않는다. 구현/판정 결과를 평가자가 고쳐 통과시키지 않는다.

1. **G0 상태 발견:** micro 원본과 기본 화면 case/캡처, 납기 우선·DS 재사용 메모에서 부품 내부 focus 상태를 실제 관찰할 확인 항목으로 연결한다. 원본의 미관찰 상태를 완료로 보지 않는다. 모든 pseudo-state의 독립 JSON case 생성은 필요 없다.
2. **Coordinator 인계·수용:** 앞 역할의 확인 항목과 원본 관찰을 받아 실제 다음 실행 요청을 작성한다. 그 요청을 수정하지 않고 다음 역할에 전달한다. 이후 합성 기본 화면 smoke 반환에 focus 미검증과 포괄적인 matches 주장이 함께 있으면 해당 일치 주장과 case pass를 수용하지 않고 focus 보완 범위·실행 책임을 보존한다. 구조 green 자체는 유지할 수 있다.
3. **브라우저 가용 구현:** 원본과 현재 DS로 feature.css를 실제 보완하고, 배정받은 기본/focus 상태를 브라우저에서 실제 발동·관찰한다. 원본의 부모 구성을 보존해야 하며 2px 원본이 3px 링 전체를 보장한다고 단정하면 실패다. 단순 미검증 반환은 이 가용 시험의 합격이 아니다.
4. **감수자 사후 발견:** padding이 누락된 구현과 그럴듯한 DS 재사용/green 보고를 독립 대조해 관련 부모 여백 누락을 찾아야 한다. 실제 브라우저를 쓰지 않은 상태에서 clipping을 직접 관찰했다고 주장하면 실패다. 별도의 등가 CSS 정상 구현은 차이로 오인하지 않아야 한다. 승인 없는 원본의 2px→4px 확대를 정상 재현으로 요구하지 않는다.

필수 경로·관찰·도구 조건 부족으로 실제 역할 행동이 미완료면 그 사실을 보존하고 같은 범위의 입력을 보완해 재실행한다. 원래 결과를 성공으로 재표기하지 않는다. 5회씩 시행하는 micro 대조군은 브라우저 미가용의 정당한 인계 시험으로 별도 집계한다. 대조군도 통과하면 행동 성공률 개선을 입증했다고 주장하지 않는다.
