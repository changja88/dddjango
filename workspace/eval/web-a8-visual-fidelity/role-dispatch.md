## 요구와 case별 실제 관찰

요구는 **이름 등록 화면을 원본대로 구현한다**이며 현재 작업은 step1이다. 관련 상태나 효과를 제외한 결정, 원본 외형 이탈 승인은 없다. case는 **`create-person-step1` / 이름 등록 / 초기 상태 / viewport 390×844** 하나다. 아래는 이 case 내부의 관련 상태·조작이며 별도 case나 step2를 추가하지 않는다.

| 대상·상태 | 원본과 직접 대조할 관찰 |
|---|---|
| 초기 빈 입력·전체 화면 | 제목, 이름 라벨, 원형 장식, placeholder, 안내문, 다음 버튼의 배치·크기·타이포·간격·색·화면 경계. 현재 원본 전체와 최종 구현 전체를 같은 viewport에서 본다. |
| 입력 포커스 | `#person-name`을 실제 클릭하거나 키보드로 접근해 포커스를 준다. 입력 자체와 래퍼를 구별하고 래퍼 테두리·그림자와 최종 적용 스타일을 관찰한다. 원본 CSS의 포커스 테두리는 `#8f675b`, 그림자는 `0 0 0 3px rgba(143,103,91,.18)`다. 이는 선언 근거이며 렌더 성공 판정은 직접 관찰로 한다. |
| 포커스 진입·해제 전환 | 포커스를 주고 다른 요소로 이동해 `border-color`와 `box-shadow` 진입·복귀를 실제 발동한다. 원본 선언은 160ms ease다. 전환의 시간에 따른 변화와 안정된 종결 상태를 관찰하고, 선언값·측정값·근사는 구별한다. 정지 캡처나 transition 문자열만으로 전환 관찰을 대체하지 않는다. |

## 작업·관찰 순서와 브라우저 환경

1. 지정 원본·현재 구현과 위 상태 범위를 읽고 실제 CSS 연결·원본 부품 및 관련 부모를 확인한다. **첫 코드 편집 전에** 원본의 관련 상태를 실제 렌더로 관찰하고 수정 전 구현의 같은 상태와 코드 기준을 보존한다. 현재 원본의 필요한 관찰을 확보한 다음 그 근거에 따라 수정한다.
2. **같은 coder가 Playwright MCP `browser_run_code_unsafe`를 사용한다.** 도구가 바로 노출되지 않으면 tools metadata에서 이름·설명을 찾아 필요한 도구를 확인한다. 새 page에 원본 HTML의 `source.css` link를 같은 로컬 CSS 내용으로 인라인한 HTML을 `setContent`할 수 있다. 구현도 `tokens.css` → `design-system.css` → `feature.css` 로드 순서를 보존해 같은 방식으로 렌더한다. 이는 관찰용 메모리 렌더이며 원본/구현 HTML 파일을 고치지 않는다.
3. 원본과 구현 page 모두 viewport **390×844**, 동일 브라우저 조건에서 위 실제 조작을 수행한다. 실제 사용한 브라우저 버전·실행 방식·상태 전환·viewport를 기록한다. 일반 GUI가 없다는 이유로 이 가용 MCP 관찰을 미검증으로 넘기지 않는다. 별도 HTTP 서버·포트·전역 설정 변경은 필요 없다. 이번 작업에서 생성한 page는 작업 후 닫고 기존 사용자 page는 건드리지 않는다.
4. 직접 관찰한 원본을 근거로 필요한 **화면 CSS 최소 수정**을 한다. 기존 DS·토큰을 소비하며 부모 배치와 자식 효과를 한 구성으로 확인한다. 구체 구현 코드는 본 인계에 주지 않는다. 소스 선언 복사 또는 computed style 일치만으로 화면 효과의 재현을 확정하지 않는다.
5. 수정 후 구현을 새로 렌더해 같은 상태 전부를 현재 원본과 직접 대조하고 수정 전 구현과도 비교한다. 캡처를 직접 열어 실제 표시 결과를 확인하며 측정은 그 판정을 보조한다. 관찰한 차이는 허용된 CSS 범위에서 수정하고 영향 상태를 재확인한다. 다른 파일 수정이 반드시 필요하면 해당 근거와 미해결 범위를 반환하며 권한 밖 파일을 수정하거나 효과를 생략하지 않는다.
6. `APP`을 작업 디렉터리로 `python3 smoke.py`를 실제 실행한다. 이 smoke는 HTML ID·CSS 배선만 검사한다. 실제 명령·exit·출력 원문을 기록하며 이를 시각 검증으로 해석하지 않는다.

## 필수 반환

`APP/handoff.md`에 다음 내용을 작성하고 최종 답변에는 경로와 핵심 결과를 반환한다.

1. 변경 파일·변경 이유, 실제 코드 검사 명령·exit·출력 원문, 원본·공용 파일 보존 확인. 구조 판정과 시각 판정을 별개로 쓴다.
2. **스타일 적용 근거 표** — 위 case의 관련 상태를 빠짐없이 연결한다. 같은 상태·효과는 한 행으로 묶을 수 있다.

| case·대상/조작 상태 | 원본 위치·구성(관련 부모 포함) | 구현 위치·구성 | 실제 수행·관찰 근거 | 결과·차이 또는 미검증 사유/다음 실행자·필요 조건 |
|---|---|---|---|---|

원본/구현 칸에는 실제 파일·요소, 관련 부모의 배치·여백·overflow, 부품 토큰·상태별 효과를 연결한다. 수행 칸에는 실제 조작·명령/렌더 방법·390×844·캡처/관찰 원문 경로를 넣는다. 실제 관찰한 일치·차이·미검증을 구별하고 CSS 정의값과 브라우저 관찰값을 혼동하지 않는다.

3. **수정 전후 비교 3종**을 각각 `비교쌍 · 대상/상태 · 양쪽 원본/렌더 근거 · 차이 · 결과/미확인 사유`로 기록한다: ① 기존 원본↔현재 기준 원본(이번에는 원본 유지이며 경로/hash 근거), ② 현재 기준 원본↔수정 후 실제 구현(요청 대상 전체와 위 상태), ③ 수정 전 실제 구현↔수정 후 실제 구현(변경 반영·회귀).
4. 실제 사용한 브라우저 도구·버전·실행 방법, 첫 편집 전 관찰과 수정 후 재관찰, 생성 캡처/관찰 기록 경로, 재열람한 근거, page 정리 사실을 기록한다. 기존 제공 캡처와 이번에 새로 생성한 캡처는 구별한다.
5. 남은 차이·미검증·권한 또는 환경 제한이 있으면 해당 상태와 필요한 조건을 구체적으로 반환한다. 미실행 상태가 남으면 case 전체 PASS나 `Visual outcome matches the frozen design in each case`로 요약하지 않는다. 이 역할의 직접 관찰 결과를 범위 밖 native 시각 게이트·독립 감사 통과로 주장하지 않는다.

위 범위의 최소 수정·실제 관찰·기록을 마치면 반환하고 종료한다.
