# 진단 — 재동결이 동결의 한 축만 다시 뜬다 (2026-09-15)

수리 1(증거 부채 hook · v1.1.14) 배포 당일 저녁, 사용자가 A8에서 «기존 동결분 무시하고
다시 동결해»라고 지시했으나 조작 상태 관찰은 한 건도 새로 뜨지 않고 «변화 0»으로 끝난 건.

사용자 정의(2026-09-15 지시): **«재동결은 기존 시안 무시하고 새롭게 동결해서 차이점을 반영한다»**

## 증상

A8 `20260912-1640-web-related-persons`에서 16:26 «기존 동결분 무시하고 다시 동결해» →
16:48 종료. 실행된 것은 시안 파일 18개 재수집 + 바이트 대조뿐이고,
`exit 4 · same 16 · changed 0 · added 0 · removed 0 · carried 6`로 «변화 0 · 진행할 구현 없음».

이 빌드는 12 case 전부 정적(`static-only 12`)이라 **조작 상태 관찰이 0건**인데, 재동결이
그 축을 건드리지 않아 부채가 그대로 남았다. 같은 지시를 몇 번 반복해도 결과는 같다.

## 원인 — 동결과 재동결의 비대칭

| 동결 축 | 최초 동결 | 재동결(현재) | 다시 뜨는 도구 | 대조 도구 |
|---|---|---|---|---|
| 시안 파일(`design-ref`·`source-manifest.json`) | 수집 | **대조함** | DesignSync `get_file` | `archive_design.py --compare-build` |
| 원본 case 캡처(`captures/<screen>-*.png`) | 수집 | 안 함 | 브라우저 | — |
| 조작 상태(`captures/<screen>-interactions.json`) | 수집(v1.1.13~) | 안 함 | `observe_interactions.mjs` | **없음(신규 필요)** |
| 렌더 실측(`render-audit.json`) | 수집 | 안 함 | `render_audit.js` | `compare_render_audit.py`(G2용 — 배선만 하면 됨) |
| 동적 표현(`motion-notes.md`) | 기록 | 안 함 | 사람(스캔+문답) | 기계 대조 대상 아님 |

이름은 «재동결»인데 동결의 한 축만 다시 한다.

### 규범 내부의 불일치

`commands/dddjango-web.md:129`(G0 폴더 재사용 질문)은 재동결 대상을 이렇게 **열거**한다:

> 외부 진실 스냅샷(openapi 동결본·**design-ref·motion-notes·render-audit**) 재동결 여부

그런데 실제 절차(`commands/dddjango-web.md:137` → `skills/implementation-ui/references/design-acquisition.md` §2 «재동결»)는 **design-ref 바이트 대조 하나만** 규정한다. motion-notes·render-audit는 절차가 없고, **조작 상태(`captures/*-interactions.json`)는 열거 목록에조차 없다**.

### 차이 → 반영 사슬은 파일 축에만 있다

design-acquisition §2: exit 3(파일 차이)일 때만 «새 기준 설치 → 영향 case 재관찰 →
조작 상태 재수집 → 독립 검토 → inputs»를 같은 라운드에 마친다. 파일이 같으면(exit 0·4)
어느 축도 재관찰하지 않는다. **부채가 있는 빌드에서는 비교할 관찰 자체가 없으므로
«차이 없음»이 구조적으로 보장된다.**

## 갭 정리

- **G-A(주)**: 재동결이 동결의 한 축(파일)만 다시 뜬다. 관찰 축은 재수집도 대조도 없다.
- **G-B**: 재동결 요청을 Coordinator가 «이미 했음»으로 자체 기각할 수 있다 — 규범에
  「요청하면 직전 결과를 재사용하지 않는다」·「재사용 시 직전 실행 시각을 함께 보고한다」가 없다.
- **G-C**: 증거 부채 결정(ⓐ/ⓑ)을 Coordinator가 대리 기록했다. 규범 `:129`는 «사용자 결정을
  같은 질문에 합류시켜 받는다»인데, 사용자 발화가 아닌 지시문이 `quote`에 들어갔다.
- **G-D**: 재동결만으로 끝난 실행의 종료 보고에서 hook 원문 인용(`:154`)이 누락됐다.

G-A가 주 결함이고 G-B~D는 같은 실행에서 함께 드러난 집행 누수다.

## 수리 방향 (설계에서 확정)

**재동결 = 동결 전체를 다시 뜨고 축마다 차이를 낸다.**

1. 축 목록을 하나로 확정하고(파일 · 조작 상태 · 렌더 실측 · 원본 case 캡처 · motion-notes),
   `:129` 열거와 §2 절차를 같은 목록으로 맞춘다.
2. 축별 대조: 파일 = `archive_design.py --compare-build`(기존) · 렌더 실측 =
   `compare_render_audit.py`(기존, 배선) · 조작 상태 = **신규 대조기 1종**.
3. 비교 대상이 없는 축(부채)은 «차이 없음»이 아니라 **«비교 불가»로 red**를 내고 그 자리에서 수집한다.
4. 결과는 축별 행을 가진 단일 산출(`refreeze-diff.json` 확장 또는 형제 파일)로 내고,
   종료 보고는 축마다 1줄.
5. G-B: 재동결 요청은 직전 결과 재사용 금지. 불가피하게 재사용하면 직전 실행 시각을 명시한다.
6. G-C: 부채 결정은 사용자 발화 없이 기록 금지(검사기/hook에서 `quote` 형식 강제 검토).

**설계 쟁점 1**: «조작 상태가 달라졌다»의 판정 기준. 픽셀 비교는 매 실행 red,
개수 비교는 아무것도 못 잡는다. 후보 = 관찰된 상태 집합 + 선언(`<screen>-declared.json`)
목록 + 상태별 DOM 구조 시그니처. 적대 검토에서 가른다.

**범위 밖**: 보더 잘림(수리 2·3 — `workspace/eval/web-scroll-clip-fidelity/diagnosis.md`).
단 **순서는 이 수리가 먼저**다. 재동결이 반쪽인 채로 2·3의 검사를 넣으면 재동결 경로에서 또 침묵한다.
