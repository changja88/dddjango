# 표준 준수 점수 루브릭 (100점) + 런별 채점

> "점수 = dddjango 플러그인(표준)을 얼마나 잘 따랐나". 가중 항목별 채점.
> ⚠️ **방어 가능한 추정치이지 정답 아님** — 메인 에이전트 판단이 들어가고, N=2이며 2차는 통제 이탈(아래). 순위 단정 금지.

## 해석 (신뢰도 낮음)

- 평균은 Claude(84) > Codex(70). **단 claude 분산(27) > 평균차(14)** → N=2로 순위 단정 불가(한 번 더 돌리면 뒤집힐 수 있음). claude 바닥(70)이 codex 범위로 떨어지고 claude-2(70) < codex-3(76).
- **점수 변동의 거의 전부 = C2 도메인소유(20점) 한 축.** claude만 1차 18 ↔ 2차 6으로 출렁. 나머지 항목은 양 런타임 비슷(60~80%).
- Claude의 강점은 "항상 더 나음"이 아니라 "**가끔 훨씬 나음(높은 천장·높은 분산)**". Codex는 낮지만 일관.

## 더 신뢰할 측정을 하려면 (미실행)

1. 게이트 답 전부 고정(구조 옵션A·동일 프레임워크/러너)으로 교란 제거.
2. 런타임당 N≥5~10 → 점수 분포 비교(평균±편차).
3. 기계검증 항목은 **정적 grep 말고 스키마 inspect·테스트 실행**으로(예: stock≥0는 PositiveIntegerField 자동 CHECK라 grep만으론 오판).
4. 블라인드 채점(런타임 식별 제거).
5. 태스크 1개론 부족 — 형태 다른 기능 3~5개.
