- [MINOR] 재신뢰 절차가 배선되지 않았다: Codex는 hook *정의*(hooks.json 명령 문자열) 해시로 신뢰하므로 hooks.json이 바뀌는 릴리즈마다 사용자 재신뢰가 필요하고, 스크립트 본문만 바뀌면 재신뢰 없이 실행된다. 설계 T3의 REQUEST_GUIDE 문장은 «설치·갱신 후 1회»로만 적고 릴리즈 절차(docs/DEVELOPMENT.md §6·`release-web`)에는 없다. — 근거: 설계 N1 Codex 한계 문장; docs/DEVELOPMENT.md:136-145; Makefile:295-299 — 제안: DEVELOPMENT §6에 «hooks.json 변경 릴리즈는 릴리즈 노트에 Codex 재신뢰 1줄» 규칙을 추가하고 REQUEST_GUIDE는 «hooks.json이 바뀐 버전으로 갱신했을 때 `/hooks` 재신뢰»로 정확히 쓴다.
- [MINOR] `${PLUGIN_ROOT}`는 Codex 문서상 env 변수 제공(`PLUGIN_ROOT`·`PLUGIN_DATA`, 호환 `CLAUDE_PLUGIN_ROOT`)이라 명령이 셸 경유가 아니면 미치환 위험이 있고, 호환 env가 있으므로 H2를 H1과 byte 동일하게 둘 수도 있다. — 근거: learn.chatgpt.com/docs/hooks(env 절); 설계 §2 H2 — 제안: B4에서 치환 실패 케이스를 1회 확인하고, 통과하면 H2=H1 byte 미러(경로만 `skills/dddjango-web/scripts/`)로 계약을 단순화.
