## 1. 채점 프로토콜 (결정 레인 ∥ 의미 레인)

모든 척추(S) 차원 + 의미가 필요한 Q 차원에 적용.

### 1.1 결정 레인
- **구조-인지 스크립트/grep** (경로 고정 금지 — `orders`vs`order`·포트 위치 이동에 강건; 예: `find -type d -name port`의 부모가 `domain_layer`인지로 SH-7 판정).
- 산출 = `{신호 有/無}` + 줄 인용.
- **각 스크립트에 "원리상 못 보는 것" 카드 동봉** — 예: `check-error-centralization.py` → "status-bearing 객체 계층 흐름·operation 수제 응답·status맵 변수 우회는 못 봄". 카드가 의미 grader의 사각 탐색을 유도.

### 1.2 의미 레인 (스크립트 결과에 **blind**)
- **blind 필수**: 스크립트 exit0/PASS를 grader가 보면 "통과했으니 PASS"로 수렴(= DR-24 exit0 오판 재발). 의미 채점은 결정 결과 **비공개** 상태 수행 → 사후 대조.
- **이진 하위질문**으로 분해. "잘 지켰나?"(인상) 금지. 예 SD-6: "오류→status를 *고르거나 만드는* 줄이 operation·application·domain에 있나? (Y/N)+줄".
- **필수 줄 인용** — 인용 없는 PASS 무효.
- **판정 바 = 표준 규칙(§근거 조항)**; 앵커(RUBRIC §E)는 *예시*로만 대조(임계값 아님). 앵커는 **라벨 마스킹**(어느 게 플러그인 PASS 앵커인지 grader에게 안 알림 — "앵커 닮음=PASS" 휴리스틱 차단, 적대리뷰 C2·grader 호의).
- **N≥3 blind grader**(런타임·디렉터리명 마스킹) 중 **1명은 적대 grader**("이 산출을 통과시키지 마라" — DR-21 권고강등 상쇄) + **차원별 일치율(κ)** 보고.
- **치명 항목은 보수적**: 2:1 split이어도 *치명*에서 1명이라도 줄인용 동반 FAIL이면 인간 판정 큐 + 보수 FAIL(다수 호의가 정당한 소수 FAIL을 못 덮게). 비-치명만 2:1→WEAK.

### 1.3 대조 — 측정의 주 산출물
- 결정 ∥ 의미 결과를 나란히.
- **`[결정 PASS ∧ 의미 FAIL]` = "의미적 변종"** 별도 플래그·집계. **이 칸이 플러그인의 진짜 갭**(DR-24가 정확히 여기서 나옴). "결정 PASS면 의미 생략" 절대 금지 — 의미 레인은 *항상* 수행.

### 1.4 기능 정확성 측정 (FC — 형태가 아니라 동작)
- **FC-1 골든 오라클**: 채점자가 *명세를 읽기 전에* 요청(태스크 프롬프트)+표준만으로 외부 행위표를 사전등록(§5 동결). 각 케이스=(입력 상태, 요청)→(기대 status, 기대 부작용). fixture `.venv`로 코드를 실행(인수 테스트와 *독립한* 호출 스크립트)해 표와 대조. **명세·기존 테스트는 오라클로 인정 안 함**(명세·코드·테스트 순환 차단).
- **FC-2 mutation**: 핵심 로직(차감·판정·status)에 mutation 주입(부호 뒤집기·`>=`→`>`·status 값) → 기존 테스트 실행 → red면 PASS(테스트가 그 동작을 실제 검증), green이면 FAIL(vacuous). 수동 또는 `mutmut`/`cosmic-ray`.
- **FC-3 도메인 정합**: 의미 grader가 명백한 도메인 오류(음수 재고·차감 역전·인과 역전)를 골든 표 결과 + 코드 정독으로 판정.

## 2. 집계 (사전식 lexicographic — 가중 평균 금지)

```
1) 기존규약 마스크(RUBRIC §C) 적용.
2) TIER-S 치명 게이트(치명=✅: SD 전부·FC 전부·SH-1·2·4·7·조건부 NJ-1·2): 하나라도 FAIL
   → 픽스처 전체 FAIL, 종료. (SD-6은 의미 레인 FAIL이면 스크립트 exit0이어도 치명.)
2.5) 실질성 관문(degenerate 차단): 치명 항목 산출이 *비-trivial*인가 —
   도메인 메서드가 실제 불변식 분기를 갖나(trivial `return True` 아님)·
   테스트가 명세 행위별 어서션을 갖나(vacuous 아님)·종류폴더가 *사용*되나(빈 골격 아님).
   N이면 치명 FAIL.
3) "의미적 변종"(결정PASS∧의미FAIL) 플래그 ≥1 → "준수" 라벨 금지(상한 WEAK; SD-6은 §2서 치명).
4) 통과 시에만 TIER-Q 가중합 → 품질 등급.
```
- 사전식이 척추 FAIL을 비-척추 PASS로 희석하는 것을 차단(빈혈 도메인이거나 *기능이 틀리면* "준수"라 부르지 않는다 = 사용자 확정의 조작적 정의).
- **증거 단위**: 차원×픽스처마다 `{라벨, 줄인용, grader 라벨 N개, 일치율, 스크립트 신호, (해당시) 의미적변종 플래그, (FC) 골든 케이스 통과/실패·mutation red율}`.

## 3. 회귀 bisect 인과 규칙 (교란 통제)

- **인과 1차 증거 = 같은 태스크·같은 런타임 timeline만**: 태스크B 주문생성·Codex 4점(`final-codexB`→`smoke2-codexB`→`livefire-codex`→`p1a-v3-codex`). dual(`{livefire,p1a-v3}-{codex,claude}`)=*런타임 효과 분리*만. 태스크A Claude 2점(`final-claudeA`→`smoke2-claudeA`)=*보조*. **태스크A↔B 직접 차분 금지**.
- **3분류**: (a) 패치前 **이미** 있던 행위 → **성향**(패치 책임 아님). (b) 패치前 없고 後 신규 → **사이드이펙트 후보**. (c) **위치만 이동** → **성향의 변위**(예: P1a가 operation try/except → app service catch로 이동; H1 멱등성도 이 가능성).
- **N=1 한계 박제**: 4점은 각 시점 N=1 → LLM 샘플링 노이즈와 패치 효과 분리 불가. **"이 timeline에서 관측됨"까지만**, "패치가 야기" 단정 금지. 강한 인과는 same-task A/B(pre-commit vs post-commit, N≥3) 별도.
- **정적/라이브 분리**: 정적 채점은 "산출물 구조적 준수"만. "게이트 라이브 발화"(G1 에스컬레이션·reviewer blocker)는 산출물에 없음 → spec *흔적*까지만 대리, "라이브 발화"의 대리로는 **무효**(DR-21: 텍스트판별 통과≠라이브 발화).

### 3.1 검증할 사이드이펙트 가설 (bisect 대상)
- **H1** §9.6 8행 블록(P3)이 *Idempotency storage·API handoff* 행을 채우려는 압력으로 architect가 멱등성 발명 → Codex C3. (성향 vs 변위 vs 사이드이펙트?)
- **H2** 누적 게이트(P1a+P2+P3 + G2 스크립트 2종)가 coder 반송↑ → Claude 1h12m(속도 회귀, NEW-2). (telemetry 별도)
- **H3** catalog 이관 압박(DR-16/17 + ddd §3.2)이 Claude 0001 재작성 유발 → L1.
- **H4** 게이트 증가 = 판정점 증가 = 런타임 비결정 표면↑(G1 에스컬레이션 C5).

## 4. 결승선(완료) 정의

다음 **모두** 충족 시에만 "플러그인 규칙준수+기능정확성 완료(이 축에서)":
1. **척추 치명 FAIL 0건** — 양 런타임·복수 태스크 형태에서 SD·**FC**·SH 치명 항목 통과(SD-6 의미변종 포함).
2. **의미적 변종 0건** — `[결정 PASS ∧ 의미 FAIL]` 칸이 빔.
3. **N·태스크·런타임** — 각 런타임 **N≥5 블라인드** + 태스크 형태 **2종 이상**(N=1·단일태스크로 "완료" 선언 자격 없음).
4. **핵심 게이트 라이브 발화** — P1a·P2·P3 게이트가 *위반 주입* 조건에서 실제 라이브 blocker 발화(준수만 보는 exit0은 차단 행위 미stress).

하나라도 미달 = "보류". **명시 한계**: 이 완료는 "규칙 준수+기능 정확"까지다 — baseline 대비 가치·미시 유지보수성·명세 내적 품질은 *별도/후속*(과대주장 금지).

> **정적 vs 라이브**: 요건 1·2·**FC(골든 오라클·mutation)**는 저장 fixture에 정적 측정 가능. 요건 4(라이브 발화)만 fresh 위반주입 런 필요 → **"정적 완료"(1·2·FC)와 "라이브 완료"(4)를 분리 보고**.

## 5. 과적합 방지 (사전등록·홀드아웃)

- **사전등록(criteria)**: 차원·판정 기준·FC 골든 표·임계값을 **채점 *전*에 동결**(RUBRIC + 이 문서 freeze). 채점 결과 본 뒤 기준 변경(예: "Codex가 FAIL이니 carve-out 추가")은 측정이 아니라 사후 합리화.
- **순환 방지(앵커 재정의 — 적대리뷰 C1·C2 해소)**: 앵커는 *임계값이 아니라 예시*다(RUBRIC §E v2). 따라서 "홀드아웃 격리" 불요(이전 초안의 'dual 1쌍을 앵커서 제외'는 §E가 앵커로 쓰며 모순이었음 — 제거). 대신 **채점 criteria를 표준 조항에서 도출하고 8벌을 보고 조정하지 않는다.**
- **새 태스크 홀드아웃(형태 다양 — CF-6)**: 8벌 전부 '생성+재고차감 API'라 형태 편향. 완료 판정 전, *형태축이 다른* 태스크 **≥2종**(쓰기-생성 / 조회-무거운 read model / 다중 애그리거트 트랜잭션)으로 sanity — 환불/취소는 같은 쓰기형이라 불충분. 형태별 *어느 차원이 N/A*가 되는지 사전 매핑.
