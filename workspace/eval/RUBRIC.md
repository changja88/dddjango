# dddjango Codex 포트 — 코드 품질 평가 루브릭 (정적)

> 산출물 **정적 평가**만 한다(세션 로그 파서 없음). 평가 단위는 각 런이 남긴 소스 트리 + Codex/Claude가 출력한 요약값(토큰·시간) 수기 기록.

## 평가가 답하는 두 질문 (반드시 분리)

- **Q1 — 포트 충실도**: *같은 입력*에서 Codex 산출이 Claude와 **동등한가**. ← 포트 품질의 핵심. Claude 신규 런 1회가 비교 기준.
- **Q2 — dddjango 표준 부합**: §0 4계층·§4 명명을 지키는가. ← **런타임 무관**. 이미 추적 중인 `catalog 미정합`(§1 기존 관례 vs §0 불변식 충돌)·DR-06 축이라 Codex 고유 결함 아님. 부(副)로만 기록한다.

평가 대상 런: `claude-1`(비교 기준) · `codex-2` · `codex-3` (+ 선택 `codex-4`). `codex-1`은 PoC 보존본이나 빌드 중 역할 스킬 재설치 이력이 있어 **참고용**(깨끗한 비교·결정성 판정은 codex-2~3 우선).

## Q1 — Claude ↔ Codex 동등성 (주)

각 차원을 **동등(=) / 유사(≈) / 상이(≠)** 로 판정하고 근거를 적는다. "상이"는 결함 판정이 아니라 *차이의 성격*(타당한 변형 vs 품질 격차)을 한 줄로 분류한다.

| # | 차원 | 무엇을 보는가 |
|---|---|---|
| Q1-1 | 파일 트리 형태 | 평면 catalog vs `application/` 4계층 — 양쪽이 같은 배치 선택을 했나. 폴더 의미군(domain/service/test) 분리 정도. |
| Q1-2 | 도메인 모델 배치 | `deduct_stock`·주문 생성 규칙이 어디에(모델 메서드 / 서비스 / 도메인 객체) 사는가. Product↔Order 책임 분할. |
| Q1-3 | 트랜잭션·동시성 경계 | `transaction.atomic` 범위, `select_for_update` 등 락 전략 유무. **DR-06 축**: 동시성 문제를 설계 반송 없이 코더가 자작 우회(예: sqlite 락 핵)했는가. |
| Q1-4 | 불변식 표현 | 재고 음수 금지·수량>0 등을 DB CheckConstraint / 코드 가드 / 둘 다 중 어디로 강제하나. |
| Q1-5 | 예외 설계 | 커스텀 예외(InsufficientStock 등) 유무·위치·계층. |
| Q1-6 | 네이밍 규약 | 클래스·메서드·파일명. (평면 catalog면 ORM=도메인 합침이라 §4 `<Name>Model`·Repository·Port 적용이 제한됨 — 그 사실 자체를 기록.) |
| Q1-7 | 테스트 구조 | unit/integration/e2e 분리, 파일 배치, 테스트 수. |
| Q1-8 | 테스트 커버리지·품질 | 케이스(정상 차감 / 재고부족 거부 / 경계 0·정확량 / 트랜잭션 롤백), 행위중심성(과도한 mock 없음), AAA. |
| Q1-9 | 타입·주석 | 프로덕션 시그니처 타입 힌트, 주석/문서 언어 관례. |
| Q1-10 | 빌드 건전성 | `migrate`·`check`·테스트 전부 통과하는가(양쪽). |

**Q1 종합 판정**: 동등/유사 다수 → 포트 충실(Claude 품질 보존). 상이 중 "품질 격차"가 있으면 그 항목이 포트 작업의 개선 대상.

## Q1′ — Codex 결정성 (codex-2 ↔ codex-3 [↔ codex-4])

같은 입력·같은 게이트 답인데 런 간 **무엇이 흔들리는가**. 메모리 `BC 경계 비결정성`(architect가 런마다 경계를 다르게 정함)의 재현 여부 포함.

| 차원 | 런 간 변동 관찰 |
|---|---|
| 구조 선택 | Q1-1 배치가 런마다 같은가. |
| BC/애그리거트 경계 | Order를 catalog에 둘지·별 경계로 뺄지 등 경계 결정이 흔들리는가. |
| 동시성 전략 | Q1-3 락 전략이 런마다 다른가. |
| 네이밍 | 클래스·파일명이 런마다 다른가. |
| 테스트 수·케이스 | 커버리지가 런마다 다른가. |
| 빌드 건전성 | 매 런 check/test 통과하는가(기능적 결과는 안정적인가). |

**결정성 판정**: 표면(네이밍·파일명) 변동은 허용 범위. **구조·경계·동시성 전략이 런마다 갈리면** 비결정성 리스크로 기록(가드 필요 여부 판단 근거).

## Q2 — dddjango 표준 부합 (부)

런타임 무관. 통과/미흡/해당없음으로만 빠르게 체크하고, 미흡은 기존 추적 항목(`catalog 미정합`/DR-06)과 연결한다.

- §0 4계층 컨테이너(`application/<app>/{domain,application,infra,presentation}_layer/`) — 평면 catalog면 **미적용**: 기존 관례 존중(타당) vs §0 불변식 위반(결함) 중 어느 쪽인지 한 줄 판정.
- ORM 모델 `<Name>Model` 명명 / 도메인 엔티티와 분리.
- 리포지토리·포트 명명 규약(§4).
- 테스트 unit/integration/e2e 의미군 분리.
- 프로덕션 시그니처 타입 힌트(누락=important).
