# 스코프 메모 — 주문 생성 API (재고 검증·차감)

> 상태: **G0 승인 완료** (2026-05-29). design-architect 입력으로 확정.

## 무엇을 (What)
클라이언트가 상품과 수량을 보내 **주문을 생성**하는 API.
- 재고가 **충분하면**: 재고를 차감하고 주문을 생성한다 → 성공 응답(201).
- 재고가 **부족하면**: 거절한다 → **409 Conflict**. 재고·주문 상태는 변하지 않는다.

## 경계 (Boundaries)

### 이번 범위 안 (In scope)
- 주문 생성 단일 엔드포인트 (POST).
- 요청: 대상 상품 식별자 + 주문 수량.
- 재고 충분성 검증.
- 재고 차감(`Product.stock`).
- 주문 레코드 생성(상품·수량·가격 스냅샷·생성시각 등 — 필드 확정은 설계 단계).
- 응답 계약: 성공 201 / 재고 부족 409 / 잘못된 요청·없는 상품 등 표준 오류 코드.
- **동시성 안전**: 동시 주문 시 재고 초과 차감(oversell) 방지. (핵심 제약)

### 이번 범위 밖 (Out of scope)
- 결제·정산.
- 장바구니, 주문 수정/취소/환불, 재고 복원.
- 주문 조회/목록 엔드포인트(생성만).
- 배송·쿠폰·할인.

## 제약 (Constraints)
- **동시성**: 재고 차감은 race condition 하에서도 oversell이 발생하면 안 된다(원자적 차감 / 잠금 / 조건부 UPDATE 등 — 방식은 설계가 결정).
- **API 어댑터 미설치**: 현재 프로젝트에 JSON API 프레임워크가 없다(Django 4.2만). 어댑터 선택(Django Ninja 등)과 의존성 추가 여부는 설계가 결정.
- 기존 `catalog.Product`(name, price, stock=PositiveIntegerField)를 사용한다.
- 스택: Django 4.2.30 / Python 3.9 / SQLite.

## 확정 결정 (G0, 2026-05-29)
1. **배치**: ✅ **새 독립 영역(`ordering` 앱)으로 분리**. 주문 애그리거트는 catalog와 분리하고, 주문↔catalog(재고) 사이 연결은 설계가 정한다(애그리거트 간 참조/포트 방식 등).
2. **주문 구성 단위**: ✅ **단일 상품 + 수량**(주문 1건 = 상품 1개 + 수량). 다중 라인아이템은 범위 밖.
3. **인증**: ✅ **이번 범위 제외(익명 허용)**. 주문에 사용자 소유자 개념을 넣지 않는다.

## 제안 설계 lens
- **ddd**: 항상 활성 — 주문 애그리거트 경계, 재고 차감 불변식.
- **api**: 활성 — 새 외부 계약(엔드포인트·201/409 상태코드·오류 형식).
- **db**: 활성 — 신규 주문 테이블·마이그레이션, 그리고 **동시 재고 차감 트랜잭션/잠금**(Risky Write)이 핵심.

## 배치 결정 기록 (architect 전달용)
- 새 `ordering` 앱으로 분리(사용자 명시 선택). architect는 ordering 애그리거트 경계와 catalog 재고와의 협력 방식(직접 ORM 참조 vs 포트/도메인 서비스)을 설계에서 결정해 명세에 명시할 것.
- 활성 lens 확정: **ddd · api · db** (전부 활성).

## G1 결정 기록 (2026-05-29, 설계 승인 시 확정)
- **OD-1 = 옵션 A 승인**: oversell 방어를 위해 **catalog 변경을 승인**한다 — `catalog.Product`에 `version` 컬럼 + `deduct_stock(qty)` 도메인 동작 추가. G0의 "catalog 무변경"을 이 항목에 한해 **의도적으로 확장**한다(재고 판정 소유자를 catalog에 유지하기 위함). 동시성 방어선은 version CAS 조건부 UPDATE 단일 경로.
- **OD-2 = 멱등키 미도입**: Idempotency-Key 도입하지 않음. 재시도로 인한 중복 주문 계약 노출이 후속까지 잔존함을 수용.
- **OD-3 = FK 미설정·인덱스 없음**: `OrderModel.product_id`는 정수 컬럼만(DB FK·인덱스 없음). 주문은 가격 스냅샷으로 자기완결.
- 설계 명세는 이 결정으로 모든 열린 결정이 닫힌 **단일 근거**다 → acceptance-tester·coder 입력.
