# 스코프 메모 — 재고 검증 주문 생성 API

## 기능 한 줄
재고가 부족하면 409로 거절하고, 충분하면 재고를 차감하며 주문을 생성하는 API.

## 무엇을 (What)
- 주문 생성 엔드포인트(HTTP API): 상품 + 수량을 받아 주문을 만든다.
- 요청 시점 재고가 수량보다 적으면 **409 Conflict**로 거절(재고 변화 없음).
- 충분하면 해당 수량만큼 재고를 차감하고 주문을 생성, 성공 응답.

## 경계 (Boundary)
- 포함: 단일/복수 품목 주문 생성, 재고 검증·차감, 부족 시 409, 동시성 안전(차감 경쟁).
- 제외(이번 범위 아님): 결제, 배송, 주문 취소/환불, 인증·권한(별도 합의 없으면 미적용), 장바구니, 가격 정책/할인.

## 제약 (Constraints)
- 기존 `catalog.Product`(name, price, stock=PositiveIntegerField)를 재고 출처로 사용.
- 재고 차감은 음수가 되면 안 됨(불변식). 동시 요청에서도 초과 판매 금지.
- API 프레임워크 미설치 상태 — 설계에서 도입 방식 결정(플러그인 기본은 Django Ninja).
- DB: SQLite(개발), 트랜잭션·행 잠금 동작은 설계 db lens에서 검토.

## G0 결정 (사용자)
- 주문 형태: **단일 품목 주문**(주문 1건 = 상품 1개 + 수량). 복수 품목은 이번 범위 제외(추후 확장).
- 배치: **기존 catalog 앱에 포함**(별도 orders 앱 분리하지 않음).

## 미정/설계 위임 (열린 질문)
- 멱등성 키 필요 여부(중복 주문 방지).
- 성공 응답 형태(주문 id·상태·차감 결과).

## 활성 lens (제안)
- ddd: 항상 활성.
- api: 활성 — 신규 엔드포인트·요청/응답·상태코드(409) 신설.
- db: 활성 — 주문 스키마 신설 + 재고 차감 트랜잭션·동시성·마이그레이션.
