## 목적과 범위

설계 문서의 읽기·전달 비용을 줄일 후보를 비교한다. 플러그인·코퍼스·진행 중인 작업은 바꾸지 않는다. 이 디렉터리의 코드는 실험용이며 배포용 구현이 아니다. 3번 문제는 이번 실험에 포함하지 않는다.

사용자는 자료조사→실험 선정·문서화→선정한 모든 실험의 실행·결과 정리를 승인했다. 다음 단계의 제품 반영·커밋·배포는 승인 범위가 아니다.

## 조사에서 얻은 설계 근거

1. 원문을 필요할 때 읽는 방식은 초기 입력을 줄이지만 탐색·왕복 비용이나 누락을 늘릴 수도 있다. 요약 대체부터 시작하지 않고 무손실 접근과 선택을 분리한다. [Anthropic, Effective context engineering, 2025-09-29](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).
2. 조각만 떼면 식별 문맥이 사라질 수 있다. 절 제목·출처 정보를 붙인 검색을 원문 검색과 비교한다. Contextual Retrieval의 수치는 검색 재현율에 관한 것이므로 dddjango의 시간·품질 개선율로 인용하지 않는다. [Anthropic, Contextual Retrieval, 2024-09-19](https://www.anthropic.com/engineering/contextual-retrieval).
3. 정보를 찾는 능력과 그 정보로 올바르게 판단하는 능력은 다르다. 긴 입력의 위치 효과는 실험 설계 근거이지 현재 모델의 실패율 추정치가 아니다. [Liu et al., Lost in the Middle, 2023](https://arxiv.org/html/2307.03172v3).
4. 단일 검색 외에 여러 근거·연결·집계를 검사한다. 합성 검색 과제와 실제 과제의 상관이 검증되지 않았다는 한계를 지킨다. [Hsieh et al., RULER, 2024, §8](https://arxiv.org/html/2404.06654v3).
5. 질문과 직접 비슷하지 않은 연결 사실 및 시간 순서를 별도 시험한다. 해당 연구의 검색기 최적화 한계 때문에 현대 RAG 일반에 대한 실패 주장으로 확대하지 않는다. [Kuratov et al., BABILong, 2024](https://arxiv.org/html/2406.10149v2).
6. SPARQL은 입력된 관계를 질의하는 수단이다. JSON과 동일한 관계·원문을 주어야 엔진 비교가 된다. [W3C, SPARQL 1.1 Query Language, 2013, §9](https://www.w3.org/TR/sparql11-query/#propertypaths).
7. 반복 시행·격리·실제 결과 채점을 사용한다. 도구 호출 기록과 최종 결과를 혼동하지 않는다. [Anthropic, Demystifying evals for AI agents, 2026-01-09](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents).

7개 1차 자료에서 무손실성·검색·관계·실제 작업 평가의 구분과 반례가 수렴했다. 추가 일반 검색보다 실제 과거 자료의 복원과 실험을 진행한다. 상세 로컬 근거는 [작업용 참고 자료](../../../design/2026-09-06-dddjango-speed-working-notes.md)를 따른다.

## 실험 4 — 개정·결손 안전성

실제 개정 전후 명세로 오래된 인덱스 거부, 재생성 후 원문 일치, 내용 변경·절 이동을 확인한다. 추가로 관계 한 개 제거·없는 대상 참조·오래된 digest를 주입한다.

검출되는 결손과 검출되지 않는 결손을 모두 기록한다. 특히 ‘관계가 애초에 기록되지 않음’을 엔진이 자동으로 알 수 있다는 주장을 하지 않는다. 갱신에 든 기계 시간과 수동 의미 검토의 미측정 비용을 구분한다.

## 실험 5 — 실제 Claude 반복 작업

별도 신규 세션, Claude Code 2.1.261, `claude-fable-5-1`, effort xhigh, fast off. 읽기 전용 가용성 확인에서 실제 모델 실행을 확인했다. 기존 세션을 resume하거나 설정·도구 연결을 바꾸지 않는다.

- A·B 2개 작업 × 입력 3종 × 3회 = **18회**. 실행 순서는 반복별로 교차한다. 결과를 보고 반복 수를 늘리거나 성공만 골라내지 않는다.
- 입력 3종: 전체 명세 원문 / 실험 2의 본문 검색 원문 / 원문 위치와 관계를 연결한 작업 묶음. 같은 질문·코드·출력 형식이며 차이는 명세 전달 부분이다.
- 전체 원문 입력은 Read 오류를 우회해 한 번에 제공하는 강한 대조군이다. 당시 전체 파이프라인의 정확한 재생이라고 부르지 않는다.
- 관계 묶음의 필수 의무 완전성을 먼저 확인한다. 사람이 보완한 경우 그 사실과 비용 미측정을 밝히며, 성공해도 자동 구축의 효과로 확대하지 않는다.
- 모델에는 정답 판정값이나 이후 수정 결과를 주지 않는다. 작업별 결정 결과와 제한된 순수 함수 구현을 JSON으로 받는다. 실행 대상 코드는 허용 AST·이름·연산 범위를 검사한 뒤 제한된 환경에서 동작을 채점한다.
- A는 None·빈 문자열·공백·유효 subject·자리 없는 템플릿·표 밖 상황·새 placeholder 템플릿을 검사한다. 별도 상황 집합을 복제하면 확장된 템플릿 검사에서 실패해야 한다.
- B는 필수 인자·nullable 유지·호출 순서·로더 계약·기존 테스트 의미 보존을 채점한다. 부분 점수와 모든 필수 조건 충족을 함께 기록한다.
- 호출 전후 벽시계, API 시간, 입력/캐시/출력 사용량, 오류·권한 거절, 실제 모델을 보존한다. 캐시가 다른 실행은 섞어 ‘순수 모델 속도’라고 부르지 않는다.
- 도구·스킬·MCP·프로젝트 자동 로드는 실험 세션에서 끄고 모든 입력을 명시한다. 모델이 평가 밖 파일이나 서비스에 접근하지 못하게 한다. 모델 하향·fallback은 없다.
- 과금/사용량 오류·모델 불가·출력 한도·실행 실패는 실패/미측정으로 남긴다. 장애 재시도는 동일 조건으로 1회만 허용하고 원 시도를 보존한다. 정상적으로 오래 실행되는 작업을 임의 실패로 만들지 않도록 15분 상한을 둔다.
