- **행위**(판정은 루트가 소유 — 인프라로 복제 금지 §3.2 빈혈 차단):
  - `Visit.open(key) -> Visit` — 새 방문(stage `idle` · `version 0`·`persisted_version 0` = **미영속** — `open()` 직후 저장하지 않는다; 첫 저장은 점유 성공 또는 S2 이월 놓기(`carry_request` — 목표 방문 선행 생성 §5.18 ①) 둘 중 먼저 오는 것).
  - `mark_persisted() -> None` — 저장 성공 직후 리포지토리가 부른다(`persisted_version = version` · version 무변).
  - **version 규약(루트 소유 · §7.3)**: 루트는 `version: int`(변경 메서드마다 `+= 1` — 한 attempt에 여러 변경 메서드를 불러도 된다)와 **`persisted_version: int`**(리포지토리가 로드 시 저장된 version으로 채우고, `open()`은 0 · 저장 성공 뒤 리포지토리가 `mark_persisted()`를 불러 `version`과 같게 맞춘다)를 함께 든다. 리포지토리 가드는 산술이 아니라 **`WHERE version = persisted_version`**이고 INSERT는 `persisted_version == 0`일 때다 — S1+에서 한 attempt에 루트 변경 메서드 둘을 불러도 깨지지 않는다. 루트가 version을 올리지 않은 호출(`REJECTED_IN_PROGRESS`·`end_turn → False`·`reconcile → False`)은 `save`를 부르지 않는다(불필요 왕복 — 정확성엔 무관). 첫 영속은 INSERT(version은 그때의 값 — S0 점유 뒤 1).
  - `begin_turn(turn_id, now, deadline) -> TurnAdmission` — **턴 진입 점유**(발주서 §5.27 ②): ⓐ `lease is None` → 점유 → `TurnAdmission(kind=ADMITTED, rewind=None)` — **단 S3: `lease is None ∧ stage is ANSWERING`(고아 답 구간 — `abort_answer`/`complete_answer` 2회 CAS 미스 뒤 `end_turn`이 점유를 정상 해제한 잔재 · «점유 없는 `ANSWERING`은 크래시 잔재다»)이면 `_rewind` 동형 접기(`stage = IDLE` · `selection.with_rewind()` · `request` 유지 §3.3) 뒤 점유 → `TurnAdmission(kind=ADMITTED_AFTER_REWIND, rewind=RewindRecord{previous_turn_id=None, previous_stage=ANSWERING, released_reservation_id=<비운 포인터>})`**(«`ANSWERING` ⇒ 점유 있음»의 복구 자리 · 새 VO 0 · **`last_turn_outcome` 무변** — 고아를 만든 옛 턴은 `end_turn`으로 정상 종결해 참값(`COMPLETED`/`INTERNAL_ERROR`)을 이미 적었다 · `DEADLINE_EXCEEDED`는 «끝나지 못한 턴»의 stale 되감기 ⓑ만이라 고아에 덮어쓰면 O-8 재료에 거짓 사실이 남는다(ddd imp1 = db nit 2 · 라운드 B) · `lease`는 이미 `None`(정리 대상 아님) · 구현 재량: `_rewind`를 «접기(stage·selection)»와 «점유 정리(lease·outcome)»로 나누면 ⓐ·ⓑ가 공유하는 부분이 정확히 접기다 — 명세는 형태를 강제하지 않는다 · `previous_turn_id`는 옛 점유가 없어 `None`(§3.4 타입 확장) · 응용은 값으로 로그만 — 해제·확정 0 D39 ① · `released_reservation_id`는 이미 released(`abort_answer` 미스) 또는 confirmed(`complete_answer` 미스) 전표일 수 있다 — 이름은 «포인터가 가리키던 전표»이고 상태 판정은 admin이 wallet에서 §7.7 · ddd imp1 = db imp2 ⓐ) ⓑ `lease`가 있고 `lease.is_stale(now)`(= `now ≥ lease.deadline`)이면 **되감기**(§3.3) 후 점유 → `TurnAdmission(kind=ADMITTED_AFTER_REWIND, rewind=RewindRecord{previous_turn_id, previous_stage, released_reservation_id})` ⓒ 그 밖(살아 있는 점유 — 같은 `turn_id`여도) → `TurnAdmission(kind=REJECTED_IN_PROGRESS, rewind=None)`(**상태 무변 · version 무변**). ⓐⓑ만 `version += 1`(되감기+점유를 합쳐 1회). 되감기 사실은 값(`RewindRecord`)으로 돌려주고 응용이 그 값으로만 운영 로그를 쓴다(도메인은 로거를 모른다 · 응용의 판정 복제 0).
  - `end_turn(turn_id, outcome: TurnOutcome) -> bool` — 이 턴이 점유자일 때만 점유 해제 + `last_turn_outcome = outcome` + `version += 1` → `True`; 다른 턴이 점유 중이거나 점유가 없으면 **no-op·`False`**(stale 되감기 뒤 늦게 끝난 옛 worker 보호 · 응용은 `False`면 저장하지 않는다).
  - `reconcile_pending_card(present_call_ids: frozenset[str]) -> bool` — 대본에 슬롯 `call_id`의 `function_call`이 없으면 슬롯 폐기 + `stage: SELECTING → IDLE`(불변식 유지) + `version += 1` → `True`(§5.22 ⑦ 슬롯↔장부 정합); 슬롯이 없거나 살아 있으면 `False`(무변 · 저장 0).
  - `pending_call_id() -> str | None` — 슬롯 `call_id`(응용이 내부 구조를 더듬지 않게 캡슐화 — 원칙 02).
  - `notice_language(operating_language: str) -> DisplayLanguage` — 캐시 또는 운영 언어(§4.3 ③ 폴백의 단일 소유 자리).
