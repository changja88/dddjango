## 2. 클러스터 (모드 공기 + 상류/하류)

### C-a 집행력 결핍 (enforcement-deficit) — 진짜 회귀의 지배 클러스터
처방이 **결함 공간보다 좁게/약하게 착지**해 형제 변종을 못 막음. L2+L4+L6 공기. 두 하위 메커니즘:
- **C-a1 architect-단계 산문 코인플립**: 가드가 *디스크에 있는데* architect가 라이브서 번복(집행력 0). → catalog(DR-26 "코인플립")·C3(DR-28 "가드 이미 있었으나 번복")·P1a 초기.
- **C-a2 좁은 텍스트-계약 앵커**: 백스톱/처방이 한 형태만 고정밀 커버, 형제 누수. → ACL-EX(포트 도메인예외만)·깨진JSON(415 CT만)·pytest-MISS(깨진설정만)·C4(C형만)·P1a-v3(application_layer만→C2 변종).

**상류 근본:** "표준 텍스트/reviewer 산문은 *집행력*이 없다" — L2가 박은 척추(P1a→DR-21→22→23→C2/C3→28). **해결된 사례(P2·P3·C3·C4) 전부 "결정적 Bash 백스톱 + 생산자 예방"으로 수렴** = 이 클러스터의 검증된 처방 형태. 단 백스톱이 좁으면 C-a2로 재발(저-recall).

### C-b 비결정 × N=1 오측정 (run-variance) — "회귀로 오인되는 측정 문제"
같은 입력인데 런마다 다른 잠재결함 노출. L1 지배. **회귀가 아님** — 처방은 stick했고 측정이 N=1이라 다른 게 우연히 터진 것. → NJ-2(DR-35 후 양 PASS)·FC-2(런간 커버리지)·P4③(의도된 여지)·BC-FK(런간 해석)·C6(5/6 준수 단발). DEVLOG가 직접 "반전·비결정·N=1·우열 아님" 라벨.

### C-c 진단/검증 방법 실패 (diagnostic-method) — 메타 증폭기
1차 진단 철회(L5)·exit0을 준수로 오독(DNR-11/14)·N=9 텍스트판별≠라이브(DNR-10). **두 방식으로 다른 클러스터를 증폭**: ① *팬텀 회귀 생성*(안 됐는데 "됐다" 선언→다음 런서 "회귀"로 보임: DR-23→24, DR-44→45) ② *반복 사이클 소모*(P1a 5회·NJ-1 곁길 3회·진단 철회). DNR-1~14 전수가 이 박제.

### C-d 위장 green 테스트 (test-authenticity)
테스트가 vacuous/오귀속으로 통과해 결함 은폐. → 위장-oversell(순차라 CAS 미실행)·위장-constraint(암묵 CHECK 오귀속). **C-a2의 공범**: ACL-EX 인프라 누수가 sequential 테스트라 *영구 green*(은폐).

## 3. 핵심 가설 검정 — 측정 문제 vs 수정 문제

L6에서 "회귀처럼 보인" 에피소드를 분류한 결과:

| 분류 | 건 | 함의(처방 방향) |
|---|---|---|
| **진짜 수정 문제 (C-a)** | catalog·C3·ACL-EX·pytest-MISS·깨진JSON (+P1a 부분) | 표준 *텍스트 추가* 아님 → **집행 아키텍처**(올바른 고도의 결정적 집행 + 스코프-완전 앵커) |
| **측정 문제 (C-b)** | NJ-2·FC-2·P4③·BC-FK·C6 | 표준 텍스트 추가 **금지/무익** → **측정 개선**(N≥5 블라인드). 여기 텍스트 더 박으면 낭비·해악 |
| **메타 증폭 (C-c)** | DNR 14 + 철회들 | 진단·검증 *방법* 자체 — exit0≠준수·N=9≠라이브를 규율로 |

**검정 결론(초안):** "수정해도 회귀"의 정체는 **단일 원인이 아니라 ~절반은 측정 문제(C-b), ~절반은 집행력 결핍(C-a), 그리고 둘을 증폭하는 진단방법 실패(C-c)**. → 가장 위험한 함정 = **C-b를 C-a로 오인해 표준 텍스트를 더 박는 것**(DNR-13·DR-38이 이미 밟은 헛다리). 그리고 C-a의 진짜 처방은 *개별 텍스트*가 아니라 **"집행은 결정적 백스톱+생산자 예방, 백스톱은 스코프-완전하게"라는 메타 규율**(프로젝트가 P2·P3·C3·C4서 이미 수렴했으나 매번 재발견).

## 4. 열린 발견 → 클러스터 매핑

| 열린 발견 | 클러스터 | 처방 방향(진단 차원·설계 아님) |
|---|---|---|
| ACL-EX | C-a2 (+C-d 은폐) | 인프라 transient *소유 계층* 결정 → 스코프-완전 앵커. 결정적 백스톱은 *원리상 불가*(전파-도달성 FP무한)라 예방+테스트 진정성에 의존 |
| 깨진JSON | C-a2 | problem+json 중앙화를 415-CT 너머 *모든 오류 경로*로 스코프 확장 |
| 위장-oversell | C-d | 동시성 테스트 *진정성* 집행(순차=vacuous 차단). ACL-EX 은폐 해소의 전제 |

| pytest-MISS | C-a2 + C-b | ⑬이 *무설정* 못 봄(스코프) + Codex 런간(측정). 반복확인됨(N=2)이라 C-a 처방 후보 |
| NJ-4 / SD-7 | (측정 대기) | 백스톱 정상·라이브 발화 N≥1만 |

## 5. 정직 경계 (이 초안의 한계)

- **N=1 도처**: 코퍼스 전체가 런타임당 1회. C-b 분류 자체가 N=1 위에 있음.
- **post-hoc 위험**: "C-a 5건이 공통 메커니즘"이 진짜 인과인지 사후 패턴화인지 **Phase 3가 검증**해야.
- **클러스터 경계 모호**: P1a는 C-a/C-c 혼재, pytest-MISS는 C-a2/C-b 혼재 — 깔끔히 안 갈림.
- **C-c가 진짜 "근본"인가 vs 증상 재진술인가** = Phase 3 회의론자 (d) 질문의 직격 대상.
