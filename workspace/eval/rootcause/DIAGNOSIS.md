# dddjango 수정 회귀 — 진단 (N=1 경계)

> deliverable. 질문: "왜 dddjango 수정이 여러 번 고쳐도 회귀하거나 안 고쳐지나."
> 방법: 에피소드 전수(Phase 0) → 6렌즈 병렬 수집(Phase 1) → 합성(Phase 2) → **3-회의론자 적대 검증(Phase 3)**. 본문 = 적대 검증 *생존* 결론만. 기각은 §부록.
> 경계: **진단까지** — 처방 *방향*만 제시(설계·구현 아님, 별도 합의). 라벨은 DR/루브릭 코드로 환원.
> ⚠️ **N=1 도처**: 코퍼스 전체가 런타임당 1회 관측. 가장 견고한 것은 *런 무관 구조적 사실*이고, 나머지는 신뢰도를 명시한다.

---

## 1. 실패모드 분류표 (적대 검증 생존)

6렌즈가 L1~L6으로 수집했으나 적대 검증이 일부를 통합·강등했다. 생존한 *근본* 4 + *증폭기* 2 + *메타-제약* 2.

| 코드 | 종류 | 정의 | 핵심 증거 앵커 |
|---|---|---|---|
| **R1 스코프-갭** | 근본 (가장 견고) | 처방이 결함 공간보다 좁게 앵커 — 한 형태/계층만 고정밀 커버, 형제 변종 누수. **런 무관 구조적 사실** | ACL-EX 포트 도메인예외만(DEVLOG:404)·깨진JSON 415-CT만(:377)·C4 C형만(DR-32)·P1a-v3 application_layer만(:164) |
| **R2 비결정** | 근본 | run-variance/N=1 — 같은 입력 다른 결과. *회귀가 아니라 측정 산물* | NJ-2 양방향 반전(:262)·FC-2 런간 커버리지(:279)·P4③(:260)·DR-14 13:2:5 정정(:78) |
| **R3 런타임-prior** | 근본 (회의론자3 발굴) | 모델/런타임 *사전확률*이 표준텍스트·백스톱 *둘 다 무력화*. 비결정도 스코프갭도 아님(런 *불변*) | pytest-MISS Codex `manage.py test` prior 양 런 불변(SPXOFF:106·108)·C3 stub-as-convention 오판·C4 gpt-5.5 TestCase prior(§0:31 현 1순위) |

## 3. 근본 클러스터 순위 (체계적 순 + 신뢰도)

1. **R1 스코프-갭 — 가장 견고·가장 체계적.** 유일하게 *런 무관 구조적 사실*(N=1에 안 흔들림). "처방 스코프 < 결함 공간"이 텍스트로 성립. **신뢰도 높음.**
2. **R2 비결정 — 견고하나 멤버십 경계 자의적.** run-variance 존재는 확실(NJ-2·DR-14). 단 어느 에피소드가 R2냐는 N=1이라 미결. **신뢰도 중(존재) / 낮음(멤버십).**
3. **R3 런타임-prior — 비자명·중요.** 프로젝트 자신의 현 1순위(§0:31)인데 합성 4 클러스터가 놓침. 표준·백스톱 둘 다 무력이라 *별도 도구* 필요. **신뢰도 중(N=2: pytestlive·aclex).**
4. **R4 릴리스-미완결 — 구조적 상류.** "왜 *반복* 관측되나"의 닫힌 루프 설명. **신뢰도 중-높음(구조적·반박 안 됨).**
5. **A1 진단-방법 — 횡단 증폭기(근본 아님).** 모든 근본을 증폭하나 그 자체가 결함을 *만들진* 않음(못 본 것이지). **규율로 다룸.**
6. **A2 위장-테스트 — 표본 부족.** 단일 감사 1회. **신뢰도 낮음(N≥2 확인 필요).**

## 4. ⭐ 가장 비자명한 중심 통찰 (적대 검증 생존)

> **프로젝트의 단골 처방 "결정적 백스톱 + 생산자 예방"은 백스톱이 *구조적으로 가능한 곳*에서만 검증됐다(생존자 편향). 그리고 미해결 프론티어 — ACL-EX·위장green·pytest 무설정·R3 런타임prior — 가 정확히 그 처방의 *사각*에 모여 있다.**

- 해결된 사례(P2·P3·C3·C4)는 *전부* 백스톱이 가능했던 결함(텍스트/AST 신호 존재).
- ACL-EX는 백스톱 *원리상 불가*(전파-도달성 정적분석 FP-무한, DR-44:366) = 정확한 반례.
- ∴ **"백스톱 더 쌓기"는 프론티어에 안 닿는다.** 프론티어는 *다른 도구*가 필요: 테스트 진정성(A2)·생산자 예방·측정(R2)·런타임-targeted 개입(R3).

## 5. "왜 회귀하나"에 대한 직접 답 + 처방 *방향* (설계 아님)

**세 가지 서로 다른 것이 "회귀" 하나로 위장된다:**
1. **닫힌 적 없는 스코프-갭(R1)** — "회귀"가 아니라 *미완성*. 처방 방향 = 처방 시 *결함 공간 전체*를 명시(한 형태 아님). 백스톱 불가 영역은 예방+테스트 진정성.
2. **회귀로 오인된 비결정(R2)** — N=1 측정 산물. 처방 방향 = **표준 텍스트 추가 중단**, *측정(N≥5 블라인드)*으로 "수정 문제인지"부터 판정. ⚠️ 오분류는 **양방향**(R2를 R1로 → 텍스트 낭비[DNR-13·DR-38] / R1을 R2로 → 처방 회피[ACL-EX 놓침]) — N=1이라 에피소드별 방향이 미결 = *측정 선행*이 최고 레버.
3. **표준·백스톱이 못 닿는 런타임-prior(R3)** — 런타임-targeted 개입(예: Codex prior 교정) 또는 런타임 특성으로 수용. 프로젝트가 §0:31에 이미 명명했으나 *별도 근본*으로 표면화 필요.

**증폭 차단:**
- **R4 닫힌 루프** — 처방 방향 = 릴리스/머지 규율로 부채 누적 차단("라이브 미검증" 항목에 검증→릴리스 cadence).
- **A1 진단-방법** — "exit0≠준수·N=9≠라이브·단일소스≠독립"을 상시 검증 규율로(일부 DO-NOT-RETRY에 이미).
- **M2 단일-조정자** — 자기보고 서사보다 독립 증거(probe·mutation·cross-runtime) 비중↑.

## 6. 열린 발견 → 근본 매핑 (처방 방향)

| 열린 발견 | 근본 | 처방 *방향* |
|---|---|---|
| **ACL-EX** | R1(+A2 은폐) | 인프라 transient *소유 계층* 결정→스코프-완전 앵커. 백스톱 불가 → **예방+테스트 진정성**(또 다른 백스톱 아님) |
| **깨진JSON** | R1 | problem+json 중앙화를 415-CT 너머 *모든 오류 경로*로 스코프 확장 |
| **위장-oversell/constraint** | A2 | 동시성/제약 테스트 *진정성* 집행(순차=vacuous 차단). ACL-EX 은폐 해소의 전제 |
| **pytest-MISS** | R3(+R4) | 백스톱 스코프 확장이 *아님*(prior는 안 바뀜) → 런타임-targeted 또는 수용. N=2 확인됨 |
| **NJ-4 / SD-7** | (측정 대기) | 백스톱 정상·라이브 발화 N≥1만 — R4 릴리스 cadence에 포함 |

## 7. 신뢰도·잔여 N=1 (정직)

- **가장 신뢰**: R1 스코프-갭(구조적·런 무관)·중심 통찰 §4(생존자 편향은 반박 안 됨).
- **중간**: R3(N=2)·R4(구조적이나 미해결).
- **낮음·미결**: R2 멤버십 경계·A2 표본(단일 감사)·근본 간 상대 가중치·R2↔R1 교락 방향.
- **전체 한계(M2)**: 이 진단은 *단일 조정자 산물* — 6렌즈·합성·3회의론자 전부 같은 사람이 같은 DEVLOG를 읽음. 독립 확증은 probe·mutation·md5뿐. **처방 단계는 이 비독립성을 명시하고, 독립 증거(특히 R2의 N≥5)를 먼저 늘려야.**
