## 결정 불능 잔여

1. **오버레이 add 충돌(기본 HEAD 경로) 의 일괄 반송** — 현 구현은 `materialize:1010` 첫 건 raise(n 건이면 n 회전). 계획 Δ1 «일괄 반송: add 충돌·update/remove 부재를 … materialize 앞에서 1회 반환» 이 기준선 측 add 충돌만 뜻하는지, `_overlay_dirty` 뒤 materialize 앞에서 오버레이 충돌까지 모으라는 뜻인지 문면 확정 필요. R-3445 ② 가 Phase 2 재실행에 `--base` 를 요구하므로 실전 빈도는 낮다(reading run 36→37 판형은 `--base HEAD` 명시 = lift 경로).
2. **파서 앵커 강화(⑥-5) vs 규범 금지 문면** — 실행기 자기 형식 정규식(결정적·규범 무관)과 R-3438 문면(코디네이터 제목 접두 금지) 중 택1은 B 축 소관. A 축 권고는 전자(문면 의존 0).
