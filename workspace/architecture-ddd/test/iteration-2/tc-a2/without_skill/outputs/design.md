# 대형 병원 통합 시스템 — DDD 분석

## 1. 하위 도메인 식별 및 분류

### 핵심 하위 도메인 (Core Subdomain)

비즈니스 차별화의 원천이며, 병원의 경쟁력과 직결되는 영역이다.

| 하위 도메인 | 설명 | 핵심인 이유 |
|---|---|---|
| **진료 예약 및 대기열 관리** | 환자의 진료 예약 생성/변경/취소, 실시간 대기열 운영, 의사별 스케줄 최적화 | 환자 경험과 병원 운영 효율의 핵심 차별화 요소. 병원마다 진료 프로세스, 우선순위 정책, 대기열 알고리즘이 다르며 이것이 곧 경쟁력이다. |
| **전자 의무 기록(EMR)** | 환자의 진료 기록, 검사 결과, 진단 이력, 투약 이력 등 의료 데이터의 생성과 관리 | 병원 운영의 가장 본질적인 도메인. 의료 데이터의 구조화 방식, 진료 워크플로우 지원 수준이 의료 서비스 품질을 결정한다. |
| **수술 스케줄링 및 수술실 자원 관리** | 수술 일정 계획, 수술실/장비/인력 배정, 충돌 감지, 긴급 수술 대응 | 고가 자원(수술실, 마취팀, 장비)의 최적 배분이 필요한 복잡한 스케줄링 문제. 병원 수익과 환자 안전에 직접적 영향을 미친다. |

### 지원 하위 도메인 (Supporting Subdomain)

핵심 도메인을 지원하며, 병원 업무에 특화된 로직을 포함하지만 그 자체가 차별화 요소는 아닌 영역이다.

| 하위 도메인 | 설명 | 지원인 이유 |
|---|---|---|
| **처방전 발행 및 약국 연동** | 의사의 처방 생성, 약물 상호작용 검증, 약국 시스템과의 연동, 처방 이력 관리 | 의료 도메인에 특화된 규칙(약물 상호작용, 용량 검증 등)이 있지만, 표준화된 프로세스가 존재한다. 핵심 도메인(EMR)을 보조하는 역할이다. |
| **보험 청구 및 수납** | 진료비 산정, 보험 청구서 생성, 심사 평가원 연동, 환자 수납 처리 | 병원 운영에 필수적이나, 건강보험심사평가원의 규격과 수가 기준을 따르는 규칙 기반 영역이다. 병원마다 일부 커스터마이징이 필요하지만 큰 차별화 요소는 아니다. |
| **환자 포털** | 환자가 예약을 조회하고, 검사 결과를 확인하며, 기본적인 정보를 관리하는 셀프서비스 채널 | 핵심 도메인의 데이터를 환자에게 노출하는 프레젠테이션 계층. 병원 특화 로직(어떤 정보를 어떻게 보여줄지)이 포함되지만, 데이터의 원천은 핵심 도메인에 있다. |

### 일반 하위 도메인 (Generic Subdomain)

도메인 특화 로직이 거의 없으며, 범용적으로 해결 가능한 영역이다.

| 하위 도메인 | 설명 | 일반인 이유 |
|---|---|---|
| **사용자 인증 및 권한 관리** | 사용자 로그인, 세션 관리, 역할 기반 접근 제어(RBAC), 감사 로그 | 모든 엔터프라이즈 시스템에 공통으로 필요한 기능이다. 병원 고유의 비즈니스 로직이 거의 없으며, 성숙한 범용 솔루션이 다수 존재한다. |

## 2. 하위 도메인 유형별 솔루션 전략

### 핵심 하위 도메인 — 사내 구현 (In-house Development)

핵심 도메인은 반드시 사내 최정예 팀이 직접 구현해야 한다. 이 영역이 곧 병원 시스템의 경쟁력이며, 외부에 맡길 경우 차별화 기회를 잃는다.

| 하위 도메인 | 전략 | 근거 |
|---|---|---|
| **진료 예약 및 대기열 관리** | 사내 구현 | 병원별 진료 프로세스와 우선순위 정책이 다르다. 실시간 대기열 최적화 알고리즘은 병원의 핵심 노하우이며, 지속적 개선이 필요하다. |
| **전자 의무 기록(EMR)** | 사내 구현 | 의료 데이터 모델과 진료 워크플로우는 병원의 가장 본질적인 자산이다. 규제 준수, 데이터 주권, 빠른 요구사항 반영을 위해 내부 통제가 필수적이다. |
| **수술 스케줄링 및 수술실 자원 관리** | 사내 구현 | 수술실 배정 최적화, 긴급 수술 대응 정책 등은 병원 운영 효율의 핵심이다. 복잡한 제약 조건 하의 스케줄링은 병원마다 고유한 알고리즘이 필요하다. |

**설계 원칙:**
- 도메인 전문가(의사, 간호사, 운영팀)와 긴밀히 협업하여 유비쿼터스 언어를 정립한다.
- 풍부한 도메인 모델(Rich Domain Model) 패턴을 적용한다.
- 각 핵심 도메인은 독립된 Bounded Context로 설계하여 자율적 진화를 보장한다.

### 지원 하위 도메인 — 하청 개발 또는 간소화된 사내 구현

지원 도메인은 도메인 특화 로직이 있으나 복잡도가 상대적으로 낮다. 외부 파트너에게 위탁하거나, 사내에서 간소화된 패턴으로 구현한다.

| 하위 도메인 | 전략 | 근거 |
|---|---|---|
| **처방전 발행 및 약국 연동** | 하청 개발 + 사내 감독 | 약물 상호작용 검증 등 표준화된 규칙이 존재한다. 외부 개발사에 위탁하되, 의료 안전과 관련되므로 사내 도메인 전문가가 검증과 감독을 수행한다. 약국 연동 프로토콜은 표준 규격을 따른다. |
| **보험 청구 및 수납** | 하청 개발 또는 외부 솔루션 커스터마이징 | 심사평가원 규격, 수가 기준 등 외부 규칙에 의존하는 영역이다. 기존 보험 청구 솔루션을 커스터마이징하거나, 해당 도메인 경험이 있는 외부 파트너에게 개발을 위탁한다. |
| **환자 포털** | 하청 개발 | UI/UX 중심의 프레젠테이션 계층이다. 핵심 도메인의 API를 소비하는 구조이므로, 프론트엔드 전문 외부 파트너에게 위탁하기 적합하다. 사내 팀은 API 계약 정의와 보안 검토에 집중한다. |

**설계 원칙:**
- 트랜잭션 스크립트(Transaction Script) 또는 액티브 레코드(Active Record) 패턴으로 충분하다.
- 핵심 도메인과의 통합은 잘 정의된 API 계약(Anti-Corruption Layer)을 통해 이루어진다.
- 외부 위탁 시에도 도메인 지식의 사내 보유를 보장한다.

### 일반 하위 도메인 — 외부 솔루션 도입 (Buy / Adopt)

일반 도메인은 검증된 외부 제품이나 오픈소스를 도입하여 비용과 시간을 절약한다.

| 하위 도메인 | 전략 | 근거 |
|---|---|---|
| **사용자 인증 및 권한 관리** | 외부 솔루션 도입 | Keycloak, Okta, Azure AD 등 성숙한 IAM 솔루션이 다수 존재한다. 의료 시스템 특성상 강화된 인증(MFA, 세션 타임아웃 등)이 필요하지만, 이는 기존 솔루션의 설정으로 대응 가능하다. 직접 구현은 보안 위험만 높인다. |

**설계 원칙:**
- 기성 솔루션을 그대로 사용하고, 커스터마이징을 최소화한다.
- Anti-Corruption Layer를 두어 외부 솔루션 교체 시 핵심 도메인에 영향이 없도록 한다.

```
┌─────────────────────────────────────────────────────────┐
│                    핵심 (Core)                           │
│  ┌──────────────┐ ┌──────────┐ ┌─────────────────────┐  │
│  │ 진료 예약 및  │ │   EMR    │ │ 수술 스케줄링 및     │  │
│  │ 대기열 관리   │ │          │ │ 수술실 자원 관리     │  │
│  └──────┬───────┘ └────┬─────┘ └──────────┬──────────┘  │
│         │              │                   │             │
├─────────┼──────────────┼───────────────────┼─────────────┤
│         │        지원 (Supporting)         │             │
│  ┌──────▼───────┐ ┌────▼─────┐ ┌──────────▼──────────┐  │
│  │  환자 포털   │ │ 처방전   │ │ 보험 청구 및 수납    │  │
│  │             │ │ 및 약국  │ │                     │  │
│  └─────────────┘ └──────────┘ └─────────────────────┘  │
├─────────────────────────────────────────────────────────┤
│                    일반 (Generic)                        │
│         ┌─────────────────────────────┐                 │
│         │ 사용자 인증 및 권한 관리      │                 │
│         └─────────────────────────────┘                 │
└─────────────────────────────────────────────────────────┘
```

## 4. 솔루션 전략 요약 매트릭스

| 하위 도메인 | 유형 | 솔루션 전략 | 구현 패턴 | 인력 배치 |
|---|---|---|---|---|
| 진료 예약 및 대기열 관리 | 핵심 | 사내 구현 | 도메인 모델 | 최정예 사내 팀 |
| 전자 의무 기록(EMR) | 핵심 | 사내 구현 | 도메인 모델 | 최정예 사내 팀 |
| 수술 스케줄링 및 수술실 자원 관리 | 핵심 | 사내 구현 | 도메인 모델 | 최정예 사내 팀 |
| 처방전 발행 및 약국 연동 | 지원 | 하청 + 사내 감독 | 트랜잭션 스크립트 | 외부 파트너 + 사내 감독 |
| 보험 청구 및 수납 | 지원 | 하청 또는 외부 솔루션 커스터마이징 | 트랜잭션 스크립트 | 외부 파트너 |
| 환자 포털 | 지원 | 하청 | 트랜잭션 스크립트 | 외부 프론트엔드 파트너 |
| 사용자 인증 및 권한 관리 | 일반 | 외부 솔루션 도입 | 설정 기반 | 사내 인프라 팀 (설정/운영) |
