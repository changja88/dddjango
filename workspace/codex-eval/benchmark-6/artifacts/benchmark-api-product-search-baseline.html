상품 검색 API 컨벤션

1. 기본 원칙

상품 검색 API는 Django Ninja 기준으로 다음 책임을 분리한다.

  • api.py: HTTP 엔드포인트, 인증/권한, 응답 스키마 연결
  • schemas.py: 요청/응답 DTO
  • selectors.py: 상품 조회 QuerySet 구성
  • pagination.py: 공통 페이지네이션 유틸
  • errors.py: 표준 에러 응답
  • models.py: 도메인 데이터

검색 조건, 정렬, 페이지네이션은 Query Parameter로 받는다. 비즈니스 규칙이 들어간 필터링은 view 함수 안에 직접 쓰지 않고 selector로 분리한다.

2. Endpoint


GET /api/products

예시:


GET /api/products?q=iphone&category_id=3&min_price=100000&max_price=2000000&status=active&sort=-created_at&page=1&page_size=20

3. Query Parameters


from decimal import Decimal
from typing import Literal

from ninja import Schema


class ProductSearchParams(Schema):
    q: str | None = None

    category_id: int | None = None
    brand_id: int | None = None

    min_price: Decimal | None = None
    max_price: Decimal | None = None

    status: Literal["active", "sold_out", "hidden"] | None = "active"

    sort: Literal[
        "created_at",
        "-created_at",
        "price",
        "-price",
        "name",
        "-name",
    ] = "-created_at"

    page: int = 1
    page_size: int = 20

컨벤션:

  • 검색어는 q를 사용한다.
  • 범위 조건은 min_, max_ prefix를 사용한다.
  • 정렬은 sort 하나로 처리한다.
  • 내림차순은 Django ORM 관례와 동일하게 -field를 사용한다.
  • 페이지는 page, page_size를 사용한다.
  • 기본 정렬은 최신순 -created_at이다.
  • 기본 노출 상태는 active이다.

5. Selector 설계


from django.db.models import Q, QuerySet

from .models import Product
from .schemas import ProductSearchParams


ALLOWED_PRODUCT_SORTS = {
    "created_at",
    "-created_at",
    "price",
    "-price",
    "name",
    "-name",
}


def search_products(params: ProductSearchParams) -> QuerySet[Product]:
    queryset = (
        Product.objects
        .select_related("category", "brand")
        .all()
    )

    if params.q:
        queryset = queryset.filter(
            Q(name__icontains=params.q)
            | Q(description__icontains=params.q)
        )

    if params.category_id:
        queryset = queryset.filter(category_id=params.category_id)

    if params.brand_id:
        queryset = queryset.filter(brand_id=params.brand_id)

    if params.min_price is not None:
        queryset = queryset.filter(price__gte=params.min_price)

    if params.max_price is not None:
        queryset = queryset.filter(price__lte=params.max_price)

    if params.status:
        queryset = queryset.filter(status=params.status)

    return queryset.order_by(params.sort)

컨벤션:

  • API 함수에서 직접 filter() 체인을 길게 만들지 않는다.
  • 조회 목적 로직은 selectors.py에 둔다.
  • select_related, prefetch_related는 selector에서 책임진다.
  • 허용되지 않은 정렬 필드는 스키마 또는 별도 validator에서 차단한다.
  • 검색 API에서는 N+1 쿼리를 방지하는 구성을 기본으로 한다.

6. Pagination


from math import ceil

from django.core.paginator import EmptyPage, Paginator


DEFAULT_PAGE_SIZE = 20
MAX_PAGE_SIZE = 100


def paginate_queryset(queryset, page: int, page_size: int):
    page = max(page, 1)
    page_size = min(max(page_size, 1), MAX_PAGE_SIZE)

    paginator = Paginator(queryset, page_size)

    try:
        page_obj = paginator.page(page)
    except EmptyPage:
        page_obj = paginator.page(paginator.num_pages or 1)

    return {
        "items": list(page_obj.object_list),
        "meta": {
            "page": page_obj.number,
            "page_size": page_size,
            "total_count": paginator.count,
            "total_pages": paginator.num_pages,
            "has_next": page_obj.has_next(),
            "has_previous": page_obj.has_previous(),
        },
    }

컨벤션:

  • page는 1부터 시작한다.
  • page_size 기본값은 20이다.
  • page_size 최대값은 100이다.
  • 범위를 초과한 page는 빈 배열 대신 마지막 페이지로 보정하거나, 팀 정책에 따라 400으로 통일한다.
  • 대량 데이터에서 offset pagination 성능 문제가 생기면 cursor pagination을 별도 API로 추가한다.

7. Ninja Router 예시


from ninja import Router, Query

from .pagination import paginate_queryset
from .schemas import ProductSearchParams, ProductSearchResponse
from .selectors import search_products


router = Router(tags=["Products"])


@router.get("", response={200: ProductSearchResponse})
def list_products(request, params: Query[ProductSearchParams]):
    queryset = search_products(params)
    return paginate_queryset(
        queryset=queryset,
        page=params.page,
        page_size=params.page_size,
    )

8. Error Response 표준

모든 에러 응답은 아래 형태로 통일한다.


from ninja import Schema


class ErrorDetail(Schema):
    field: str | None = None
    message: str
    code: str


class ErrorResponse(Schema):
    error: str
    message: str
    details: list[ErrorDetail] = []

예시:


{
  "error": "VALIDATION_ERROR",
  "message": "요청 값이 올바르지 않습니다.",
  "details": [
    {
      "field": "page_size",
      "message": "page_size는 100 이하이어야 합니다.",
      "code": "max_value"
    }
  ]
}

권장 에러 코드:


VALIDATION_ERROR
INVALID_SORT
INVALID_FILTER
NOT_FOUND
UNAUTHORIZED
FORBIDDEN
INTERNAL_SERVER_ERROR

HTTP status 기준:


400: 잘못된 필터, 정렬, 페이지 파라미터
401: 인증 필요
403: 권한 없음
404: 리소스 없음
500: 서버 오류

9. 팀 컨벤션 요약

  • 목록 API 응답은 항상 { items, meta } 구조를 사용한다.
  • 검색어 파라미터는 q로 통일한다.
  • 정렬 파라미터는 sort 하나만 사용한다.
  • 정렬 가능 필드는 명시적인 allowlist로 제한한다.
  • 페이지네이션은 page, page_size를 사용한다.
  • page_size 최대값은 서버에서 강제한다.
  • QuerySet 조합은 selectors.py에서 처리한다.
  • View 함수는 요청 파싱, selector 호출, 응답 반환만 담당한다.
  • 에러 응답은 { error, message, details } 구조로 통일한다.
  • 필터 조건이 늘어날 때도 성급하게 범용 필터 DSL을 만들지 말고, 반복되는 변경 축이 확인된 뒤 추상화한다.
