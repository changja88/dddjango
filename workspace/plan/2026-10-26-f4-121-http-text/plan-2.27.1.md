# dddjango 2.27.1 — deps HTTP 소비 셈에서 문서 문자열 · 주석 빼기(F4-121) (10-26)

## 바탕
- 바탕: main(dddjango 2.27.0 봉인 뒤). 2.27.1 은 patch — 리팩토링 모드 `refactor_audit.py deps` 의 HTTP 소비 셈 고침(새 질문 · 새 흐름 · 새 기록 칸 · 규범 문면 변경 없음). 매니페스트 판은 `make release` 가 올린다. dddjango-web 무변(web `refactor_audit.py` 에는 HTTP 셈이 없다).
- 결함(장부 F4-121): `DepsScan._http_consumers` 가 `.py` · `.js` · `.html` 을 원문 줄 정규식으로 훑어 docstring · 주석에 적은 다른 BC 의 API 주소까지 «HTTP 소비» 로 셌다. 이 셈은 운영 그래프(`adjacency`)에 들어가 실제 호출이 없는 두 BC 사이에 순환 묶음을 세우고 → `deps` exit 2 «지원 안 함: 순환 묶음» → 조정자 G0 정지(묻지 않음). 같은 셈이 «HTTP 소비자» 갈래 · 받는 쪽 BC · web 단위 겹침도 넓혔다.
- 판정: 결함(의도된 상위 집합 아님). 근거 — `_http_consumers` docstring 의 «상위 집합» 은 마운트 접두를 결속하지 않는다는 뜻(«URL 문자열 … 조각을 품은 줄 — 앞에 어떤 마운트 접두가 와도 센다») · 리팩토링 정의 설계(`2026-10-03-refactor-definition/design-v15.1.md` §5)의 «URL 문자열 접두 일치» · «HTTP 소비자 = 저장소 안 호출 자리와 그 시험» · 같은 그래프의 참조 수집(`_scan`)은 문장 자리 문자열을 이미 뺀다 · 2.26.1 공급 면 ④ `code_url` 도 `.py` 문서 문자열을 이미 뺐다 · 규범 문면 «대상 운영 코드가 HTTP 로 부르는 그 BC API» · «대상 API 를 소비하는 web 단위».
- 설계: 1판(재현 · 현장 읽기 대조 · 시제품) → 적대 검토(고친 뒤 구현 · 차단 3 · 중요 3 · 사소 8) → 운영자 결정(D1 = 나 · D2 = 규범 문면 개정 없음 · 검토 항목 방향) → 구현.

## 설계 요지

원칙 하나: **실행될 때 주소로 쓰일 수 없는 글만 뺀다** — 주석과 문장 자리 문자열. 그 밖은 지금처럼 센다.

| 파일 | 세지 않는다 | 그대로 센다 |
|---|---|---|
| `.py`(파싱됨) | `#` 주석 · 문장 자리 문자열(모듈 · 클래스 · 함수 docstring + 몸 가운데 문자열 식 문장 — `_scan` 과 같은 `_doc_ids`) | 그 밖 문자열 · 바이트 상수 전부(대입 · 인자 · 반환 · f-string 조각 · `%` 틀 · 이어 쓴 리터럴 · `description=` · 로그 · 오류 글) · `>>>` 를 품은 docstring(doctest — 실행되는 글) |
| `.html` | Django 주석(`{# #}` 한 줄 · `{% comment %}…{% endcomment %}` — `{% verbatim %}` 안 제외) · 닫힌 HTML 주석 `<!-- -->`(`<!-->` · `<!--->` 포함) | 태그 · 속성 · 본문 글 · 날 글 요소(script · style · textarea · title) 안 글 · 템플릿 태그 · 변수 안 글(그 안 `<!--` 는 주석이 아니다) |
| `.js` · 계약 JSON · 파싱 못 한 `.py` | — | 원문 전부(지금과 같음) |

- 가를 수 없을 때(모를 때 원문): 파싱 못 한 `.py` 는 원문 줄(`요약:` 의 «파싱 못 한 파일 n» 은 그대로) · HTML 에서 닫히지 않은 `<!--` · 날 글 요소 · 태그 · 따옴표 · `{% %}` · `{{ }}` 를 만나면 그 뒤는 지우지 않는다 · 닫히지 않은 `{% comment %}` · 줄을 넘는 `{# #}` 는 주석이 아니다(Django 와 같음).
- 쓰는 곳 넷(운영 · 시험 포함 그래프 · «HTTP 소비자» 갈래 · 공급 면 ④ · `http_owners` → 받는 쪽 BC · web 단위)이 모두 같은 걸러진 글을 쓴다. 계약 · `url_hits`(web 실행 계약의 계획된 소비)는 무변.
- 구현(`dddjango/scripts/refactor_audit.py` · Codex byte 미러):
  - `_doc_ids(tree)` — `_scan` 과 2.26.1 `code_url` 에 두 벌 있던 «문장 자리 문자열 id» 를 한 함수로(`_scan` 동작 무변).
  - `DepsScan.literals` — `_scan` 이 이미 모든 `.py` 를 파싱하며 걷는 문장 자리 밖 `str` 상수 가운데 `/` 를 품은 것 + 바이트 상수 + `>>>` 를 품은 docstring 을 (시작 줄, 값) 으로 모은다(추가 파싱 0 · 칸 없음 = 파싱 실패 = 원문).
  - `_mask_html(text)` — 주석을 공백으로 지운 글(줄 끝 글자 · 글자 자리 그대로 — `str.splitlines` 의 모든 줄 끝 보존). Django 주석 먼저(`_DJANGO_COMMENT`), HTML 주석은 낱말 정규식 `_HTML_TOKEN` 하나로 왼쪽부터 가린다.
  - `DepsScan._body(rel, text)` — `.html` 은 지운 글(파일마다 한 번 — `_masked` 캐시) · 그 밖은 원문. `_text_hits(body, owner)` — 글 전체를 공급 BC 마다 한 번 훑어 맞은 자리를 줄 번호로(접두 조각은 줄을 넘지 않아 줄마다 맞춘 것과 같은 결과). `_url_lines(pieces, owner)` — `.py` 리터럴 조각용 · 본 짝은 set.
  - `_http_consumers` — `.py` 는 `literals` · 그 밖은 `_text_hits`(원문에 접두가 있는 `.html` 만 `_body`) · `_is_test_path` 는 파일마다 한 번.
  - 공급 면 ④ `code_url` — 같은 글(`literals` · `_body`)에 접두 일치 · (파일, 공급 BC) 짝마다 한 번만 판정.
  - docstring 고침 둘: `_http_consumers` · `_supplier_faces` ④.

## 받아들인 한계
1. **문자열 값 속 설명 글은 센다** — `Field(description="… GET /api/x …")` · `help_text=` · 로그 · 오류 글 · 접두와 같은 조각을 품은 파일 경로 문자열. 값이라 주소로 쓰이지 않음을 증명할 수 없다(설명은 docstring · 주석에 두면 세지 않는다).
2. **JS 주석 속 주소는 센다**(D1 = 나 — 지금과 같음 · 더 세는 쪽).
3. **HTML 의 `<script>` 안 JS 주석 · 본문 산문(설명 문서 HTML)은 센다** — 지우는 것은 HTML · Django 주석뿐. 문서 HTML 의 주인은 BC 가 아니어서 순환 · BC 겹침에는 안 들고 «HTTP 소비자» 갈래 · 공유 표면 경로에만 든다.
4. **남는 덜 세는 길**(드묾 — HTML 주석 · 문장 자리 문자열 안의 실행되는 글): Knockout 류 주석 바인딩(`<!-- ko … -->`) · SSI(`<!--#include … -->`) · `<!-- -->` 안에 두고 스크립트가 읽어 쓰는 글 · 문장 자리 문자열을 런타임에 읽는 코드(`__doc__` 를 주소로 쓰는 꼴 — `>>>` doctest 는 셈).
5. **우연히 잡던 비글자 호출을 이제 안 잡는다** — docstring · 주석에만 주소를 적고 실제 호출은 `reverse` · 상수 · 이어 붙인 주소로 하던 자리는 2.26.1 까지 그 설명 글 때문에 «HTTP 소비» 로 잡혔다. 2.26.1 부터의 «글자 URL 만» 한계와 같은 갈래다(현장 꼴 대조에서 빠진 `.py` 가운데 그 공급 BC 경로 조각을 품은 리터럴 0 — 글자 URL 범위의 증거).
6. **새로 세는 꼴**(실제 주소라 맞는 방향): 이어 쓴 리터럴(`"/api/" "other-api/1"`) · 이스케이프(`"\x2fapi\x2fother-api"`)는 2.26.1 이 줄 글자로 못 보고 새 판은 값으로 본다 — 2.26.1 에서 통과하던 deps 가 새로 멈출 수 있다(현장 꼴 0).
7. **다른 BC 설명 글 속 옛 주소** — 레인이 대상 API 주소를 바꾸는 V 를 승인받아도 다른 BC 의 docstring · 주석에 적힌 옛 주소는 이 레인의 «HTTP 소비자» 갈래가 아니라 고치지 않는다(실행 결과 무관 · 그 BC 몫).
8. **`else:` · `finally:` 블록 몸의 문자열 식 문장**은 지금처럼 센다(`_doc_ids` 는 `_scan` 과 같은 `.body` 규칙).
9. **2.26.1 부터의 한계 그대로** — `reverse` · 이어 붙인 URL(`+`) · 대상 밖 상수로 부르는 호출은 못 본다 · 마운트 접두는 결속하지 않는다.

## 진행 중 레인
- `dddjango/scripts/` 가 바뀌어 pre-gate 실행 트리 digest 가 바뀐다 → 진행 중 dddjango 레인은 설치본을 갱신하면 재예보(배포 보고에 적음).
- 설치본을 갱신한 G1 뒤 리팩토링 레인이 «다른 BC 편집 목록» 에 설명 글만 가진 파일을 «HTTP 소비자» 로 적어 두었으면 `changes` 가 «deps 출력과 다르다» 로 붉을 수 있다(그 줄을 빼거나 «다른 BC 몫» 으로).
- 띄운 판 그대로 끝까지 도는 레인은 그 판의 셈을 쓴다.
