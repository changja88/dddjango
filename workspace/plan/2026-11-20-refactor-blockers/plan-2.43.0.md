## 현장 보고

- **F4-190 · 192**(수리됨): 로그인 필요를 401 로 낼 승인된 길이 모자랐다 — 401 의 `WWW-Authenticate` 헤더를 붙일 꼴이 없고, 인증 틀을 지난 뒤 알게 된 인증 실패를 `raise AuthenticationError()` 로 다시 던지면 code-json 검사기가 #125 · 계약 줄 red. 이제 인증 실패는 Ninja 401(헤더 안 붙임 · 확립 계약이 challenge 를 요구하면 G1 멈춤) · 인증 틀 뒤 인증 실패 Exception · 검사기 `--auth-failure`.
- **F4-191**(수리됨): 스트리밍(`text/event-stream`) 응답의 설명서 규칙이 없어 JSON 용 «이름 + 판별 키» 규칙이 걸렸다 — OpenAPI 3.2 꼴 새 규칙(oneOf + event 고정값 · 판별 키 요구 없음) · JSON 판별 키는 JSON 에만.
- **F4-193**(수리됨): 중복 금지(«모아라»)와 유스케이스 공유 금지가 부딪혔다 — 유스케이스 사이 흐름 중복은 DRY 의무 밖(Exception) · 업무 판정은 도메인 한 곳.
- **F4-194 · 195**(수리됨): 동작 보존 장치가 시험 케이스 · 단언 든 도움 함수를 다른 파일로 옮기는 나누기 · 모으기를 삭제 · 추가로 잡았다 — G1 승인 retain «옮김» 행. 현장 재연 장난감: 옛 판 0T 나누기 red 5 · 모으기 red 4 → 옮김 행이 있으면 녹색.
- **F4-196**(수리됨): 본문이 같은 예외 여럿의 이름 바꾸기를 짝짓지 못해 이름만 따라 바꾼 시험 파일이 red — 이름 단서 짝. 현장 사본 재연 red 11 → 0.
- **F4-197 (+ 보류 F4-35 · 133 · 188)**(수리됨): 포트 자료의 도메인 값 객체 · enum 을 규칙(R-0589)은 허용하고 검사기(#228)는 막았다 — 검사기를 규칙에 맞춤. 현장 사본 #228 6 → 0.
- **F4-198**(수리됨): 200 스트림 설명서를 모듈 상수로 빼자 문서 검사기가 그 경로의 `openapi_extra` 를 통째로 못 읽었다 — 응답 보충을 status 칸마다 판정. 현장 사본 ⓓ 7 → 0 · 가림 ⓓ 7 → #63 3.
- 계획 확정 뒤 장부에 붙은 새 항목 F4-199 · F4-200 · F4-201 은 다음 판(도구 한계 둘 · 정본 결함 하나 — 이번 판이 고친 자리 밖).

  2. 옮김 행의 «묶임 맥락 같음» 을 픽스처 풀이 전이(`name=` · conftest 사슬 · 저장소 안 import · 별 import · `pytest_plugins` · `pytestmark` · `usefixtures`) · 모듈 수준 이름 전이 · 고쳐 쓰는 문장 대조까지(구현 검토 IT-B 차단 · 중요 — 실제 pytest 로 값이 바뀌는 꼴 열하나). 정적으로 다 볼 수 없으면 «모름» → 케이스 옮김은 파일 안 픽스처가 이름 · 원문 모두 같을 때만. 저장소 밖 `pytest_plugins` 는 설치 플러그인처럼 대조 밖(설계 §9.5 와 같게).
  3. 0F 허용 파일을 주는 `retain` 행(개명 행 · 칸 개명 행 포함)은 옮긴 뒤 경로로 적는다 — 글을 장치에 맞춰 좁힘(구현 검토 IP 차단). 옮긴 단위의 개명은 옮긴 뒤 창에서 새 경로 개명 행으로.
  4. `--auth-failure` 값은 slot 10 행 예외 칸의 정의 모듈 원 경로(설계자가 적고 조정자는 그대로 렌더 — IP · IT-C 중요).
  5. 2.42.0 이 연 창 기록을 2.43.0 으로 이어 닫을 때 새 칸(`retain_alias` · `moves`)을 빼고 대조(진행 중 실행 호환 · IT-B 차단).
  6. 같은 모듈 상수를 뒤에서 고치면 «못 읽음»(IT-C 사소) — 2.42.0 이 받던 «통째 상수 + 뒤 고침» 은 #63 · headers 상수 + 뒤 고침은 그 status ⓓ(옳은 쪽 판정 변화 · 현장 0건).
  7. 행 없는 같은 창 디렉터리 이동 + remove(키 옛 경로)는 옛 판 red → 새 판 녹색(IT-B S4 · 옳은 쪽 판정 변화 · 고치지 않음).
  8. `anchor_diff_smoke` 옛 판 `--help` 대조는 새 인자 칸만 뺀 글자로(검사기 무변).
  9. 새 보고 F4-199 · 200 · 201 은 다음 판.

## 교훈

1. 동작 보존 장치의 «같은 맥락» 판정은 정적 대조만으로는 구멍이 안 보인다 — 검토자가 실제 pytest 로 값 변화를 재는 하네스가 거짓 녹색 열하나를 잡았다. 장치 검토는 실제 실행 대조를 늘 붙인다.
2. 엄한 «모름» 은 안전하지만 흔한 꼴(`pytest_plugins` · 별 import · 두 파일 같은 맨 문장)에서 기능 목적을 꺾는다 — 거짓 red 도 흔한 꼴이면 중요로 다룬다.
3. 구현자의 러너 PASS 는 병합 전 브랜치(다른 단위의 rulepack 없음)에서 잰 것일 수 있다 — 합친 트리에서 커밋 전에 make verify 를 한 번 미리 돌리면 검토 밖 붉음을 일찍 잡는다.
4. 새 CLI 인자는 옛 판 `--help` 대조 시험을 붉힌다 — 검사기 인자를 더하는 설계는 그 시험을 계획에 적는다.
5. `git status` 의 `??` 는 새 폴더를 접어 보인다 — 새 픽스처는 파일 수로 센다.
6. 구현자 지시의 «신호 금지» 가 구현자 자신이 띄운 대기 루프까지 막는다 — 구현자 C 는 자기가 띄운 대기 루프 둘만(pid · 시작 시각 기록 · 앞뒤 프로세스 확인 · 다른 프로세스 0) 멈췄다. DEVELOPMENT §7.5 «직접 띄우고 기록한 것» 에는 맞으므로 다음 지시문은 그 조건을 그대로 적는다.
