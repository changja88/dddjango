# 수리 배치 2 — 절차·적대 리뷰 루브릭 (2026-09-03 사용자 합의)

## 절차 (6단계 + 종점)

1. **문제 검증 적대 리뷰** — 8건이 실측·재현 가능한 문제이며 처방 방향이 퀄리티 무손실인지 확인
2. 수정 계획(규모별 분할: 소규모 5건 1계획 · 대형 3건 각 별도)
3. **계획 적대 리뷰** — 심각도 + 3축(코퍼스 정합·일반화·무손실) 항목별 병기
4. 구현
5. **구현 적대 리뷰** — 계획대로인지 + 3축 재적용(구현 드리프트 검출)
6. 수정 → 릴리즈 → **실측 검증**(다음 실전 레인 ledger 판형)이 종점

결정 게이트: 각 적대 리뷰 결과는 10줄 이하 브리프로 상신, 사용자 확정 발화 후 다음 단계.

## 1단계 공격 질문 (항목마다 필답)

- ⓐ **실측 재현성** — 사례가 ≥2건인가, 결정적으로 재현되는가, 일회성/환경 우연은 아닌가. 표본 외(kkebi-server 등) 재현 여부.
- ⓑ **무손실 판정식** — 처방이 «진짜 위반 검출 집합»을 하나라도 줄이는가. 통과 조건: 잡음/오귀속/오차단만 제거, 진짜 검출·게이트 강도·STOP 권한은 불변. 반례(처방이 있었다면 놓쳤을 진짜 검출)를 능동 탐색.
- ⓒ **효과 과대 추정** — 근거 표본이 무엇이고 일반화가 성립하는가. 정량 추정의 산출 근거 재검.

## 3·5단계 3축 (항목마다 판정 병기)

- **코퍼스 정합** — 건드리는 규칙 ID 전부 열거(rulepack·ontology·references·검사기), 각각 충돌/중복/약화 없음 판정.
- **일반화(과적합 아님)** — 프로젝트 고유 관행(발주서 형식·herdr·STOP 규약)에 의존하지 않음. Claude/Codex 양 런타임 동일. kkebi-server 레인 ≥2건 대조 성립.
- **무손실** — ⓐ 검출 집합 단조성(소급 대조 진탐 ID 전부 유지·픽스처 red 유지) ⓑ 게이트 강도 불변(완화는 별도 결정 게이트) ⓒ 오차단 0(신규 검사는 무의존 명세 green 픽스처 필수).

## 심각도

BLOCKER(문제 불성립 또는 처방이 품질 훼손) · MAJOR(재현성/효과 근거 약함·수정 필요) · MINOR(표현·범위 조정) · 검증됨(반증 시도 후 성립).
