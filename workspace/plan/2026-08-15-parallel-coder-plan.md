## 1. 선행 트랙 B0 (리뷰 최상위 권고 — 사용자 결정 ①)

10th man·premortem·PRR·보드 자체 순위가 공명: 병렬화 이득 천장(라운드당 45~90분)보다 큰 풀이 둘 있고, 병렬은 이 둘의 부하를 **곱한다**(승인 표면 3배·재료 결함 다중 STOP).

- **B0-1 검사기 5종 수정**(개선 후보 ⑤ — G2 직접 계열 brownfield 계약): 재료 결함 축 봉쇄 = 병렬 실패 귀속의 교락 차단 전제. **별도 선행 릴리즈 권고**.
- **B0-2 승인 allowlist 정비**: 실측 왕복 ~45회 전부 read-only/허용 경로 — 정비 여지 실증. 병렬 시 승인 interleave 폭증(PR-4)의 선행 조건이기도 함.
- Phase A(읽기 전용)는 B0과 무관하게 즉시 가능.

## 2. 단계 구성

### Phase A — 소급 분석 (구현 0 · 중단 게이트 · 리뷰 G11 재설계)

- 입력: r2″ 레인 A 세션 기록 + git 이력 + **AST 참조 그래프**(`.venv/bin/python` 3.14 — import·심볼 참조. 편집 집합만으로는 참조 접촉면을 못 봐 배타율 과대평가).
- 절차: ① 공유층 후보(2개 이상 슬라이스가 참조하는 파일)를 먼저 wave 0으로 분리 ② **잔여분**의 배타율·슬라이스×파일 행렬(restricted 접촉률 열 포함) ③ wave 시뮬레이션(폭 3)에 **직렬 항 3종 차감** — wave 0 비중·합류 체인(merge+merged-state+감사+acceptance 슬라이스당 소요)·중재 대기 추정 ④ 산출: 실효 병렬 폭 기대값 + **비용 차감 후 단축 추정**(상한 아님).
- **중단 게이트(08-15 사용자 확정)**: 차감 후 **총 실행시간 단축 추정 < 30%** 또는 실효 폭 < 2 → 중단·축소 재설계. (참고: 리뷰의 Amdahl 추산 상한은 12~24% — 30% 문턱은 이 상한을 넘으므로, Phase A 실측이 30% 미만이면 병렬 단독으로는 불성립이라는 판정이 조기에 나온다. 이것이 이 게이트의 목적.)

**▶ Phase A 결과(08-15 실측 완료): 게이트 양 조건 모두 미달 — 중단 권고.**
- 방법: 세션 기록 255 edit 호출 귀속(하위 agent 20개·시간 창 불일치 0)+AST import 그래프(`.venv` 3.14)+wave 시뮬레이션 3패킹×중재 3시나리오.
- 편집 집합 공유는 12%(10/83 파일)지만 **참조 포함 시 58%(48/83)** — 편집 집합만 보면 배타율 과대평가라는 리뷰 G11 지적이 실측으로 확인됨.
- **실측 의존 = S1→S2→S3→S4→S5 완전 직렬**(r2″는 레이어 축 슬라이스 — domain→application→persistence→driving→admin 사슬이 슬라이스 축과 일치). 실효 폭 1.00, 최대 패킹(실측 의존 위반 가정)도 1.67 < 2.
- 총 단축 추정 최대 **+10.3%**(P3·중재 0회 낙관) ≪ 30%. 중재 2~5회 시나리오는 **역효과(총 시간 증가)** — S3가 S2 파일 4개를 직접 편집한 실측(retry 통합)상 중재 0회 가정은 비현실.
- 교차 삭제 2건 실증(후행 슬라이스가 선행 산출물 삭제·이전) — 병렬이면 merge conflict 재료.
- 유보: 유스케이스 축 재절단이면 다를 수 있으나 이 라운드 데이터로 검증 불가·공유 파일 wave 0 비대화 방향. 표본 N=1이나 products=최소 BC라 대형 BC에서 레이어 사슬 구조가 유지되는 한 개선 근거 없음.
- **귀결: 병렬 coder(2.10.0)는 게이트에서 중단. B-①(구조화 배차 명세·증거 장부 — 직렬 무해분)만 독립 가치로 후보 존치. B0(2.9.0=검사기 5종+승인 allowlist)는 이 판정과 무관하게 확정대로 진행.**

## 4. master coder 좌석 규율 (신설 — 리뷰 G3)

1. 원인 배정은 **증거 선행**: ①은 단독 재현 커맨드+exit, ②는 각자 green+조합 red 매트릭스 — 장부 기록 없이 선언 불가.
2. **③(계약·공유층=자기 산출물) 후보는 coordinator 직행**(자기 사건 자기 판정 금지). «양쪽 다 계약대로» 신호 1개라도 있으면 ③ 후보.
3. 수리·재배차 시도 상한 2회 → coordinator 상소 → 정박 소진 시 STOP(현행 규율 접속).
4. 전 커밋에 사유 라벨(merge/②수리/③수리/중복통합/migrations) — 장부 대조 가능. 전부 경량 감사 대상.
5. 합류 중 판단 불가 coder분은 **defer**(격리 보존·잔여 merge 속행) — 전체 정지 최소화.
6. 중복 통합(§7.5)은 판정 기록 의무: 두 구현의 동작 차 유무+차이 시 spec 인용 정본 선정. 차이를 핀하는 테스트가 없으면 coordinator 격상+핀 테스트 추가 후 통합. 승격은 G1 공용 재료 절 또는 G1′ 경유만(감사 문면 정합 — C2②).
7. coordinator의 wave별 배정 분포(①:②:③:④) 검토 — ② 비율 이상치=자동 상소(RT-1).
