# dddjango 2.30.1 — 쓰기 울타리 임시 폴더를 쓰고 나면 지운다

상태: 계획 사용자 승인(«진행») 뒤 구현 · 운영자 확인에서 찾음(사용자의 «시험 뒤 자원 반환» 확인 요청 · 현장 보고 장부 번호 없음) · 장부 다시 읽음 2026-10-30 17:00(마지막 F4-129 · 장부 바뀐 시각 14:27 — 새 항목 없음).

## 문제

- 조정자 «쓰기 울타리»(`dddjango/commands/dddjango.md` «산출물 위치» 절 — 그래프 정본 `ontology/rules/command-dddjango.ttl` 의 코드 블록 `s002/b12` · 규범 블록 `s002/b13` = R-3599)는 울타리 대상 역할(리뷰어 넷 · acceptance-tester `PHASE1_ARRANGE_CHECK`)을 부를 때마다 임시 폴더 두 종류를 `$TMPDIR` 에 만든다.
  - 울타리 폴더 `<폴더명>-fence-XXXXXX` — 객체(`objs/`) · 스냅숏마다 작업 트리 인덱스 사본(`idx-$$`) · 덧붙이기 대조 사본 · 창 안 명령 출력.
  - 역할 스크래치 `<폴더명>-<역할|lens>-XXXXXX` — 역할마다 하나.
- 두 폴더 모두 지우라는 말이 없다. Codex 조정자(`codex-dddjango/skills/dddjango/SKILL.md`)도 같다.

재현 표

| 재현 | 조건 | 생기면 | 누가 찾았나 | 운영자가 본 정도 |
|---|---|---|---|---|
| 재현됨 — 배포판 2.30.0 글에 지우는 말 없음(`git show dddjango--v2.30.0:dddjango/commands/dddjango.md`) | 울타리 창 하나마다 | 창마다 10~20MB(인덱스 사본 하나 약 10MB × before · after) + 빈 역할 폴더 3~5개가 재부팅 때까지 남는다 | 운영자(자원 반환 확인) | 실제 작업에서 본 것 — 2026-10-30 실레인 두 곳의 흔적: 울타리 폴더 6개 113.8MB 중 인덱스 사본 11개가 112.5MB(99%) · 역할 폴더 29개(열어 본 것은 모두 빔) |

- macOS 는 `$TMPDIR` 를 재부팅 때 비운다(오늘 13시 재부팅 앞 항목 0). 그 전까지는 레인이 도는 내내 쌓인다.
- 자매 확인: dddjango-web 조정자에는 울타리 장치가 없다(해당 없음).

## 고침 (그래프 정본 → 렌더 → Codex 같은 뜻)

1. **코드 블록 `b12`**(규범 없는 코드 블록 — 글만 고침): before · after 스냅숏 명령이 트리를 쓴 뒤 인덱스 사본을 바로 지운다 — `sh -c '… git write-tree'; rc=$?; rm "$idx" </dev/null; [ "$rc" = 0 ] || exit 1`. 트리는 `objs/` 에 남으므로 대조 · 덧붙이기 대조는 그대로다. 창 도중에 세션이 끊겨 폴더가 남아도 1MB 아래로 줄어든다.
2. **규범 블록 `b13`**(R-3599 개정 2 · amendment):
   - 지우는 때 — 울타리 창을 닫아 대조를 끝냈고 이 창에서 띄운 백그라운드 작업(pre-gate 등)이 끝나 그 출력을 읽고 옮길 것(`group-moves.txt` 등)을 옮겼으면. before 스냅숏을 못 떠 호출하지 않은 창의 폴더도 지운다.
   - 지우는 꼴 — 창을 열 때 적어 둔 경로 그대로 `rm -r -- "<경로>" </dev/null`. 힘 옵션 `-f` 는 쓰지 않는다(런타임이 거부하거나 확인 창을 띄운다) · `</dev/null` 은 꼭 둔다(git 객체가 읽기 전용이라 터미널이 붙으면 파일마다 묻는다) · 이름 무늬로 찾아 지우지 않는다(같은 폴더명을 쓰는 병렬 세션) · 역할 입력에 울타리 폴더 경로를 넘기지 않는다.
   - 붙이는 자리 — 지우기만 하려고 셸을 따로 부르지 않고 그 뒤에 도는 셸 명령 **앞에** `rm … ;` 로 붙인다(뒤에 붙이면 그 명령의 exit 을 가린다 · 뒤 명령이 없으면 따로 한 번).
   - 허용 밖으로 멈춘 창 — 이 폴더들은 증거라 남기고 STOP 기록에 경로들을 적은 뒤, 사용자의 답에 따른 조치가 끝나면 지운다.
   - 맞물린 고침 — 역할 스크래치는 창을 열 때 만들어 경로를 적어 둔다 · 이어 부르기도 새 창이라 새 스크래치를 다시 준다(앞 창의 것은 지워졌다) · 배너의 `울타리 차이` 수는 창을 닫을 때 한 줄 상태에 남긴다(지운 뒤에는 대조를 다시 돌릴 수 없다).
   - R-3599 prefLabel 에 요지를 더한다.
3. **Codex 조정자** 같은 자리를 같은 뜻으로(런타임 낱말만 다르다 — «다발과 겹쳐 돌린 작업» · «같은 스레드 followup»).
4. 검사기 · 에이전트 · 스킬은 바꾸지 않는다.

## 되돌아옴 막기

- `Makefile` `verify-base-core` 계약 줄(Claude · Codex 조정자 둘 다): 스냅숏의 `rm "$idx" </dev/null` · 지우기 문장 · 붙이는 자리 문장 · 허용 밖 문장이 있고, rm 힘 옵션이 없다. 배포판 글에 대면 붉음 · 힘 옵션 변형(`rm -r -f` · `rm -Rf` · `rm --force` · `rm -v -f` · `rm -rf` · `rm -fr`)을 넣으면 붉음을 확인했다.

## 행동 시험

- **코드 블록**(인덱스 1.6MB · 파일 2만 개 장난감 저장소 · 옛 2.30.0 명령과 새 명령을 같은 상태에서): 1행 트리 SHA · 2행 상태 줄 · 대조 출력(`A` · `M`) · 덧붙이기 대조 exit 이 두 판 같다. 남은 인덱스 사본은 옛 판 2개 · 새 판 0개. 트리 쓰기가 실패할 때도 exit 1 이 같고 새 판은 사본이 남지 않는다. `/bin/sh` · `/bin/bash` · `/bin/zsh` 모두 같다.
- **규범 문장**(맥락 없는 새 세션 · 규칙 발췌만 · 같은 장면):
  - 옛 글 — 폴더를 지우지 않는다(«규칙에 정리 단계가 없다»).
  - 새 글 첫 판 — 적어 둔 경로 셋을 지우고 허용 밖 장면에서는 남겨 STOP 기록에 적는다. 다만 지우기를 다음 명령 뒤에 붙였고(`openssl …; rm …`) «두 폴더» 에서 망설였다 → 글을 고침.
  - 새 글 최종 판(다음 명령을 exit 이 곧 판정인 `--check-report` 로 둔 장면) — `rm -r -- … </dev/null ; python3 … --check-report` 로 앞에 붙인다. 이어 부르기에는 새 창 · 새 스크래치를 주고 울타리 폴더 경로는 주지 않는다. 허용 밖 뒤 «되돌려» 답을 받으면 before 트리로 되돌리는 조치를 끝낸 뒤 지운다.
  - 세션이 망설인 나머지 둘(무효가 된 부속 기록을 치우는 법 · `울타리 차이` 의 k 에 `pregate-report.md` 를 세는지)은 원래 글의 빈자리라 이번 범위 밖이다.

## 독립 검토 반영(차단 1 · 중요 1 · 사소 5 → 좁은 재확인 7건 모두 닫힘 · 새 사소 2)

- 차단 1 받음: Codex 는 `rm` 에 힘 옵션이 있으면 스크립트 어디에 있든 위험 명령으로 분류한다 — 승인 정책 `never` 면 거부(스냅숏이 거부되면 첫 울타리 창에서 레인이 선다) · 그 밖이면 승인 창. 운영자 재현: 설치본 0.165.0 바이너리에 거부 문구가 있다. 분류 규칙은 검토자가 같은 판 소스(`is_dangerous_command.rs` · `exec_policy.rs`)로 읽었다 — Codex 실행 결과는 아니다. 힘 옵션을 빼고 `</dev/null` 을 둔다(운영자 재현: 읽기 전용 객체 폴더가 `</dev/null` 이면 지워지고 터미널이 붙으면 묻다가 남는다).
- 중요 1 받음: 계획의 «앞에 붙인다» 가 글에서 빠졌다 — 뒤에 `; rm` 으로 붙이면 판정 명령의 붉음이 0 으로 가려진다(운영자 재현: exit 2 → 0). 글 · 계약 줄에 넣음.
- 사소 받음: 3 출력을 옮긴 뒤 지움 · 역할 입력에 울타리 폴더 경로 금지 · 4 `울타리 차이` 수를 먼저 남김 · 5 이어 부르기에 새 스크래치 · 6 답에 따른 조치 뒤 지움 · 7 호출하지 않은 창도 지움.
- 사소 7 뒷부분은 고치지 않고 아래 «한계» 로 받음.
- 재확인 새 사소 받음: A 이 기록 · LEDGER 메모를 지금 글에 맞춤 · B 계약 줄의 힘 옵션 무늬를 변형까지 넓힘.

## 판 · 문서

- 사용자에게 보이는 동작 변화 없음 — README · master 문서는 고치지 않는다(core 패치 선례 2.27.5 와 같음). 요청 가이드는 확인해 보고에 적는다.

## 한계

- 창 도중 세션이 끊기면 폴더가 남는다 — 인덱스 사본을 바로 지워 1MB 아래 · 재부팅 때 OS 가 지운다. 이름 무늬로 쓸어 지우는 장치는 두지 않는다(병렬 세션의 폴더를 지울 위험).
- 지우기는 조정자 글 규칙이라 검사기가 집행하지 않는다(읽어야 보이는 규칙).
- 지우라는 말이 닿지 않는 작은 임시물 둘은 받아들인다(KB 단위 · 재부팅 때 사라짐): 재리뷰 전 `mktemp` 로 떠 둔 명세 사본 · 창 밖 백그라운드 출력(`$TMPDIR`).
- 성능 · 시간: 지우기 실측 — 인덱스 사본 하나 0.1ms · 울타리 폴더째 6ms(실레인 폴더 사본 20MB). 조정자 글은 255KB 에 1KB 남짓 는다.
- 권한: Codex 쪽 판단은 소스 읽기다(Codex 실행 시험 없음 · 실레인 승인 정책 미확인). Claude 쪽은 이 컴퓨터의 기본 권한 모드가 auto 라 검토 세션에서 막히지 않은 것까지 봤고 실레인에서 재지는 않았다 — 확인 창이 뜨면 레인이 그 자리에서 기다린다. 배포 뒤 첫 실레인에서 보고, 뜨면 다음 판에서 폴더 지우기를 걷고 스냅숏 안 인덱스 사본 지우기(용량의 99%)만 남긴다.

## 멈출 기준

- 코드 블록 시험에서 대조 출력이 옛 판과 다르면 멈춘다.
- 행동 시험에서 새 글도 지우지 않으면 글을 다시 쓰고, 두 번째도 같으면 멈추고 묻는다.
