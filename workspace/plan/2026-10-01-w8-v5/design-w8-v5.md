# dddjango-web W8 v5 설계 — 요소별 정확값 입력과 G2 전 시안 대조

작성일: 2026-10-01  
대상: dddjango-web v1.2.0, 현재 워크트리 HEAD 78a731bdc3cc  
성격: 설계안. 아래 파일·명령·스키마는 후속 구현의 계약이며 이미 배포된 기능을 뜻하지 않는다.

## 1. 결론 — 8줄

1. G0에서 시안의 요소별 계산값과 부모·자식 관계를 기록하고, G1에서 그 요소를 토큰·부품 variant·구현 파일에 연결한다.
2. G2 전 W8은 그 원본 측정값을 그대로 기대값으로 쓴다. 구현에 맞춰 기대값을 다시 쓰지 않는다.
3. 핵심은 숫자 복사보다 연결 보존이다. P1 실제 차이 35묶음의 최초 연결 손실은 명세 34, 코드 1이었다.
4. foundation 토큰만·근접 토큰 금지·공용 부품 재사용 규칙을 유지하고, 실제 렌더 계약으로 이행을 확인한다.
5. 경고 먼저라는 결정을 v4.1의 봉인된 재생 그림자로 실현한다. 진행 레인은 그대로 두고 새 G0 레인부터 입력 표를 도입한다.
6. 같은 도구 판의 그림자 레인 두 개가 관문을 통과해야 차단으로 전환한다. 반송 재관찰 축소는 별도 관문을 통과한 뒤다.
7. 육안 대조·독립 시각 감사·기존 검사·사용자 G2를 유지한다. 새로 확인한 실제 결함은 배포 전에 해소한다.
8. 속도 절감은 아직 확정하지 않는다. v4.1의 −75/−70분은 발주자 확인 축소까지 포함한 조건부 추정이며 입력 표의 효과는 따로 잰다.

## 2. 쉬운 말 요약

1. **부품마다 조립 설명을 붙인다.** “유리판”이라고만 적지 않고 “모서리 26px, 그림자 2단계, 윤광 자식 있음, 이 상태에서는 불투명 바탕”을 함께 남긴다.
2. **위치 숫자만 베끼지 않는다.** “버튼 y=768” 대신 본문과 하단 버튼이 형제이고 본문이 남는 높이를 차지한다는 원본 관계를 기록한다.
3. **기존 부품도 실제 모양을 확인한다.** 이름이 같은 GlassPanel이어도 34px 모서리·윤광 없음이면 그대로 재사용할 수 없다. 필요한 정확 토큰과 변형을 설계에 연결한다.
4. **같은 자로 결과를 다시 잰다.** 원본 표의 요소와 구현을 짝지어 배경·선·그림자·글자·아이콘·틈을 비교한다. 데이터 차이와 도구 오류도 따로 가른다.
5. **처음에는 결과가 현장 반송에 끼어들지 않는다.** 평가자가 결과를 먼저 봉인하고 기존 검증자의 판단 뒤 대조한다. 진행 레인의 명세·데이터·설치본은 바꾸지 않는다.
6. **믿을 만한 증거를 쌓은 뒤 막는다.** 실제 결함 놓침, 오탐, 잘못된 제외, 데이터 차이 해소, 비용을 함께 검증한다. 조건을 못 채우면 경고 상태를 유지한다.
7. **눈으로 보는 검사는 남는다.** 영상 내용·실제 데이터 표기·모션·흐림 뒤 장식·데스크톱 등 기계가 완전히 판정하지 못하는 범위를 숨기지 않는다.
8. **첫 제출부터 끝 승인까지 빨라져야 개선이다.** G2 시간을 G0의 표 작성 시간으로 옮긴 것만으로 절감이라고 하지 않는다.

## 3. 설계 본문

### 3.0. 기준과 확인한 사실

최신 결정인 “web 배포 뒤 바로 W8 + 입력 표, K1~K3보다 먼저”를 따른다. [동결 W8](../2026-09-30-speed-improvement/design-W8.md)의 이전 보류 결정과 [초기 로드맵](../2026-09-30-speed-improvement/roadmap-v1.md)의 순서는 대체하되, v4.1의 측정과 품질 관문은 유지한다.

| 접근 | 장점 | 부족한 점 | 선택 |
|---|---|---|---|
| 출력 대조만 추가 | 구현 후 누락을 드러낸 실측이 있음 | 처음 잘못 만드는 정보 손실이 남음 | 단독 채택하지 않음 |
| 토큰 표만 상세화 | 기존 절차와 가까움 | 토큰이 있어도 잘못된 요소·variant에 붙임 | 단독 채택하지 않음 |
| 요소별 입력 + 같은 측정의 출력 대조 | 필요한 정보와 실제 이행 확인이 연결됨 | 수집·매핑·오탐 처분 비용 증가 | **v5 채택** |

[충실도 실험 §4](../2026-09-30-speed-improvement/exp-fidelity-p1-report.md)의 요소별 적용 계약·부모 배치·렌더 계약 재사용·과거 매핑 소비처 확인·출력 전수 대조를 모두 반영한다. 현행 규범도 이미 이 방향을 요구한다. 이번 변경은 빈 연결을 드러내고 검사 지점을 구체화하는 일이다. React/Tailwind 도입이나 Django/HTMX 책임 변경은 포함하지 않는다.

**이번 읽기 전용 재생 [실측]:** scratch의 v4 대조기를 메모리에 읽어 compare_case/group만 호출했다. 파일을 쓰는 run 함수, 서버·DB·브라우저·네트워크는 사용하지 않았다. 구형 보관 자료라 재생에만 W8_ALLOW_LEGACY=1과 기존 선언 모드를 적용했다. 제품 게이트 통과 증거는 아니다.

| 보관 제출 | case | 전체 묶음 | 차단 묶음 / 구성원 |
|---|---:|---:|---:|
| P1 G2#1, 507c12cc3 | 5 | 122 | 84 / 346 |
| P1 G2#2, 44cfb2a14 | 5 | 91 | 49 / 216 |
| P1 끝, ab97d0964 | 5 | 60 | 31 / 114 |
| P2 반송2 직전, 423693212 | 10 | 104 | 56 / 110 |
| P2 반송3 직전, 4f0df1761 | 10 | 67 | 28 / 46 |
| P2 끝, 834dfe97a | 10 | 63 | 24 / 42 |

P1 첫 제출의 독립 라벨 T35·D35·F8·H6을 결과 ID에 연결했고 **T35/35가 차단**임을 재확인했다. 저장 JSON SHA-256은 ba23e8f5f106a8ac799015df5589328849a0fade1376e46f41ebca958bc667c6이다. 대조기와 라벨은 frozen-v4 사본과 byte 동일했다.

재생에서 보고서 결정성의 한계도 확인했다. P2 끝 판을 PYTHONHASHSEED=0·1·2·3으로 실행하면 묶음 ID·차단 24/42는 같지만 e2e120afd2의 examples 순서가 달랐다. 다른 재생에서는 묶음 배열 순서도 동일성 검사에 영향을 주었다. v5는 짝짓기 동점 처리·묶음 정렬·표본 선택 전 구성원 정렬을 결정적으로 만들고 시험한다. v4.1의 수집물 결정성을 최종 보고서의 byte 동일성으로 확대하지 않는다.

### 3.1. 입력 쪽 요소별 정확값 표 — G0/G1

#### 3.1.1. 원본 사실과 구현 결정의 소유

원본 소스와 실제 렌더가 외형 정본이다. 입력 표는 출처 있는 관찰 기록이며 새로운 디자인 정본이 아니다.

| 산출물 | 작성 소유 | 내용 |
|---|---|---|
| style-scope.json | Coordinator, 독립 입력범위 검토 뒤 동결 | case·프레임·제외 근거·데이터/시각·최소 높이·SDK 기대·재렌더 대응표 |
| style-census/<case_id>.design.json.gz | Coordinator가 스니펫으로 생성 | 원본 측정 원문·요소/층/부모 관계·환경·완결성 |
| style-reference.json | 도구 생성, Coordinator가 원본 출처 연결 관리 | **요소별 정확값 표**: 원문 참조·행 ID·값·관계·원본 토큰/부품 인자·측정/소스 확인/미확인 |
| design-spec.md 안 요소 적용 결속 블록 | architect만 작성 | 원본 행 ID → 목적 파일·토큰/조합·variant·자식 효과·배치 관계·이탈 |
| style-census/<case_id>.impl.json.gz 및 data-snapshot/<case_id>.json | Coordinator, coder는 허용된 관찰 결과 반환 | 구현 측정과 그 화면을 실제로 만든 데이터 |
| style-compare.json/.md 및 style-dispositions.json | 도구 / Coordinator | 전체 대조·구성원별 처분·재검증 근거 |
| style-impact.json | 도구 생성, 독립 감사 확인 | 반송 시 재관찰·재사용 case와 근거 |

정확값을 명세에 사람이 다시 입력하지 않는다. 명세는 reference digest와 행 ID를 인용한다. 사람이 읽는 표도 같은 JSON에서 출력한다. 기존 visual-check/명세에 그 인용을 연결하며 별도의 수기 값 표를 중복 관리하지 않는다.

G1 결속은 기존 시각 연결표에 대응하는 **같은 명세 안의 기계가독 블록**이다. architect에게 별도 evidence JSON 쓰기 권한을 주지 않는다. 필수 필드는 reference_digest, row_ids, source_refs, target_files, token_bindings, component_contract, effects, layout_refs, deviation_id다. 동일 부품·variant·상태는 정의를 공유하되 적용 row_ids를 전개해 빈 인스턴스가 없게 한다. 무제한 와일드카드 “전부 채택”은 허용하지 않는다.

원본 사실과 G1 매핑을 각각 동결한다. G2 기대값은 G0 사실에서 읽는다. G1의 잘못된 토큰 선택이나 구현값으로 원본 기대값을 덮어쓰지 않는다.

#### 3.1.2. 수집 대상과 v4 대비 필요한 보강

수집기는 style_census_dv4.js를 출발점으로 **census_version=5**로 올린다. v4는 페인트 조상을 기록하지만 투명 flex 부모의 배치 계약 전체는 없으며 일부 문자열·좌표를 축약한다. 구형 자료를 이름만 바꿔 v5로 인정하지 않는다.

| 분류 | 필수 사실 | 주의 |
|---|---|---|
| 정체 | case·상태·프레임·node_id·종류·원본 위치·부품 인스턴스 | 클래스 앞부분·문구만을 유일 ID로 쓰지 않음 |
| 칠·효과 | 배경/gradient 전체, 4면 테두리, 반경, 모든 shadow 층, opacity, filter/backdrop-filter, blend·clip·transform | 층 순서와 소유 부모 보존 |
| 글자·아이콘 | 글꼴 실제 적용 근거, family/size/weight/line-height/letter-spacing/color, 정렬·줄바꿈·clip, 아이콘 크기 | 선언된 글꼴과 로드 성공 구분 |
| 치수·틈 | rect, padding/margin, row/column gap, 앞 형제 간격, min/max width/height | rect는 관찰 결과. 고정 CSS 값으로 자동 채택하지 않음 |
| 배치 | 부모·앞 형제·칠한 부모, display, flex 방향/grow/shrink/basis, justify/align, grid, overflow, position·앵커·scroll owner | 투명 wrapper와 root도 필요 |
| 자식 효과 | 자식/가상 요소 ID·칠·opacity·clip·쌓임·소속 프레임 | sheen/aura/divider를 토큰 목록으로 대신하지 않음 |
| 환경·자원 | 전체 URL과 byte digest 또는 unreadable, browser/DPR/viewport/root/scroll, SDK·폰트·안정 상태 | basename 충돌·다른 환경을 동일시하지 않음 |

범위는 “요구 상태에서 보이는 모든 요소 + 그 배치를 설명하는 조상”이다. root의 칠도 수록한다. 숨김 요소를 무조건 구현 대상으로 바꾸지 않으며, 가림·흐림·미관찰은 구분한다.

비교용 정규화 뷰와 별도로 **선정 속성의 원문은 자르지 않고 저장**한다. 기존 gradient 300자/가상 요소 160자 자르기, URL basename 변환, 문구 40자 요약은 원본 표에 적용하지 않는다. 요약 표시만 줄인다. 제한을 넘으면 부분 수집이며 성공이 아니다. 다중 그림자와 효과 순서를 같은 집합으로 축약하지 않는다.

200개 상한은 없다. 기존 캡처의 page.evaluate에 동기 스니펫을 추가하며 새 서버·실행기·영구 관찰 엔진은 만들지 않는다. 기본 5초 예산은 탐색·가림 판정 모두에 적용한다. 쪽 나눔은 전체 수·모든 페이지·snapshot ID·공통 내용 digest가 맞아야 하며 페이지 사이 DOM/값이 달라지면 재수집한다. lazy-load·내부 스크롤로 미생성된 영역을 완전 수집으로 세지 않는다. 기존 상태 도달·스크롤 관찰로 보완하거나 사람 확인 범위에 남긴다.

#### 3.1.3. 값에서 자동 추론하지 않을 것

getComputedStyle은 최종값을 주지만 token 이름·variant 기본값·JSX 호출 출처까지 알려주지 않는다. 같은 값의 토큰 검색은 후보일 뿐 자동 확정이 아니다.

Coordinator는 G0에서 호출 위치·부품 정의·토큰 CSS·인라인 선언·렌더 상태를 source_refs로 연결한다. 도구는 DOM locator와 읽을 수 있는 선언/custom property의 후보를 제공한다. 동적 번들·기본 인자·CSSOM 제한은 원본을 직접 읽어 보완한다. 미확인 필드는 unknown과 이유로 남긴다. 파일/행에 archive digest·심볼/선언 앵커를 함께 붙여 버전 연결을 보존한다.

입력범위 리뷰는 실제 요구 상태에 그 요소가 쓰였는지 확인한다. architect는 G1에서 호출부와 정의를 직접 읽어 variant·기본값·자식·부모 연결을 완성하고 구현 매핑을 결정한다. 추측으로 채운 연결은 완료로 보지 않는다. 새 case/필수 원본 부족은 기존 입력 보완 경로로 반환한다.

이미지 단독 입력에는 computed 값을 발명하지 않는다. 이미지 영역·측정/추정·확신을 구별하고 DOM 대조는 비적용 사유를 적는다. 자체 설계도 원본 census 비적용이다. 정상 이미지 입력을 DOM이 없다는 이유로 막지 않으며 기존 육안·독립 감사가 남는다.

#### 3.1.4. 실제 행에 남길 내용

행 ID는 reference 한 판 안의 case/node_id/층을 식별하고 값과는 분리한다. 재동결 시 새 digest를 만들어 과거 행 인용·처분이 무효가 되게 한다.

아래는 P1 실험에서 확인된 예다. 실제 표에는 원문·출처·전 인스턴스 ID를 넣는다.

| 대상 | 정확값/선언 | 보존할 연결 | 구현 결정 |
|---|---|---|---|
| GlassPanel | radius 26px, elevation=2, sheen 기본 true | 본체와 윤광 자식을 별도 행으로 연결 | radius-card, shadow-2+glass-edge, 윤광 opacity까지 |
| empty/info 패널 | solid, #fffdf9ff, 1px #1f1c181a | strong과 다른 variant | 이름이 아닌 해당 렌더 계약 |
| 정보 요약판 | padding 4px 14px | 세 ListRow 모두 divider, 편집 행 padding 6px 0 4px | 높이 262px 고정 대신 구성 복원 |
| empty/info 본문 | flex:1, min-height:0, column, center, gap 20px | 여유 높이 소유자, 스크롤 본문과 footer의 형제 관계 | 원본 관계를 화면 CSS/토큰에 연결 |
| 정보 고치기 | 아이콘 15px | 편집 행 justify-content:flex-end | 아이콘과 부모 정렬 각각 연결 |
| 원국 세우기 | lg 아이콘 20px, gap 10px | 아이콘·텍스트가 같은 버튼의 형제 | 모든 적용 상태에 같은 lg 계약 |
| Badge soft | jade 녹색 14%, neutral 먹색 6% | tone+variant와 배경 결속 | 토큰 없으면 정확값 신규 등록 |
| AppFrame aura | 네 blob의 색·크기·위치 | 뒤 설정/앞 chart 프레임의 소유 분리 | 누락된 앞 자식 복원, “A ; A”를 CSS로 복사하지 않음 |

값의 전수 기록은 도구가 맡고 명세는 실제 부품·variant·상태 조합별로 읽게 한다. 모든 CSS 속성의 수기 행이나 미사용 토큰 전량 소비는 요구하지 않는다.

#### 3.1.5. 단계별 실행 계약

1. **G0 Coordinator:** 기존 원본 archive·design-input·캡처를 성립시킨 뒤 W2의 제품 모드/앱 경계를 소비해 scope를 만든다. 같은 상태에서 census/reference를 생성한다. 기존 render_audit의 texts/pinned·모션 관찰은 유지한다.
2. **G0 독립 리뷰:** case 양방향 전수성·root 하나·제외 근거·상태/데이터/폰트·출처·미측정 범위를 확인한다. 기존 reviewed-input과 별개로 reviewed-style-input digest를 같은 반환에 더한다. check_design_evidence의 digest 의미는 바꾸지 않는다.
3. **G1 architect:** 원본 ID를 시각 연결표와 결속 블록에 연결한다. 토큰·복합식·variant·자식·부모 관계·목적 파일을 정한다. 과거 “신규 토큰 0”, “부재→sunken”, “윤광 제외”의 코드 주석·선택자·참조 소비처를 확인해 변경 파일에 연결한다.
4. **G1 도구:** raw→reference 누락/중복 0, 필수 행의 적용/허용 이탈/미측정 기록, ID·parent/effect·digest·목적 파일을 검사한다. 측정값 변조·unknown의 확정 위장·통째 제외를 거절한다. 기존 토큰/모션/identity 검사는 따로 유지한다.
5. **G1 독립 리뷰:** 원본 호출·정의의 의미와 재사용 계약을 확인한다. 같은 이름·같은 색 후보라는 이유만으로 고른 매핑은 반송한다. 원본 수집 오류와 적용 매핑 오류를 갈라 소유자에게 반환한다.
6. **coder:** 해당 row_ids와 원본 정의를 직접 확인하고 토큰/조합·자식·부모 관계를 구현한다. 보고는 행 ID→실제 파일/선택자/토큰→적용 결과다. 범위 밖 파일이 필요하면 소유 슬라이스 재개를 요청하고 효과를 생략하지 않는다.
7. **Coordinator:** 실제 locator를 짝짓기 단서로 기록하되 그 자기신고만으로 통과시키지 않는다. 같은 원본 측정과 실제 구현을 W8으로 다시 잰다.

새 시험 레인에서 G0/G1 표를 완성하지 못하면 그 단계에서 해결하고 비용을 기록한다. **경고는 출력 차이의 자동 차단 유예**이며 깨진 원본 연결을 정확한 입력으로 승인하는 뜻이 아니다.

#### 3.1.6. 기존 규칙과의 충돌 해소

| 접점 | 해소안 |

| foundation 토큰만 vs 표의 px | 숫자는 원본 관찰 근거. 제품 CSS는 정확 토큰으로 연결한다. 배치 키워드와 관찰 rect까지 고정 숫자 토큰으로 만들지 않음 |
| 근접 토큰 금지 vs 허용 오차 | 구현 목표는 정확값. 측정 오차는 근접 토큰 선택 허가가 아님 |
| component 재사용 우선 | tone/size/elevation/default·자식·상태 외형을 실사해 재사용. 같은 외형을 중복 구현하지도, 다른 외형을 같은 이름으로 덮지도 않음 |

| 산문 레이아웃 금지 | 출처 있는 원본 부모/형제/배치 선언의 참조는 허용된 대응 좌표의 구체화. 새 형상 발명은 금지. architecture-web §1·§8/역할 문면에 명시 |
| 모든 CSS 속성 개별 행 불요 | 사람이 전사하지 않는 원칙 유지. 선정 축의 기계 전수 기록과 조합별 매핑을 추가한다고 implementation-ui §2 명시 |
| 기존 토큰/render-audit 표 | 기존 형식·검사를 유지하고 같은 원본 ID로 연결. 새 표로 old gate를 우회하지 않음 |
| 커스텀 컴포넌트 정체 | 외형이 같아도 native 평탄화 금지. 기존 identity 검사 유지 |

### 3.2. W8 G2 전 대조 — 입력 표가 기대값

#### 3.2.1. 하나의 측정·정규화·짝짓기

    동결 시안/원본 렌더 → census v5 → 원본 reference
       → G1 적용 결속 → 구현 census v5 → 동일 정규화/짝짓기
       → 차이·미대조·미실행·사람 확인 → 수리/처분
       → 독립 시각 감사·기존 백스톱·G2

reference와 구현에 같은 정규화 함수를 적용한다. 입력 생성기와 대조기가 각각 색/반경/그림자 동등성을 정의하지 않는다. 원문은 유지하고 비교 뷰만 파생한다. 승인 이탈도 원본 값을 고치는 대신 해당 행·case·속성에 결속된 처분으로 적용한다.

v4의 페인트 영역·글리프·아이콘·앞 형제 간격 대조를 유지한다. v5의 node_id·owner frame·부모 관계는 발견을 원본 표로 되돌리는 좌표다. React와 Django의 DOM 경로가 같아야 한다고 강제하지 않는다. 투명 wrapper의 display 차이만으로 시각 차이를 차단하지 않는다. 배치 의미는 설계에서 보존하고 결과·스크롤 거동은 렌더로 검증한다.

짝짓기는 프레임/영역 경계 → 명시 대응 단서 검증 → 공통 구역 안 라벨 → 짝지어진 부모 안 상대 위치 → 같은 자리/쌍둥이 후보 순서다. v4의 같은 자리 ±6px, 공통 절 머리 사이 교차 금지, 글리프 정규화를 출발점으로 한다. 대응 locator는 해당 상태에서 유일한지 검사한다. 이름·값이 같다는 이유로 다른 구역의 요소를 끌어오지 않는다.

동점 후보가 남으면 임의로 통과시키지 않고 ambiguous-pair로 원본/구현 요소와 캡처를 보여준다. 대응 ID 누락은 면제가 아니며 누락 효과도 missing/extra 검사 대상이다. 경계/owner 보강으로 바뀌는 짝짓기는 보관 회귀와 새 결함 시험으로 검증한다.

#### 3.2.2. 차단 기준

v4.1 기준을 좁히지 않는다. 다음 수치는 출발점이며 v5 재리허설 전 성능 보증이 아니다.

| 항목 | 기본 기준 |
|---|---|
| 색 | alpha를 곱한 채널 차이 ≤2/255. v4 코드의 alpha 차이 ≤3/255도 명시·시험 |
| px / 기하 | 각각 ±0.5px / ±1px |
| opacity | v4의 ±0.02를 명시·시험. 원문과 조상/자식 합성은 보존 |
| 알약 | 짧은 변 절반 이상인 양의 반경 정규화. 0 반경은 알약 아님 |
| 배경·선·반경·shadow·blur·글자 등 모양 | 오차 밖 차이는 차단 후보. 데이터 선언/낮은 글 일치율만으로 풀지 않음 |
| 세로 틈·첫 자식 inset | 대조 case에서 차단 |
| 가로 틈 | 인접 ≤40px 또는 내용 동일이면 차단 |
| 크기·있음/없음 | 내용 동일이면 차단. 내용이 달라 불확실하면 사람 확인 |
| 미작동 min/max·정렬·줄바꿈 | 잠재 차이로 보고. 요구 경계 상태에서 실제 차이가 나면 차단 |
| 흐림 뒤 작은 요소·무한 애니메이션의 기하/opacity/transform·unreadable·영상/canvas 내용 | 사람 확인. 기계 통과를 전체 시각 통과로 바꾸지 않음 |

같은 rect의 층도 원본 자식/프레임 소유를 잃지 않는다. 합쳐진 gradient 문자열을 독립 결함 개수나 복사할 CSS로 오해하지 않도록 원인 후보와 전 구성원을 함께 표시한다.

#### 3.2.3. case 상태·종료 코드·게이트

| 상태 | 조건 | 처리 |
|---|---|---|
| 대조 | 프레임·상태·환경 일치, 글 일치율 ≥0.85 | 차단 기준 적용 |
| 미대조(틀) | G1 이탈의 frame 행이 해당 틀 차이를 구체적으로 덮음 | 전수 사람 확인·배너 1급 행. desktop 폭 무시 비교는 별도 미승격 보고 |
| 미대조(데이터) | G0 선언·독립 검토 case에서 글 일치율 <0.85 | 모양 차단 유지, 기하·있음/없음은 사람 확인 |
| 미실행 | 미선언 저일치·root≠1·누락/구형 스키마·부분 수집·폰트 실패·불안정·비표준 SDK 조건·stale | 성공 아님. 원인 복구 후 재수집 |

재수집은 최대 두 번이다. 같은 실패를 반복하지 않고 복구 조건을 반환한다. 데이터 선언/제외를 자동 추가하지 않는다. 정당한 기계 대조 한계로 비적용/미대조 처리할 때는 독립 검토와 배너가 필요하며 기존 inputs/visual 실패를 사용자 수락으로 통과시킬 수 없다. v4.1의 미실행→미대조 문면을 자동 폴백으로 오해하지 않게 좁힌다.

종료 코드는 0=유효 평가 완료·차단 없음, 1=미실행/증거 불일치, 2=미해소 차단, 3=허용된 G2 사용자 결정 항목만 남음이다. 함께 있으면 1→2→3→0 우선순위로 판정하되 전 발견을 출력한다. 미대조/사람 확인을 포함한 exit 0도 독립 시각 확인을 면제하지 않는다. 정상 비적용 0 case는 이유를 별도로 내며 “전수 일치”로 표시하지 않는다.

승격 뒤 순서는 **3-1 관찰 → 새 3-2 W8 → 기존 감사 → 백스톱/최종 freshness → G2**다. 3-2 차이가 F인지 가르기 위한 독립 감사자의 **처분 확인**은 blocked 상태에서도 호출할 수 있다. 이것은 최종 시각 통과가 아니다. 수리/처분 뒤 3-2를 재실행하고 최종 감사를 닫는다. “F는 감사에서만 풀리는데 차단 때문에 감사에 못 간다”는 순환을 만들지 않는다.

첫 제출은 design-input 전 case를 평가한다. 감사·백스톱 수리로 구현이 바뀌면 현재 digest로 W8과 관련 시각 증거를 재확인한다. 옛 성공 보고서를 그대로 배너에 싣지 않는다.

#### 3.2.4. T/D/F/H와 승인 이탈

| 종류 | 증거·판정자 | 처리 |
|---|---|---|
| T 실제 차이 | 원본 값/관계·구현·캡처 대조 | coder 수리, 매핑 오류는 architect 반송. 배포 전 해소 |
| D 데이터 차이 | G0 map+구현 snapshot으로 생성한 원본 재렌더, 독립 감사 확인 | 유효한 대응에서 해당 구성원의 차이가 없어질 때 스타일 차단만 해소 |
| F 도구 오탐 | 독립 시각 감사가 양쪽 요소·전체 높이/내부 스크롤 캡처·TL 기제 확인 | 구성원별 처분·전 회차 집계. “데이터 탓” 한 줄로 면제하지 않음 |
| H 무관/수집 오류 | Coordinator scope 수정 + 독립 차분 검토 | 올바른 범위 재동결·재대조. 구현 오류를 제외해 없애지 않음 |
| 승인 이탈 | 구체 G1/G1′ 결정 + 원본 행/case/속성/값 결속 | 해당 구성원만 덮고 배너에 계속 표시 |
| 공용 부품/이전 실행 | 동결 DS 근거·영향 화면 | 차단 면제 없음. §3.1.6 수리 경로 |

묶음은 읽기 위한 집계다. 처분은 구성원 집합과 양쪽 값/정체·case·reference/scope/tool digest에 결속한다. 구성원 추가·값/짝/기대값 변경은 재확인한다. 구현 digest가 바뀌면 결과를 다시 생성하며 동일 구성원의 처분 증거도 여전히 성립하는지 확인한다.

큰 모양 차이는 F 한 줄로 덮지 못한다. v4.1의 색 Δ>8/255, 반경 >2px, shadow 층 유무, 글자 크기 >1px 기준을 유지한다. 짝 오류가 큰 차이를 만들었다면 대응/수집을 바로잡아 다시 비교하거나 도구 결함으로 승격을 보류한다. 거짓 차이를 없애려고 제품을 바꾸지 않는다.

TL-1~9(아이콘 줄 상자, 흐림, 무한 애니메이션, canvas/영상, 스크롤 띠, 읽지 못한 상태 규칙, shadow DOM, 저일치 짝 오류, 데이터가 다른 목록)를 초기 목록으로 유지하며 증거 레인 사이에서만 개정한다.

**D 재렌더**

- 비교 데이터를 먼저 시안 예시·시각에 맞춘다. 자리와 수명은 빌드 폴더 캡처 하네스/전용 모듈뿐이다. 기존 시험 fixture·factory·실사용 데이터는 바꾸지 않는다.
- data-snapshot은 실제 구현 case를 그린 view-model/state의 필요한 데이터다. 민감 원문은 기존 비공개 증거 경계를 따른다.
- G0 rerender_map은 props·데이터 묶음 파일·이름 붙은 상수와 snapshot JSON Pointer, 허용 변환(그대로·명시 서식·열거 대응)을 고정한다. tone/variant/size 같은 스타일 선택 필드는 제외한다.
- 도구 생성 입력과 실제 하네스 입력이 byte 동일해야 한다. 불·수·문자열·열거형 모두 같은 규칙이며 map 밖 값은 원본과 같아야 한다.
- 원본 파일은 수정하지 않는다. P1 const는 선언 초기값을 구문 경계로 특정해 route fulfill 사본에서만 치환한다. 전역 정규식 치환은 금지한다. 지원 문법에서 위치가 유일하지 않으면 실패하며 범용 JS 변환기를 만들지 않는다.
- archive·입력·snapshot·map·재렌더 census digest를 묶는다. 요소가 사라지거나 미짝/미대조로 바뀐 것은 “차이 해소”가 아니다. 유효한 대응에서 해당 속성이 맞아야 하고 새 차이도 전부 평가한다.
- 재렌더 불가인 G0 선언 데이터 case의 남은 모양 항목만 exit 3을 쓸 수 있다. ≤2묶음, 사용자 항목 특정이 필요하다. T·실행 실패·원본 부족을 이 경로로 우회하지 않는다.
- D는 스타일이 그 데이터에 맞음만 증명한다. 지장간 한글/한자처럼 데이터 표기 자체의 요구 위반은 별개다. D 목록은 감사·발주자에게 계속 보인다.

**H 변경과 재관찰**

scope는 첫 구현 census 열람 전에 동결한다. 이후 수정 횟수와 H 라벨을 모두 기록한다. v5 reference/G1 인용도 scope에 결속한다.

기존 raw로 root/제외 재투영이 가능하고 원본 캡처·상태·case가 같으면 브라우저 재촬영 없이 reference/3-2만 갱신한다. 새 root 자료가 없거나 viewport·상태·원본 캡처가 바뀌면 관련 case를 실제 재수집하고 기존 inputs/독립 리뷰도 갱신한다. “H면 무조건 수 초 재대조”로 약속하지 않는다. 기대값/요구 범위가 달라지면 G1 결속도 재검토하고 필요한 G1′을 거친다.

#### 3.2.5. freshness·SDK·경계 높이

--check는 source manifest, design-input의 case 판, reference 원문/출처, G1 결속/이탈, scope, 현재 implementation_digest, 도구 판, 데이터/자원/폰트/브라우저/host 조건, 페이지 완결, 처분을 확인한다. hash 교체만으로 새 관찰을 만들지 않는다. 기존 visual-evidence 스키마/input_digest는 바꾸지 않고 W8 자기 digest와 현재 기존 입력 digest를 연결한다.

SDK case는 운영자 호스트만 context에서 차단한 표준 라우트로 측정하고 프로젝트 정적/미디어 CDN은 막지 않는다. SDK 호출 관찰 wrapper 설치 전 census를 얻는다. 실제 로드 파일/응답/전역 변수와 기대값을 교차 확인한다. registry가 있는데 SDK 절이 없으면 미실행이다. 캐시의 responseStatus를 알 수 없으면 성공으로 추정하지 않고 실제 응답/자원 byte 증거로 확인하며, 근거 없으면 미실행이다. 운영자 차단 라우트와 case 전용 라우트의 수명을 구별한다.

비교 쌍의 browser 판·DPR·프레임·상태를 맞춘다. desktop 원본 앱 프레임을 별도로 재도 원래 요구 viewport의 시각 증거는 유지한다. 최소 지원 높이는 G0 요구로 정하고 없으면 v4.1의 320을 출발점으로 쓴다. 해당 높이에서 상태를 직접 열어 재며 P2의 150px 차이를 가리는 326 이상으로 임의 상향하지 않는다.

#### 3.2.6. 반송 재관찰 축소

차단 승격과 별개다. 관문 9, 이번 회차 exit 0, 같은 host·서버·browser·route·reference·데이터 조건을 모두 만족해야 켠다.

매 회차 **전 case의 현재 census와 안정 여부**는 확인한다. 줄이는 것은 비영향 case의 전체 캡처·상호작용 재실행·독립 시각 재관찰이다. 이미 전부 촬영한 뒤 “축소”라고 세지 않는다. 상태 도달/census 비용은 계속 계산한다.

영향 집합은 다음의 합집합이다.

- 반송 항목이 가리키는 case.
- 현재 census·자산·폰트 지문이 달라진 case.
- 변경 JS/HTMX/UI 동작 파일·모션 인벤토리를 쓰는 case.
- 변경 CSS 상태 규칙의 선택자가 걸릴 수 있는 case.
- vendor/SDK registry가 바뀌었을 때 해당 SDK를 로드하는 모든 case.
- 데이터·조건부 가시성·case 구성이 달라지거나 영향 근거가 불충분한 case.

규칙 단위 CSS diff와 전/후 DOM 어휘를 사용한다. :is/:where/:not/:has, @media/@container, 상속 custom property, 공용 keyframes, 읽지 못한 sheet를 단순 토큰 AND로 안전하다고 판정하지 않는다. 선택자 가지의 합집합을 쓰거나 해당 파일 소비 case 전체로 확대한다. 불명확하면 영향 있음이다.

나머지는 이전 직접 관찰 포인터+현재 동일 지문/의존성 근거로 독립 리뷰어가 재사용을 확인한다. 첫 제출·재동결·host 전환·미실행/exit 2/3·부분 수집에는 축소하지 않는다. 슬라이스 임시 host 캡처를 최종 G2 host의 관찰로 재사용하지 않는다.

“영향 case”는 W8 한 곳이 소유하고 슬라이스 감사 반영·수정 모드 step 6·G2 반송이 공통 소비한다. [W5~W7 §7](../2026-09-30-speed-improvement/design-W5-7.md)의 위임을 따른다. W5/W6′ 보류, W7 기각, W6m 감사 빈도는 바꾸지 않는다.

### 3.3. 도입 순서 — 경고와 그림자 관문의 결합

경고 먼저를 유지하며 경고 출력을 실구현 자동 수리 지시로 쓰지 않는다.

| 단계 | 레인 안 | 평가/전환 |
|---|---|---|
| A 도구·오프라인 리허설 | 현장 절차 그대로 | raw v5·표/결속·대조/처분·양 플랫폼 검증 |
| B 경고/그림자 | 진행 레인은 v1.2.0 그대로. 새 G0 시험 레인에만 표 도입. W8 출력은 레인 밖 봉인 | 같은 v5 판으로 연속 두 레인 |
| C 차단 | 다음 새 G0부터 3-2 차단, 기존 실행에 소급 안 함 | 관문 0~8·10 + v5 입력 조건 |
| D 재관찰 축소 | 전 case census 유지, 비영향 직접 관찰만 재사용 | C + 관문 9 |
| E 발주자 전수 축소 | **기본안에 포함하지 않음** | 사용자 별도 결정 |

v4.1과 다른 점을 명확히 한다. **표를 받는 새 G0 레인은 입력 절차와 비용이 늘어난다.** “레인 절차 무변경·벽시계 0”은 기존 진행 레인의 출력만 봉인해 보는 그림자에 한정한다. 입력 표가 있는 v5 시험 레인의 총효과는 새로 측정한다. 옛 레인의 과거 재생을 v5 입력 효과나 새 승격 레인으로 세지 않는다.

build-state의 w8에 policy, schema, toolchain/reference/scope digest, impact_reuse 허용 여부만 둔다. 키가 없는 기존 실행은 legacy다. 재개 시 새 설치본이 보인다는 이유로 자동 추가/승격하지 않는다. 정책은 G0에서 고정한다. 수정 모드의 기존 빌드는 기존 재동결/신규 채널 선택을 통해 진입하며 진행 단계 중 표를 소급 요구하지 않는다. 트리비얼 채널을 W8 전수 절차로 자동 확대하지 않는다.

**현장 영향 방지:** 설치 캐시 직접 수정 금지, 구현/리허설은 별도 범위에서 수행한다. 배포는 진행 레인의 G2 착륙 뒤 안전한 창에서 make release-web으로만 한다. 평가 사본은 별도 허용 경로를 쓰고 기존 서버·DB·세션을 건드리지 않는다. 같은 기계의 부하도 동시 상한/대기 구간과 함께 측정한다. 이번 설계 작업은 이러한 실행·배포를 하지 않는다.

**그림자 절차**

1. 첫 구현 census 열람 전에 원본 표·scope·데이터·도구 SHA를 동결한다. 표 생성기·정규화·짝짓기도 판 고정에 포함한다.
2. 제출마다 전 design-input case를 평가하고 시각·커밋·도구·입력·결과 SHA를 장부에 먼저 적는다. 결과를 레인/발주자에게 전달하지 않는다.
3. 첫·끝 제출은 독립 발주자 전수 대조를 한다. 첫 전수는 가능하면 첫 수리와 겹친다. 중간은 좁힐 수 있으나 범위·출처를 적는다.
4. 해당 발주자 판정 기록 뒤 결과를 열어 원래 반송과 대조한다. 레인 반송에는 기계 결과를 섞지 않는다.
5. 끝 판 검증이 끝나면 **배포 전에** W8만 찾은 T/T?·D·미검증을 공개한다. 확인된 실제 결함은 기존 수리·재검증으로 닫는다. 이 후속 수리 시간/결과는 원래 그림자 판정과 나누어 기록한다.
6. 의심 후보는 독립 판정으로 가른다. 경고라는 이유로 알려진 T를 배포하지 않는다. 제품 요구 변경이나 환경 부족만 해당 기존 결정 경로로 보낸다.

이는 v4.1의 “끝 판 통과 뒤 공개·후속 수리 사용자 선택”을 최신 원칙에 맞춘 것이다. 공개는 최종 배포 전이며 확인된 T 수리는 품질 완료 조건이다. 배포 없는 평가라면 결함 목록으로 남기되 미해결 판을 출시 완료로 표시하지 않는다.

**전환 관문 — 같은 판의 연속 두 레인에서 각각 충족**

| 번호 | 증거 |
|---|---|
| 0 | collector·표 생성기·정규화·대조기·재렌더·판정 정책 SHA 고정. 바꾸면 새 판으로 두 레인 다시 계산 |
| 1 | 첫·끝 전수 제출의 원래 발주자 항목 중 대조 case 놓침 0, 두 레인 합 ≥10. 미대조/미실행은 사람 목록에 존재. 중간 좁힌 회차 놓침도 설명 전 보류 |
| 2 | 레인별 7계열 20~30개, 계열별 ≥3·절반 이상 문턱 근처. 차단 ≥95%, 심은 요소 밖 새 모양/있음·없음 오탐 0 |
| 3 | 첫·끝 전수의 실제 case/속성 범위·출처 기록. 판정보다 늦게 봉인한 결과는 제외 |
| 4 | 전 회차 유일 차단 묶음 F ≤5%, 회차당 ≤3. H=0: 동결 뒤 scope 수정 횟수+H 라벨 |
| 5 | 범위/후보 라벨과 독립인 두 번째 판정자가 F/H 전수 확인. 교차 ≥30묶음 일치율 ≥85% |
| 6 | 끝 판 D는 실제 snapshot 생성 재렌더로 입증. 끝 판 T의 수리 완료와 처분을 구분하고 exit 0 또는 허용 exit 3 ≤2묶음에 도달 |
| 7 | 끝 판 T/T?를 사용자 기준으로 확인. 실제 차이로 받아들이지 않은 항목은 F 집계 |
| 8 | 재수집 두 번 안 안정, 미실행 루프 0, 글 일치율 중앙값 ≥0.95, 선언 미대조 ≤10%, 끝 판 미선언 저일치 미실행 0 |
| 9 | 축소만: 전 회차를 역검증해 “뺐을 case”의 반송 결함 0 |
| 10 | 실제 하네스·표 작성/검토·라벨·처분·재관찰 시간으로 손익 재계산. 차단+축소 중앙값 ≥0이면 품질/시간 선택을 사용자에게 올림. SDK 화면은 실제 census 확인 |

미라벨/불가 판정을 정상 분모로 넣어 F 비율을 낮추지 않는다. 전 회차 T/D/F/H/미판정 수와 coverage를 같이 공개한다. 자연 결함이 줄어 원래 항목 ≥10이 안 되면 세 번째 이후 레인을 더 모으며 심은 결함으로 채우지 않는다.

v5 추가 조건은 원본 행→출처/관계→G1 연결 누락 0, 미확인·추정의 확정 위장 0, stale·부분 수집의 성공 0, P1 T35 검출 보존 또는 정당한 재분리 설명, 기존 검증 유지다. desktop·실제 SDK 등 검증하지 못한 영역은 별도 비승격 범위로 명시한다.

### 3.6. 속도 효과 — 보수 셈

#### 3.6.1. v4.1 출발점

[실측·기존 시간 분석] P1 G2는 474.3분(레인 227.4+발주자 246.9), P2 반송은 약 394분(227+167)이다. 실제 수리·요청 추가·데이터/시간대·시험·증거 작업이 섞여 있으므로 전체가 W8 절감 대상은 아니다.

[추정·v4.1 유지, 음수=절감]

| 단계 | P1형 | P2형 |
|---|---:|---:|
| ③ 차단 | −20~+145분 | −35~+100분 |

#### 3.6.2. 입력 표 추가분

[실험의 정적 판정] 입력 표 ‘예 23/부분 12’는 정보 충족 가능성이다. 실제 재구현으로 23개를 예방했다는 뜻이 아니다. 부모 관계는 부분 11개를 보완하지만 이미 올바른 명세를 어긴 R12는 입력만으로 예방을 보장하지 못한다.

    v5 총 시간 변화 = v4.1 해당 단계 변화 + C - S + Q
    C: 입력 표 작성·매핑·검토·갱신의 순증
    S: W8만 있었을 때보다 입력 표가 추가로 없앤 수리/처분/반송
    Q: 이전 검증이 놓친 실제 결함 수리

C는 기존 G0 수집·토큰/시각 연결표와 중복된 시간을 뺀다. S는 더 나은 첫 구현 덕에 실제 사라진 사전 수리·처분·후속 반송만 센다. v4.1에서 이미 절감으로 센 G2#5/#6 등을 다시 전부 더하지 않는다.

| 추가분 | P1형 | P2형 | 근거 |
|---|---:|---:|---|
| C 계획 범위 | +30~90분 | +45~120분 | **[추정·미측정]** 34/73 case, 부품/variant 공유 전제 |
| S의 보장 하한 | 0분 | 0분 | 재구현/현장 비교 없음 |
| Q | 발견에 따라 별도 | 기존 +25~50 외 추가분 미정 | 실제 수리 시간 |

현재 순절감은 확정하지 않고 계획에서는 S=0을 쓴다. ③+④ 중앙값 기준 단순 손익분기는 P1 S>40~100분, P2 S>65~140분이다. P2 Q까지 넣으면 더 필요하다. 이는 예측 중앙값이 아니라 **조건부 손익분기 계산**이다.

⑤의 −75/−70분을 기본 효과로 약속하지 않는다. 기본안은 전수 확인을 유지하며 경고 레인에서 C·S·Q를 실제로 잰다.

#### 3.6.3. 측정 방식

레인 벽시계·발주자/평가자 시간·모델 시간은 구분한다. G0/G1 순증, 첫 구현 T 원인 수, 첫 3-2의 T/D/F/H·미실행, 사전 수리, 실제 G2 회차, 재관찰/처분을 기록한다. G2 회차 감소와 G2 전 수리 증가를 같이 보고한다. 서로 다른 레인의 단순 전후 시간으로 입력 표의 인과 효과를 확정하지 않는다.

v4.1의 두 그림자 레인 합 비용도 남는다. 발주자 약 4~8.5시간, 레인 밖 평가 약 6~13.5시간, 하네스 준비 약 3.5~9시간은 **[추정]**이다. 표 작성은 이 준비/매핑과 중복되지 않는 순증만 더한다. 첫·끝 전수 대조를 레인 수리와 겹치지 못하면 v4.1 추정상 레인당 최악 +110~225분이다. 레인 밖 실행이라는 이유로 비용 0이라고 하지 않는다.

#### 3.7.3. 심은 결함과 실제 수집

기존 27개 변이(색·배경·반경·그림자·글자·틈·아이콘), 같은 데이터 대조를 회귀한다. P1 원본 24/27·같은 데이터 27/27, P2 27/27·문턱 근처 26/27은 **이전 실측**이며 이번 새 렌더 결과가 아니다.

새 리허설은 범위 설정자와 다른 사람이 seed를 고르고 구현 census에서 무작위·층화 대상을 고른다. 계열별 ≥3, 절반 이상 문턱 근처, 단일 요소 변이·데이터가 다른 목록을 포함한다. 심을 값이 이미 원본 승인값인 가짜 시험은 먼저 거른다. 심은 요소 밖 모양 오탐과 실제 배치 연쇄를 분리한다.

v5 추가 씨앗은 잘못된 정확 토큰, solid→strong, sheen/세 번째 divider 누락, footer를 본문 안으로 이동, gap 부모 오연결, badge alpha 근접 대체다. P1 배치/유리판과 P2 영상 칸/짧은 높이에서 표 생성→G1 결속→coder 소비→출력 대조→수리→현재 보고까지 작게 재현한다.

D는 P1 상수 생성과 P2 props/데이터 묶음을 각각 최소 한 건 실제 검증한다. 문자열만 성공하고 bool/numeric 세탁 방지까지 증명했다고 하지 않는다. desktop 폭 무시·SDK 캐시/로드·긴 목록/내부 스크롤·가림/모션도 실제 수집하며 미측정 영역은 승격 범위에 숨기지 않는다. 서버/DB가 필요한 부분은 승인된 후속 구현 환경에서만 수행한다.

make verify-web에는 브라우저 없이 가능한 회귀·문면·미러를 넣는다. 성공을 실제 렌더 성공과 혼동하지 않는다. web 변경 커밋 전 make verify-web와 기본 make verify를 모두 실행하고 결과/미실행을 구분한다.

### 3.8. 구현 계획 — 커밋·순서·규모

Coordinator에는 시점·담당·exit만, 기계 계약은 design-evidence, 구조/토큰 결정은 architecture-web, 구현 표기는 implementation-ui가 소유한다. 스키마를 긴 본문에 반복하지 않는다.

[개발 가이드 §4~§6](../../../docs/DEVELOPMENT.md)에 따라 검증하고 Makefile 등 봉인 대상 변경 뒤 별도 봉인 chore를 수행한다. 매니페스트/구조를 바꾸면 claude plugin validate dddjango-web --strict도 실행한다. 배포는 안전한 창의 make release-web만 사용한다. 첫 릴리즈는 경고판, 차단판은 관문 뒤 별도 릴리즈이며 소규모 커밋마다 현장 설치본을 바꾸지 않는다.

## 4. 사용자에게 물을 것

**현재 설계를 완성하기 위해 멈춰 물을 것은 없다.** 우선순위·정확값·경고 먼저·검증 유지·새 결함 배포 전 수리는 기존 결정에서 나온다. 아래는 실제 증거가 생긴 뒤 사용자만 정할 판단이며 지금 승인을 요청하거나 실행 권한으로 간주하지 않는다.

1. **승격 때 속도가 늘어나면 품질 이득을 위해 추가 시간을 쓸 것인가.**  
   배경: v4.1도 ③+④만으로 확실한 절감을 보이지 않았고 표 비용이 추가된다.  
   실례: 레인당 40분 늘지만 기존 검사가 놓친 판 재질 차이를 꾸준히 찾는 경우다.  
   바꾸면: 품질 도구로 차단을 채택하거나 경고를 유지하고 비용을 줄일 수 있다.  
   위험: 근거 없이 차단을 켜면 속도 목표와 어긋난다. 관문 10의 실제 표를 보고 결정한다.

2. **승격 후 발주자의 전수 대조를 표본 확인으로 줄일 것인가.**  
   배경: v4.1의 −75/−70분은 이 ⑤까지 포함한다. 설계자가 발주자 확인을 대신 줄일 수 없다.  
   실례: 전수 108~113분을 표본 20~30분으로 바꾸되 desktop·미대조·D·사람 확인은 전부 보는 경우다.  
   바꾸면: 레인당 약 80~95분 추가 절감 가능성이 있다 [추정].  
   위험: 기계와 사람이 원본 범위/짝짓기를 함께 잘못 잡을 수 있다. 현재 기본안은 전수 유지다.

## 5. 확신이 낮은 것·자료 한계

- **예방률/순속도 미측정:** 23/12는 정보 충족 분석이다. 부모 관계 보강으로 35/35 예방 또는 G2 1회를 보장하지 않는다.
- **A34/B1 해석:** 최초 연결 손실 위치이며 architect만의 책임 비율이나 시간 비중이 아니다. coder도 원본 확인 의무가 있었다.
- **표본/오염:** P1 5·P2 10 case는 전체보다 작고 도구 개발에 사용했다. 독립 라벨은 P1 첫 제출 한 회차이며 다른 자료 일부는 설계자 라벨/미라벨이다.
- **파생/병합:** R6은 선행 배치, R8 일부는 뒤/앞 프레임 병합이다. 독립 수리 건수로 과장하지 않는다.
- **자동 source 연결 한계:** computed는 token/variant 출처를 보장하지 않는다. 동적 번들·기본값·복합 CSS의 직접 확인 비용이 크다.
- **v5 자체 미구현:** 관계 수집·손실 없는 원문·결정적 직렬화의 비용을 기존 v4 수치로 확정하지 않는다. examples 순서 변동을 이번에 확인했다.
- **D 미실행:** P1 const/P2 데이터 생성과 실제 재렌더, bool/numeric 결속은 후속 관문이다.
- **일반화 한계:** SDK 합성과 실제 SDK 수집, desktop 폭 무시, 캐시, 긴 내부 스크롤, 영상/canvas를 구별한다.
- **dddart 99%:** 사용자 체감 배경이며 통제 비교가 없다. Flutter 일반 우월성이나 웹 표현력 부족을 결론으로 삼지 않는다.
- **실행 범위:** 지정 보고서와 읽기 전용 자료/메모리 재생만 수행했다. 플러그인·규범·scratch·설치본 변경, 커밋/push, 서버/DB/네트워크, 다른 프로세스 제어는 하지 않았다. make verify-web는 후속 계획이며 이번에 실행했다고 보고하지 않는다.
- **도구:** 지시대로 Serena·Graphify를 사용하지 않았고 서브에이전트도 호출하지 않았다.
