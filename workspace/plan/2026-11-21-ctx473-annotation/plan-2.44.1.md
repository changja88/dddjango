상태: 배포 끝(2026-11-22 02시 47분 · 태그 `dddjango--v2.44.1` · 고침 81b7b268 · release 77a1ed54 · 봉인 70cf3997 · d5a44cc3).

- 구현 중 바뀐 것은 이 문서 «결정» · «독립 검토 반영» 이 정본이다. 규칙 글은 바뀌지 않았다(검사기 판정만).

## 현장 보고

- **F4-187**(수리됨): 판정 ACL 의 받은 글 검증 try 안 지역 이름에 단 타입 주석(하우스룰 «모든 이름의 첫 대입에 타입»)을 #473 이 «상대 창구가 돌 수 있음» 으로 잡았다. coder 는 코드 꼴을 바꿔 피했다.
- **F4-202**(수리됨): 같은 결 — try 안 `wire: <짝 ACL wire> = <짝 ACL wire>.model_validate_json(v)` 의 주석 이름(짝 ACL import)을 #473 이 셌다. 레인은 검증을 사설 함수로 빼 피했다. 하우스룰(#493)을 지키면 #473 이 붉고, 주석을 빼면 #493 이 붉은 맞부딪침.
- **F4-167 남은 몫**(꼴 ② · 열림 그대로): 검증 try 안에서 같은 파일 변환 함수를 부르는 꼴은 붉음 그대로다(검사기를 넓히지 않음). 곧은 꼴 — 검증 부름만 try 안 · 주석 단 지역 · 변환은 try 밖 — 은 2.44.0 에서 주석 탓에 붉었고 이제 녹색이다. 현장 한 곳은 그 BC 리팩토링 때 곧은 꼴로 고친다.

## 원인

- 판정 ①(«try 몸통에 상대 창구 · ACL 이름이 글자로 나오면 돈다 — 모르면 돈다»)이 `ast.AnnAssign.annotation` 의 이름 마디와 대입 · 지움 대상 이름(Store · Del)을 «실행되는 마디» 로 셌다.
- 파이썬 사실(재현 일꾼이 3.9 ~ 3.15 로 잼): 함수 스코프의 변수 주석은 평가되지 않는다(`from __future__ import annotations` 무관 · 바이트코드 `co_names` 에 주석 이름 없음). 속성 · 첨자 대상 식은 평가된다. 클래스 몸통 · 모듈 자리 주석 · 중첩 def 의 매개변수 · 반환 주석은 3.13 이하에서 평가된다.
- 같은 착각이 #14(`_constructor_only_port_names`)에도 — 메서드 안 `clock: ClockPort = self._clock` 의 주석을 «포트 구현» 증거로 셌다.

## 결정

- **사용자**:
  - 범위(11-21): «그럼 그 셋을 먼저 수리하는게 맞을거 같아. 이전처럼 뭐가 문제인지 부터 확인하고 보고해줘» = F4-187 · F4-202 · 꼴 ②.
  - 방향: «애초에 주석을 무시하고 보면 되는거 아니야?» 뒤 운영자 «검사기 고침은 주석 무시 하나 · 꼴 ② 현장 한 곳은 변환을 try 밖으로 · 이렇게 진행할까요?» 에 «어» = 검사기는 실행되지 않는 주석을 세지 않게만 · 꼴 ② 는 검사기를 넓히지 않음.
  - 계획 v1 «승인»(11-21).
- **운영자 처리**(질문 생략 · 설계 처리 · 이의 시 뒤집음):
  1. 같은 착각 둘도 이번 판 — #473 이 try 안 대입 · 지움 대상 이름을 셈 · #14 가 함수 몸통 지역 주석을 포트 구현으로 셈.
  2. 붉은 줄 글(메시지)은 한 글자도 바꾸지 않는다 — 진행 중 실행의 registry_gate 가 옛 줄을 글자로 짝지으므로.
  3. 덧셈 대입 대상 이름은 그대로 센다(읽고 쓰므로). 속성 · 첨자 대상 식 · 중첩 class 몸통 · 모듈 자리 · 중첩 def 서명 주석도 그대로 센다(평가되므로 · 3.14 지연 평가는 보수로 3.13 이하에 맞춤).
- 판 번호 **2.44.1**(patch) — 검사기 오탐 줄임만 · 새 붉음 0. dddjango-web 은 바뀌지 않는다(같은 장치 없음). 요청 가이드 바뀔 것 없음(사용자 칸 · 플러그인이 묻는 일 그대로).
