### 3-4. 최소 수정 W6m — 문면 충돌만 닫는다 (채택 · 0분)

**왜 이 방향인가**

- 지금 문면은 두 갈래로 읽힌다. Phase 2 step 4 «슬라이스 3개 이상이면 슬라이스별 경량»과, 수정 모드 4 «touched 파일 한정 경량 1회»다.
- 두 레인은 슬라이스별 감사 + G2 직전 1회로 읽었다. 측정상 이 리듬이 결함 대부분을 슬라이스에서 잡았다.
- 문자 그대로 «1회만»으로 읽는 레인이 나오면 두 레인 슬라이스 검출 28건(P2 21 · P1 7)의 경로가 사라진다.
- 그래서 실제 리듬을 규칙으로 적어 충돌을 닫는다. 감사 수 · 범위 · 시점은 레인 관행 그대로이므로 **줄어드는 시간은 0분**이다. 관찰된 «이중 감사»는 서로 다른 결함을 찾았으므로 없애지 않는다.
- «적용 범위 규범» ⑵(`CX:319`·`CL:294` · `MK:101` byte 대조 · `refactor_audit` 이 읽음)가 «수정 모드 touched 한정 감사 조항»을 이름으로 부른다. 그래서 그 조항의 **머리 문구(«touched 파일 한정 경량 1회»)는 바꾸지 않는다** — ⑵ 는 손대지 않는다.

**(1) Phase 2 step 4 첫 문장**(`CX:243` · `CL:220` — `MK:103` 대조 밖)

- 앵커: «기본 G2 직전 홀리스틱 1회 + 슬라이스 **3개 이상**이면 슬라이스별 경량»
- 바꾼 뒤(뒤따르는 «— `spawn_agent`로 …»(CX) / «. **입력(필수)** …»(CL)는 그대로):

> 기본 G2 직전 홀리스틱 1회 + 슬라이스 **3개 이상**이면 슬라이스별 경량(수정 모드도 이 리듬이다 — «수정 모드» 4 는 G2 직전 1회의 범위를 정한다)

**(2) 수정 모드 4**(`CX:267` · `CL:244` — 머리 문구 보존 · 뒤에 덧붙임 · 두 플랫폼 byte 동일 · `MK:103` 대조에 새로 넣는다)

- 바꾼 뒤(앵커 문장 그대로 + 덧붙임):

> 4. **discipline 감사 = touched 파일 한정 경량 1회**(규율 위반은 작은 수정의 누적으로 침전하므로 0회는 불가, 트리비얼 채널이 라벨급을 흡수하므로 경량으로 충분). 이 1회는 Phase 2 step 4 의 «G2 직전 홀리스틱 1회» 자리(step 3-1 관찰 뒤)에서 부르는 호출이고, 머리의 «경량»은 범위를 touched 로 좁힌다는 뜻이다 — 점검 깊이는 홀리스틱과 같아서 홀리스틱 점검 항목·행위↔코드 대조·최종 시각 감사(아래 6 의 영향 범위 관찰과 영향 없는 case 재확정 포함)를 줄이지 않고 이 호출이 한다. touched 는 감사 대상 변경의 범위다 — 행위 추적과 판정에 쓴 touched 밖 의존은 읽고, 명세 행위가 touched 밖에서 실현돼야 하는데 빠졌으면 누락으로 보고한다. 슬라이스가 **3개 이상**이면 step 4 의 슬라이스별 경량도 그대로 부른다. touched = `git_snapshot` 이후 이번 실행이 만든 첫 부모 비병합 커밋과 미커밋 편집이 바꾼 파일 + 첫 부모 병합마다 레인이 병합 안에서 고친 파일(`git show --cc --name-only`)이다 — 둘째 부모가 기준 가지(main) 이력 밖인 병합(`git merge-base --is-ancestor <병합>^2 <기준 가지>` 거짓 · 형제 가지 등)만 들여온 파일 전부를 넣는다. 이 정의는 감사 범위 정의이고 슬라이스 0 끝 green ④ 치환 판정의 승인 병합 의미론(`approved-merges.txt`)과 별개다 — 감사 범위 때문에 그 등재를 기다리지 않는다. 빌드 폴더는 감사 입력(증거)으로 따로 준다.

## 7. W8 과의 상호작용(W8 설계자에게 넘기는 것)

1. **«영향 case» 정의는 W8 한 곳이 소유한다.** 소비처는 셋이다.
   - ① `CX:243` «감수 리포트의 지적을 … 반영하고 변경 후 영향 case 를 재관찰·재감사» — 슬라이스 감사 반영 고리(W6m 으로 그대로 남는다).
   - ② `CX:269` 수정 모드 6 «영향 없는 case 는 독립 영향 확인 후 … 재확정».
   - ③ W8 의 G2 반송 재관찰.
   - W8 이 착륙하기 전까지는 지금 문면과 독립 리뷰어 판정 그대로다(fail-closed · 전 case 가 기본).
2. **파일 단위 정의(공용 CSS·토큰·페이지 JS → 전 case)는 쓸모가 없다.** 두 레인 화면 슬라이스 10/11 에서 걸렸다[실측]. G2 반송 수정도 공용 CSS 를 고친다. 예를 들어 P2 반송3 은 `conversation.css` 두 줄이었는데, 레인은 hero 를 가진 case 만 5 viewport 로 다시 찍었다(64 PNG)[실측].
3. **쓸 만한 판정 수단**[실측 실행 · 수 초]: 규칙 단위 CSS diff(`w7/css_rule_diff.py`) · 훅 존재 확인(`w7/selector_hooks.py`) · 값이 바뀐 기존 토큰만 영향 확대. 같은 host 에서 전후를 찍는 반송 재관찰에서는 계산 스타일 지문 비교도 쓸 수 있다. **host 가 다른 슬라이스 캡처 ↔ G2 캡처 재사용에는 쓸 수 없다**(§4-3).
4. W8 이 «최종 시각 감사» 앞에 기계 대조를 두면, W6m 의 수정 모드 G2 직전 1회(3-1 뒤) 안에서 순서를 정한다: 3-1 관찰 → W8 기계 대조 → G2 직전 1회(규율 + 최종 시각) → 백스톱 → G2.

## 부록 B — W6′ 보류판 판형(구현하지 않음 · 재평가 때 출발점)

검토 §5 방향을 반영한 판형이다. 재평가 조건(§3-6)이 서면 이것으로 다시 설계·검토한다.

1. **시각 경로는 슬라이스에 남긴다.**
   - 화면 슬라이스마다 «슬라이스 캡처·동작 기록 ↔ 원본» 대조와 동작 재현을 한다(`CX:243` 시안 입력 전부).
   - 실제 트리 재현이므로 다음 coder 보다 앞에 직렬로 둔다.
   - 데이터 전용 슬라이스는 이 확인이 없다.
2. **코드 규율 감사만 끝으로 모은다.**
   - 시점: 지금 끝 감사 자리(3-1 뒤).
   - 조각
     - 줄 예산(귀속 구간 ≤3k 줄 · ≤60k 토큰)으로 닫는다.
     - 공유 파일은 최종 트리 `git blame` → 커밋 → 슬라이스로 줄 구간을 귀속한다.
     - 조각 입력 = 그 슬라이스들이 만든 파일 전체 + 공유 파일 귀속 구간과 둘러싼 단위(함수·규칙·블록) + 파일 머리 구조.
   - «전량 실독» = 그 단위 전부다. 표도 그 단위로 쓴다.
   - 크기 때문에 «미완료»가 나면 같은 입력으로 다시 부르지 않고 쪼갠다. 같은 조각 재호출은 1회까지다.
   - 레거시 줄 발견은 «빚 후보»로 따로 보고하고 `CX:268` 분업으로 넘긴다.
3. **의존과 경계**
   - 도구가 `deps`(touched 템플릿·JS 가 include/load 하는 DS 부품·공용 JS · 1-hop)와 `edges`(조각을 가로지르는 include/extends · `{% static %}` · import · URL 이름 · data-*/class ↔ 템플릿)를 낸다.
   - `deps` 읽기는 의무다(인용).
   - 종합은 간선마다 양 끝 코드를 읽는다. 홀리스틱 점검 항목(행위↔코드 대조 · `RX:68`)도 종합이 한다.
4. **델타 재감사 1회**: 감사 기준 커밋 이후의 레인 편집(3-1 수정 · 최종 시각 감사 반영 · 백스톱 반송 · Coordinator 추가 커밋)을, 최종 시각 감사·백스톱 앞에서 담당 조각에 diff 와 함께 다시 싣는다(교차면 종합도).
5. **도구 `backstop.py --touched <기준> <대상> --build <산출물 폴더>`**(byte 미러 · 목록·조각만 · 판정 exit 2 없음)
