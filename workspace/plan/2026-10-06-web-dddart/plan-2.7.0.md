## 도구 동작
### 시험 범위 `backstop.py <루트> --test-scope <산출물 폴더> [--since <커밋>]`
- 산출물 폴더는 프로젝트 루트 기준(절대 경로도 받음) `.dddjango-web/` 아래 실재 폴더 · `build-state.json` 의 `test_command` · `test_web_paths` 를 읽는다 · 시험은 돌지 않는다 · 다른 러너 모드 · 게이트 선택지와 함께 쓰지 않는다.
- **web 시험 경로(W)** = `web_test`(없어도) · 루트 바로 아래 `test/web` · `tests/web` · `test_web_paths`(있어야 하고 기록 폴더 밖 · 다른 W 의 조상 · 자손이면 판정 불가). 기록 폴더 아래는 어디에도 들지 않는다.
- **넓이**: `&&` · `;` 단계마다 pytest 시험 경로(없으면 `-c`·`--config-file` 설정 — testpaths 는 그 파일 폴더 기준 — 또는 루트 설정 첫 파일의 testpaths). exit 0 = 모든 경로가 W 원소이고 W 원소마다 빠짐없이 모임 · 2 = 넓음 · 좁음(빠진 W · 짝 없는 `-m` · W 안 `-k`·`--deselect`·`--ignore*` · `--lf`·`--sw`·`--sw-skip`) · 1 = 판정 불가(`make` · 파이프 · 재지정 · `$(` · 괄호 · **셸이 풀 낱말 `$` · 맨 앞 `~` · 앞 대입 값의 `~` · 글롭 `*?[` · 중괄호 펼침 `{}`** · `--pyargs` · `-o`/`--override-ini` testpaths · `--rootdir` · pytest 없는 단계 · 뜻 모를 선택지 뒤 프로젝트 안 경로 · build-state · pytest 설정 읽기 실패 · git 저장소 아님 · `--since` 커밋 못 풂). 붙은 값 꼴(`-n0` · `-kexpr` · `-mE` · `--deselect=…`)은 같은 선택지 · 설정 `addopts` 는 판정 밖.
- **단계 줄**: 시험 경로 자리를 바꾼 꼴로 내며 낱말마다 셸 따옴표로 다시 감싸고 앞 `이름=값` 은 값만 감싼다(셸이 대입으로 읽는다).
- **소비자** = W · `web/` · `docs/` 밖 시험 쪽 파일 가운데 web 을 import 하거나 `web.<패키지>` 점 경로 · 실재 `web/…` 경로 글자 · 다른 맨 위 폴더와 함께 쓴 `"web"` 을 쓰는 파일, 그런 web 밖 비시험 모듈(settings · 루트 urls 제외)을 import 하는 시험(한 걸음), 소비자 conftest 폴더의 시험. 돌 경로 = 시험 파일 · conftest 폴더 · 지원 모듈이면 그것을 import 하는 W 밖 시험(한 걸음). 구문 해석이 안 되는 파일은 알림 줄.
- **`--since`** 바뀐 파일 = 첫 부모 사슬의 비병합 커밋 ∪ 병합이 들인 바꿈 ∪ 커밋 안 된 바꿈 ∪ 미추적 비무시 — **승인 병합 M 이 상류판 그대로(`blob(M,p) == blob(M^2,p)`) 들인 경로만 뺀다**(TG4 기준판과 같은 술어 · 충돌 해소 · 미승인 병합은 센다 · 승인 목록을 못 읽으면 알림 줄과 함께 모두 센다).
  - `계층 중 시험` = 바뀐 시험 파일(지원 파일 · conftest · 지운 파일 빼고) · 일꾼 `-n0`.
  - `슬라이스 끝 시험` = 바뀐 web 파일의 거꾸로 참조 닫힘이 닿는 단위의 `web_test` 미러 · 닫힘 모듈을 import 하는 W 시험 · 닫힘 파일 글자를 쓰는 W 시험 파일(지원 · 자산 파일은 줄에 넣지 않음) · 바뀐 시험 파일 · 바뀐 지원 모듈을 import 하는 W 시험 · 바뀐 conftest 폴더(루트 conftest 면 W 전체 · 지운 폴더는 넣지 않음) · 닫힘에 닿는 소비자와 닫힘이 비지 않으면 `web 전체` 소비자. W 를 다 덮으면 `= web 시험 전체` 와 함께 W 경로와 그 밖 경로를 한 줄에. fail-fast(낱말 그대로의 `-x`·`--exitfirst`·`--maxfail`)를 떼고 일꾼 최대 6. 바뀐 web 파일이 없으면 닫힘을 계산하지 않는다(속도).
  - `G2 더할 시험` = 소비자 전부 · 바뀐 W 밖 시험 파일 · **바뀐 W 밖 지원 모듈을 import 하는 W 밖 시험과 W 밖 conftest 의 폴더(한 걸음 · 루트 conftest 면 프로젝트 전체 필요) · 바뀐 W 밖 conftest 폴더** · fail-fast 뗌 · 일꾼은 프로젝트 명령 그대로.
  - `프로젝트 전체 필요 — <까닭>` = ⓐ web/ · **W 아래 파일** · 시험 쪽 · 기록 폴더 · `docs/` · 문서 · 그림 밖 파일 ⓑ web 전역 진입점 파일 자체(표준 여덟 자리 · settings · 루트 urls 가 부르는 `web.` 모듈) ⓒ 루트 conftest(바꿈 · 소비자 · 바뀐 W 밖 지원 모듈을 import).
- 넓음 · 좁음 · 판정 불가면 `--since` 줄을 내지 않는다(Coordinator · coder-web 은 실행문 exit 0 이 아니면 시험을 돌지 않고 원문을 보고).

### TG4 브라우저 시험 꼴
- 같은 기준점에서 이번 실행이 바꾼 시험 쪽 파일(TG2 시험 · 지원 파일 + 시험 트리 `.js`·`.cjs`·`.mjs`)의 **띄움 자리 수** · **띄우는 시험 경우 수** 두 합을 기준판 · 현재판으로 견줘 늘었을 때만 발화(빚 패밀리 밖 · 슬라이스 끝에도 · `--only tg` · `--only tg4`).
- 기준판 = 파일마다 기준..HEAD 첫 부모 사슬에서 그 파일을 상류판 그대로 들인 마지막 승인 병합 판(없으면 기준점) — 승인 병합이 들인 띄움은 발견이 아니다 · 승인 목록을 못 읽으면 기준점 판으로 센다(승인 유입 쪽 «판정 불가 — 모든 지적을 이 레인 몫» 알림과 같은 뜻 · TG4 를 끄지 않는다).
- 발견 자리 = 그 수가 자기 기준판보다 는 파일마다(없으면 새쪽 추가 줄에 자리 · 시험이 있는 파일) · 줄 = 첫 새 자리 · 시험 · «외 n곳»은 자리 · 닿는 시험 수.
- 기준판과 현재판 바이트가 같은 파일은 읽지 않는다(blob id 로 견줌 — git 호출 없이). 해석 실패 파일은 그 파일(이름 바꿈 짝 포함)만 두 쪽 셈에서 빼고 알림.
- 브라우저 실행 파일 = 첫 낱말이 브라우저, 또는 `--headless` 와 브라우저 전용 낱말(`--dump-dom`·`--screenshot`·`--print-to-pdf`·`--remote-debugging-port`)이 함께 — `--headless` 하나는 다른 도구도 쓰므로 자리가 아니다. 글자 명령 · `shell=True` 글자는 shlex 로 나눈다.
- 따라가기: 시험 쪽 모듈은 import 를 계속 따라간다(`import a.b.c` 점 사슬 포함) · 시험 쪽이 아닌 프로젝트 모듈(web/ 밖)은 그 모듈 안 정의만 보고 띄움 낱말이 없으면 읽지 않는다 · 도우미 순환은 센 차례와 무관 · 경우 수를 못 세면(아주 큰 `range` 포함) 1 로 세고 알림.

## 설계 2판과 다르게 정한 것
- 도구의 «바뀐 파일»: 2판 글(`git diff <커밋>` 전체)은 승인 병합 유입까지 들여 main 을 받은 실행의 G2 가 남의 시험을 돌았다 → 첫 부모 · 비병합 커밋 + 커밋 안 된 바꿈 + 미추적, 그리고 병합 유입은 승인 술어로 가른다(재검토 R-B1 · R-S2).
- 실행문 exit 0 이 아니면 green 이 아니고 G2 는 멈춰 보고(R-I1) · exit 5 규칙을 coder 가 읽는 글(coder-web · implementation-test)에도(R-I2).
- TG4 발견 자리는 자기 기준판보다 는 파일(R-S4) · 해석 실패는 그 파일만 두 쪽에서 뺀다(R-S6 — 2판의 «하나라도 실패하면 TG4 미실행»을 바꿈).
- TG4 는 시험 쪽이 아닌 모듈의 import 를 더 따라가지 않는다(슬라이스 끝마다 도는 검사의 속도 — 응용 코드 깊이의 띄우는 도우미는 감수).
- 루트 conftest 를 바꾸면 슬라이스 끝은 W 전체(2판 글대로면 프로젝트 전체가 되어 «슬라이스 끝은 프로젝트 전체를 스스로 돌지 않는다»와 어긋남 — 프로젝트 전체는 G2 몫).
- 승인 목록을 못 읽으면 TG4 는 기준점 판으로 센다(«TG4 미실행» 대신 — TG4 를 끄지 않는다).
- 단계 줄 다시 감싸기: 앞 `이름=값` 은 값만 감싸고, 셸이 풀 낱말(`$` · `~` · 글롭)은 다시 감싸면 뜻이 바뀌므로 판정 불가.
- G2 더할 시험에 W 밖 지원 모듈을 쓰는 시험 · 그 지원 모듈을 import 하는 W 밖 conftest 의 폴더 · 바뀐 W 밖 conftest 폴더(2판의 빈틈 — 시험 쪽 파일이라 «프로젝트 전체 필요»에도 걸리지 않았다).
- W 아래 파일 전부를 «프로젝트 전체 필요» 에서 뺀다(비-.py 자산 · 관례 밖 이름의 지원 파일).
- TG4 브라우저 실행 파일 자리를 «`--headless` 와 브라우저 전용 낱말이 함께»로 좁혔다(재검토 R-N6).
- 슬라이스 끝 일꾼 최대 6(사용자 결정 — 2판에는 없던 줄).

## 작은 A/B(옛 판 2.6.1 vs 시험판 · Claude 세션만 · 한 쌍 한 번)
- **① 좁은 명령 · 계층 반복 · 우회 꼴 재발 자리(한 슬라이스 — 라우트 연결 · 새 브라우저 시험 셋)**: 걸린 시간 **3시간 12분 → 1시간 16분** · 시험 실행 **161회 5,292초 → 36회 915초**. 옛 판의 큰 몫은 test_command 전체(7,253 시험) 3번 2,037초 · 10 ~ 40초 좁은 실행 100번 2,436초(브라우저 시험 흔들림 쫓기 포함)이고, 새 판은 G0 가 test_command 를 web 시험 경로 두 단계로 바꾸고 슬라이스 끝은 도구가 고른 2,481 시험(70 ~ 96초)을 돌았다. 꼭대기(표본기 · 그 세션 자손 RSS 합 — 공유 메모리 겹쳐 셈): 크롬 수 44 → 111 · 크롬 MB 8,459 → 22,640 · 파이썬 MB 426 → 2,744 — 옛 판 test_command 는 일꾼 지정 없는 한 줄이고 새 판은 호스트 무-DB 단계의 `-n auto` 를 물려받았다(G-5 → 위 «슬라이스 끝 일꾼 수»). 한 쌍 한 번이라 옛 판의 흔들림 쫓기는 우연 몫이 섞였다.
- **② 넓은 명령 · 크롬 폭주 자리(시험 고정물 옮기기 한 슬라이스 · 발주가 프로젝트 무-DB 표준 전수를 요구한 실행)**: 걸린 시간 **54분 → 66분** · 시험 실행 **10회 1,441초 → 22회 약 1,100초**(새 판 합 1,578초에서 부 일꾼 결과를 주 세션이 다시 읽은 겹침 231초 · 조정자 실수 전체 실행 248초를 뺌). 새 판이 늦은 몫은 감수 결과(새 판 쪽만 고칠 것 4건 → 세 실행 다시) · 부하 때 브라우저 시험 요동 재실행 · 조정자 실수(노드 id 의 대괄호 매개변수가 셸 글롭으로 풀려 경로 없는 전체 실행)이고 도구 차이가 아니다. 발주가 두 판 모두에 프로젝트 무-DB 전수를 요구해 좁히기 이득이 작은 실행이었다. 새 판 G0 는 넓은 옛 명령(넓이 exit 2)을 호스트 두 단계 + web 시험 경로로 바꿨고, TG4 는 기존 node 하니스를 옮긴 고침을 막지 않았다(하위 프로세스 인자 동적 — 알림만 · 거짓 막음 0). 꼭대기: 크롬 49 → 171개 · 크롬 MB 18.0 → 27.3 GB — 새 판의 큰 꼭대기는 시험마다 node 로 브라우저를 띄우는 21 시험을 일꾼 20 으로 돈 때다(그중 둘은 발주 표준 명령 · 실수 실행). 단서: 옛 판 쪽 감수자가 이웃 새 판 사본을 읽었다(읽기만 · 새 판이 끝난 뒤) — 옛 판 감수 판정에 새 판 결과가 조금 섞였을 수 있어 «감수 결과» 비교는 그만큼 덜 깨끗하다.
- 멈출 기준 고침(재검토 R-S5): 메모리 꼭대기가 옛 판보다 크면 **끝까지 돌린 뒤** 판정에서 숫자와 함께 묻는다 · 기계 위험선(메모리 압박 경고 · 스왑 급증)만 즉시 멈춘다(측정이 슬라이스 끝 직전에 끊기지 않게).

## 가장자리
- ㉡ 줄의 시험 경로는 pytest 낱말 바로 뒤 — 예 `pytest web_test tests/web -rF -n0 --maxfail=1 -m db --import-mode=importlib && pytest web_test tests/web -rF -n auto --maxfail=1 -m "not db" --import-mode=importlib`(표 밖 불리언 선택지 뒤에 경로를 붙이면 판정 불가로 ㉢ 까지 내려간다).
- web 시험 안 DB 시험: 표식으로 단계를 나누는 호스트면 test_command 도 두 단계 · 표식에 걸린 시험이 없는 단계의 exit 5 는 통과 · 모든 단계 5 는 아님 · 단계는 따로 돈다.
- coder 가 슬라이스 끝 소비자 붉음을 «web 쪽으로 닫히지 않음»으로 보고한 노드 — G2 에서 **다시 돌되 반송하지 않는다**(G2 배너 목록).
- 재개(2.7.0 전 판으로 연 실행) · 수정 모드(요청마다 G0 가 다시 고름) · 트리비얼(시험 없음 · 접수 백스톱에 TG4) · 리팩토링(전역 진입점 파일을 옮기면 `프로젝트 전체 필요` — 동작 불변 확인으로 맞다) · 0T(행의 시험을 모으는 단계).
- pytest-playwright 설치: 개발 선언 · 잠금 파일 바꿈 = `프로젝트 전체 필요`(G2 한 번). 설치가 안 되면 coder 는 우회하지 않고 멈추고 Coordinator 는 사용자에게 묻는다.

## 한계
- **진입점 파일만 본다** — 진입점이 부르는 아래 모듈의 바꿈이 web 밖 요청(API · admin)을 깨면 G2 web 전체가 잡지 못할 수 있다. 실행 기록 26 가운데 옛 판보다 덜 도는 실행은 2(넓은 무-DB 1 · G2 호스트 전체 1) — 바뀐 것은 BC form · view_model · ui_extension. ui_extension 은 템플릿 builtins 로 전역 등록되므로 Django 기본 필터 이름과 겹치는 새 필터가 남은 길이다. 장부에 재발이 오면 잰다.
- **닫힘이 놓치는 길** — 동적 템플릿 이름 · `reverse()` 이름 글자 · JS 가 다른 BC 주소를 부르는 길 · `getattr` import · 형제 import(`from _support import h` — 모듈은 프로젝트 루트 기준으로만 푼다) → 슬라이스 끝에서 못 잡고 G2 web 전체에서 잡힌다(늦게 고침).
- **TG4 지원 밖(감수)** — 함수 인자로 넘긴 도우미 · `getattr` · 동적 import · 기존 node 스크립트 안의 새 장면 · `Test*` 클래스 안 도우미 메서드(`self.…()`)로 띄우기 · 형제 import · 바이트가 같아 읽지 않은 시험이 레인이 고친 지원 모듈 · conftest 를 거쳐 새로 띄우게 된 경우. 승인 병합이 들인 시험 파일을 이름만 바꾼 경우는 기준판 대응이 없어 늘어남으로 셀 수 있다 — 감수가 아니라 Coordinator «검사기 이의»로 푼다(오탐).
- fail-fast 떼기는 낱말 그대로만 — `-xvs` 처럼 묶은 짧은 선택지는 나누지 않는다(그 줄은 붉으면 첫 실패에서 멈춘다).
- 셸이 풀 낱말(`$` · `~` · 글롭 · 중괄호 펼침)이 든 명령은 판정 불가 — G0 는 다음 갈래로 간다(따옴표로 감싼 글롭 · 매개변수 노드 id 도 같다).
- 환경 접두(`PYTEST_ADDOPTS` · `PYTEST_XDIST_AUTO_NUM_WORKERS`)로 준 일꾼 설정은 도구가 읽지 않는다 — `PYTEST_ADDOPTS` 에만 든 일꾼 지정에는 계층 중 `-n0` · 슬라이스 끝 상한이 닿지 않는다.
- W 밖 시험 트리의 비-.py 러너(`.js`·`.cjs`·`.mjs`)를 바꾸면 시험 쪽 파일이라 «프로젝트 전체 필요»에도 G2 더할 시험에도 들지 않는다 — 그 러너를 부르는 시험은 감수 몫(운영 호스트의 node 러너는 W 안이라 지금 실해는 작다).
- 메모리: 옛 직렬 실행이 호스트 `-n auto` 를 물려받는다 — 슬라이스 끝은 일꾼 최대 6 · G2 는 프로젝트 명령 그대로(일꾼 상한은 호스트 쪽 요청 몫 — 운영 관찰(2026-10-20): 호스트가 web 전용 시험 명령을 따로 두고 무-DB 단계 일꾼 상한 6 을 넣었다 · 그 명령이 web 시험 경로를 다 모으지 않으면(넓이 exit 2) ㉡ 로 가도 호스트 단계의 일꾼 옵션(`--maxprocesses` 포함)은 그대로 물려받는다).
- 소비자 판정은 매 호출 web 밖 비시험 파이썬을 읽는다(한 걸음 다리 모듈 찾기) — 큰 호스트에서 1초 안팎 [추정].
