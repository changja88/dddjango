# dddjango-web 2.6.1 — 미디어 요소의 재생 검증은 G2 사용자 확인 (F4-102)

## 문제
- 현장 보고 F4-102: 지속 셸의 보관 중 멈춤(P12)을 지키는 미디어 기능 JS 둘(배경 영상 · 안내인 영상)을 검증하려고 설계자가 실제 브라우저로 native 재생 결과를 재는 영구 시험 25 조합을 스스로 지었다. 결과(재생 성공 · 취소 · `ended` · `readyState` · 준비 시각)가 브라우저 내부 시점에 달려 재현되지 않았고(`play()` 직후 같은 호출 안에서 `pause()` 를 불렀는데 그 `play()` 약속이 AbortError 가 아니라 이행됨 — WHATWG 알고리즘상 보장 없음), «유효하게 돈 테스트의 미통과는 환경 면제 없이 coder-web 반송» 과 맞물려 제품 결함 없이 반송 · 정지가 되풀이됐다.
- 플러그인 글: 행위마다 자동 시험 필수(coder-web) · 미디어 검증 방법 없음(implementation-javascript §7 지속 셸 행은 «보관 중 타이머 · 요청 멈춤» 까지) · 붉은 시험은 coder 반송(Coordinator 전수 테스트) · 슬라이스 0 끝 green ⑤ 의 재현된 새 실패는 슬라이스 0 이 고침 · 시험을 지워 green 금지(discipline-test §5).
- 호스트 본선 시험 트리에 미디어 자동 시험이 이미 있다(실제 재생을 기다리는 시험 · `video` 상태를 읽는 브라우저 시험 · `HTMLMediaElement` 대역 시험).

## 고침 (규칙 글만 · 검사기 · root_shell.js · 템플릿 표준 글 무변)
- **implementation-test §8** «안 쓰는 것» 에 «미디어 재생 자동 시험 — 비채택» (이미지 비교 비채택과 같은 꼴):
  - 대상 = 미디어 요소(`<video>` · `<audio>` · `new Audio()`)의 재생 동작(재생 · 멈춤 · 이어 감 · 소리 켜기/끄기 · 보관 중 멈춤 · 늦은 재생 완료 · 재생 취소 · 재생 상태에 따라 바뀌는 표시). 실제 재생이든 대역이든 자동 시험으로 재지 않는다 · 승인 명세에 있어도 예외 아님.
  - 명세 행 꼴(칸 셋) `시험 방법: G2 사용자 확인(미디어) · 화면 <화면> · 차례 <…> · 보여야·들려야 <…>` — 시험 없음은 검증 빼기 · 오라클 완화가 아니다. 제품 코드는 그대로 짓는다.
  - 경계: State 가 정한 미디어 마크업 값 · 미디어 아닌 P12 · `root:screen-hide`/`root:screen-show` 짝(이벤트 · 리스너 수) · root 시험 · root 처리기 시험은 그대로 자동 시험. 미디어가 있는 화면의 이 시험과 완성 그림 case 는 미디어 재생 결과 · 미디어 바이트 요청을 단언하지 않는다. 섞인 행은 나눈다.
  - «미디어 재생 결과» 한 정의(실행 중 요소 값 `paused` · `readyState` · `currentTime` · `ended` · `muted` · `volume` · `play()` · `pause()` 의 결과 · 미디어 이벤트 · 재생에 따른 표시 · 대역 시험의 흉내 낸 호출 기록). 실패한 단언이 미디어 재생 결과에서 갈린 시험(그 결과를 기다리다 넘긴 시간 초과 포함)은 **어느 모드 · 단계에서도 반송 · 새 실패 · 정지 사유가 아니다** — green 판정에서 빼고 G2 «미디어 자동 시험 붉음»(사용자 확인 권장 · 뒤 단언 미실행 n개 · root 시험이면 ★)으로.
  - 기준점 · 승인 병합으로 들어온 미디어 시험은 지우거나 나누지 않는다(준비 · 호출 맞춤은 평소대로 · 재생 관찰을 새로 더하지 않음). 이번 실행이 새로 쓴(슬라이스 커밋이 새로 쓴 · 기준점에 없던) 미디어 재생 시험은 지운다(자기 작업 되돌림 — 약화 · 삭제 아님). 미디어 재생 결과를 단언하는 함수는 `시험 전환:`(0T) 행으로 받지 않는다.
  - §4 root 시험의 «서버 요청 0» = 문서 · htmx · `fetch` 요청(미디어 바이트 요청은 세지 않음).
- implementation-test · discipline-test SKILL.md 와 discipline-test §4 · §5(붉은 재생 결과 시험은 코드를 고칠 근거가 아님 · 그 지움은 약화 아님) · implementation-javascript §7(재생 동작은 표 밖 · 보고는 `G2 사용자 확인 대기(미디어)`) · implementation-django 지속 셸 «앱과 다른 점»(«(그 기능 JS 가 이어 가지 않으면) 멈춘 채 돌아온다»).

## 한계
- Web Audio · 플레이어 SDK · iframe 임베드 플레이어의 재생은 이번 판 밖(기존 규칙 그대로 — 공식 SDK 는 SDK 행). 장부가 «미디어 요소» 를 적었고, 플레이어 SDK 는 공식 SDK 규칙(대역 시험 · G2 SDK 경계 확인)과 맞물린다.
- 기준점에 있던 미디어 자동 시험은 지우지 않는다 — 붉어도 막지 않으니 G2 보고로 남고, 지우기는 슬라이스 0 보존 · 치환 확인 · 리팩토링과 맞물려 다음 판 후보(설계 세 판이 바퀴마다 새 가장자리를 냈다).
- 섞인 기준점 시험이 재생 단언에서 붉으면 그 뒤 미디어 아닌 단언은 돌지 않는다 — 덮지 않고 «뒤 단언 미실행 n개» 로 정직하게 보고한다(검증 대기).
- 미디어 시험 꼴을 기계로 가르는 검사기는 없다(속성 읽기와 재생 결과 읽기가 같은 API) — 채택 확인 셋(UI 리뷰어 · Coordinator · discipline)이 막고, 재발하면 잰다.
- P12 코드 규칙에 미디어 줄은 더하지 않았다(사용자 «제품 코드는 그대로»).
