# dddjango-web 2.9.0 — 슬라이스 끝 시험 걷기 · 멈춘 시험 깨우기 · G2 실패 노드만 한 번 다시

함께 나가는 판: dddjango 2.31.0(같은 감시 도구 · 같은 깨우기 절차 — `workspace/plan/2026-11-04-test-watch/plan-2.31.0.md`).

## 문제(실레인 기록 · 대략 = 정규식 분류)

1. **멈춘 시험을 아무도 끄지 않는다** — 한 레인의 슬라이스 끝 시험(약 3,800개)이 90% 자리에서 6시간 멈췄다가 바깥에서 꺼졌고, 다시 돌려도 같은 자리에서 멈췄다. coder 는 배경 시험의 끝 알림이 와야만 깨어난다. 규칙에는 «끄는 법»만 있고 «무엇이 깨우나»가 없었다.
2. **슬라이스 끝 시험이 공용 부품 하나에 web 시험 거의 전부가 된다** — 공용 대화상자 CSS 한 파일을 바꾼 슬라이스가 13,761개를 44분 돌았다(«그 줄이 web 시험 전체를 덮어도 그대로 돈다»). 그 가운데 83% 는 HTML 만 보는 시험이라 CSS 가 바뀌어도 결과가 같다.
3. **흔들린 시험 하나에 줄 전체를 다시 돈다** — 따로 돌리면 통과하는 브라우저 시험 하나 때문에 12,828개를 16분 다시 돌았다.
4. (받아들임) 레인 사이 겹침 — 사용자 결정 «나중에 또 발생하면 해결».

슬라이스 끝 시험의 값: web 레인 18개에서 약 250번 · 합 20시간 이상(레인당 약 1시간). 실패가 난 36번 가운데 그 슬라이스가 고치지 않은 시험의 실패 20번 — 그중 16번은 제품 고침 없이 다음 실행에서 사라졌고(흔들림), 다른 화면을 깨뜨린 것을 실제로 잡은 것은 4번.

## 결정

- 사용자: «4번은 나중에 또 발생하면 해결» · «가.»(멈춘 시험은 시간 상한이 아니라 확인 절차 — «타임 아웃을 정하면 오래걸려서 실패하면 안될거 같은데? 오히려 테스트를 확인하는 절차를 넣어야 하는거 아니야?») · «가.»(dddjango 에도) · 계획 «진행해.»(슬라이스 끝 시험 걷기 확정 · 효과는 실레인 기록으로 갈음 · Codex 도 감시 도구로 끔).
- dddjango 는 이미 전체 suite 를 G2 앞 한 번만 돈다 — web 이 같은 꼴이 된다.

## 고침

- **슬라이스 끝 시험 걷기**: 러너 `--test-scope --since` 는 `슬라이스 끝 시험` 줄 · `= web 시험 전체` 줄을 내지 않는다(닫힘 계산 · 일꾼 상한 걷음). coder-web 의 슬라이스 끝 green = 마지막 편집 뒤에 돈 `계층 중 시험` 줄 exit 0. 일꾼 상한 6(10-20 사용자 «6개로해»)은 쓸 곳이 사라졌다. 설계자의 «기존 커버» 조사 길은 houserules §8 «거꾸로 참조 닫힘» 정의로 남긴다. 조정자 3 · 6 단계의 «web 시험 경로 밖 시험» 문장은 지우지 않고 `계층 중 시험` 줄을 가리키게 고쳤다(계층 줄에도 바뀐 밖 시험이 들 수 있다).
- **멈춘 시험 깨우기**: 새 도구 `scripts/test_watch.py`(run · attach · stop · list)와 pytest 기록 플러그인 `scripts/watch_probe/test_watch_probe.py`. 시험 명령을 새 묶음으로 띄우고 출력과 시험 기록이 10분 동안 그대로면 결과 줄 «멈춤 의심»과 5분 넘게 끝나지 않은 시험의 노드 id 로 깨운다(시험은 끄지 않음 · 느린 시험 실패 없음). 판정은 마지막 결과 줄(끝 exit · 멈춤 의심 · 끊김 · 끝 코드 모름 · 도구 오류). 조정자 · coder 의 깨어난 뒤 순서: attach 한 번 → 멈춤 확정이면 stop → 멈춘 노드만 한 번(그 실행에도 같은 순서) → 끝까지 돌면 원래 실행 한 번 다시(흔들림 보고 · 또 멈추면 판정 불가) · 결과 줄 없으면 list → attach · 끝나는 때 살아 있는 묶음 0. 출력을 모았다가 끝에 내는 `switch-check` 는 감싸지 않는다. coder-web 은 조정자가 플러그인 경로를 편 «감시 도구 실행문» 한 줄을 입력으로 받아 쓴다(역할 글에서 플러그인 경로 변수가 펴지지 않는다). 감시 폴더는 작업 트리의 git 디렉터리 아래(못 쓰면 `$TMPDIR`). 자식은 중단 신호를 기본 처리로 띄운다(셸 `&` 로 띄운 시험이 INT 를 무시하던 꼴).
- **G2 실패 노드만 한 번 다시**: 전수에서 web 시험 경로 안 시험이 붉으면 그 단계의 실패 노드만 모은 한 실행(`-n0`)을 한 번 — 다시 붉으면 반송 · 통과면 «요동»(반송한 노드는 세지 않음). 20개 넘으면 다시 돌지 않고 반송. 이번 실행이 쓰거나 고친 시험 파일(옮기기만 한 R100 빼고)의 노드는 다시 통과해도 반송. G2 배너 `시험:` 줄에 `요동 n · 멈춤 m`.
- **Codex**: 같은 도구를 앞에서 돌리고 셸 시간 제한을 넉넉히 준다. 감시로 돌린 실행은 `stop` 으로 끄고, 감싸지 않은 실행은 지금처럼 신호를 보내지 않는다.

## 행동 변화(전 → 후)

- 공용 CSS 하나를 고친 슬라이스: 슬라이스 끝에 web 시험 거의 전부(44분) → 그 슬라이스가 고친 시험 파일만.
- 배경 시험이 멈춤: 끝 알림을 기다리며 몇 시간 → 10분 뒤 깨어나 오래 도는 시험 이름을 받고 정해진 순서로 처리.
- G2 전수의 흔들림 하나: 줄 전체 다시(16~23분) → 실패 노드만 한 번.

## 설계 검토 · 행동 시험

- 독립 설계 검토: 차단 2 · 중요 9 · 사소 9 → 좁은 재확인 셋(마지막 차단 0). 고친 큰 것 — 출력을 모으는 실행은 감싸지 않음 · 실행마다 새 감시 폴더와 끝 코드 파일 · 브라우저 시험은 덤프에 시험 함수가 안 나와 노드 id 기록 플러그인으로 · 기록 플러그인은 스레드 없이 · 멈춤 순간에 목록 고정 · 플러그인을 못 실으면 한 번 다시 · 내 묶음 확인 · 결과 줄 없을 때 겹쳐 띄우지 않음. 검토 권고와 다르게 정한 것: Codex 도 감시 도구로 끈다(재확인에서 받아들여짐).
- 운영자 장난감 실측: xdist 일꾼에서도 기록이 닿음 · 노드 id 가 클래스 · 매개변수까지 정확 · 스레드 수 · join 시험 통과 · INT 무시 상태로 띄운 pytest 는 INT 에 꺼지지 않고(30초) 기본 처리면 0.3초.
- 행동 시험(새 판 규칙 글만 준 역할 셋 · 시간 상수를 줄인 도구 사본 · 장난감 저장소): web coder(조용히 멈추는 시험) · web 조정자(흔들림 · 진짜 깨짐 · 이번 실행이 쓴 흔들리는 시험) · dddjango coder — 셋 다 기대 판정(멈춤 확정 → 끔 → 노드만 → 결함 · 요동 1 / 반송 2 · 살아 있는 묶음 0). 역할이 짚은 모호한 곳(«그 결과 줄» · 노드 실행에도 같은 순서 · exit 75/70 · 끊긴 실행 요약은 green 근거 아님 · 반송 노드는 요동에 안 셈 · 고친 뒤 전수 다시)을 글에 반영. 옛 판의 멈춘 기다림은 실레인 기록(6시간)으로 갈음.
- 독립 구현 검토: 중요 4 · 사소 9 — 고친 것: coder 역할 글의 도구 경로(펴지지 않는 플러그인 경로 변수 → 조정자가 주는 절대 경로) · Codex 의 `attach` 셸 시간 제한 · 끊김 뒤 제한 늘리기 · README · 파일 트리 문서의 옛 슬라이스 끝 시험 글 · 도구의 내 묶음 확인 실패를 «확인 못 함»(신호 없음 · 목록에 보임)으로 · 셸 별칭 · 함수 안 씀 · web ↔ dddjango 도구 byte 대조 · `.venv-probe` 필요 표기. 다음 판으로 미룬 것: 러너 `Consumer.targets` · 감시 폴더 쌓임(아래 한계).

## 한계

- 다른 화면 깨짐은 G2 전수에서 처음 잡힌다(실측 4/250) → 반송 → 전수 한 번 더.
- 깨우기 · 끄기 · 끝 판정은 도구(결정적) · 깨어난 뒤 판단은 정해진 순서(모델). 멈춘 경우 처리 최악 약 2시간.
- Codex 실행 확인 없음(저장소 규칙 — 글만 같은 뜻).
- 감시 폴더는 지우지 않아 git 디렉터리 아래에 쌓인다(작업 트리를 지우면 함께 지워진다).
- macOS 에서 시스템 실행 파일만 남은 묶음은 표지를 볼 수 없어 «번호 재사용 의심»으로 신호 없이 끝난다(안전한 쪽).
- `switch-check` 묶음 정리 첫 칸(INT)도 셸 `&` 로 띄운 실행에서 헛돌 수 있다 — 다음 판 후보.
- 러너 `Consumer.targets` 는 이제 읽는 곳이 없다 — 다음 판 정리 후보.
- 효과 재기는 옛/새 A/B 대신 실레인 기록(아낀 시간 레인당 약 1시간 · 늘 비용 약 10분). 멈출 기준: 배포 뒤 첫 web 레인들에서 «다른 화면 깨짐으로 G2 반송» 이 레인당 1회를 넘으면 다시 연다.
