## CS1의 정의
- 문서 후보는 `design_system/`·제품 셸 밖 HTML 가운데 `view/` 바로 아래 템플릿 또는 자기를 extends하는 템플릿이 없는 것이다. 상속·block 덮음·`block.super`·include를 따라 렌더에 `<head>`가 있으면 문서, 없으면 조각이다. 다른 문서·조각의 렌더 집합에 들지 않는 조각만 조각 뿌리로 보고한다.
- 렌더 집합의 부품마다 문서 제품 뿌리의 같은 군·stem CSS가 있으면 필요하다. own 뿌리에 없고 평면 CSS만 있으면 own 경로가 빠짐이다. 상속당하는 `view/` 페이지와 머리를 include로 만든 문서도 본다. 지속 셸 문서를 면제하지 않는다.
- 실림은 머리의 살아 있는 stylesheet link와 그 CSS의 무조건 `@import` 닫힘이다. 경로를 글자로 적은 static 태그 또는 정적 경로만 읽는다. 변수·별칭·표현식과 rel·media·disabled·href 속성 안 동적 토큰(주소 꼬리의 변수 포함)은 동적 주소 미검증이고 template·noscript 안 link는 실림이 아니다. href의 Django 토큰을 보존해 겹따옴표·따옴표 없는 static 주소도 읽는다. `@import`는 첫 `{` 앞이고 꼬리 없음·`all`·`screen`만 받는다. 본문·인쇄 전용·disabled·alternate link·일반 `url()`·조건 꼬리 import·CSS 규칙 뒤 import는 실림이 아니다.
- include의 `with 이름="…html"` 글자 대입과 안쪽 with 글자 대입을 따라가고 `only`의 묶음 경계를 지킨다. for·변수 with가 가린 이름은 바깥 대입으로 풀지 않는다. block.super는 필터 없음 또는 `|safe`만 부모 block을 잇고 다른 필터는 못 읽음이며 실림으로 세지 않는다. 조건·for·template 안 include도 필요로 센다. 조건 안 머리 link로만 실리면 조건부 미검증이다. 진짜 변수 extends·include는 못 읽음, 동적 link 주소는 살아 있는 머리 link일 때만 못 읽음이다.
- 현재 트리와 기준점 트리를 같은 방식으로 계산한다. 판정 입력이 byte 같은 문서의 새 blocker는 건너뛰고, 입력이 바뀐 문서의 새로 빠진 (문서, CSS) 쌍만 blocker, 옛 빠짐의 기존 누락 알림만 판정 파일에 변경이 있는 문서로 한정한다. 새 미검증은 변경 파일 거름 없이 기준점에 없던 키 전부를 세 종류의 알림으로 보고한다. 파일 판독이 실패한 기준점의 누락을 기존으로 확정하지 않는다. 문서·CSS 이동은 정확한 git R100과 명세 슬라이스 0 `경로:` 행으로 대응하되 옛 파일은 기준점에만, 새 파일은 현재에만 있어야 한다.
- 승인 유입은 원인 파일 전부가 승인 병합 하나의 상류판·HEAD와 같은 바이트이고 작업 트리 수정 중이 아니어야 한다. 기준 뒤 원인 파일을 바꾼 첫 부모 걸음도 그 병합 하나뿐이어야 한다. 같은 발견이 그 병합 둘째 부모에만 있다는 L 증명도 그 병합에서만 받는다. 여러 병합에 원인이 나뉘거나 레인이 다시 고쳤으면 이 레인 몫이다.
- 출력은 구현된 문구 그대로 하우스룰 §8에 둔다. 미검증 종류는 조각·조건부·못 읽음이며 요약 건수는 표시 줄 수다. 미검증은 통과가 아니다.

## 명세와 닫기 절차
- 파일 목록 절의 `### 부품 CSS 표`에는 새로 짓거나 고치는 문서와 그 문서가 받는 조각 응답(임베드·hx-get 전용 — 고치지 않는 기존 조각도 포함), 받은 G0 미검증 중 그 문서가 받거나 그리는 항목을 모두 적는다. 칸은 `문서(또는 조각 응답) | 쓰는 부품 | 부품 CSS | 싣는 자리`다. 조각의 싣는 자리는 `받는 문서: <페이지>[ · <페이지> …]`이고 이번 범위의 받는 문서 전부와 각 문서 행의 같은 CSS가 있어야 한다. 표는 감수 근거이며 러너 입력이 아니다.
- G0의 기존 누락은 이번에 싣기 또는 둠(사유)으로 적고 범위 밖은 보고만 한다. 기존 CSS 누락 고침은 화면 모양을 바꾸므로 기능 슬라이스다. 리팩토링 모드에서는 이 표와 완성 그림 행을 쓰지 않고 기존 누락·미검증을 보고만 한다.
- Coordinator의 «부품 CSS 미검증»에서 정한 이번 요청 몫만 G0·슬라이스 끝·G2 직전 원문으로 `cs_unverified[]`에 모은다. G2 직전에는 그 출력에 없는 게이트 줄을 빼고 같은 조각·같은 자리를 한 항목으로 센다. 감수는 받는 문서 전부의 근거를 확인해 항목마다 `실림 — <받는 문서>:<줄>[ · <받는 문서>:<줄> …]` / `빠짐 — <받는 문서>` / `판정 못 함 — <사유>`로 답한다. 기능 요청의 이번 요청 몫에서 빠짐은 구현 반송, 표에 없는 조각은 설계 반송이다. 범위 밖은 «범위 밖 미검증 k건(보고만)», 리팩토링의 빠짐은 «빠짐(보고만 · 기능 요청 몫)»으로 올리며 CSS 추가로 반송하지 않는다. 판정 못 함은 검증 대기이고 배너·마무리 보고에 0건도 포함해 요약을 남긴다.
- G0는 화면별 동결 시안 렌더의 실제 픽셀 크기를 지정한 PNG 명령으로 읽어 `design_render`에 적고 창 크기를 확인한다. 2배 그림이라는 답이면 width·height는 절반 창 크기이며 `scale: 2`를 적는다. 설계는 `완성 그림: <화면> · 시안 <png> · 창 W×H · 상태 단언: <선택자> <기대> ; …`를 적는다. 고른 탭·목록 수·채운 값은 해당하면 모두, load 임베드는 자리마다 채워진 요소를 관찰한다. 관찰 0개 행은 ui 반송이다.
- 갈무리 case는 시험 트리의 기존 VM 대체 장치와 `tmp_path`만 쓴다. 루트 정확히 1개·행의 모든 상태 관찰을 자동 재시도 단언으로 통과한 뒤 `document.fonts.ready` → 바로 screenshot이다. 실패하면 그림이 없다. 감수는 순서와 관찰 전수를 확인하고 감수 뒤 case가 바뀌면 그 case만 다시 본다. G2는 그 case만 같은 러너·settings·실행 옵션으로 실행하고 매 행 실행 직후 `captures/`로 옮겨 지정 명령으로 창 W×H를 확인한 뒤 `captures/tmp`를 지운다. case 부재·수집 실패는 코더 반송이고 브라우저 부재·밖 실행 불가·거절만 미실행·검증 대기다. 이번 명세가 짓거나 고치는 `design_render` 화면의 행이 없으면 설계 반송이다. 픽셀 자동 비교는 하지 않는다.

## 한계·대가
- 가지를 구분하지 않는다. 한 번이라도 그려질 수 있는 include는 필요로 센다. 반례는 기존 «검사기 이의» 절차로 처리한다.

- `view/` 밖에서 상속당하는 템플릿을 직접 그리는 표준 밖 꼴은 문서 후보 밖이다.
- 거짓 승인 `경로:` 행으로 지운 문서와 새 문서를 맞대면 같은 CSS의 누락이 옛것으로 읽힐 수 있다. 다른 CSS의 새 누락은 그대로 blocker다.
- 원인이 여러 승인 병합에 나뉜 경우는 보수적으로 이 레인 몫이다. 지속 셸의 같은 누락은 SH4와 CS1이 함께 보고할 수 있다(고침은 머리 한 줄).
- 시안 렌더가 있는 화면의 갈무리에는 pytest-playwright·Chromium과 허용된 브라우저 실행 환경이 필요하다. 상태 단언의 통과와 사람이 보는 시각 일치는 다른 확인이다.

- 제품 교차 include는 쓰는 문서 제품 뿌리에 같은 stem CSS가 없으면 요구를 놓칠 수 있다. 감수가 교차 부품과 실제 CSS를 확인한다.
- block으로 head 전체를 감싼 셸은 머리 문맥을 정확히 읽지 못한다. 감수가 실제 렌더의 머리 link를 확인한다.
- `@import … layer()`와 `media="screen, print"`는 실림으로 읽지 않는다. 감수가 실제 화면 적용을 확인한다.
- 조건부 link의 import 닫힘은 조건부 집합에 잇지 않는다. 감수가 그 CSS의 import와 include 조건을 확인한다.
- `</head>` 생략은 본문 link를 머리로 오인할 수 있고 서로 include하는 조각 둘은 뿌리 보고에서 빠질 수 있다. 감수가 받는 문서와 렌더를 확인한다.
- verbatim·토큰 경계 읽기는 CS와 셸 도우미에 두 벌로 남는다. 감수가 경계 해석의 일치를 확인한다.
- 사용자 정의 inclusion 태그·Python에서 그리는 부품·`{% partialdef %}` 안의 link/include는 CS1이 잇지 못한다. 감수가 실제 부품 렌더와 CSS 실림을 확인한다.

## 2차 검토 반영
- P1: static 별칭의 대입·렌더 순서 해석을 삭제한다. 부품 CSS link는 문서 머리의 literal `{% static '…' %}`로 쓰며, checker는 이 형식 또는 literal 정적 경로만 센다. 변수·별칭·표현식과 rel/media/disabled/href의 동적 토큰은 `동적 link 주소`, `block.super`의 `|safe` 외 필터는 `block.super 필터 판독 불가`다. 필요 CSS는 그대로 미충족이며 literal 교정으로 닫는다.
- P2: BLOCKER만 같은 입력을 건너뛴다. 입력은 렌더 닫힘의 모든 템플릿(extends·include·block 출처), link CSS와 읽는 @import 닫힘의 내용, 필요한 CSS의 존재 여부, 제품 선언이다. 권한만 바뀌거나 index에서 빠져도 현물 바이트가 같으면 새 발견이 아니다. 링크↔일반 파일은 읽힌 본문이 달라지므로 변경이다. 기준점 목록 판독 실패를 빈 기준점으로 삼지 않는다. own CSS가 있으면 새 flat CSS는 그 문서의 필요 CSS 입력이 아니다. 미검증은 변경 파일 거름 없이 기준점 키만 비교하고 기존 누락 info 거름은 유지한다.
- P3: 파일 목록 밖 CSS·web 밖 템플릿·없는 include/extends 대상·없는 CSS 링크 대상은 부재다. 실제 git show·디코딩·링크 형식 등의 판독 실패만 기준점을 불확실하게 하며 그 문서의 누락은 기존으로 확정하지 않는다(P2 건너뛰기는 유지).
- P4: Git 이동은 R100만, 고친 이동은 승인된 슬라이스 0 `경로:` 행으로 대응한다. 스테이징하지 않은 이동은 한계다 — `git mv` 또는 명세 `경로:` 행을 쓴다.
- P5: 공용 `ctx.rename_pairs`를 삭제한다. 기존 검사는 두 fixture와 호스트의 TMP 사본에서 종수만 정규화해 2.4.1 도구와 byte 대조한다.
- 공유 조각을 이 실행이 만들거나 고치거나 CSS·문서 변경으로 조각 줄이 새로 나오면 요청 범위 밖까지 받는 문서 전부를 표에 적고 감수한다. 빠짐은 그 문서 머리를 고친다. 각 문서와 조각 행은 그 문서 제품 뿌리의 같은 군·같은 이름 CSS 경로를 구분한다.

## 3차 검토 반영 (2026-10-13 · 사용자 «가.» 12:25)
- 제품 소속: BLOCKER 건너뛰기(P2)는 문서의 제품 소속이 기준점과 다르면 다시 판정한다. 파일 삭제로 BC 가 area 로 읽혀 제품이 바뀌는 경우 — 렌더 입력은 같아도 필요 CSS 뿌리가 바뀐다.
- HTML 기호: `&#123;% static … %&#125;` 처럼 HTML 기호를 풀어 생긴 글자는 Django 토큰이 아니다. 원문 토큰이 있던 속성만 static 태그 · 동적 토큰으로 읽고, 나머지는 글자 주소로 읽는다.
- literal 경로 + SH4 꼬리: 동적 판정도 꼬리를 뗀 href 로 한다(P1′ 을 literal 경로에도 같게).
- `block.super` 필터: 필터가 붙어도 부모 block 은 렌더될 수 있다 — 부모 block 의 부품 요구는 세고 그 안 link 는 실림으로 세지 않는다. 머리면 지금처럼 `block.super 필터 판독 불가` 를 알린다.
- stylesheet 아닌 link(canonical · icon · preconnect …)는 주소가 동적이어도 미검증을 내지 않는다(rel 이 동적이면 그대로 미검증).
- G1′: hx-get · 임베드 자리를 더하거나 바꾸면 «부품 CSS 표» 가 있어도 생략하지 않는다(Claude · Codex 조정자 같은 글).

## 4차 검토 반영 (2026-10-13 · 사용자 «가.»)
- 토큰 출처는 href 조각마다 가린다: HTML 기호로 쓴 `{% static %}` 글자 + 진짜 SH4 꼬리는 실림이 아니고, 진짜 static + HTML 기호 꼬리(또는 줄을 넘는 `{{`)는 글자 꼬리라 실림이다.
- literal 정적 주소는 `/static/` 으로 시작해야 실림이다 — 맨 앞 `/` 없는 글자 주소는 페이지 주소 기준으로 풀린다.
- 제품 소속 비교는 파일 변경이 없어도 한다(빈 폴더로 area ↔ BC). 기준점 판독 실패로 제품을 못 정한 문서는 비교하지 않는다(같은 입력 보호 — 3차 고침의 회귀를 되돌림).
- 제품 소속만 바뀐 문서는 그 `application/<area>/` 아래 생성·삭제 파일을 원인으로 보고, 승인 병합이 들인 변화면 승인 유입으로 가른다.
- area 판별은 다른 검사처럼 작업 트리(빈 폴더 · 무시 파일 포함)를 따른다 — 로컬 파일이 area 를 바꾸면 손대지 않은 문서도 다시 판정된다(한계로 적음).

## 5차 검토 반영 (2026-10-13 · 사용자 «가.» — 고치고 재현만 확인 뒤 배포)
- static 태그 바로 뒤에는 `?`·`#` 꼬리만 온다 — 사이 공백은 주소 안 글자라 실림이 아니다(떼어 낸 SH4 꼬리 앞 공백 포함). 주소 끝 공백은 브라우저가 뗀다.
- 제품 소속 비교에서 빼는 것은 기준점 판독 실패로 제품을 잃은(None) 문서뿐이다 — 제품이 확정된 문서는 다른 렌더 파일 판독 실패와 함께여도 비교한다.
- area 생성·삭제를 원인에 더하는 것은 다른 원인이 없는(제품 소속만 바뀐) 문서뿐이다 — 선언 변경 승인 유입이 레인의 같은 BC 새 파일로 깨지지 않는다.
- 승인 유입 증명: HEAD 에 없는 원인 파일이 작업 트리에 있으면(무시 파일 포함) 이 레인 몫이다.
- 글: literal 주소는 맨 앞 `/` 이고 `.`·`..` 를 접은 결과가 `/static/` 아래일 때 실림이다.
