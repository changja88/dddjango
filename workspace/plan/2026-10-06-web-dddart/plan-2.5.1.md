# dddjango-web 2.5.1 — 프로젝트 루트가 저장소 하위 폴더일 때 판정을 맨 위 프로젝트와 같게

## 문제
- 프로젝트 루트(`manage.py` 가 있는 폴더)가 git 저장소 맨 위가 아니라 하위 폴더(`<저장소>/server/` 등)면 git 이 내는 경로 기준이 명령마다 달라(`ls-tree` 는 부른 폴더 기준 · diff · status 는 저장소 기준) 러너 · 도구가 조용히 틀렸다(첫 판부터).
  - 기준점 파일 목록이 늘 비어 ST 폴더 갈래 · ST4 · TG1 · PU2 · SH4 가 거짓으로 막고, SH4 · SH3 한 갈래는 거짓으로 통과.
  - `--subst-check` 거짓 막힘 · `--debt-residual` 이 이동을 못 봄(거짓 통과) · TG2 · TG3 미실행 · `refactor_audit.py residual` · `standing --gate` 의 판 대조 어긋남 · SDK «사용자 원문» 자리 금지가 하위 폴더에서 서지 않음.
- 같은 판에서 함께 고친 기존 결함(맨 위 프로젝트에도 있던 것):
  - 프로젝트 루트를 대소문자만 다른 철자로 넘기면(macOS 기본 볼륨 · `…/REPO` 처럼) 기준점 목록 · 바뀐 파일이 비어 거짓 막힘 · 거짓 통과가 났고, 승인 병합 유입 가르기를 조용히 건너뛰었다. 저장소 폴더 이름이 공백 · 줄바꿈으로 끝나도 승인 유입 가르기를 건너뛰었다.
  - `refactor_audit.py` 가 리뷰어 행 위치 · `check-verdict` 의 편집할 곳 · residual 해소 근거 · 해소 지문을 작업 트리에서 읽을 때 심볼릭 링크를 따라 또는 `..` · 절대 경로로 프로젝트 밖 파일을 읽어 받았다.
  - 하위 폴더 이름이 공백으로 시작하면 CS1 의 기준점 목록 · 개명과 WV10 이 접두의 앞 공백을 깎아 읽었다(CS1 거짓 막힘 · WV10 거짓 통과). 하위 폴더 이름에 한글(비ASCII)이 들면 벤더 시대 판정이 git 이 따옴표로 감싼 경로를 읽어 목록 이전 사본을 거짓 WV13 으로 막고 그 SDK 의 정식 등재를 되돌렸다.
  - git 기본 설정(`core.quotePath=true`)에서 한글 이름 파일의 git 개명을 빚 잔존이 이동으로 보지 못했다(«ⓑ 이동 묶음 의존» 이 서지 않음 · 승인 병합이 들인 이동 알림이 나지 않음).
  - 사용자 git 설정 `grep.fullName=true` 인 하위 폴더 프로젝트에서는 `refactor_audit.py plan` 의 참조 조회가 조용히 0 이었고, `log.showRoot=false` 면 목록과 벤더 파일을 함께 들인 첫 커밋을 못 봐 WV13 이 사라졌다.
- 지금 그런 꼴의 실제 프로젝트는 없다(재현으로 확인한 기존 결함).

## 고침 (소스 10 파일 · 32 자리 · Codex byte 미러)
- git 경로의 기준은 둘이다.
  - 저장소 기준 — 게이트(`src/common.py`)와 벤더 검사(`src/check_vendor.py`)는 저장소 기준 경로에서 프로젝트 접두를 떼는 코드라 git 출력을 저장소 기준으로 맞춘다: 기준점 목록은 `ls-tree --full-tree` · 두 모듈의 git 호출에 `-c diff.relative=false`(`common.py` 의 `_git_raw` · `check_vendor.py` 의 `_git`). 벤더 검사의 git 호출은 `-c core.quotePath=false -c log.showRoot=true` 도 함께 준다.
  - 프로젝트 루트 기준 — 치환 확인(`src/subst.py`) · 빚 잔존(`src/debt.py`) · 바뀐 시험(`src/check_tests.py`) · `refactor_audit.py` 는 명세 · 기록 · 시험 경로가 모두 폴더 기준 글자라 git 출력을 폴더 기준으로 맞춘다: `--relative` · `<판>:./<경로>`. 빚 잔존의 개명 · 머리 목록 읽기 셋에 `-c core.quotePath=false`.
- 사용자가 적는 경로 두 자리(`--except` · 상시 답 위치)는 정규형일 때만 `:./` 로 읽고 아니면 2.5.0 처럼 읽는다. 접은 경로가 프로젝트 밖(`..`)으로 나가면 읽지 않는다.
- 프로젝트 접두는 넘겨받은 루트 글자로 셈하지 않고 git 에게 묻는다(`rev-parse --show-prefix` — `src/common.py` · `src/inflow.py`). 승인 유입의 링크 조사도 그 접두로 프로젝트 자리를 잡는다. 접두는 줄바꿈만 떼고 앞뒤 공백은 그대로 둔다(`src/common.py` · `src/inflow.py` · `src/sdk_registry.py` · `src/check_component_css.py` 세 자리 · `src/check_vendor.py`). 승인 유입의 저장소 최상위 경로는 끝 줄바꿈 하나만 뗀다(`src/inflow.py`).
- `src/sdk_registry.py` SDK «사용자 원문» 자리 금지를 프로젝트 접두 기준으로 — 쓴 글자의 첫 성분이 `web` · `.dddjango-web` 이면(저장소 뿌리의 web/ · 2.5.0 과 같은 뜻) 또는 `./` 로 시작하는 글자를 접은 경로 · 저장소 기준 글자가 프로젝트의 web/ · .dddjango-web/ 안(폴더 자체 포함)이면 거절.
- `refactor_audit.py` 는 작업 트리의 위치 · 지문 파일을 실제 경로(realpath)가 해석된 프로젝트 루트 안의 일반 파일일 때만 읽는다(새 함수 `_inside` 하나 — `_location_ok` · `_file_sha`). 프로젝트 안을 가리키는 링크와 루트 자체가 링크인 꼴은 그대로 받는다. 경로가 될 수 없는 글자(NUL)는 2.5.0 처럼 «없음».
- 두 `git grep` 호출(`src/debt.py` 의 참조 조회 · `sdk_vendor.py` 의 템플릿 참조 줄)에 `-c grep.fullName=false`.

## 바뀌는 동작
- 하위 폴더 프로젝트: 게이트 · 치환 확인 · 빚 잔존 · refactor_audit 판정이 맨 위 프로젝트와 같다(아래 «한계» 의 갈래는 빼고). 저장소 기준 철자(`server/…`)나 프로젝트 밖 글자(`../…`)로 쓴 `--except` 는 exit 1, 상시 답 위치는 ③ red. 하위 폴더 이름에 한글이 들어도 목록 이전 같은 자리 사본이 빚(WV12)으로 남고 SDK 정식 등재가 선다.
- 맨 위 프로젝트 — 일부러 바꾼 여섯 갈래:
  - SDK «사용자 원문» 출처를 `./` 로 시작하는 글자로 web/ · .dddjango-web/ 안(파일 · 폴더 자체)을 가리키면 이제 거절(전에는 자리 금지를 지나 받았다). 끝 빗금 철자(`./web/…/note.py/`)는 전에도 거절이었고 사유 글만 «원문 파일 … 없다» 에서 «web/ 안» 으로 바뀐다.
  - 프로젝트 루트를 대소문자만 다른 철자(또는 한글 이름의 자모 분리 · 합친 꼴이 디스크와 다른 철자)로 넘겨도, 저장소 폴더 이름이 공백 · 줄바꿈으로 끝나도 정상 판정이다(전에는 기준점부터 있던 폴더 · 기존 단위의 거짓 막힘, 지운 자산의 SH4 · 선언 삭제 뒤 SH3 · 상대 import IM24 의 거짓 통과, 승인 유입 가르기 건너뜀).
  - `refactor_audit.py` 에서 심볼릭 링크를 따라 또는 `..` · 절대 경로로 프로젝트 밖 파일에 닿는 위치는 읽지 않는다 — `check-verdict` 의 별도 요청(web/ 밖 · 경계 교차) 편집할 곳은 «편집할 곳 … 실재하지 않는다» 로 채택 재분류(2.5.0 은 밖 파일을 읽어 별도 요청으로 받았다 · 모노레포 하위 폴더에서 `../shared/…` 를 편집할 곳으로 든 별도 요청도 채택으로 돌아간다), residual 해소 근거 · `check` 의 리뷰어 행 위치는 밖으로 풀리는 링크일 때 «근거 판형 아님» · «인용 불일치»(`..` · 절대 경로는 2.5.0 도 판형 · 범위 검사로 거절했다), 앞 확정의 해소 지문에 밖 링크 경로가 있으면 이월하지 않고 다시 리뷰어 확인 대상이다.
  - 한글 이름 파일의 git 개명을 빚 잔존(`--debt-residual` · `refactor_audit.py residual` 의 의미 ⓑ 키 — 2.5.0 exit 2 → 1)이 이동으로 본다 — 미룬 키의 파일을 옮기면 «ⓑ 이동 묶음 의존» 으로 멈추고, 승인 병합이 상류판 그대로 들인 개명은 알림과 함께 뺀다.
  - 사용자 git 설정 `log.showRoot=false` 여도 목록 시대 첫 커밋의 벤더 내용을 본다(WV13).
  - 벤더 파일 이름 자체가 비ASCII 이면 벤더 시대 판정이 그 경로를 따옴표 없이 읽는다(같은 결함의 맨 위 갈래).
- 그 밖의 맨 위 출력은 2.5.0 과 같다. 사용자 git 설정 `grep.fullName` · 접두의 공백 고침은 맨 위에서 출력이 같다.
- 빚 지문 `e49c83776ff9faf6` · 검사 92종 무변.

## 한계
- 0T 확인 도구(`refactor_audit.py switch-check`)는 하위 폴더 루트 · 대소문자만 다른 루트 철자 · 이름이 공백으로 끝나는 저장소를 계속 거절한다(큰 소리).
- 하위 폴더 프로젝트에서 경로의 기준이 둘이다 — 명세 행 · `--except` · 상시 답 위치 · residual 근거는 프로젝트 루트 기준, SDK 출처만 저장소 기준. 글의 «저장소 상대 경로» 문장은 이번 판에서 고치지 않았다(뒤 판 후보).
- 프로젝트 폴더 이름이 `web`(또는 `.dddjango-web`)이면 SDK 출처를 저장소 기준 철자(`web/docs/…`)로 적을 때 2.5.0 처럼 거절된다 — `./docs/…` 로 적는다.
- 두 인자를 받아 서로 견주는 도구(`--debt-residual <폴더>` · `sdk_vendor.py install --build`)는 루트와 폴더의 대소문자 철자가 서로 다르면 «… 아래 폴더여야 한다» 로 거절한다(큰 소리).
- 프로젝트 밖 파일을 편집할 곳으로 드는 «web/ 밖» 별도 요청은 받지 않는다(채택으로 재분류) — 모노레포의 다른 폴더를 고쳐야 하는 일은 별도 요청이 아니라 다른 요청으로 넘긴다.
- 빚 잔존의 개명 읽기는 따옴표 · 탭 · 줄바꿈이 든 파일 이름(git 이 비ASCII 와 따로 감싸는 글자)을 여전히 놓친다. 같은 까닭으로 하위 폴더 이름(또는 벤더 경로)에 따옴표 · 탭 · 줄바꿈이 들면 벤더 시대 판정이 목록 이전 같은 자리 사본을 거짓 WV13 으로 막고 그 SDK 정식 등재를 되돌린다(2.5.0 부터 · 2.5.2 에서 `-z` 읽기로).
- 오류 글 · 표시 글 세 곳(«미커밋 web/ 밖 변경 — …» · «범위 파일 변경 […]» · WV10 위반 글)의 경로는 저장소 기준 꼴로 남는다(판정과 무관).
- 다른 사용자 git 설정은 `diff.relative` · `grep.fullName` · `log.showRoot`(벤더 검사) · `core.quotePath`(벤더 검사 · 빚 잔존 개명)만 막았다.
- 알려진 기존 결함(2.5.0 부터 · 2.5.2 로 미룸): `refactor_audit.py plan` 의 조각 줄 수 셈이 밖으로 풀리는 링크 파일을 읽는다(판정 아님) · SDK 사본 검사(WV2)가 링크 성분을 문제로 적은 뒤에도 링크를 따라 밖 바이트를 읽는다(판정은 거절 그대로) · 사용자 git 설정 `color.ui` · `color.diff=always` 면 게이트의 더한 줄 범위가 비어 IM24 가 거짓 통과하고, `color.ui` · `color.grep=always` 면 `plan` 의 참조 조회가 실행 불능 · `grep.column=true` 면 참조 조회가 열 번호를 줄 글로 읽는다 · 0T 확인 도구의 저장소 최상위 경로도 끝 공백을 깎는다(큰 소리 거절).
- git 은 2.54.0 하나로만 쟀다.
