## 넣은 것
### 계약 E1 — G1·G1′ 배너와 답 받음
- 배너 직전 `shasum -a 256 <산출물 폴더>/design-spec.md`(없으면 `sha256sum`) 한 번 → `명세 sha <앞 12자>` → `g1_decisions`의 `G1 배너:` 또는 `G1′ 배너:` 줄(시각 포함).
- 답 받음에 같은 명령 한 번. 지문으로 판을 가리킨 답은 X의 길이만큼(12자 이상) 지금 값과 앞에서부터 대조하고, 지문 없는 승인은 마지막 배너 줄과 대조한다. 같으면 `G1 승인:` 또는 `G1′ 승인:` 줄에 지문과 출처를 적는다.
- 다르면 승인으로 받지 않고 방금 잰 값으로 배너를 다시 내며 그 값의 `G1 배너:` 줄을 새로 적는다(배너 행은 지금 명세에서 다시 뽑음). 지문 12자 미만 · 커밋으로 가리킨 판 · 지문 없는 승인인데 배너 줄 없음(앞 판 배너)은 판정 불가로 같은 방식으로 다시 낸다. 명세 읽기 불능은 사유를 보이며 다시 묻는다. 대조는 그 배너의 명세 승인 답만 — SDK 지문 · `candidate_token` · 출처 커밋은 판 지정이 아니고, 같은 배너의 다른 문항 답이나 이미 받은 승인의 되풀이는 다시 재지 않는다. staged · unstaged · 미추적 · git 무시 · 비git 모두 같은 파일 바이트를 판정한다.

## A/B 판정 기준(설계 v2 §5 · 실행 전 고정)
- 같은 `S/sha-ab/snapG1`에서 A1(옛 Codex) · B1(새 Codex) · C1(옛 Claude · 참고) · N1(새 Codex · 미커밋 명세 한 줄 변경 후 옛 지문 승인)을 나눈다. A1 · B1 · C1은 첫 슬라이스 green(G2 전), N1은 조정자의 첫 답에서 멈춘다.
- 성립: A1에서 Hw ≥ 3 또는 R ≥ 1. 아니면 재현 실패로 보류하고 사용자에게 배포 판단을 묻는다. Hw/Hc는 직접 계산 명령만 세며 정해진 도구 실행과 커밋 해시는 빼고, R은 역할의 과제·후속 입력에 담긴 승인 지문의 수다.
- B1: Hw = 0 · R = 0 · G1 Hc ≤ 2 · `G1 승인: 명세 sha …` 줄 · 첫 슬라이스 green · coder 시험 실행/슬라이스 끝 백스톱/조정자 슬라이스 끝 검사 각각 ≥ 1. 하나라도 어기면 배포하지 않고 한 번 보완·재시험하며 두 번째 실패는 멈춘다.
