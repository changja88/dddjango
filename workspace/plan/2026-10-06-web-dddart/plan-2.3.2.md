### 계약 A — 메서드 이동(치환 확인 `--subst-check`)
- **승인 행**(명세 `## 슬라이스 0` 절): `메서드 이동: <옛 모듈>.<옛 클래스>.<옛 메서드> → <새 모듈>.<새 클래스>.<새 메서드> · 시험 <파일>::<함수> [<파일>::<함수> …]` — 경로 꼴 `^web(\.[a-z_][a-z0-9_]*)+\.[A-Z]\w*\.[A-Za-z_]\w*$`(식별자 ASCII) · 시험 = 저장소 상대 경로의 시험 파일 `::` 최상위 함수(클래스 안 시험 · 글롭 불가). G1(G1′) 배너 1급 행 `메서드 이동 k건 — <옛> → <새> · 시험 n 함수(목록)`(`이름:` 행과 같은 급). 승인 행 판독은 `debt.py` 한 곳이다(`메서드 이동:` = 치환 확인 · `plan --names` / `시험 전환:` = 치환 확인 · `switch-check`).

- **제품 쪽 확인**(git blob): 기준 판에 옛 def · 대상 판에 새 def · 대상 판에 옛 def 가 남으면(클래스 본문의 조건문 아래 포함) «이동이 아니다» red · 해석할 수 없는 구조는 판정 불가 exit 1. 옮긴 본문이 다르면 `[info] 메서드 이동 <옛> → <새> — 옮긴 본문 다름(동작 불변 근거는 명세 · 감수)` — architect 가 보존 근거를 적고 감수가 필수로 확인하며 G2 배너에 알림 원문을 올린다.

## 알려진 한계
- **0T 정적 대조는 동등성 증명이 아니다 — 기대값 무변은 도구가 보장하지 않는다**(결정 26 · 재현 `fix232-n.md` v1): 남은 준비 문장이 만든 별칭(첨자 · 속성으로 꺼낸 이름 · 내장 타입 메서드 호출)을 거쳐 기대 객체를 넓히는 0T 는 치환 확인과 `switch-check` 를 모두 지난다(`switch-check` 는 반례에서 옛 · 새가 같은 순번 단언에서 실패하는지만 본다 — 반례가 내지 않는 값으로 넓힌 기대값은 못 막는다). 같은 부류: 바탕 시험 모듈의 도움 함수가 모듈 기대값을 바꿈 · 입력 객체 그래프를 거친 속성 대입 · 값 잎 보존을 지키며 입력을 바꿔치기. 막는 자리 = 0T 경량 감수 ④ · 보호 실패마다 하나인 반례. 기대값을 비우는 꼴은 `switch-check` 가 막는다. 새 감수 문장이 실제 레인에서 이 꼴을 잡는지는 미확인.
- **0T 로 못 받는 옳은 꼴**(막는 쪽): 위 «경계» 의 좁은 범위에 더해 — 단언이 읽는 이름(입력 객체 · import · enum · parametrize 인자)을 새 준비 문장에서 읽는 꼴 · 시험 함수 인자(fixture)의 메서드를 새로 부르는 꼴(비켜 가기: 새 행위 인자 안에서 넘김 · `RequestFactory()` 로 직접 만듦 — 실측 막힘 다섯 exit 2 · 비켜 가는 꼴 exit 0) · 모듈 안에서 정의 · 대입한 장식자가 붙은 시험(판정 불가) · 한 줄 단언 둘 · 반복문 안 단언의 실패. 6-3-33 의 상담 화면 도움 함수 `_saved_intent`(모듈 머리 import · 한 시험이 두 번 부름)는 화면 함수 안으로 넣는 정리라면 못 받는다 — 합치기 일꾼의 추정이고 레인 기록으로 확인하지 않았다.
- **진행 중인 슬라이스 0 에는 0T 를 끼울 수 없다**(6-3-26 이 그 상태 — 레인 기록 사본 기준 슬라이스 0 작업이 커밋 없이 작업 트리에 있다): 미커밋 작업을 둔 채면 `switch-check` 가 거절하고, 먼저 커밋하면 «0T 는 첫 0C 앞» 에 걸린다 → 지금 작업을 커밋하고 새 요청으로 다시 시작해 슬라이스 0 첫 커밋 앞에서 0T 를 연다.
- **`switch-check` 의 입력 · 환경**: `--test-cmd` 에서 시험 경로 · 고르는 선택지(`-k` · `-m` · `-x` · `--deselect` · `--lf` · `--maxfail` 등)를 빼야 한다(남기면 실행 전 거절) · `-n`(xdist)은 거절하지 않지만 판독을 확인하지 못해 빼라고 적었다 · addopts · `PYTEST_ADDOPTS` · conftest 가 대상 case 를 거르면 미검증 · `python -m <pytest 가 아닌 모듈>` 감싸개는 `-m` 으로 잘못 거절할 수 있다 · 맥락 줄이 없는 반례 diff(`@@ -2 +2 @@` 꼴)는 줄 번호 · 내용이 맞아도 `git apply --check` 가 거절해 실행 불능이다(architect 는 통합 diff 를 손으로 쓴다) · pytest-xdist · DB · 브라우저 · 컨테이너 · `uv run` 시험 명령 미확인 · Python 3.14.8 · macOS 에서만 돌렸다 · 실행 수는 행마다 (4 + 4 × 반례) 번이라 백그라운드로 돌린다(글에 적음).
- **끊김과 복구**: SIGTERM 처리가 없다 — 끊기면 반례가 작업 트리에 남고 다음 호출이 먼저 복구한다(취소 · 작업 중단 전에 `pending` 을 비운다 — 글에 적음) · 끊긴 뒤 명세 행을 바꾸면 복구 불능(손대지 않고 멈춤 — 명세를 되돌려 다시 부른다) · 도구 임시 폴더는 만든 직후 기록 전에 죽으면 남는다 · 위조한 복구 기록의 임시 폴더 정리는 «도구가 만든 꼴» 까지만 확인한다.
- **메서드 이동**: «옛 def 남음» 은 클래스 본문 구문만 본다 — 클래스 밖 대입(`Old.m = New.m`) · `setattr` · 상속으로 남는 옛 메서드는 «없음» 으로 읽힌다(감수의 보존 근거 몫) · 자리 꼴은 다섯뿐(동적 `getattr` · fixture 가 돌려준 인스턴스 · `self.vm` · 팩토리 · `@patch` decorator 꼴은 red) · 본문이 같아도 동작이 같다는 증명은 아니다 · 시험 커밋이 새 클래스를 만드는 제품 커밋보다 앞서면 거짓 red · 꼴이 어긋난 `메서드 이동:` 줄(끝 마침표 · 쉼표 목록 · `->` · 줄 전체 백틱 등)은 «행 없음» 과 같은 red 가 된다 · 옛 클래스 이름을 재수출 · TYPE_CHECKING import 하는 모듈은 판정 불가 · `plan --names` 의 메서드 적중은 낱말 일치라 흔한 이름이면 늘어난다.
- **신뢰 경계**: 치환 확인은 `verified` 기록과 증거 파일이 있는지만 본다(내용은 `switch-check` 가 대조 — 끝 green ④ · G2 직전에 한 번 더 부르라고 글에 적음) · 0T 앞 커밋 대조는 행의 시험 파일 · 보호 분기 파일만 지킨다 — 보호 분기 밖 제품 동작 변화는 끝 green ⑤ 의 전체 시험과 G2 감수 몫이다(`switch-check` 가 막는다고 읽지 않는다) · 0T 뒤(0C 앞) 기록 없는 커밋이 보호 분기 파일을 바꾸면 치환 확인은 exit 0 이고 `switch-check` 만 시작 거절한다(글은 STOP) · 배포 전 후보가 만든 증거(실행 결과 칸 없음)는 exit 1 — 다시 검증한다.
- **ⓑ 정형**: 활성 경계는 결정 줄의 꼴이다 — `미룸 유형 =` 칸이 `· 결정 =` 과 같은 줄에 없으면 새 행은 조용히 무시된다(요약 꼬리 ` · legacy 잔존 ⓑ …` 가 없으면 비활성) · 출처 검사는 머리 글자만 본다(참 · 거짓은 Coordinator 몫) · 스캔 표의 «해로움» 판정과 의미 의존은 기계가 안 본다 · 검증은 `--debt-residual` 을 돌릴 때(슬라이스 0 끝 green ② · G2)에만 선다 · 미룬 키의 발견이 0 이면 줄은 나오는데 요약 꼬리는 그 키를 빼 어긋난다.
- **`{% static %}`**: 템플릿으로 서지 않는 꼴은 과보고 쪽이다 — 주석 뒤 붙은 필터(`'…'{# c #}|upper`) · `{% verbatim %}` 안 · 닫히지 않은 태그 뒤 같은 줄의 안쪽 태그.
- **글 · 픽스처**(덜 적힘 — 어긋남은 아니다): discipline-test reference 의 0T 문단은 conftest · fixture · 한 줄 단언 둘 · 반복문 조건을 적지 않는다 · 하우스룰은 «단언이 읽는 이름과 같은 이름의 속성도 읽는 것으로 본다» 를 적지 않는다(도구가 더 좁다) · 리팩토링 상시 답과 `시험 전환:` 행이 함께 있을 때 «상시 답이 먼저» 를 무엇으로 가르는지 한 구가 없다(어느 쪽으로 읽어도 닫힌 쪽) · 새 픽스처 파일 이름과 끝줄의 판 글자는 «231 · 2.3.1» 그대로이고 재현 장면 묶음(22)은 장면 변수를 줄 때만 돈다 · 글 계약 픽스처는 커밋 밖이다.
- 실제 에이전트 레인을 새로 돌린 시험은 없다 — 재현 장면 · 실연 프로젝트 · 고정 장면 여덟 · 호스트 시점별 사본에서 도구로 확인.
