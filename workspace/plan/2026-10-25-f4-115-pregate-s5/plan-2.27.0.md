## 설계 요지

### A1 — update 도메인 서비스 서명(#304 · #305 · #307 · #308)
- 대상 칸 = 검사기 선택(`vocab.bc_dirs` → `_has_adoption_signal` → `<bc>/domain_layer/domain_service` → `slot_glob(…, "*.py")` · `__init__.py` 뺌 — 번들 `check-domain-model.py` 의 함수를 그대로 부름) ∩ file-plan update(계획 경로는 정규화 · 승격 칸은 본체로 맞춤). add 칸은 스텁이 registry 에 실려 이미 귀속되므로 넣지 않는다.
- 재료: symbols 의 클래스 · 메서드 행과 모듈 함수 행 · 명시 import · 전사 전 기준선 실물(`forecast_baseline` — 앵커 커밋 뒤 · materialize 전 · 저장소 예보 기준선과 같은 자리).
- 투영 = 기준선 전 깊이 import + 명시 import + 기준선과 서명(수신자 뺀 인자 이름 · 주석 · 반환 주석)이 다르거나 새로 생긴 공개 이름의 메서드 · 모듈 함수(본문 `...`). `_` 로 시작하는 이름은 뺀다(검사기와 같다 — 클래스 이름은 보지 않는다: 사설 클래스의 공개 메서드는 판정).
- 칸마다 빈 폴더 둘(`domain-service/<n>/decl` · `…/base` — 기준선 실물도 같은 판정)에서 `_check_domain_services()` 를 부르고 폴더째 지운다. 결과는 «경로 + 줄» 로 투영 행에 맞춘다(같은 BC 두 칸이 섞이지 않는다).
- 기존 빚 열쇠 = G2 와 같은 «파일 · 규칙 · 판정문»(판정문에는 클래스 이름이 없다 — #307 · #308 은 함수 이름, #304 · #305 는 인자 이름만 싣는다):
  - 기준선에 없음 → **선언 확정**
  - 있음 · 같은 소유자(그 자리 · 그 이름) → 뺀다(기존 빚 · G2 도 0)
  - 있음 · 다른 소유자 → (가) 그 판정문의 기준선 소유자를 이 명세가 **모두** 고쳐 다시 적어 그 줄이 사라지면 **확정**(바꿔치기) · (나) 기준선 소유자들과 함수 이름이 다르면 **확정**(같은 인자 이름의 #304 · #305 — 새 정의 · K2) · (다) 같은 함수 이름이 다른 자리에 있으면 **후보**(클래스 개명 K1 · 모듈 함수 → 메서드 K3 · 조상 정의 다시 적기 K4 · 중첩 함수 · 두 소유자 가운데 하나만 고침)
  - 소유자 = 함수 정의 줄을 둘러싼 자리(클래스 직계 = 클래스 이름 · 모듈 직계 = "" · 그 밖 = 자리 경로).
- 기준선 읽기 · 파싱 불능 · 같은 이름 클래스 · 메서드 · 함수 중복 → 그 서명의 검사기 판정이 있을 때만 후보(규칙은 검사기가 낸 그대로 — 규칙과 무관한 후보를 내지 않는다) · 기존 빚으로 빼지도 않는다.
- 남기는 규칙은 #304 · #305 · #307 · #308 뿐(#301 · #302 · #303 · #310 · #311 은 투영이 파일 일부라 셀 수 없다).
- «확정» = G2 귀속 ∪ G2 집합 차분이 지우는 실검사기 새 줄((가) · (나) — F4-73 과 같은 쪽의 엄격 구석). 후보로 내린 (다)는 실검사기 줄 수가 그대로인 꼴(1 → 1)이다.

### A2 — 예외 번역표 «번역 출처» 칸(#474 · #62)
- 문법: `<published 예외><탭|2+공백><raise 창구 파일>[<탭|2+공백><= <잡는 예외 맨 이름>[ as]]`. 점 이름 · `as <이름>` · `AS` · `<-` · 괄호 묶음 · 공백 하나 · 끝 주석은 형식 red. 셋째 칸이 없는 행은 지금과 같다(블록 해시 무변 — 2.26.1 과 대조).
- 판정 대상 = 창구 경로가 검사기 OHS 선택(`…/application/<bc>/driving_layer/open_host_service/**/*_service.py`)과 같은 행. 그 밖 행의 출처 칸 = 판정 0 + 채널 메모 1행.
- `Exception` · `BaseException` 출처 → `as` 와 무관하게 최소 catch 투영을 검사기 트리 슬라이스(`_slice_check_controller_ast`)에 돌려 **#62 확정**.
- 그 밖 출처 해소(검사기 조건 그대로 — 절대 `ImportFrom` · 모듈 마디 `domain_layer` · 전 깊이 · 지역 이름 = asname|name · 처음 찾은 출처에서 멈춤): ① 그 창구 칸의 boundary-imports(소비 경로 정규화) ② update 면 기준선 실물 ③ 이 명세 symbols 의 같은 이름 클래스(하나뿐) ④ 내장 예외.
  - `as` ∧ 도메인 → 최소 투영(그 import + `except X as _caught: _caught`) → **#474 확정**
  - `as` ∧ 가를 수 없음 → **후보**(물음: domain_layer 것이면 그 import 를 boundary-imports 에)
  - 비도메인 · 내장 · `as` 없음 → 0
- update 창구 행마다 메모: (a) 출처 칸 없음 → «S5 입구 catch 미검증» · (b) `as` 없음 ∧ 도메인 · 해소 불가 → «S5 입구 catch 확인(… OHS 는 잡은 도메인 예외 값을 쓰지 않는다(R-3690) …)». 투영은 칸마다 빈 폴더(`catch/<n>`)에 쓰고 지운다.
- 처분: 새 선언 확정(#304 · #305 · #307 · #308 · #474 · #62)은 다른 선언 확정(#197 · #202 · #355 · #597 · #541)과 같게 `ignored` · `filtered` 를 받는다(`--check-report` 무변 — #574 만 filtered 불인정).

## 받아들인 한계
1. **K8 — 낡은 출처 칸**: 출처 칸은 architect 의 자기 신고다. `as` 없이 적힌 칸은 «타입으로만»(올바름)과 가를 수 없어 예보가 서지 않는다 — 메모 (b) 가 매 실행 같은 자리를 짚고(올바른 설계에서도 뜬다 — 받아들인 소음), R-3689(본문만 바뀌어도 칸을 고쳐 적음) · R-3690(OHS 는 잡은 값을 읽지 않음) · G2 registry 가 막는다. 그래서 현장 반송의 #474 쪽은 «architect 가 R-3689 · R-3690 을 지켰다면» 의 조건부로만 당겨진다(#308 쪽은 symbols 에 적혀 있어 조건 없이 당겨진다).
2. **놓침 셋**: ① 번역 없는 OHS catch(값을 읽고 `None` 을 돌려주는 꼴 — 번역표에 실을 행이 없다) ② symbols 에 적지 않은 기존 메서드 서명 바꿈(R-3426 개정으로 의무가 됐지만 지키지 않으면 G2 몫) ③ update 칸 import 규칙(#288 · #303 등 — S3). 모두 G2 registry 가 잡는다.
3. **엄격 구석**: 도메인 서비스 (가) · (나)와 저장소 F4-73 은 G2 집합 차분이 지우는 새 줄도 확정한다 — G2 가 통과시키는 확정이 설 수 있고(기존 줄을 지운 개명 #304 등), 처분은 고침 · 빚 목록 · filtered 다. (다)는 후보라 «기존 줄이 그대로 남는 새 자리» 는 물음으로만 남는다.
4. **시간**: A1 은 투영 칸당 3 ~ 6ms · 칸 수에 선형(칸마다 빈 폴더 — 200 칸 시험 · 현장 9 칸 판정 16 ~ 26ms). 대상 칸이 있으면 검사기 대상 선택(`bc_dirs`)으로 사본 트리를 한 번 훑는다(저장소 예보의 `_find_bcs` 와 같은 꼴 — 현장 크기 사본 꼴(약 1.4만 파일)에서 약 0.3 ~ 0.4s). A2 는 투영 행 하나에 수 ms(검사기 적재 포함 첫 행 수십 ms). 대상이 없으면 검사기를 적재하지 않는다.
5. 판 섞임: 옛 실행기 + 새 칸 = 형식 red. 레인 안에서는 툴체인 stale 이 막는다. 배포 뒤 진행 레인의 첫 재예보에서 새 확정이 설 수 있다.
