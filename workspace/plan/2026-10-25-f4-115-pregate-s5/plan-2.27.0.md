# dddjango 2.27.0 — pre-gate 사각 S5 의 update 칸 두 자리를 선언 예보로(F4-115) (10-25)

## 바탕
- 바탕: main(dddjango 2.26.1 · dddjango-web 2.8.2 배포와 봉인 정렬 뒤). 2.27.0 은 minor — 명세 문법에 선택 칸이 생기고(옛 실행기는 새 칸을 형식 red 로 읽는다), 바뀌지 않은 명세에도 새 선언 확정(exit 2)이 설 수 있다. 매니페스트 판은 `make release` 가 올린다. dddjango-web 무변.
- 결함(장부 F4-115): 현장 레인의 G2 앞 registry 가 #474 · #308 새 귀속으로 설계 반송을 냈는데, G1 pre-gate 는 귀속 0 이었다. 둘 다 update 칸 본문(사각 S5)이라 전사도 선언 검증도 닿지 않았다 — ① update 도메인 서비스 칸에 공개 `-> bool` 메서드를 더한 symbols(#308) ② update OHS 창구가 잡은 도메인 예외 값을 로그에 쓰는 catch(산문에만 적힘 · #474).
- 설계: 1판 → 적대 검토(차단 0 · 중요 3 · 사소 7) → 2판 → 좁은 확인(구현 가능 · 중요 둘 N1 · N2 · 사소 여섯) → 구현(2판 + 운영자 결정) → 구현 검토(차단 0 · 중요 2 · 사소 3) → 같은 판 안 고침(운영자 결정 I1 = (가) · I2 = 속도 · 사소 셋). → 좁은 재확인(차단 0 · 중요 1 · 사소 2) → 같은 판 안 2차 고침(운영자 결정 I1′ = 싼 좁힘 · S-a · S-b).
- 운영자 결정(좁은 확인 반영): **N1** — F4-73(#355 · #597)의 «다른 클래스의 같은 판정문 = 확정» 은 그대로 둔다(G2 집합 차분이 지우는 진짜 새 줄 — F4-73 재검토의 차단 A 결정). **N2** — 도메인 서비스 예보의 «다른 소유자» 를 셋으로 가른다. 사소: R-3426 은 개정 · R-3690 은 금지(Prohibition) · 기준선 파싱 불능 때 규칙과 무관한 후보를 내지 않음 · 출처 해소 1단 경로 정규화 · 승격 본체 칸 · 메모 (b) 문구는 «OHS 는 잡은 도메인 예외 값을 쓰지 않는다(R-3690)» 를 앞에 · 시간 서술은 «칸당 3 ~ 6ms · 선형».

## 설계 요지

### A1 — update 도메인 서비스 서명(#304 · #305 · #307 · #308)
- 대상 칸 = 검사기 선택(`vocab.bc_dirs` → `_has_adoption_signal` → `<bc>/domain_layer/domain_service` → `slot_glob(…, "*.py")` · `__init__.py` 뺌)과 같은 경로 ∩ file-plan update(계획 경로는 정규화 · 승격 칸은 본체로 맞춤). 선택은 **계획 경로로 BC 를 바로 맞춘다**(`_checker_bc` — `application` 다음 마디가 BC · BC 이름이 점으로 시작하지 않음 · `application` 절대 마디에 검사기 SKIP_DIRS 없음 · `application` 의 조상(사본 안)에 링크 폴더 없음 — `rglob` 이 링크 폴더 안으로 내려가지 않기 때문) — 그다음 채택 신호 · 칸 고르기는 검사기 함수 그대로. 사본 전체 훑기가 없다(구현 검토 I2). add 칸은 스텁이 registry 에 실려 이미 귀속되므로 넣지 않는다.
- 재료: symbols 의 클래스 · 메서드 행과 모듈 함수 행 · 명시 import · 전사 전 기준선 실물(`forecast_baseline` — 앵커 커밋 뒤 · materialize 전 · 저장소 예보 기준선과 같은 자리).
- 투영 = 기준선 전 깊이 import + 명시 import + 기준선과 서명(수신자 뺀 인자 이름 · 주석 · 반환 주석)이 다르거나 새로 생긴 공개 이름의 메서드 · 모듈 함수(본문 `...`). `_` 로 시작하는 이름은 뺀다(검사기와 같다 — 클래스 이름은 보지 않는다: 사설 클래스의 공개 메서드는 판정).
- 칸마다 빈 폴더 둘(`domain-service/<n>/decl` · `…/base` — 기준선 실물도 같은 판정)에서 `_check_domain_services()` 를 부르고 폴더째 지운다. 결과는 «경로 + 줄» 로 투영 행에 맞춘다(같은 BC 두 칸이 섞이지 않는다).
- 기존 빚 열쇠 = G2 와 같은 «파일 · 규칙 · 판정문»(판정문에는 클래스 이름이 없다 — #307 · #308 은 함수 이름, #304 · #305 는 인자 이름만 싣는다):
  - 기준선에 없음 → **선언 확정**
  - 있음 · 같은 소유자(그 자리 · 그 이름) → 뺀다(기존 빚 · G2 도 0)
  - 있음 · 다른 소유자 → (가) 그 판정문의 기준선 소유자를 이 명세가 **모두** 고쳐 다시 적어 그 줄이 사라지면 **확정**(바꿔치기) · (나) 기준선 소유자들과 함수 이름이 다르면 **확정**(같은 인자 이름의 #304 · #305 — 새 정의 · K2) · (다) 같은 함수 이름이 다른 자리에 있으면 **후보**(클래스 개명 K1 · 모듈 함수 → 메서드 K3 · 조상 정의 다시 적기 K4 · 중첩 함수 · 두 소유자 가운데 하나만 고침)
  - 소유자 = 함수 정의 줄을 둘러싼 자리(클래스 직계 = 클래스 이름 · 모듈 직계 = "" · 그 밖 = 자리 경로).
- 기준선 읽기 · 파싱 불능 · 같은 이름 클래스 · 메서드 · 함수 중복 → 그 서명의 검사기 판정이 있을 때만 후보(규칙은 검사기가 낸 그대로 — 규칙과 무관한 후보를 내지 않는다) · 기존 빚으로 빼지도 않는다.
- 남기는 규칙은 #304 · #305 · #307 · #308 뿐(#301 · #302 · #303 · #310 · #311 은 투영이 파일 일부라 셀 수 없다).
- «확정» = 대개 G2 귀속 ∪ G2 집합 차분이 지우는 실검사기 새 줄((가) · (나) — F4-73 과 같은 쪽의 엄격 구석). 다만 (나)는 #304 · #305 기존 빚 메서드를 개명하면(옛 정의를 지움) 실검사기 줄이 그대로이고 G2 도 0 인 거짓 확정이 될 수 있다(받아들인 한계 3 · 구현 검토 S1). 후보로 내린 (다)는 실검사기 줄 수가 그대로인 꼴(1 → 1)이다.

### A2 — 예외 번역표 «번역 출처» 칸(#474 · #62)
- 문법: `<published 예외><탭|2+공백><raise 창구 파일>[<탭|2+공백><= <잡는 예외 맨 이름>[ as]]`. 점 이름 · `as <이름>` · `AS` · `<-` · 괄호 묶음 · 공백 하나 · 끝 주석은 형식 red. 셋째 칸이 없는 행은 지금과 같다(블록 해시 무변 — 2.26.1 과 대조).
- 판정 대상 = 창구가 검사기 OHS 선택(`_tree_bcs2`(`CODE_SKIP_DIRS`) → `<bc>/driving_layer/open_host_service` → `rglob("*_service.py")`)과 같은 행 — A1 과 같은 BC 바로 맞추기 + 그 창구 폴더 아래 rglob 조건(이름 `*_service.py` · 창구 아래 링크 폴더를 지나지 않음 · 실물 있음 — add 창구는 실체화 뒤에 판정한다 · 구현 검토 S2). 그 밖 행의 출처 칸 = 판정 0 + 채널 메모 1행.
- `Exception` · `BaseException` 출처 → `as` 와 무관하게 최소 catch 투영을 검사기 트리 슬라이스(`_slice_check_controller_ast`)에 돌려 **#62 확정**.
- 그 밖 출처 해소(검사기 조건 그대로 — 절대 `ImportFrom` · 모듈 마디 `domain_layer` · 전 깊이 · 지역 이름 = asname|name · 처음 찾은 출처에서 멈춤): ① 그 창구 칸의 boundary-imports(소비 경로 정규화) ② update 면 기준선 실물 ③ 이 명세 symbols 의 같은 이름 클래스(하나뿐) ④ 내장 예외.
  - `as` ∧ 도메인 → 최소 투영(그 import + `except X as _caught: _caught`) → **#474 확정**
  - `as` ∧ 가를 수 없음 → **후보**(물음: domain_layer 것이면 그 import 를 boundary-imports 에)
  - 비도메인 · 내장 · `as` 없음 → 0
- **기존 빚 열쇠**(구현 검토 I1 · 재확인 I1′ · 운영자 결정): update 창구면 기준선 실물을 같은 슬라이스로 판정해 그 규칙 줄을 낸 catch(빚 catch)를 찾는다 — #474 는 같은 출처를 잡는 catch 만, #62 는 판정문이 고정이라 이름과 무관한 catch-all(`Exception` · `BaseException` · bare) 빚 전부(S-a). 빚 catch 가 없으면 확정 그대로다. 있으면 행의 published 예외를 기준선에서 누가 내는지로 그 행이 고칠 catch 를 가린다: ① 빚 catch 가 냄 → **후보**(그 catch 를 고치는 행 — 기존 빚) ② 빚 없는 catch(#474 는 같은 출처를 잡는 것)가 냄 → **확정**(그 catch 가 값을 읽거나 catch-all 이 되는 새 줄 — G2 집합 차분은 지울 수 있다 · N1 과 같은 기준) ③ 둘 다 아님 → **후보**(대상을 바꾼 기존 catch 인지 새 catch 인지 가를 수 없다). 사건 좌표를 맞추지 못하면 후보. 후보 글은 빚 catch 의 자리(함수)와 묶음 이름을 적고 «이 행이 그 catch 를 고치는 것이면 기존 빚 · 새 catch 이거나 다른 catch 면 새 줄 — #474 는 묶음 이름이 다르면 G2 가 막는다 · 같은 이름이나 #62 는 집합 차분이 지울 수 있다» 를 알린다(«G2 도 0» 단정 없음). 여덟 꼴: C1(빚 catch 의 대상만 바꿈) · C1b(빚 catch 본문만) · C2(기존 `except Exception`) · C7(기존 `except BaseException` 을 `except Exception` 으로 좁힘) = 후보, C3 · C4(다른 함수의 빚 · 빚 없는 catch 가 값을 읽음 — 실검사기 1 → 2) · C5(빚 없음) · C6(다른 함수의 catch-all 빚 · 빚 없는 catch 를 `except Exception` 으로 — 1 → 2) = 확정.
- update 창구 행마다 메모: (a) 출처 칸 없음 → «S5 입구 catch 미검증» · (b) `as` 없음 ∧ 도메인 · 해소 불가 → «S5 입구 catch 확인(… OHS 는 잡은 도메인 예외 값을 쓰지 않는다(R-3690) …)». 투영은 칸마다 빈 폴더(`catch/<n>`)에 쓰고 지운다. 검사기는 출처 칸이 있는 OHS 꼴 행이 있을 때만 적재한다(S-b) — 메모 (a) 는 앞 거름 정규식 꼴로만 고르므로 검사기 선택보다 조금 넓다(점 이름 BC · `CODE_SKIP_DIRS` 조상의 창구에도 뜬다 · 막지 않는 글).
- 처분: 새 선언 확정(#304 · #305 · #307 · #308 · #474 · #62)은 다른 선언 확정(#197 · #202 · #355 · #597 · #541)과 같게 `ignored` · `filtered` 를 받는다(`--check-report` 무변 — #574 만 filtered 불인정).

### 리포트 · 사각
- `BLIND_SPOTS` S5: 선언 예보 셋(저장소 · 도메인 서비스 · 번역 출처 칸)은 S5 가 아니다 · **두 채널(pre-gate 선언 예보 · G2 registry)의 기존 빚 기준 차이** 한 줄 · 출처 칸 무기재 · 낡은 출처 칸 · 번역 없는 catch · 그 밖 본문 규칙은 미검증 · update 칸 import 규칙(#288 · #303 등)은 S3.
- 미시뮬레이션 줄: 실제 예보 대상 칸에만(`forecast_scope` — materialize 전에 잼 · 구현 검토 S3) — 검사기 선택 안의 update 도메인 서비스 칸에 symbols 선언이 있으면 «선언한 서명만 예보 · 본문 미검증» · 검사기 선택 안의 update OHS 창구 칸에 번역 출처 칸을 적은 행이 있으면 «번역 출처 칸만 예보 · catch 본문 미검증». 배너(R-3437)는 그대로.
- F4-73 은 판정 그대로(N1) — 저장소 예보는 다른 클래스의 같은 판정문도 확정한다. 대상 선택만 같은 BC 바로 맞추기로 바꿨다(`_repository_selected` — `_find_bcs` 훑기 없음 · 결과 같음). source root 가림(표준 라이브러리 이름)은 출처가 기준선의 표준 라이브러리 import 뿐인 반환 이름을 확정 근거로 쓸 때만 그때 한 번 훑어 잰다(`_ShadowAwareStdlib` — 미리 잰 집합과 같은 값 · 반환 이름 판정에서 표준 라이브러리 판정을 맨 뒤로 미뤄 다른 이름이 먼저 확정하면 묻지 않는다).
