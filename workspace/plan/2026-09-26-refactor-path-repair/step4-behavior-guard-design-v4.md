## 2. 측정 — `scripts/behavior_guard.py`

### 2.1 분류 (G3 M-3)

- **테스트 쪽** = ① 경로 조각 `test`·`tests`·`factories`·`fake`·`fakes`·`fixtures` 아래이거나 파일명이 `test_*.py`·`*_test.py`·`conftest.py` 인 `.py` ∪ ② `test_*.py` 를 품은 `test`/`tests` 디렉터리 아래의 **모든 파일**(golden json 등 비 `.py` 오라클) ∪ ③ pytest 설정 절(`pyproject.toml [tool.pytest.ini_options]` · `pytest.ini` · `setup.cfg [tool:pytest]` · `tox.ini [pytest]`)의 파싱 값.
- **제품 쪽** = 그 밖(`.dddjango/`·`.git`·가상환경·`node_modules`·무시 파일 제외).
- 알려진 사각: 테스트만 import 하는 제품 분류 모듈(`scripts/seed/*` 등 — 운영 CLI 와 구별 불가) · 재수출 심을 남긴 이동의 `patch("옛.경로")` 헛돎(보고 1행) · 제품 튜플로 도는 parametrize 케이스 감소.

### 2.2 창과 명령 (G3 M-1 · m-2 · m-7)

- 산출 폴더: `<산출물 폴더>/behavior/<실행 줄 G0 승인 값>/w<n>-open.json`·`w<n>-close.json`(close 는 판정 이력 배열 — 마지막이 유효).
- `open <산출물 폴더> --kind test|code` — `build_anchor` 가 이미 있어야 한다(순서: 앵커 기록 → open). 열린 창(close 가 없거나 마지막 close 가 green 아님)이 있으면 거부. 기록: open HEAD · dirty 경로와 그 내용(`.py`·테스트 쪽만 본문 · 나머지는 해시) · 테스트 쪽 전체 해시 · 테스트 케이스 이름 · pytest 설정 값 · 마이그레이션(정적·동적). 제품 쪽은 HEAD + dirty 로 복원한다(전체 해시 맵 없음 — m-7).
- `close <산출물 폴더>` — 창의 마지막 슬라이스 보고 뒤, 다음 파견 전. **다음 파견 전까지 몇 번이든 다시 돌린다**(red → 철회 → close 재실행 — M-1). exit 2 면 파견하지 않는다.
- `verify <산출물 폴더>` — G2 배너 직전. 이번 실행 `refactor-scope.md`(«앞 실행» 절 앞)에 `결정 = ⓐ` 줄(ⓐ′ 제외)이 있는데 창이 0 이고 `ⓐ 재상정` 절도 없으면 red «창 누락»(grep 판정 — m-6) · 열린 창이 있으면 red · 전부 green 이면 green · ⓐ 없으면 «해당 없음».
- 창 안 머지(G3 M-7 (가)): close 가 open HEAD..HEAD first-parent 의 머지 M 마다 `M^1..M` 변경 경로를 판정에서 뺀다. 그 경로가 레인 편집(비머지 커밋 · 작업 트리)과 겹치면 exit 1 «판정 불가(머지 겹침)».
- exit: 0 green · 2 red · 1 실행 불능. 모든 경로가 `요약:` 1행.

### 2.3 0C 판정 — 정의 단위 대응 + AST 비교 (G3 B-1 · 결정 9)

- **대응표**(창 안에서 바뀐 제품·테스트 파일로 만든다 — 빈 파일·`__init__.py` 는 쌍에서 제외 · 유일 일치만 · 동률이면 대응 없음 — m-5):
  - 모듈 대응: import 를 뺀 AST 가 같은 삭제·추가 쌍 ∪ 옛 모듈의 함수·클래스 정의가 옮겨 간 후속 모듈(과반).
  - 정의 대응: 옛 모듈에서 사라지고 다른 모듈에 하나만 나타난 최상위 정의 `(이름, AST 해시)` → `옛모듈.이름 → 새모듈.이름`.
  - **이름 대응**(결정 9): 사라진 정의와 나타난 정의가 **이름만 빼고** AST 가 같으면 `옛모듈.옛이름 → 새모듈.새이름`(같은 파일 안 개명 포함). 메서드 개명은 클래스 본문이 바뀌므로 대상 밖(red).
- **비교**: 테스트 파일은 import 를 바인딩 집합 `(묶인 이름, 모듈 | 모듈.속성)`으로(순서·줄바꿈 무관 · 상대 import 해소), 그 밖은 AST dump 로 본다. 치환은 **옛 판에만 한 번** — 모듈 경로 최장 접두 · 정의·이름 대응 · 문자열 안 dotted/파일 경로(식별자 경계). 이름 대응이 바꾼 바인딩은 본문 이름(`Name`·모듈 속성)도 새 이름으로 바꾼다. docstring 은 판정에서 빼고 보고만(m-4).
- 테스트 쪽 ②·③ 변경 → red. 테스트 `.py` 추가·삭제 → red(이동 쌍 제외).

### 2.4 0T 판정

- 제품 쪽(비 `.dddjango/`) 변경 → red(이동 쌍은 분류 중립이라 테스트 쪽 이동만 허용).
- 테스트 케이스 이름 다중집합이 **같아야** 한다 — G1 입장 표 `remove` 행의 `path::test` 만 빠질 수 있다(m-3). 새 case 는 red(재조직 규범 — M-2). 같은 이름 재작성·단언 약화는 DR hunk 몫(사각).

### 2.5 마이그레이션 (G3 M-8 · m-1)

- 정적: `**/migrations/NNNN_*.py` 의 `(app_label, 파일 이름)` → 내용 해시. app_label 은 같은 앱 `apps.py` 의 `label`(Assign·AnnAssign), 없으면 앱 폴더 이름. 차이 → red.
- 동적: 인터프리터는 저장소 `.venv`/`venv` 또는 `--python` 만(`uv run` 폴백 없음 — 가상환경을 만들 수 있다 · 구현 리뷰 J-m13 정정) · settings 는 pytest 설정의 `DJANGO_SETTINGS_MODULE` · 있으면 **기본 실행** `manage.py makemigrations --check --dry-run --skip-checks`. 비교는 정규화한 변경 목록(앱별 `- …` 행 집합)이다. close 가 «No changes»이고 open 이 측정 안 됐으면 green(빠른 경로) · open 성공 ∧ close 실패 → red · 둘 다 미측정이면 사유를 `요약:` 에 싣고 정적 판정만.

## 5. 구현 리뷰 J 이후 개정 (2026-09-27 — `review-J-step4-impl.md` · 처분 `step4-impl-log.md` §4)

- **비교 규칙(J-B1·J-M1)**: 이름 참조를 전체 경로 `⟨pkg.mod.Name⟩` 로 풀어서 비교한다(import 로 묶인 이름 · 모듈 속성 사슬 · 패키지 재수출 한 단계 · 문자열 어노테이션). 대응표는 «구조 쌍(문자열·import 를 뺀 골격) → 정의 대응(dm·rn — 대응표를 적용한 정규형) → 후속 모듈(def·class 과반) → 디렉터리 대응(사라진 디렉터리의 쌍 과반 · 부모·자식 번짐) → 디렉터리+파일 이름 쌍»을 더 늘지 않을 때까지 되풀이한다. 이름 치환은 짧은 이름 문자열에 적용하지 않고(전체 경로·`patch.object(대상, "이름")` 류만), 이름 뺀 해시는 정의 이름과 짧은 자기 참조만 비운다(문자열 상수 유지 — 결정 9 «이름 말고 같을 때만»). import 비교는 본문에서 안 쓰는 바인딩(부수 효과 import)만 본다. 테스트 케이스(test*·Test*)는 정의 대응 밖이다.
