## 2. 설계

### C1 정리 요청은 풀 파이프라인 · 이동 근거는 ⓐ 하나 (P1)
«시작: 모드 판별»(R-0164 개정 + 새 규범 1):
- 모드는 둘뿐이다. **밖에서 보이는 동작은 유지하고 기존 코드의 구조 정리를 원하는 요청(정리 요청)은 풀 파이프라인으로 간다** — 정리 대상은 Phase 0 빚 스캔(→ ⓐ)과 사용자가 적은 불편이 정한다. 요청·발주가 붙인 모드 이름(«동작 보존 리팩터링» 등)은 모드가 아니다.
- 정리 요청이어도 기존 코드의 **이동 근거는 G0 ⓐ → 슬라이스 0 하나**다(HR:29 재확인) — 요청·발주 문면을 «이동 자체가 이번 기능»으로 읽어 ⓐ 없이 옮기지 않는다(현장 법리 «발주 본체/기능» 8건 봉쇄).
- **C1b(표면화만)**: 사용자가 적은 정리 항목이 백스톱 위반이 아니면서 기존 파일의 이동이 필요하면, G0 배너에 «현행 규범상 이동 권한 없음 — 줄 변경으로 다루거나 범위에서 뺀다»로 올려 사용자가 고르게 한다(새 권한을 만들지 않는다 · 열거 항목 ⓐ 등재 R4 B1(b) 는 사용자 결정 대기 — §4).

### C2 수정 모드 G0 에 빚 스캔·질문 (P2 · R1)
수정 모드 1번(R-0416·R-0417 개정):
- 영향 범위를 확인하고 **Phase 0 의 3번(빚 스캔)·4번(빚 질문·산출물 폴더 절차)을 그대로 수행한다**. 스캔 대상 = 이번 수정이 속한 BC(G0 스코프의 BC).
- 새 폴더 금지 문구(«보통 ⓐ 재사용·새 폴더 생성 금지»)는 «기존 폴더 목록에서 사용자가 고른다»로 — 폴더 절차는 Phase 0 4번 그대로(C5 가 재사용의 앵커 문제를 푼다).
- 수정 모드 G1′ 생략 조항(R-0428 개정): **G0 ⓐ 항목이 있으면(슬라이스 0) G1′ 을 생략하지 않는다.**
- Phase 0 3번 스캔 계약(R-0185~ 블록)에 한 문장: **발주·요청이 도구·검사기·범위를 좁혀 지정해도 빚 스캔은 27종 계약 그대로다**(부분 스캔 3건 · registry_gate 대체 1건 봉쇄).

### C3 정리할 것이 없으면 G0 에서 멈춘다 (P3)
Phase 0 4번(새 규범 1): 정리 요청인데 빚 0(증거 있는 0 — «증거 없는 0 = blocker» 그대로)이고 사용자가 적은 불편·정리 항목도 없으면, 설계로 넘어가지 않고 G0 배너에 스캔 증거와 함께 올려 **불편을 적을지 끝낼지** 묻는다. 자율 실행이면 STOP 기록(현장 정상 정지 형식 0913-0818 과 같은 형태).

### C4 ⓑ 는 결정 출처가 있어야 받는다 (P4 · R2)
Phase 0 4번(R-0198 개정 + 새 규범 2) · 경계 절(R-0454 개정):
- **ⓑ(미룸)의 결정 출처는 둘뿐이다** — ① 이 실행에서 사용자가 직접 답함(시각) ② 사용자 원문 인용(원문 · 시각 · 출처). ⓑ 답은 사유와 함께 출처를 받는다.
- **출처가 아닌 것**: 발주서의 쓰기 경계·금지 경로·편집 금지, 선례 인용(«다른 레인과 같은 처분»), 발주자·대리 세션의 판단, 코디네이터 추론. **쓰기 경계가 ⓐ 정리를 막으면 그것은 ⓑ 가 아니라 충돌이다** — G0 에서 «경계를 넓혀 정리 / 사용자 원문으로 미룸»을 표면화한다.
- 출처 없는 ⓑ(발주 문면 고정 포함)는 결정으로 받지 않는다 — 대화형이면 사용자에게 직접 다시 묻고, 발주 문서가 정지를 계약한 자율 실행이면 `STOP_FOR_USER_APPROVAL`.
- 발주가 ⓐ 로 미리 정했으면 그대로 받는다(사용자 방침 인용 포함).
- `refactor-scope.md` 결정 줄에 출처를 적는다: `결정 = ⓐ|ⓑ · 출처 = 사용자 직접(<시각>) | 사용자 원문 «…»(<시각> · <출처>) | 발주 고정 ⓐ(<발주서:행>)`. **«사용자 결정»이라는 표기는 ①·② 출처가 있을 때만 쓴다**(오표기 8파일 봉쇄).
- 경계 절 «발주가 답을 고정한 게이트(자율 라운드의 G0 빚 등)»에 괄호: G0 빚에서 발주 고정은 ⓐ 이거나 출처 있는 ⓑ 뿐이다.

### C5 앵커는 «실행»마다 (P5)
Phase 2 6번(R-0304·R-0309 개정) · Phase 0 4번 · Phase 3(새 규범 1):
- **실행** = 사용자의 G0 승인 하나로 시작해 Phase 3 마무리로 끝나는 빌드. G0 승인 때 Coordinator 가 `scope.md` 끝에 실행 줄 `실행 <date +%Y%m%d-%H%M> — G0 승인` 을 append 한다. Phase 3 마무리 때 그 줄에 `· 마무리 <시각>` 을 덧붙인다.
- `build_anchor` 는 **실행마다 한 번** 쓴다: Phase 2 첫 파견 직전, 최신 실행 줄에 앵커가 없으면 `git rev-parse HEAD` 를 `build_anchor` 에 쓰고(옛 값 덮어씀) 실행 줄에 `· build_anchor <SHA>` 를 덧붙인다. 있으면 재기록하지 않는다(G1′ 반송·회전·STOP 재개·세션 재시작·머지 뒤 재개 — 0924-0502 형).
- **새 실행은 G0 승인으로만 생긴다.** 앞 실행이 마무리되지 않았으면 G0 를 다시 거쳐도 그 실행의 재개다 — 사용자가 G0 에서 앞 실행을 버린다고 명시한 경우만 새 실행(미완 실행의 귀속을 새 앵커로 지우는 세탁 차단). 마무리된 폴더의 증분(D54 형)은 새 실행이다 — G0 상속 없이 G0(빚 스캔 포함)를 다시 한다.
- 이 규칙 이전 폴더(실행 줄 없음): 새 G0 승인이 첫 실행 줄을 만든다. 실행 줄 없이 진행 중인 실행(재개)은 앵커를 건드리지 않는다.
- 옛 앵커는 실행 줄에 남는다(감사).

### C6 재사용 폴더의 refactor-scope.md (P6)
새 실행은 `refactor-scope.md` 를 새로 쓴다(첫 줄 = 실행 줄 · 앞 실행 기록은 git 이력). 앞 실행의 ⓑ 는 이월하지 않는다 — 새 스캔이 다시 낸다(현행 «이월·누적 금지»의 실행 단위 명시).

### C7 가이드 정합 (P7)
- §4 질문 목록: «기존 기능의 작은 수정에서는 이 조사를 하지 않을 수 있습니다» 삭제 → «작은 수정에서도 조사합니다». 미룸: «미루는 결정은 사용자가 직접 하거나, 다른 세션이 대신 요청할 때는 사용자 원문과 시각을 함께 적어야 합니다. 요청에 적은 수정 범위 제한은 미루는 결정으로 보지 않습니다.»
