## 2. 수리 설계 ①

### 2-1. 원칙

- **완료 기준 하나**: 슬라이스 0 에서 «해소»는 원 행(verdict 행 · 원 리뷰어 행 · 병합 행)의 위반 요지가 원 규칙 기준으로 사라진 것이다. G2 잔존 확인과 같은 기준이다.
- **대체 형태 금지**: 원 규칙의 처방을 채우지 않는 다른 개선은 해소가 아니다. 슬라이스 0 에 넣지 않는다. 예: 파생형 대신 생성 시 검증 · 인수 객체 대신 키워드 전용 · 전제 검사 대신 docstring 단정.
  - 근거 ①: G0 ⓐ 가 승인한 것은 «그 위반의 정리»다.
  - 근거 ②: residual 은 대체 형태를 해소로 세지 않는다(§1-2 t05 문언).
  - 근거 ③: 뺀 요지의 별도 요청이 대체 형태를 걷어 내게 된다(M37 예외 클래스).
  - 플러그인 자신의 정의에서 답이 나오므로 묻지 않는다.
- **판정 단위는 요지**: 항목 판정은 요지 판정에서 파생한다(전부 해소 = 가능 · 일부 = 부분 · 없음 = 불가).

### 2-3. 판정 표 형식

- 위치: 명세의 `## 슬라이스 0 해소 판정` 제목 아래 표(입장 표와 같은 방식).
  - `<!-- machine: … -->` 마커는 쓰지 않는다. pre-gate 는 어휘 밖 마커를 형식 red 로 낸다(`scripts/design_pregate.py:434-435`) — pre-gate 는 건드리지 않는다.
- 열: `M<n> | 요지# | 요지(원 행 발췌) | 판정(해소 | 불가) | 불가 범주 | 막는 것(파일:행) | 처방 앵커`
  - 처방 앵커 = 명세 본문에서 그 항목 처방 블록의 첫 줄 원문(예 `**M55 — 긴 위치 인자 목록 제거**`). 도구는 앵커 줄부터 다음 `**M` 줄이나 제목 줄 앞까지를 해시해 예보 낡음을 잰다.
- **불가 범주(닫힌 목록 6)** — 모두 현행 규범에 있는 사유다.

| 범주 | 현행 근거 | R8-R 예 |

### 2-4. G1 재상정 선택지 — 결정과 근거

- **부분 항목은 요지 축소를 묻지 않고 기본으로 적용한다.** 근거는 넷이다.
  - 해소 요지는 G0 ⓐ 가 이미 승인한 정리다.
  - 사용자 원칙 B1 «빚은 예외 없이 항상 먼저 정리»다.
  - M8 선례: 사용자가 «① 카탈로그 부분만 빼고 진행 (권장)»을 골랐다(`8-rehearsal/user-answers.md:9`). 그 결과가 G2 «부분 1»로 집계됐다.
  - 자명한 결정은 묻지 않는다.
- **묻는 것은 뺀 요지의 처분뿐이다**: 기존 «동작 불변 불가» 선택지 그대로 «별도 요청 / 출처 있는 ⓑ / 작업 중단»이다. 선택지마다 대가 한 줄을 붙인다(`commands/dddjango.md:221`).
  - 요지 축소 항목의 대가 줄 예: «남긴 요지는 이번에 정리한다 · 뺀 요지는 별도 요청이 이어 받고 남긴 정리를 되돌리지 않는다».
- **«전부 별도 요청»은 선택지로 두지 않는다.**
  - 남길 요지가 뺀 요지를 정리할 때 되돌려질 형태라면, 그것은 해소 요지가 아니라 대체 형태다. 그러면 항목 판정은 «불가»가 된다(§2-1).
  - 즉 «전부냐 일부냐»는 설계 판정이 가르고, 사용자 선택으로 두지 않는다. 사용자가 그래도 원하면 G1 «수정 요청» 자유 입력으로 받는다.
- 불가 항목(M37 포함)은 현행 선택지 그대로다.

### 2-7. ② 철회 규칙 — 안전망으로 남는가

운영 세션의 가설 «① 이 되면 부분 정리 자체가 안 생긴다»는 문자 그대로는 틀리다. 계획된 부분(요지 축소)은 B1 에 따라 생긴다. 없어지는 것은 G2 에서 처음 드러나는 **계획 밖** 부분이다.

| G2 잔존이 생길 경로 | ① 뒤 | ② 발화 |
|---|---|---|
| 계획된 요지 축소 | 생긴다 | residual 이 축소를 알면 없음 · 모르면 **매번**(지금보다 나쁨 — §2-5 6 이 필수인 이유) |
| 예보 판정자 ↔ G2 판정자 편차 | 드묾(같은 역할 · 같은 원 행 · 같은 기준) | 발화 — 안전망 |
| coder 가 처방을 못 따름 | 반송 1회로 대부분 해소 | 드물게 발화 |
| Phase 2 발견(검사기 오탐 · 창 red) | Phase 2 STOP 에서 요지 축소로 기록 | 없음 |
| G1′ 로 처방 변경 | `--gate` 가 낡은 예보를 막음 | 없음 |

- R8-R 증거: 세 항목은 모두 Phase 1 에 알려져 있었다(`<S1>:176,229,239` · `phase1-ddd.md:11`). ① 이 있었다면 G2 전 잔존 STOP 은 0 이다.
- **판정**: 가설은 «residual 이 요지 축소를 안다»는 조건에서만 참이다. 그 조건에서 ② 는 판정자 편차와 coder 이탈만 받는 안전망으로 남는다.
- 비대칭(계획 축소는 유지 · G2 사후 부분은 철회)은 사용자 결정(② 유지)을 따른다. ② 발화가 드물면 대가도 작다(§4 Q3).

### 3-2. 세 안

**안 A «한 멈춤으로 합치기»** — BC 마다 사용자 판단 항목을 G1 재상정과 함께 묻는다(설계는 «위반 — 정리»로 가정).

- 규범 충돌: G0 질문 규범(`:243`)과 ⓐ 동결 시점을 바꿔야 한다. 판단 대기 항목이 file-plan·pre-gate 에 들어간다.
- 대가: «허용 — 뺌»이 나오면 그 항목 설계·리뷰가 헛돈다(R8-R 2/2 · R8-WR 0/1). G1′ 좁은 재호출과 pre-gate 재발화가 붙는다.
- 효과(25 BC): ≈50 → ≈25회(−50%).
- 구현: 코디네이터 규범 2~3문장 개정.

**안 B «캠페인 상시 답»(권장)** — 캠페인 시작 전에 사용자가 원문 파일 1개를 직접 쓴다. 두 종류다.

- 재상정 범주 답: ① 판정 표 불가 범주별 처분이다(예: «외부 관찰 동작·테스트 본문 동반·기존 보호 부족·검사기 오탐의 뺀 요지 = 별도 요청» · «편집 범위 밖 = ⓑ(사유 …)»).
  - 판정 표 범주가 닫힌 목록이라 매칭이 결정적이다.
- 규칙 짝 선례: 사용자 판단에 대한 첫 답을 «이 짝(규칙 R-a ↔ 반대 R-b)은 캠페인 전 BC 에서 같게»로 적은 것이다.
  - 짝 키는 `check.md` 의 블록→규범 결속으로 결정적으로 나온다(예: M3 = R-0108↔R-0636 · M43 = R-1424↔R-1489 — `<L>/audit/20260928-1517/verdict.md:9,49`).
- 적용 방식: 일치 항목은 STOP 기록(선택지·대가 포함)을 남긴다. 결정 줄 출처는 `사용자 원문 <상시 답 파일:행>` 이다. 배너에 «상시 답 적용 k건»을 표시한다(비차단). 범주·짝이 일치하지 않으면 종전대로 멈춘다.
- 규범 충돌: 작다.
  - «사용자 원문 출처»(Phase 0 결정 출처 · `:220`)는 그대로 충족한다. 대리가 아니다.
  - 필요한 개정: `:243` «항목마다 묻는다»에 «상시 답의 짝 선례가 있으면 그 줄을 출처로» 예외를 더한다. `:108` 재상정 STOP 에 «상시 답 범주 일치 시 기록만»을 더한다. 상시 답은 닫힌 범주·짝에만 출처가 된다는 한정을 둔다.
- 대가
  - 같은 규칙 짝이라도 BC 사정이 다를 수 있다(M3 은 상황 설명 뒤에 답했다). 완화: 사용자가 캠페인 전체로 적은 짝만 적용하고, 적용 건을 배너에 표시하며, 파일을 고쳐 철회할 수 있다.
  - 별도 요청 목록이 캠페인 백로그로 쌓인다. 사용자가 매번 «별도 요청 (권장)»을 고른 것과 결과는 같다.
- 효과(추정): G1 재상정 → ≈0(R8-R 13/13 · R8-WR 3/3 이 닫힌 범주). G0 → 새 짝만.
  - 가정: BC 당 판단 1.5건. 첫 5 BC 는 전부 새 짝, 이후 새 짝 비율 30~50%.
  - ≈50 → **≈14~19회**(−62~72%) + 상시 답 작성 1회.
- 구현: 코디네이터 규범 3~4문장 + (선택) `check-verdict` 짝 매칭 옵션 1개.

**안 C «파동 단위 G0 일괄 + B»** — 파동 안 BC 들의 R0~R3 를 먼저 돌려 `G0 정지`로 세운다. 사용자 판단을 한 자리에서 짝별로 묶어 묻고, 각 BC 는 «G0 정지 재개»(`:229`)로 audit 를 재사용해 잇는다.

- 규범 충돌: 작다(재개 규칙이 이미 있다). 캠페인 러너 절차가 늘어난다.
- 대가
  - 한 자리에서 수십 항목을 답해야 한다.
  - 기다리는 사이 BC 가 바뀌면 «새 점검» → 바뀐 항목을 다시 묻는다(재개 조건 `:229`).
  - 파동 앞 점검 비용을 먼저 치른다(총액은 같다).
- 효과: 파동(동시 3 레인 → ≈8~9 파동) 단위면 ≈6~10회. 전체를 먼저 점검하면 ≈2~3회.
- 구현: 캠페인 절차(플러그인 밖) + B.

### 3-3. 권장 — B

- 규범 개정 대비 감소 폭이 가장 크다.
- ① 의 닫힌 불가 범주와 기존 `check` 결속을 그대로 매칭 키로 쓴다. 결정적이다.
- 사용자 원문 원칙을 문자 그대로 지킨다.
- C 는 B 위에 절차로 얹을 수 있어 나중에 더해도 된다. A 는 헛설계 비용이 있고 B 와 겹친다.
