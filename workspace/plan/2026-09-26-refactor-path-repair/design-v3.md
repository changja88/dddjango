## 1. 설계

### G-1 라우팅 (C1)
- 모드는 둘뿐이다. **밖에서 보이는 동작은 유지하고 기존 코드의 구조 정리만 원하는 요청(정리 요청)은 풀 파이프라인으로 간다.** 기능과 정리가 섞인 요청은 정리 요청이 아니다(기능이 모드를 정한다 — 빚은 어느 모드든 G-2 로 정리된다).
- 요청·발주가 붙인 모드 이름이나 모드 지정(«수정 모드로», «동작 보존 리팩터링»)은 판별 입력이 아니다.
- 정리 요청이어도 **이동 근거는 G0 ⓐ → 슬라이스 0 하나**다 — 요청·발주 문면을 «이동 자체가 기능»으로 읽지 않는다.
- 발주·요청이 G0·빚 스캔을 생략·상속·갈음하라고 해도 따르지 않는다(«G0/G1 상속» · «빚 스캔 = 갈음» 현장형).

### G-2 빚 스캔 (C2)
- 수정 모드 G0: 영향 범위를 확인하고 **Phase 0 3번(빚 스캔)·4번(빚 질문·폴더 절차)을 그대로 수행**한다. 폴더 규칙은 현행 그대로(R-0417 · :24 «같은 기능 재빌드 = 기존 폴더»).
- 스캔 대상 BC = **이번 작업이 파일을 추가·변경하는 BC 전부**(R-0194 명확화 · 결정적).
- 스캔 계약(R-0190·R-0191 개정): 발주·요청이 **도구·검사기 목록·TARGET·flag** 를 좁혀 지정해도 27종 계약 그대로다.
- G0 배너에 **슬라이스 0 규모 1행**(ⓐ 대상 항목 수 · BC 수 · 이동이 필요한 경로 수)을 올리고 ⓐ 선택지 대가 줄에 적는다.
- **BC 가 2개 이상이면** ⓐ 의 한 형태로 «BC별 정리 요청을 먼저 따로 진행하고, 착륙 뒤 이 요청을 다시 시작»을 반드시 선택지로 둔다(빚은 여전히 먼저 정리된다 — B1 과 같다). 고르면 G0 에서 그 목록을 기록하고 정지한다.

### G-3 수정 모드의 슬라이스 0 (A-M5)
- ⓐ 항목이 있으면: 슬라이스 0 경로 목록에 Phase 0 2번 lens 판정을 적용해 G1′ lens 에 합치고 · discipline-reviewer lightweight 를 G1′ 다발에 합류시키고 · 슬라이스 0 선행·혼합 금지(R-0270)를 준용하며 · **G1′ 을 생략하지 않는다**(R-0428).
- R-0415(«국소 수정은 전체 파이프라인 재실행 금지») · R-0416(«영향 범위만 빠르게 확인») 문면 개정: «설계는 영향 lens 만 · G0 빚 스캔·질문은 Phase 0 그대로».

### G-4 정리할 것이 없으면 G0 에서 멈춘다 (C3)
- 정리 요청인데 ⓐ 대상이 0(빚 0 이거나 전건이 출처 있는 ⓑ)이고, 적힌 불편·정리 항목도 없으면 설계로 넘어가지 않고 G0 에서 스캔 증거와 함께 올린다(대화형: 불편을 적을지 끝낼지 · 자율: STOP 기록).
- 불편·항목은 누가 적었든(대리 포함) 항목이다 — 대리가 적은 불편은 사실 입력이다(가이드 §7).
- G0 단계 정지 기록은 폴더를 먼저 확정한 뒤 그 폴더에 둔다.

### G-5 결정 출처 (C4)
- **ⓑ(미룸)의 출처는 둘뿐이다**: ① 사용자 본인 직접 답 — 단 **게이트 답을 대리에게 맡긴 실행**(발주가 «게이트 답은 발주자» 류로 위임했거나 입력이 «발주자 답»으로 시작)에서는 ① 을 쓸 수 없다. ② 사용자 원문 — `파일:행` + 시각. 코디가 Read 로 그 줄에 인용 문자열이 실재하는지 확인한다. **내용 요건**: 이 실행 또는 이름을 든 BC·항목의 기존 코드 정리를 미룬다는 뜻이어야 한다.
- **출처가 아닌 것**: 쓰기 경계·금지 경로·편집 금지 · 선례·다른 레인의 처분 · 발주·투입 승인 발화 · 일정·순서 발화 · 일반 방침 · 대리 세션의 판단 · 코디 추론.
- **출처 없는 ⓑ 는 받지 않고 재질문 없이 STOP 한다**(대화형은 기존 STOP 절차 — 기록 뒤 같은 선택지를 AskUserQuestion 으로 · 자율은 기록 + 정지 커밋).
- **환경 사실이 ⓐ 를 막으면 ⓑ 가 아니라 충돌이다**(쓰기 경계 · 같은 파일을 고치는 다른 작업): G0 에서 표면화 — 선택지 «경계를 넓혀 정리 / 순서 조정(다른 작업 착륙 뒤 다시 시작) / 출처 있는 ⓑ». «미룰 수 없음» 항목은 ⓑ 없이 «경계를 넓혀 정리 / 작업 중단».
- **발주가 ⓐ 로 미리 정했으면 받는다**(방침 인용 포함).
- `refactor-scope.md` 결정 줄 정형: `결정 = ⓐ|ⓑ · 출처 = 본인 직접(<시각>) | 사용자 원문 <파일:행>(<시각>) | 발주 고정 ⓐ <발주서:행> | 발주자 답 ⓐ <기록:행>(<시각>)` — ⓑ 는 앞 둘만. **«사용자 결정» 표기는 ①·② 출처에만.**
- 위임 규칙(R-0451 · s003/b10 사전 위임 제외 목록)에 «출처 없는 G0 ⓑ»를 넣는다 — 미룸은 승인 입력이 아니다.
- **이관 빚(legacy-debt) 목록 등재도 미룸이다** — 같은 출처 규칙(:117 · :152 «사용자 승인 이관 빚» 문면).
- 경계 절 R-0454 «발주가 답을 고정한 게이트(자율 라운드의 G0 빚 등)»: G0 빚의 발주 고정은 ⓐ 이거나 출처 있는 ⓑ 뿐이다.

### G-6 실행과 앵커 (C5 v3)
- **운반체 = `refactor-scope.md` 첫 머리의 «실행 줄»**(코디 소유 — «이번 작업 기록»과 같은 이유로 바뀐다). `scope.md` 는 건드리지 않는다.
- **실행** = 새 실행으로 승인된 G0 에서 시작해 G2 승인으로 끝난다. 실행 줄: `실행 <prefix> · G0 승인 <시각>` → Phase 2 첫 파견 직전 `· build_anchor <SHA>` → G2 승인 기록 때 `· G2 승인 <시각>`. 실행 줄 추기는 코디 고유의 기계 메타 쓰기다 — «사후 개정»(R-0452)이 아니고 발주의 커밋 파일 제한 대상도 아니며, G2 승인분 커밋에 포함한다.
- **G0 에서 기존 폴더를 고르면 최신 실행을 판정한다**:
  - G2 승인 표식 있음 → **새 실행**(Phase 2 첫 파견 직전 새 앵커).
  - 표식 없음, 또는 실행 줄 없이 `build_anchor` 가 있음(규칙 이전 폴더) → **미종료** → 닫힌 선택지(빚 ⓐ/ⓑ 와 다른 이름표 «실행 선택»): ① **앞 작업 이어서**(앵커 승계 — 규칙 이전 폴더는 기존 SHA 로 첫 실행 줄 작성) ② **앞 작업은 이미 승인됨 — 근거 `<파일:행>`**(Read 확인 · G2 승인 기록·승인 커밋) → 새 실행 ③ **앞 작업 폐기하고 새로**(대가: 앞 작업 변경이 기준선으로 흡수돼 이후 귀속되지 않는다 · 출처 규칙 G-5 · 위임 불가).
  - `build_anchor` 없음 → 새 실행.
- **재개(①)**: 앵커 무변 · G0 는 다시 스캔하고 새 빚만 ⓐ/ⓑ 로 묻는다 · `refactor-scope.md` 에 `재개 G0 <시각>` 절을 append · ⓐ 동결 = 최신 G0 승인(R-0203 개정).
- **새 실행**: `refactor-scope.md` 를 새로 쓴다(앞 기록은 git 이력) · 앞 실행 ⓑ 이월 없음 · architect 입력에 «명세의 기계 블록(file-plan)은 이번 실행 델타»를 명시한다.
- 폴더 목록 표시에 미종료 실행 표시를 붙인다.
- `build_anchor` 규칙(R-0304·R-0309): «실행에 한 번» — 실행 안(G1′ 반송·회전·STOP 재개·세션 재시작·머지 뒤 재개)에서는 재기록 금지. 승인 머지 목록과 양립(새 앵커 이전 머지는 판정 불참 — `anchor_diff.py:264`·`:312-313`).

### G-7 슬라이스 0 에 못 넣는 항목 (B-B2)
- 설계·리뷰에서 **슬라이스 0 항목을 동작 불변으로 정리할 수 없음**이 드러나면 그 항목을 슬라이스 0 에서 빼고 STOP 한다(밖에서 보이는 결과가 갈리는 물음 — R-0457) — 선택지 «동작 변경은 별도 요청으로 / 출처 있는 ⓑ / 작업 중단». ⓑ 로 조용히 처리하지 않는다.
- **ⓐ 항목이 검사기 오탐으로 의심되면**(규칙 문면상 허용되는 코드가 red) 재현 근거와 함께 STOP(플러그인 결함)한다 — 우회 구현으로 red 를 지우지 않는다.
- F4-20(#195 오탐) 수리를 이 수리와 함께 낸다(`diag-B3-F4-20.md` 수리안 B).

### G-8 백스톱 위반이 아닌 이동 (A-M8 · B-M1)
- G0 의 C1b 는 없앤다. G1 에서 discipline lightweight 가 «승인 목록 밖 기존 파일 이동»을 내거나 설계가 비위반 이동이 필요하다고 보면, 명세에 넣지 않고 STOP — 선택지 «범위에서 빼고 진행 / 요청 종료». 비위반 이동 권한(R4 B1(b))은 사용자 결정 대기.
- **«이동» 정의**(houserules SKILL §1.1 한 문장): 기존 심볼·줄이 다른 경로에 다시 생기고 옛 자리에서 사라지는 변경 전부 — 재작성·분할·개명·이관 포함. 스코프 산출물로 새 파일을 만들고 옛 줄을 지우는 것도 이동이다.

### G-9 ⓐ 완결 (B-M5 최소)
- G2 배너 1행 `G0 ⓐ N건 중 잔존 M` — registry_gate legacy 잔존 ∩ ⓐ 목록(경로·규칙). **M>0 이면 G2 blocker**.
- 슬라이스 0 은 독립 커밋이고, 그 커밋에서 관련 테스트가 green 이어야 한다.
