## 2. 설계

### C1 모드 판별 — 정리 요청은 풀 파이프라인 (P1)
«시작: 모드 판별» 절에 한 문장: **밖에서 보이는 동작은 유지하고 기존 코드의 구조 정리를 원하는 요청(정리 요청)은 풀 파이프라인으로 간다 — 정리 대상은 Phase 0 빚 스캔과 사용자가 적은 불편이 정한다.** 이유: 정리 요청은 새 설계(슬라이스 0 + 불편 해소)를 만들므로 «영향받는 lens 만 재실행» 전제가 성립하지 않는다(기존 명세가 없을 수도 있다).

### C2 수정 모드 G0 — 빚 스캔·빚 질문 (P2 · R1)
수정 모드 1번을 개정: **영향 범위를 확인하고, Phase 0 의 3번(빚 스캔)·4번(빚 질문·산출물 폴더 절차)을 그대로 수행한다.** 스캔 대상 = 이번 수정이 속한 BC(G0 스코프의 BC). ⓐ 항목이 있으면 슬라이스 0 이 생기므로 **G1′ 을 생략하지 않는다**(순수 구현 수정 생략 조항에 예외 한 줄). houserules final §4 문면과 정합 — 규범 신설이 아니라 Coordinator 를 §4 에 맞추는 정합이다.

### C3 정리할 것이 없으면 G0 에서 멈춘다 (P3)
Phase 0 4번에 한 문장: **정리 요청인데 빚이 0 이고 사용자가 적은 불편·정리 항목도 없으면, 설계로 넘어가지 않고 G0 배너에 그 사실(스캔 증거 포함)을 올려 사용자에게 불편을 적거나 끝낼지 묻는다.** 자율 실행이면 STOP 기록으로 정지. «증거 없는 빚 0 = blocker»(:79)는 그대로.

### C4 ⓑ 는 결정 출처가 있어야 받는다 (P4 · R2)
Phase 0 4번 빚 질문 문장에 추가:
- ⓑ(미룸)는 사유와 함께 **결정 출처**를 받는다 — 사용자 직접 응답이거나, 발주서·대리 응답이면 **사용자 원문과 시각**. 출처 없는 ⓑ 는 결정으로 받지 않는다: 대화형이면 사용자에게 직접 다시 묻고, 자율 실행이면 `STOP_FOR_USER_APPROVAL` 로 정지한다.
- 발주서가 빚 답을 ⓐ 로 미리 정했으면 그대로 받는다(«미룰 수 없음» 항목은 원래 ⓑ 가 없다).
- `refactor-scope.md` 의 결정 기록에 출처를 적는다.
경계 절(:210) «발주가 답을 고정한 게이트(자율 라운드의 G0 빚 등)» 문구는 유지 — ⓑ 고정이 출처 조건을 통과한 경우만 여기에 든다는 괄호를 단다.

### C5 앵커는 «실행»마다 (P5)
build_anchor 규칙 개정: **앵커는 실행마다 한 번 쓴다 — 실행 = 사용자의 G0 승인 하나로 시작한 빌드.** 판정을 기계적으로 하기 위해:
- G0 승인 때 Coordinator 가 `scope.md` 에 실행 줄 `실행 <date +%Y%m%d-%H%M> — G0 승인` 을 append 한다.
- Phase 2 첫 파견 직전: 최신 실행 줄에 앵커 기록이 없으면 `git rev-parse HEAD` 를 `build_anchor` 에 쓰고(기존 값은 덮어씀) 그 실행 줄에 `· build_anchor <SHA>` 를 덧붙인다. 있으면 재기록하지 않는다(같은 실행의 G1′ 반송·회전·STOP 재개·세션 재시작).
- 앞 실행이 끝나지 않았으면(G2 승인·마무리 기록 없음) 새 G0 는 새 실행이 아니라 그 실행의 재개다 — 사용자가 G0 에서 앞 실행을 버린다고 명시한 경우만 새 실행(세탁 차단: 미완 실행의 귀속을 새 앵커로 지우지 못하게).
- 옛 앵커 값은 `scope.md` 실행 줄에 남는다(감사).

### C6 재사용 폴더의 refactor-scope.md (P6)
새 실행은 `refactor-scope.md` 를 새로 쓴다 — 앞 실행 기록은 git 이력에 남는다(«이월·누적 금지»와 같은 이유). 파일 첫 줄에 실행 줄(C5)을 적어 어느 실행의 기록인지 밝힌다.

### C7 가이드 정합 (P7)
- §4 질문 목록: «기존 기능의 작은 수정에서는 이 조사를 하지 않을 수 있습니다» 삭제 → «작은 수정에서도 조사합니다». 미룸 문장에 «다른 세션이 대신 요청할 때 미루려면 사용자 원문과 시각이 필요합니다».
- §4 예외 목록 «기존 코드 정리를 이번에는 미룬다는 결정» 뒤에 출처 조건.
- §6: «그 조사를 하지 않는 작은 수정이면 옮기는 정리도 하지 않습니다» 삭제 · 정리 요청은 조사 결과로 범위가 정해진다 · 조사해도 정리할 것이 없고 불편도 없으면 첫 단계에서 멈춘다.
- §7: 미룸 대리 불가 문장에 «원문·시각 없는 미룸은 플러그인이 받지 않고 멈춥니다».
- 명세 `workspace/design/2026-09-05-plugin-request-guides-spec.md` §0 개정 기록 · README G0 설명 확인.

## 4. 적대 검토에 묻는 것
1. C5 실행 판정이 결정적인가 — 세션 재시작·STOP 재개·G1′ 반송·동시 레인에서 앵커가 한 번만, 올바른 시점에 쓰이는가. 세탁 경로가 남는가.
2. C2 로 수정 모드 비용이 커질 때 «영향받는 lens 만» 원칙과 충돌하는 곳(슬라이스 0 설계는 누가·어느 lens 로).
3. C4 출처 규칙을 대리 세션이 형식만 채워 우회할 수 있는가 — 런타임이 할 수 있는 최선인가.
4. C1 «정리 요청» 판별이 모호할 때(기능 추가 + 정리 혼합) 어느 쪽으로 가는가.
5. C3 이 가이드 §6 약속(«불편을 알려 주세요»)과 어긋나지 않는가.

## 5. 행동 시험 계획
