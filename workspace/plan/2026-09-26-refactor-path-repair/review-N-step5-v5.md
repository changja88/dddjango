  2. v5 이후 overrides 를 갖는 규범은 **적용 범위 Override(새 R-ID) 하나**이고, 목적어는 대상 56 이다(D5:222·328).
  3. 그러면 ② 의 Override 갈래가 받는 경우는 이것 하나뿐이다. 아키텍트가 `제외 · R-NEW «리팩토링 모드의 BC 점검과 그 슬라이스 0 은 …»` 를 내면 다음과 같다.

     - ② R-NEW ∈ 그 블록 works · 종류 Override · overrides ∋ 위반 R-ID(블록 결속이라 위반은 «블록의 규범 집합» — D5:138).
     - ③ R-NEW 는 대상 목록에 없다. R-NEW 의 블록은 대상 규범을 품지 않으므로 어구 검사가 걸리지 않는다.
     - ④ 혼합 블록 아님. → **green**.
  4. 적용 범위: 대상 56 이 든 블록은 43개이고, 그 안의 의무·금지 규범은 208개다 [실측 `scopeblk.py`]. R-0115·R-0962(판정 이주 — 예시 3), R-0696·R-0673(함수형 Router — 예시 2), R-3110·R-3142(새 코드 배치) 위반이 전부 여기에 든다.

  6. 아키텍트는 R-NEW 원문과 대상 목록을 `sections.md` 로 받는다(D5:123·185). 판정 모드 문면이 ② 의 허용 근거를 나열하면, «위반 R-ID 를 overrides 로 가리키는 Override» 를 찾는 모델에게 보이는 것은 R-NEW 하나다.
  7. v4 에도 이 갈래가 있었고 대상은 5건이었다(D4:135·146). M 은 이를 짚지 않았다. v5 가 대상을 56 으로 넓히면서 구멍도 같이 커졌다.

### N-M2 곁 문면을 대신한 1행은 수신자가 볼 수 없는 문면을 가리키고, Phase 1 architect 가 수신자에서 빠졌다

- **위치**: D5:243(«파견 받는 에이전트(coder · DR · acceptance-tester)에 … 적용 범위 규범을 따른다» 1행씩) · D5:286 · D5:327 · D5:174(리뷰어 «목록 경로와 1행»)
- **근거**

## 곁 문면 대체 판단 (특히 볼 것 ③)

- 블록 문면을 바꾸지 않는 결정 자체는 옳다. 형제 규범 오독이 생기지 않는다.
- 그러나 1행이 작동하려면 수신자가 **Override 원문**을 받아야 한다. 배포 md 에 R-ID 가 없어 `djr:overrides` 는 에이전트에게 보이지 않는다. 산문으로 전달되는 것은 Override 가 문면으로 적은 조항 종류뿐이다.
- 슬라이스 0 집행은 기존 «G0 ⓐ → 슬라이스 0» 장치가 대부분 허가한다. 1행이 실제로 필요한 곳은 소수 규범(R-0697·R-0674·R-2586·R-1713/1714/1720)이다. 그중 architect 몫이 수신자에서 빠졌다(N-M2).
- N-M2 고칠 것(파견 입력에 원문 · architect 추가)이면 대체가 선다. R-0697 로 coder·DR 이 정리를 거부하지 않게 되고, 블록 편집 0 을 유지한다.
