## 1. 한쪽 고정 원칙 — 슬라이스 0 을 둘로 나눈다

| 슬라이스 | 담는 ⓐ 항목 | 고정하는 쪽 | 동작 보존 증거 |
|---|---|---|---|
| **0T 테스트 정리** | 테스트 쪽 빚(대상 경로가 테스트 파일·테스트 지원 모듈 — §2.1) | 제품 코드 | 제품 코드 무변 + 테스트 케이스 이름 집합이 줄지 않음 + 관련 테스트 green |
| **0C 코드 정리** | 그 밖의 ⓐ | 테스트 | 테스트가 치환 말고 무변 + 관련 테스트 green |

- 순서는 0T → 0C 다. 정리된 테스트가 코드 정리의 기준이 된다.
- 한 항목이 두 쪽 본문을 함께 바꿔야 하면 한 단계로 동작을 보존할 수 없다 → 기존 «슬라이스 0 과 비위반 이동의 STOP»(동작 불변 불가)으로 올린다. 새 STOP 경로를 만들지 않는다.
- 분류는 Coordinator 가 경로로 한다(§2.1 의 테스트 경로면 0T). 분류 결과는 Phase 2 시작 한 줄 상태의 슬라이스 목록에 `0T`/`0C` 로 적는다.
- 0T 가 비면 0C 만, 0C 가 비면 0T 만 있다. ⓐ 가 0 이면 창이 없다.

## 2. 측정 — `scripts/behavior_guard.py` (새 · Codex byte 미러 · 봉인 글롭)

### 2.1 파일 분류 (G2 N-8)

- **테스트 파일** = 저장소 추적·미추적(비무시) `.py` 가운데 다음 하나: 경로 조각에 `test`·`tests` 디렉터리가 있다 · 파일명 `test_*.py`·`*_test.py`·`conftest.py` · 경로 조각에 `factories`·`fake`·`fakes`·`fixtures` 디렉터리가 있다(테스트 지원 모듈 — G2 N-2 · e2e 68 중 52 가 이것을 import 한다).
- **제품 파일** = 그 밖의 `.py` 전부(`migrations/` 포함 — 마이그레이션은 §2.3 에서 따로 본다).
- `.dddjango/`·가상환경·`node_modules` 는 뺀다. 목록이 아니라 규칙이다(G2 m2-8).

### 2.2 창과 명령

- `behavior_guard.py open <산출물 폴더> --kind test|code` — 창의 첫 슬라이스 파견 **직전**. 창 번호는 스크립트가 배정한다(`behavior/w<n>-open.json` · 닫힌 창 재open 거부 · G2 m2-9). 기록: 실행 식별자(실행 줄 G0 승인 값 + `build_anchor`), HEAD SHA, 작업 트리 dirty 경로 목록, 분류된 파일별 내용 해시, 테스트 케이스 이름 다중집합(정적 — `def test_*` 모듈 함수와 `Test*` 클래스 메서드), 마이그레이션 표면(§2.3). 원문은 싣지 않는다.
- `behavior_guard.py close <산출물 폴더>` — 창의 마지막 슬라이스 보고와 그 경량 감사 반영을 받은 **뒤**, 다음 파견 전(G2 N-1: 감사가 close 보다 먼저다 — 감사 반영으로 파일이 바뀌면 close 가 그것까지 본다). 캡처와 비교를 함께 하고 `behavior/w<n>-close.json` + `요약:` 1행을 낸다.
- `behavior_guard.py verify <산출물 폴더>` — G2 배너 직전. `refactor-scope.md` 현재 실행의 ⓐ 건수 N 을 읽어, N > 0 인데 창이 0 이면 red «창 누락»(G2 N-9) · 열린 창이 있으면 red · 모든 창 close green 이면 green · N = 0 이면 `해당 없음`. `요약:` 1행이 G2 배너 `동작 보존:` 행의 기계 출처다.
- exit: 0 green · 2 red · 1 실행 불능(실행 식별자 불일치 — 폴더 재사용 · 입력 부재 등).

### 2.3 판정

**0C(코드 정리) — 테스트 고정**
- 테스트 파일의 추가·삭제·이동은 red 다(테스트 이동은 0T 의 일이다).
- 바뀐 테스트 파일은 **치환 대응표**로만 설명돼야 한다. 대응표 = 창 안 제품 파일의 이동 쌍(삭제된 경로와 같은 내용 해시·같은 최상위 정의 이름 집합을 가진 추가 경로)에서 만든 «옛 dotted 경로 → 새 dotted 경로» · «옛 파일 경로 → 새 파일 경로».
- 비교: 두 판을 토큰화해 차이 토큰이 전부 (a) import 문의 모듈 경로 조각 (b) 문자열 리터럴 안의 dotted/파일 경로 이고, 각각 대응표의 옛 값 → 새 값이면 green. 그 밖의 차이는 red(`path::line` 과 토큰 병기).
- 이름 재결합(G2 N-2 뒤 절반): import 된 이름이 대응표로 옮긴 모듈에서 **같은 이름**을 가져오는지 본다 — 이름이 바뀌면 red.
- 알려진 사각(보고 상시 병기): 이동 없이 제자리에서 본문만 바뀐 제품 코드는 테스트가 판정한다(이 장치의 대상이 아니다) · 동적 경로 조립(f-string·`+` 결합)은 대응표 치환으로 설명되지 않아 red 로 선다(과탐 방향 — 오탐 처분은 §4).

**0T(테스트 정리) — 제품 코드 고정**
- 제품 파일(마이그레이션 포함)의 내용 해시가 하나라도 바뀌거나 추가·삭제되면 red.
- 테스트 케이스 이름 다중집합이 줄면 red(이동은 무변 · 새 테스트는 허용). 이름 바꾸기는 «삭제 + 추가»라 red 다 — 이름을 바꿔야 하는 정리는 사용자 확인 대상이다(§4).
- 단언이 약해졌는지는 기계로 보지 않는다 — 경량 감사(DR)가 hunk 대조로 보고, G2 배너에 0T 의 테스트 diff 파일 목록을 싣는다.

**공통 — 마이그레이션 무변**
- 정적: `**/migrations/NNNN_*.py` 의 (app_label, 파일 이름) → 내용 해시. app_label 은 같은 앱 폴더 `apps.py` 의 `label` 리터럴, 없으면 앱 폴더 이름(G2 m2-2 — 표준 칸으로의 앱 재배치는 무변). 추가·삭제·변경은 red.
- 동적(선택): `--python <인터프리터>` 가 주어지면 open·close 에서 `manage.py makemigrations --check --dry-run --skip-checks` 를 pytest 설정의 `DJANGO_SETTINGS_MODULE` 로 돌려 «변경 없음» 여부를 비교한다. open 이 실패하면 «미측정(사유)»으로 적고 정적 판정만 한다 · open 성공 ∧ close 실패는 red(G2 m2-6). settings 가 pytest 설정에 없으면 동적 부분을 돌리지 않는다(G0 질문을 새로 만들지 않는다 — 정적 판정이 남는다).
- 창 안 머지(G2 N-6 — 절차 대신 탐지): close 가 open HEAD 에서 지금 HEAD 까지 사이에 머지 커밋을 보면 exit 1 «창 안 머지 — 창을 다시 연다». Coordinator 는 그 창을 새 창으로 다시 연다(앞 창 결과는 버린다).

## 3. 역할과 규범

- **Coordinator**(`command-dddjango` · graph-owned):
  - Phase 2 3번: 슬라이스 0 을 0T → 0C 로 나누는 규칙(§1) 한 구절.
  - 창 절차 세 문장: ① 창 첫 파견 직전 `open --kind` ② 창 마지막 슬라이스의 보고·경량 감사 반영 뒤 다음 파견 전 `close` — exit 2 면 파견하지 않고 §4 처방 ③ G2 배너 `동작 보존:` 행 = `verify` 의 `요약:` · exit ≠ 0 이면 G2 금지(7번 금지 목록).
  - 병렬 배차 예외: 창의 슬라이스는 창 안에서만 병렬이다(close 전 다음 창·기능 슬라이스 파견 금지).
  - 경량 감사: 슬라이스 0 이 있으면 슬라이스 수와 무관하게 0T·0C 창마다 경량 감사 1회(G2 N-1 — 지금은 «슬라이스 ≥3» 조건).
  - 실행 줄 기계 기록 열거에 `behavior/` 산출(경계 절 — 사후 개정 아님).
- **coder**(`agent-coder`): 입력에 슬라이스 종류(0T/0C). 0C 에서 테스트를 치환 말고 고쳐야 하면, 0T 에서 제품 코드를 고쳐야 하면 **편집하지 말고 보고**한다(G2 N-3 — «보고 → Coordinator 가 STOP 판정» 한 경로).
- **acceptance-tester**: 0C 에서 e2e 의 치환 편집이 필요하면 소유자는 AT 다 — 입력에 대응표를 준다(G2 N-3 ⓐ).
- **discipline-reviewer**: 창 경량 감사 입력에 close 보고(0T 의 테스트 diff 목록 · 0C 의 치환 목록)를 준다. 0T 는 단언 약화 여부를 hunk 대조로 본다.
- Codex 의미 미러 4곳(SKILL · coder · AT · DR) · 스크립트 byte 미러 · 봉인 글롭.

## 4. red 처방

- 1차는 **원인 편집의 철회**다(창 안이라 기능 슬라이스가 아직 없다).
- 철회로 끝나지 않으면(그 정리에 반대쪽 본문 변경이 필요하다) 기존 «슬라이스 0 과 비위반 이동의 STOP»으로 올린다 — 선택지 «별도 요청으로 / 출처 있는 ⓑ / 작업 중단 / 장치 오탐(측정 결함)». 답은 `ⓐ 재상정` 절.
- «장치 오탐»만 `behavior/accepted.txt`(Coordinator 소유 · `<항목 ID> · 장치 오탐 · 출처 …` · 실행 식별자 결속 · 이월 금지)로 close 재판정에서 뺀다.
