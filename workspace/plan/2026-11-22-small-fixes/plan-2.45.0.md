## 현장 보고

- **F4-181**(수리됨): 승인 머지 목록이 있어도 registry_gate 가 위반 줄만 provenance 로 가르고 ⓓ 줄은 가르지 않아, main 들임이 데려온 다른 레인 파일의 ⓓ 가 감수자 입력에 섞였다(현장 감사가 들임 유입 26줄을 하나씩 «기각» 으로 닫음).
- **F4-182**(수리됨): `application/__pycache__` 와 캐시만 남은 폴더(지운 BC 찌꺼기)를 BC 로 세어 거짓 red · 진짜 줄(#365) 가림.
- **F4-189**(수리됨): scope 렌더 검사기 · 도구가 `python3 -I` 에서 제 도움 모듈을 못 찾아 돌지 않음 · `PYTHONSAFEPATH=1` 이 자식에게 내려가 게이트가 조용히 green.
- **F4-201**(수리됨): 경로 앞 응답 표가 점검 제외 경로 설정을 글자로만 비교해, 정규식으로 적은 제외 경로의 생성 문서에 실제로 나지 않는 503 이 붙음.
- **F4-203**(수리됨 — 글): e2e 시험은 자기 BC 모델을 import 못 해(#390) factory 행의 타입을 달 길이 없어 보임.

## 받아들인 한계

- 빈 폴더 · `.DS_Store` 나 도구 캐시가 함께 남은 폴더 · git 무시 실파일 폴더는 지금처럼 BC 다.
- 앵커에 실파일 없이 커밋된 캐시나 gitlink 만 있는 BC 자리는 두 사본 판정이 갈려 새 red 가 설 수 있다.
- main 에 레인 없이 바로 든 커밋의 ⓓ 는 «착륙 레인 몫» 이 참이 아니다 — 읽어야 보인다.
- 묶음 물음은 읽어야 보이는 판정이다(검사기가 «답이 바뀌었나» 를 재지 않음).
- 정규식 ↔ 템플릿은 글로 정한 꼴 밖에서 어긋날 수 있고 설정 값은 검사기가 읽지 않는다.

## 교훈

1. 구현 검토 때 «볼 자리» 로 적어 둔 곳은 결함이 실제로 나는 장난감으로 옛 판부터 잰다 — 중첩 `application/` 은 운영자가 미리 적어 두고도 결함을 못 일으키는 장난감에서 «차이 0» 을 보고 넘겼고, 검토가 차단으로 잡았다.
2. 옛 판 대조 시험을 옛 배포판에 묶으면 무관한 글 한 낱말에 붉고, 술어만 갈아 끼운 대조 판은 술어 밖 변이를 못 본다 — 상대 대조(지금 scripts − 그 조건)에 절대 기대를 함께 둔다.
3. 감사 재료를 «빼기» 로 적으면 원인 파일이 빠진다 — «이 실행이 바꾼 경로» 는 더하기로(합침 · 되돌림 · 머지 안 손질까지) 적는다.
