### 고칠 설계(가‴ · v1.3)

- 끝 판정을 한 함수로 모은다: `_run_ended(실행 줄, 폴더, 착륙)` = 표식 ∨ 실행 줄 없음 ∨ 착륙.
  - `_active_runs` · `_supplier_state` · `run-state` 가 함께 쓴다(I4).
  - 착륙은 `_Landing` 이 (폴더, MH) 마다 한 번 잰다. git 은 `_History.git`(`_GIT_PINS`)로 부른다.
- 표식 blob 캐시(`hist.seed` · `_ended`)와 `:5442` 지름길에는 표식 끝만 넣는다 — 착륙 판정을 섞지 않는다(I3 seed 누수).
  - 착륙은 표식 blob 의 성질이 아니라 폴더 · 작업 트리 상태의 성질이다.
  - 그래서 표식으로 활성이 된 실행 묶음(종류, 폴더)을 다 모은 뒤 마지막에 착륙을 건다.
- `요약:` 꼬리에 `착륙 · 표식 없음 n(끝으로 셈)` 을 더한다. 폴더마다 `착륙 · 표식 없음(끝으로 셈): <폴더> · 착륙 머지 <sha12>` 줄과 deps.md «뺀 겹침 · 보류» 절 한 줄을 낸다.
- 자기 변경 판정(② · ③ · v1.3 — v1.2 의 묶은 `ls-tree` + 디스크 해시를 갈음):
  - 작업 트리마다 `git status --porcelain -z --untracked-files=all --ignored=matching --no-renames -- .dddjango` 한 번(읽기만 · `GIT_OPTIONAL_LOCKS=0` · `core.fsmonitor=false` · 처음 물을 때 모든 트리를 일꾼 8 로 함께)과 그 HEAD 의 미착륙 커밋 경로(`_History.unlanded`)로 «자기 변경 폴더» 를 정한다.
  - 미커밋 · 스테이지 · 추적 안 된 파일 · 무시 파일 · 지우고 스테이지 안 한 파일이 모두 든다(`__pycache__` · `.DS_Store` 는 뺌). git 실패는 자기 변경(보수)이다.
  - 폴더 수가 많아도 트리마다 한 번이라 run-state 폴더 목록 전부(클론 219)를 한 프로세스로 잴 수 있다.
- 공급자 상태(v1.2 · N2 · v1.3 · R3):
  - «끝» 은 동시성의 뜻(지금 아무도 그 폴더를 돌지 않음)이다. 공급자의 «정리» 는 «그 BC 리팩토링이 G2 로 끝남» 이라 «끝» 만으로 주지 않는다.

  - deps 는 이 실행 폴더를 늘 빼고(`:5385`) 기능 · 수정 모드는 deps 를 돌지 않는다. 그래서 폴더 · 실행 선택 때 부를 기계 입력이 따로 있어야 한다.
  - 폴더마다 차례로 판정한다:
    1. ② 먼저(R1) — 이 트리 말고 그 폴더를 자기 변경으로 가진 작업 트리가 있으면, 이 트리 사본이 표식이든 실행 줄이 없든 `미종료 · 까닭: ② 작업 트리 <경로> 가 이 폴더를 자기 변경으로 가짐(쓰는 중)` 이다.
    2. 읽을 판(R2) — 이 트리 사본이 자기 변경이면 디스크 `refactor-scope.md`, 아니면 MH 판 `refactor-scope.md`(deps 와 같은 판 · `ls-tree` 한 번 + `cat-file --batch` 한 번 · MH 판이 링크면 디스크)를 읽는다.
    3. `_run_ended` — 표식 · 실행 줄 없음이면 끝, 표식 없는 실행 줄이면 착륙(① · ② · ③)을 본다.
  - 출력은 폴더마다 한 줄:
    - `실행 상태 <폴더>: 끝(표식 · G2 승인 · <디스크 | MH <sha12> 판>)`
    - `실행 상태 <폴더>: 끝(착륙 <sha12> · 표식 없음) — 그 착륙 머지를 근거로 끝난 실행`
    - `실행 상태 <폴더>: 끝(실행 줄 없음 — <판>에 실행 줄 · 기록 없음)`
    - `실행 상태 <폴더>: 미종료 · 까닭: <② 작업 트리 <경로>(쓰는 중) | ① … 머지가 아님 | ② · ③ 작업 트리 <경로> | git 실패 | 못 읽음>`
  - 리팩토링 실행 줄이면 `공급자 정리 <폴더>: 예(표식 | 착륙) | 아니오 — …` 한 줄을 더한다. 끝에 `요약: run-state 폴더 n · 끝 갈래별 수 · 미종료 m` 한 줄.
  - exit: 0 = 모두 끝 · 2 = 미종료 하나 이상 · 1 = 실행 불능(`.dddjango/<폴더>` 가 아님 · 인자 오류 · MH 판을 못 읽음). 기록을 UTF-8 로 못 읽으면 그 폴더는 미종료(끝인지 모름).
  - 이 폴더에 R1 deps · R2 plan 이 쓰기 전에 부른다(폴더 · 실행 선택이 R1 보다 먼저라 흐름이 맞다 — 쓴 뒤에는 추적 안 된 산출물로 미종료가 된다 · N5).
- deps 의 ②(v1.3 판단 · 운영자 지시와 다른 몫 — 아래 «검토 처분» R1):
  - deps 는 다른 트리 사본의 실행 줄로 이미 활성을 본다 — busy 두 꼴 모두 deps exit 2(겹침 `작업 트리 … 그 폴더`)다. 착륙 길도 ② · ③ 을 먼저 본다.
  - 표식 · 실행 줄 없는 사본에 «폴더 전체 자기 변경» 을 deps 에도 거는 것은 넣지 않는다. 실행 줄(G0 승인) 전 R0′ ~ R2 산출물만 있는 레인은 아직 범위가 없어, deps 에 넣으면 그 동안 모든 BC 의 deps 가 보류로 멈춘다. «그 폴더를 누가 쓰는 중인가» 는 폴더 선택의 물음이라 run-state 가 맡는다.
- 조정자 글(Claude · Codex 같은 뜻):
  - deps 문단: «끝 표식 또는 착륙(실행 기록 파일 `refactor-scope.md` 를 마지막으로 바꾼 main 첫 부모 커밋이 머지이고 어느 작업 트리도 그 폴더를 고치는 중이 아님)» · 착륙 전제(레인 착륙 = `--no-ff` 머지 · main 은 빨리 감지 않음).
  - 폴더 · 실행 선택 ⑴ ⑵ ⑶ 과 Phase 0 4번 폴더 목록(기능 · 수정 · 리팩토링 모드 모두 · v1.2 · N1): 고를 폴더를 모두 한 번의 `run-state <폴더>…` 로 부르고 폴더마다 그 줄을 싣는다.
    - `끝(착륙 …)` 폴더는 «미종료 · 잇기» 가 아니라 «끝난 실행»(그 착륙 머지 SHA 근거)으로 보인다. 그 폴더를 다시 쓰면 새 실행이다(리팩토링 R0′ 의 같은 폴더 재사용도 같음).

### 고칠 설계(v3) — 면제는 `model_validate_json` 의 «받는 쪽» 하나에만

- **면제 조건:** try 몸통의 마디 가운데 `model_validate_json` 부르기와 그 받는 쪽만 «안 돈다» 로 바꾼다(N4 — `model_validate` · `model_validate_strings` 는 넘긴 값을 끝까지 읽어 창구 생성기 · property 가 돌 수 있어 뺀다 · 클론 ACL 에 그 둘은 0).
  - 몸통의 다른 부르기 · 이름은 배포판 판정 그대로다.
  - 그래서 검증 말고 다른 같은 파일 함수를 함께 부르면 붉다(꼴 ② · 한계).
- **파일 · 폴더 조건:**
  - 파일이 `globals` · `vars` · `setattr` · `delattr` · `__import__` · `importlib` · `exec` · `eval` · `__dict__` · (v3.1 T1) 별 import(`from .x import *`)를 쓰면 그 파일은 허용 목록 전체를 쓰지 않는다. 상대 wire 모듈도 같은 자로 wire 가 아니다.
  - (N8 · v3.1 T3) 짝 ACL 폴더(`anticorruption_layer/<partner>/` 아래 .py 전부)의 어느 파일이 위 동적 장치 · 별 import · `__setattr__` · `__delattr__` 를 쓰거나, `self.<칸>` · `cls.<칸>` 말고 다른 속성을 바꾸면(대입 · 지움 · 덧셈 대입 — wire · 그 칸 타입(계약 dataclass 등) · pydantic 바탕 어느 것이든) 그 폴더 파일들은 허용 목록을 쓰지 않는다. 못 읽는 파일이 있어도 같다.
- **이름 묶기 셈(N3):** 묶기 = 대입 · 지움 · 매개변수 · def · class · import · `except … as` · `match` 갈래 이름(`case X` · `*X` · `**X`) · PEP 695 타입 매개변수. 아래 «한 번만 묶임» · «다시 안 묶음» 은 모두 이 셈이다.
- **받는 쪽 A — 선언만 있는 wire 클래스:**
  - 자리: 같은 파일 클래스 · 또는 짝 ACL 폴더 안 상대 import 모듈의 이름. 상대 import 이름은 그 import 말고 다른 묶기가 0 이다(N3 — 모듈 대입 · 매개변수 · 지역 · 꼴 ③ 부르는 쪽 매개변수의 가림).
  - 모듈 조건(상대 모듈):
    - import 는 `__future__` · `typing` · `typing_extensions` · `pydantic` · `datetime` · `decimal` · `enum` · `uuid` · `types` · 계약(`open_host_service` 아래 `contract`)과, 같은 조건을 지나는 짝 폴더 안 상대 모듈뿐이다.
    - 하위 모듈 import(`from . import x` · `from .schema import x`)는 그 하위 모듈 파일을 읽는다. 상대 경로가 짝 폴더 밖이면 거짓이다.
    - 모듈 최상위는 import · 클래스 · 글자 · 부르기 없는 대입 · `type` 별칭뿐이다.
  - 클래스 조건:
    - 데코레이터 0 · 바탕은 pydantic `BaseModel` · `RootModel` · enum · 다른 wire.
    - 몸통은 칸 주석 · 글자 값 · `ConfigDict(...)` · `Field(...)`(글자 인자만 — `default_factory` 같은 이름 값은 안 됨) · 글자 · `pass` 뿐 — 메서드 · 검증기 0.
    - (N1) 칸 주석은 «검증 코드가 끼어들 수 없는 꼴» 뿐이다:
      - 끝 이름은 맨 타입(`str` · `int` · `float` · `bool` · `bytes` · 그릇 — 그 파일 · 모듈에서 다시 묶이지 않은 내장 이름만) · 계약 이름 · `datetime` · `Decimal` · `UUID` 들 · 같은 조건 wire 다.
      - 첨자 머리는 내장 그릇(`tuple` · `list` · `dict` · `set` · `frozenset`)과 `typing` 의 `Optional` · `Union` · `Final` · `ClassVar` · `Literal` · 옛 그릇 이름(`List` …)뿐이다. `|` · `...` · `None` 을 받는다. `Literal[...]` 안은 글자만이다.
      - 부르기 · 람다 · 속성(`a.b`) · 글자 주석(앞 참조 문자열 — Literal 안 글자 빼고) · `Annotated` 는 받지 않는다. 같은 파일 dataclass · 같은 파일 함수 · 모듈 별칭(`_LOOKUP = 창구`) · pydantic 이름(`ImportString` 같은 것)도 끝 이름이 아니다.
      - `ClassVar[...]` 안은 검증 칸이 아니라 끝 이름을 가리지 않는다(`ClassVar[ConfigDict]` · 클론 꼴). 부르기 · 람다 · 속성 · 글자는 거기서도 0 이다.
      - 같은 파일 wire 는 이 조건을 고정점으로 넓힌다(다른 같은 파일 wire 를 칸 타입으로 쓰는 것). 상대 모듈 wire 도 같은 조건이다(그 모듈 클래스 · 상대 import 이름 · 계약 · 표준 이름이 끝 이름).
  - 같은 파일 wire 는 클래스 안 이름에 창구 import 이름이 없어야 한다.
  - wire 이름은 배포판처럼 «창구 쪽» 에 남는다 — 검증 부르기의 받는 쪽일 때만 면제다(`Wire.model_construct(...)` · 속성 부르기는 붉다).
- **받는 쪽 B — 꼴 ① 같은 파일 모델 짓기 함수:**
  - 부르는 자리: 검증 부르기의 받는 쪽이 `F(인자…)` 이고, 인자가 모두 둘러싼 함수의 «값 자료» 매개변수이거나 글자다.

  - F 조건:
    - 모듈 최상위 `def` 로 한 번만 묶임 · 데코레이터 0 · `*args` · `**kwargs` 0 · 기본값은 글자.
    - 모든 매개변수가 «자료 타입» 주석이고 몸통에서 다시 묶지 않는다(짓기 함수끼리의 안쪽 부르기 `_model(name, fields)` 의 `fields: dict[str, _ModelField]` 처럼 별칭 안 `type[…]` 은 F 의 매개변수에서는 받는다 — 바깥 입구 인자가 값 자료라 그 안의 클래스는 짓기 함수 몸통의 글자에서만 온다).

    - 읽는 이름은 매개변수 · 지역 · 알려진 바깥 · wire · 다른 짓기 함수 · 자료 이름 · 자료 별칭 · pydantic 이름 · (알려진 바깥 · wire 로만 지은) 모듈 상수 · `__name__` 뿐이다. 창구 쪽 이름은 읽지도 않는다.
    - 맨 이름 부르기는 `create_model` · `Field` · 내장 몇(`tuple` · `list` · `dict` · `set` · `frozenset` · `str` · `int` · `float` · `bool` · `len` · `enumerate` · `zip` · `range` · `isinstance`) · 다른 짓기 함수 · wire · 자료 이름뿐이다.
    - 속성 부르기의 뿌리는 매개변수 · 지역 · 자료 이름 · wire 뿐이다.

    - 자신이나 부르는 짓기 함수가 `create_model` 을 부른다.
  - «자료 타입» 주석:
    - 내장 그릇 · 값(`str` · `int` · `float` · `bool` · `bytes` · `tuple` · `list` · `dict` · `set` · `frozenset` · `None`)과 그 첨자 · `|` · `Literal` · `Optional` · `Union` · `Final` · `Annotated`.

    - 계약 이름 · `datetime` · `Decimal` · `UUID` · `EllipsisType`.
