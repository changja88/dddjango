## 0. 판정 요약

1. **원칙은 옳다.** «사용자는 결과·규칙·보존 범위를, 설계·배치·모드·테스트는 플러그인이» — 현장에서 이 원칙을 어긴 발주가 준수율을 깎았고, 사용자도 09-26 같은 원칙을 원문으로 다시 말했다(W2).
2. **그러나 원칙이 권고형으로만 적혀 있고, 실제 사용 형태를 다루지 않는다.** 실제 발주는 사람이 아니라 «발주자» Claude 세션이 긴 발주서로 자율 레인을 굴린다. 가이드는 «넣지 말 것»을 금지형으로 말하지 않아, 발주서가 모드·lens·쓰기 경계·선례·빚 결정·이탈 결정을 채웠다. 가이드 인용은 P2 92%(49/53) → P3 9%(3/33)로 감쇠했다 ✔.
3. **사실 오류가 있다** — 호출명(두 가이드) · web 철거 기능 문구 · web 시안 채널 제한과 런타임 불일치.
4. **런타임과 어긋난 약속이 있다** — dddjango §6 품질 개선 · §4 «BC 는 플러그인이 정함» · 빚 질문 미고지.
5. **가이드만으로 닫히지 않는 것이 있다** — 규범이 «발주가 답을 고정한 게이트»를 허용하고(commands/dddjango.md:210 ✔), web 규범은 «명시적으로 위임된 결정»을 이탈 근거로 받는다(architecture-web final.md:21). 가이드 교정과 런타임 수리를 함께 설계해야 한다.
