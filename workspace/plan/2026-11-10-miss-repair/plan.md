# 현장 보고 수리 2판 — 위반을 못 잡고 통과시키는 항목 계획 v4 (dddjango 2.35.0 · 2026-11-10 · 계획 독립 검토 1 · 좁은 재확인 · 구현 독립 검토 1 · 트랜잭션 규칙 재결정 반영)

배포판 2.34.0(태그 `dddjango--v2.34.0` · 98dac918)으로 재현했다. 묶음 순서(사용자 결정 2026-11-09 «진행하자»)의 2판이다. 재현 근거는 작업 폴더의 r1 · r2 · p52 보고(커밋하지 않음)이고, 이 문서가 그 요지를 옮긴다.

판 번호: 2.35.0 — 새로 막히는 꼴(조회한 것 여럿을 한 트랜잭션에서 고치거나 지움 · 쓰기 메서드의 반환 · 응용 층 예외 클래스 · 프레임워크가 부르는 메서드의 필수 인자)이 생기므로 minor.

## 결정

- 사용자 결정(2026-11-10): 트랜잭션으로 묶을지는 «여러 건이냐» 가 아니라 «같이 되돌려야 하는 의미가 있느냐» 로 정한다. 처음 결정(«애그리거트는 하나의 트랜잭션으로 나머지는 여러 트랜잭션으로») 뒤 이체 꼴(따로 조회한 같은 타입 둘을 한 트랜잭션에서 저장)의 판정을 두고 사용자가 «출금 · 입금은 한 트랜잭션이 맞지 않나» 를 물어 원전을 다시 조사했고(Vernon 원문은 «경험칙» · 깨도 되는 이유를 함께 적음 · 같은 DB 의 실무 다수는 묶기를 허용 · 원장은 이체 기록과 잔액 행을 한 커밋), 그 뒤 사용자 «나.» 로 바꿨다: 평소 한 트랜잭션은 애그리거트 하나를 바꾼다. 같은 BC · 같은 DB 안에서 이미 있는 애그리거트 둘 이상을 함께 바꿔야 하면 불변식 이름 · 묶는 애그리거트 · 잠금 순서를 설계에 적고 G1 승인을 받은 경우만 허용한다(이름 붙은 승인 예외). 조회한 여럿을 돌며 고치거나 지우는 묶음(개수가 데이터에 달린 묶음)은 예외 밖이다 — 건마다 트랜잭션(반복문 안에서 `with uow`).
- 사용자 결정 «가.»(2026-11-10 · 판 나눔): 승인 장치(설계 초안 `design-joint-commit.md` v3 — 이 판에 커밋하지 않음)는 설계 검토 셋째 확인에도 차단이 남아 다음 판(2.36.0)으로 미룬다. 이 판은 준비된 넷(F4-49 · F4-103 · F4-52 · F4-50 의 조회한 여럿 묶음 막기)만 싣는다. 이체 꼴은 이 판에서 2.34.0 과 같게 둔다 — 검사기 · 리뷰 글 모두 새로 막지도 풀지도 않는다.
- 새로 여럿 만들기 묶음 예외: 사용자 «가,나 상관 없을거 같아» → 지금대로 둔다(질문 생략 · 설계 처리 · 이의 시 뒤집음).
- 사용자 결정 «현행 유지하자»(2026-11-10): 시험 본문의 타입 주석은 기계로 재지 않는다 · 규칙 글 그대로 → F4-33 · F4-83 · F4-135 접음(장부 처분 줄 끝).
- 사용자 결정 «나.»(2026-11-10): F4-52 를 보류에서 꺼내 이 판에 넣는다 — 설계 지시 글 보강 + 기계 경보(프레임워크가 대신 부르는 것으로 알려진 메서드에 필수 인자를 더하면 예보기가 멈춤). 기계로 설 수 없으면 글만으로 낮추고 알린다.
- 질문 생략 · 설계 처리 · 이의 시 뒤집음:
  - F4-49: 저장소 쓰기 메서드의 반환도 조회와 같은 허용 목록으로 본다(#287 «리포지토리는 애그리거트를 주고받는다»). 장부 기대 «None 또는 애그리거트» 는 표준(CAS 의 `-> bool` · `int`)보다 엄격해 넣지 않는다.
  - F4-103: 응용 층 유스케이스 폴더의 예외 클래스는 표준 자리 넷(#292) 밖이다 — 판정은 도메인이 소유하고(«판정 소유 1곳째부터 domain»), 값을 공개하려면 2.34.0 의 승인 값 길이 있다. 현장에 같은 꼴 파일 셋(기존 ② 승격 폴더의 `<x>_failure.py`)이 있고 앵커 기존분으로 통과한다.

## 항목 · 고침

### 단위 A — F4-50 한 트랜잭션에서 읽은 애그리거트 여럿을 바꿈(#550)

재현: `with uow:` 안에서 `for x in found: …; remove(x)` · `remove_many(tuple(found))` · 고치기(`save`) 같은 꼴이 전부 exit 0. 더 깊은 뿌리 — #550 의 조회값 추적(`check-domain-model.py` `loaded_from_read`)이 `ast.Assign` 만 봐서, 지역 변수 첫 대입에 주석을 다는 표준(#493)을 지킨 코드에서는 #550 이 아예 서지 않는다.

- 트랜잭션 구간은 `_transaction_write_regions` 를 넓혀 구간 안 쓰기 호출과 반복문을 함께 내게 한다(#546 결과 무변을 픽스처로 확인). 주석 있는 대입은 #550 몫으로만 넣는다 — 같은 집합을 쓰는 #257 에 먹이면 `found.started_at.isoformat()` 같은 읽기가 #257 확정이 된다(#257 은 이 판 밖). 서로 다른 저장소 타입 둘은 #546 몫이라 #550 이 다시 내지 않는다.
- 메시지: «같이 되돌려야 하면 한 애그리거트로 묶고, 아니면 건마다 트랜잭션을 연다(반복문 안에서 `with uow`) — 묶음은 새로 만들 때만».
- 글(그래프 → render):
  - `design-review-ddd` 점검에 한 줄(R-3741) — 애그리거트 경계 쪽(D50)의 물음으로: 유스케이스 하나가 조회한 여럿(개수가 데이터에 달린 묶음)을 한 트랜잭션에서 고치거나 지우면 blocker · 같이 되돌려야 하면 경계를, 아니면 건마다 트랜잭션 · 묶음 저장은 새로 여럿 만들 때만. 같은 절의 «트랜잭션은 db 리뷰어 몫» 과 갈리지 않게 «경계» 물음이라고 밝힌다. 이체 꼴은 말하지 않는다(판 나눔 «가»).
  - `discipline-houserules` final §1 의 틀 부품 예 «애그리거트 여럿을 한 작업 단위에서 CAS 저장» 을 «애그리거트 하나를 CAS 저장» 으로 — 이 판의 결정과 반대 길을 표준 예로 들고 있다.
  - 트리 명세 #550 · #599 행: «`save_all` 은 새로 만든 것을 받는다». #599 ㉡(맨 `bulk_update` 금지)은 남긴다 — 새 것에 `bulk_update` 를 쓰는 구현도 틀렸으니 판정은 그대로이고, 까닭 문면만 «잠금(`select_for_update`) 없는 `bulk_update` 는 경합 가드가 없다» 로 맞춘다. `check-domain-model.py` 머리말의 «같은 repository 타입의 여러 인스턴스는 구별하지 않는다» 를 «#550 ①② 가 조회 이름과 반복문으로 가른다 · 이체 꼴은 보지 않는다» 로 고친다. 결정 기록 D43 · T37 의 옛 문면(«수정은 루프 또는 FOR UPDATE + bulk_update»)은 기록이라 두고 판 기록에 «2.35.0 에서 바뀜» 을 적는다. «같은 타입 두 인스턴스는 사람 판정» 은 이 판에서 그대로다.
- 픽스처: 2.30.0 `transaction_boundary/part_flows` 의 «함께 저장»(`merge_orders` — 두 주문을 읽어 한 작업 단위에서 저장 · `fixture_matrix` «오탐 경계 0 줄» · `ok_frame_save_together`)은 이 판의 뜻에 맞게 «애그리거트 하나를 틀 부품으로 저장» 으로 바꾼다(검사기는 도움 메서드를 거친 꼴을 원래 못 본다 — 그 한계는 아래 한계 절). 이 픽스처가 함께 지키던 «#195 는 틀 부품을 보지 않는다» 경계 사례는 틀 부품의 저장 호출을 남겨 그대로 지킨다.
- 현장 영향(검토 실측): 현장의 방문 BC 에 한 작업 단위에서 방문 둘을 차례로 저장하고 미스면 둘 다 되돌리는 기존 코드가 있다(도움 메서드를 거쳐 검사기는 못 봄). 정해진 둘을 함께 바꾸는 꼴이라 이 판의 리뷰 줄(조회한 여럿)에 들지 않는다 — 다음 판의 승인 예외가 다룰 꼴이다.
- 되돌아옴 막기: 행 1 · 2 와 위 대조군 전부를 픽스처로(검토 프로토타입의 장난감 사례 이름을 따른다). 이체 꼴 하나를 «#550 판정 밖» 0 줄 대조군으로 둬 이 판이 이체를 새로 막지 않음을 고정한다. 기존 주석 없는 꼴 픽스처는 그대로 둔다. 뺀 행 3 의 검사기 · 픽스처 생성기는 다음 판 재료로 작업 폴더에 남긴다(커밋하지 않음).

### 단위 B — F4-49 저장소 쓰기 메서드의 반환(#355 · 트리 명세 행에 쓰기 반환을 더함)

재현: `save*` · `remove*` 가 dict · str · QuerySet · 도메인 밖 타입을 돌려줘도 exit 0(같은 반환의 `find_` 는 #355). `check-transaction-boundary.py` 의 #355 가 쓰기 메서드를 건너뛴다.

- 쓰기 메서드에도 같은 허용 목록(애그리거트 · 그 목록 · 값 객체 · `bool` · `int` · `None`)을 적용한다. `bool` · `int` 후보 물음(«주어가 애그리거트인가 화면인가»)은 쓰기에서 내지 않는다 — CAS 의 `-> bool` · 지운 개수 `-> int` 는 표준 길이다.
- pre-gate 저장소 채널이 같은 판정을 그대로 부르므로 예보도 따라온다(기대 파일 갱신). 진단 번호는 #355 그대로 두고 트리 명세 #355 행의 주어(«조회»)에 쓰기 반환을 더한다.
- 현장 읽기(쓰기 메서드 약 250개): 반환은 `None` · `int` · `bool` · 도메인 애그리거트 · 값 객체뿐 — 새로 막힐 현장 코드 0 으로 읽힌다.

### 단위 C — F4-103 응용 층 유스케이스 폴더의 예외 클래스(#292)

재현: 기존 ② 승격 폴더 안 `<x>_failure.py` 의 예외를 창구 · 컨트롤러가 잡아 값을 읽어도 #153 · #292 · #474 가 서지 않는다. 2.34.0 의 좁은 허용(도메인 예외의 한 문장 번역)도 이 자리로 옮기면 비켜 간다(`str(n)` · `from n` 통과). 승격 안 한 자리는 #490, ②′ 부품은 #662 로 이미 막힌다.

- `check-context-isolation.py` 의 #292 를 이름(`exception.py` · `exception/`)에 더해 클래스로도 본다: `application_layer/`(`port/` · 시험 제외)의 모듈 최상단 클래스 가운데 기반 사슬이 `Exception` · `Error` 에 닿는 것. 앞 `_` 사설 클래스는 그 모듈 안에서만 쓰일 때 뺀다 — 다른 제품 모듈이 import 하면 센다(②′ 잎의 `_` 타입을 같은 승격 폴더 형제 모듈이 import 하는 것은 houserules §1 이 허용하므로 뺀다. 승격 폴더의 `__init__.py` 는 형제로 치지 않는다 — 재수출은 바깥 공개라 센다. 시험만 import 하면 세지 않는다). 이미 이름(`exception.py` · `exception/`)으로 걸린 자리 안의 클래스는 다시 세지 않는다.
- 기반 사슬 판정 `_exception_based`(`check-usecase-dto-placement.py`)를 `checker_target.py` 로 올려 두 검사기가 함께 쓴다(같은 지식 한 출처 · 2.30.0 `is_test_path` 선례 · usecase-dto 동작은 그대로).
- 메시지: 예외 자리 넷 + «한 유스케이스의 실패도 판정이면 도메인 예외로 · 값을 공개하려면 승인 값 칸(2.34.0)».
- 글: «domain/application exception» 이 ninja final(§2.2 외 세 곳) · cleancode final · `design-architect` · `design-review-api` 에 있다. «응용 예외 = 포트 예외(바깥 행위자의 죽음)» 로 모두 같은 말로 고친다(graph-owned 는 그래프 → render).
- 픽스처 다섯 자리가 새 #292 로 붉어진다 — `skeleton/good_promoted_flows`(good) · `transaction_boundary/part_flows` · `usecase_dto/part_flows` · `api_error_controller_code` good · bad_rules(`LessonMissing`). 실패 타입을 도메인 예외로 옮겨 good 은 good 으로 남긴다. `api_error_controller_code` 는 context-isolation 을 도는 도구가 없어 그대로 둔다. 2.30.0 설계(`workspace/plan/2026-10-29-usecase-promotion/design.md`)가 «기존 ② 꼴(실패 타입 부품)» 을 정상으로 적은 것은 판 기록에 «2.35.0 에서 바뀜» 으로 남긴다.
- pre-gate 는 symbols 스텁으로 번들 검사기가 돌아 예보가 따라오는지 구현에서 확인한다.

### 단위 D — F4-52 프레임워크가 대신 부르는 길(설계 글 + 예보기 경보)
