## 결정

- 사용자 결정(2026-11-10): 트랜잭션으로 묶을지는 «같이 되돌려야 하는 의미가 있느냐» 로 정한다. 원전 재조사 뒤 «나.» = 평소 한 트랜잭션은 애그리거트 하나 · 같은 BC · 같은 DB 안 이미 있는 둘 이상을 함께 바꿔야 하면 불변식 이름 · 묶는 애그리거트 · 잠금 순서를 설계에 적고 G1 승인받은 경우만 허용 · 조회한 여럿을 돌며 고치거나 지우는 묶음은 예외 밖(건마다 트랜잭션). 8월 D43 · D50 의 판단(이체는 원전 위반 · 같은 DB 묶기 불가)은 다음 판 승인 장치와 함께 고친다.
- 사용자 결정 «가.»(2026-11-10): 승인 장치(함께 커밋)는 설계 검토 셋째 확인에도 차단이 남아 다음 판으로 미룬다. 이 판은 준비된 넷만 싣고, 이체 꼴은 2.34.0 과 같게 둔다.
- 사용자 결정 «현행 유지하자»(F4-33 · F4-83 · F4-135 접음) · «나.»(F4-52 글 + 기계 경보) · «진행하자»(계획 v3 승인).
- 운영자 처분(질문 생략 · 설계 처리 · 이의 시 뒤집음): F4-49 허용 목록은 조회와 같게(장부 기대 «None 또는 애그리거트» 는 표준보다 엄격) · F4-103 은 도메인 예외로 · #663 행을 적지 않으면 멈춤 · discipline-reviewer «대신 부르는 길» 을 blocker 로(구현 검토 1 사소 6).

## 바뀐 옛 문면

- 결정 기록 D43 · T37 의 «수정은 루프 또는 `FOR UPDATE` + `bulk_update`» 는 2.35.0 에서 «조회한 여럿을 고치는 일은 건마다 트랜잭션» 으로 바뀌었다(기록은 두고 여기 적는다). «같은 타입 두 인스턴스는 사람 판정» 은 이 판에서 그대로다.
- 2.30.0 설계(`workspace/plan/2026-10-29-usecase-promotion/design.md`)가 정상으로 적은 «기존 ② 꼴(실패 타입 부품)» 은 2.35.0 에서 #292 위반이 됐다(실패 타입은 도메인 예외로).
- #210 면제 판정도 같은 파일 베이스의 사슬을 먼저 따른다 — 같은 파일의 비예외 베이스를 상속한 클래스는 면제 밖(가장자리 변화 · 픽스처 결과는 같음).

## 한계

`plan.md` «받아들이는 한계» 그대로다. 사용자에게 닿는 것:

- #550 은 도움 메서드 · 다른 함수를 거친 쓰기를 못 보고 리뷰가 맡는다. 이체 꼴은 검사기 · 리뷰 글 모두 이 판에서 보지 않는다. `try` 몸 쓰기 → `except: continue` → `try` 밖 나감 고리는 막힌다.
- #292 는 다른 모듈 사용자 베이스만 상속한 예외 · 중첩 예외 · `framework/` 만 import 하는 사설 예외를 놓친다.
- #663 은 직계 베이스만 보고, 메서드 본문 안의 깨짐과 목록 밖 길은 글이 맡는다. 끝 칸은 증언이다.
- 새 #550 · #292 줄은 앵커 기존분이면 G2 를 통과하지만 Phase 0 빚 스캔에는 빚으로 오른다.
