구체 테스트 목록을 짜려면 기능 설명이 필요합니다. 현재 작업 디렉터리는 git 저장소가 아니고 `rg --files`로 확인되는 소스/문서도 없어, “이 기능”이 무엇인지 추론할 근거가 없습니다.

기능 설명을 아래 4가지만 알려주면 TDD 순서로 바로 테스트 목록을 정리하겠습니다.

1. 기능 이름 또는 한 줄 설명
2. 정상 동작 예시
3. 거절/실패해야 하는 조건
4. 경계값이 있다면 기준값
   예: 만료일, 수량 제한, 제외 대상, 권한, 상태값 등

기능 정보가 들어오면 이런 형태로 작성하겠습니다.

```text
1. 가장 작은 정상 케이스부터 Red-Green
   - given ...
   - when ...
   - then ...

2. 두 번째 예시로 일반화
   - 첫 테스트만 통과하는 하드코딩을 제거할 수 있는 케이스

3. 제외/거절 조건
   - 독립된 실패 축마다 하나씩 테스트

4. 경계값
   - 허용되는 경계값
   - 바로 바깥 값

5. 조합/우선순위
   - 여러 조건이 동시에 걸릴 때 기대 동작

6. 회귀 테스트
   - 이미 보고된 버그나 깨지기 쉬운 케이스
```
