현재 디렉터리에는 프로젝트 파일이 없어 특정 구현 스타일에는 맞추지 못했습니다. 우선 쿠폰 할인 정책을 도메인 단위로 TDD 진행할 때의 테스트 목록을 아래 순서로 잡는 게 좋겠습니다.

**가정**
쿠폰은 주문 금액을 입력받아 할인 금액 또는 최종 결제 금액을 계산한다. 정책에는 정액 할인, 정률 할인, 최소 주문 금액, 최대 할인 한도, 유효 기간, 활성 상태, 사용 여부가 있을 수 있다.

**추천 테스트 순서**

1. 할인 쿠폰이 없으면 주문 금액이 그대로 유지된다.
2. 정액 쿠폰을 적용하면 주문 금액에서 고정 금액이 차감된다.
3. 정액 쿠폰 할인액이 주문 금액보다 크면 최종 금액은 0원 미만이 되지 않는다.
4. 정률 쿠폰을 적용하면 주문 금액의 지정 비율만큼 할인된다.
5. 정률 쿠폰에 최대 할인 한도가 있으면 할인액은 한도를 넘지 않는다.
6. 최소 주문 금액 이상이면 쿠폰이 적용된다.
7. 최소 주문 금액 바로 아래이면 쿠폰이 적용되지 않는다.
8. 최소 주문 금액과 정확히 같으면 쿠폰이 적용된다.
9. 유효 기간 시작일 전에는 쿠폰이 적용되지 않는다.
10. 유효 기간 시작일 당일에는 쿠폰이 적용된다.
11. 유효 기간 종료일 당일에는 쿠폰이 적용된다.
12. 유효 기간 종료일 다음 날에는 쿠폰이 적용되지 않는다.
13. 비활성 쿠폰은 조건이 맞아도 적용되지 않는다.
14. 이미 사용한 쿠폰은 다시 적용되지 않는다.
15. 적용 대상 상품 또는 카테고리가 맞으면 쿠폰이 적용된다.
16. 적용 대상이 아니면 쿠폰이 적용되지 않는다.
17. 여러 쿠폰이 들어왔을 때 중복 사용 불가 정책이면 하나만 적용된다.
18. 여러 쿠폰 중 최적 할인 쿠폰을 자동 선택하는 정책이면 가장 큰 할인액이 선택된다.
19. 할인 계산 시 원 단위 절사, 반올림, 올림 규칙이 기대대로 적용된다.
20. 잘못된 쿠폰 코드이면 명확한 실패 결과를 반환한다.

**첫 Red 테스트 후보**

가장 먼저는 단순하고 구현 부담이 낮은 테스트부터 시작하는 게 좋습니다.

```text
정액 쿠폰 1,000원을 10,000원 주문에 적용하면 최종 결제 금액은 9,000원이다.
```

그다음 바로 과할인 방지 테스트로 넘어가면 핵심 불변식을 빨리 고정할 수 있습니다.

```text
정액 쿠폰 10,000원을 3,000원 주문에 적용하면 최종 결제 금액은 0원이다.
```

**아직 결정해야 할 정책**

- 할인 결과를 `discount_amount`로 반환할지, `final_price`로 반환할지
- 쿠폰 적용 실패를 예외로 볼지, 실패 결과 객체로 볼지
- 정률 할인 소수점 처리 방식
- 여러 쿠폰의 중복 적용 허용 여부
- 유효 기간 기준이 날짜인지 시각인지, 타임존 기준은 무엇인지
