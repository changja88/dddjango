코드 증거를 찾으려 했지만 현재 작업 디렉터리는 비어 있고 Git 저장소도 아닙니다. 그래서 아래는 **쿠폰 정책 도메인 초안**입니다. 실제 요구사항이나 테스트가 들어오면 용어와 애그리거트는 조정해야 합니다.

**Bounded Context**
쿠폰 정책은 우선 `Coupon Policy` 컨텍스트로 잡는 게 자연스럽습니다. 핵심 관심사는 “쿠폰이 어떤 주문/상품/고객에게 적용될 수 있는가”와 “적용되면 어떤 혜택을 주는가”입니다.

**Ubiquitous Language**
- `CouponPolicy`: 쿠폰의 적용 조건, 제외 조건, 할인 혜택, 유효 기간을 정의하는 정책
- `IssuedCoupon` 또는 `CustomerCoupon`: 고객에게 발급된 쿠폰 인스턴스
- `Benefit`: 정액 할인, 정률 할인, 최대 할인 금액 같은 쿠폰 혜택
- `EligibilityCondition`: 쿠폰을 사용할 수 있는 조건. 예: 최소 주문 금액, 고객 등급, 첫 구매 여부
- `ExclusionRule`: 쿠폰 적용에서 제외되는 대상이나 조건
- `ExclusionPattern`: 제외 대상을 표현하는 패턴. 예: 특정 상품, 카테고리, 브랜드, 판매자, 상품 태그
- `ApplicableTarget`: 쿠폰 적용 가능 대상
- `ExcludedTarget`: 쿠폰 적용 제외 대상
- `ValidityPeriod`: 사용 가능 기간
- `Redemption`: 쿠폰 사용 행위
- `RedeemedCoupon`: 이미 사용 완료된 쿠폰 상태
- `ExpiredCoupon`: 유효 기간이 지난 쿠폰 상태
- `OrderSnapshot`: 쿠폰 적용 판단에 필요한 주문 정보의 스냅샷. 주문 애그리거트를 직접 끌어오지 않기 위한 경계 객체

**Aggregate 후보**
가장 먼저 볼 애그리거트는 `CouponPolicy`입니다.

`CouponPolicy`가 보호해야 할 불변식:
- 할인 혜택은 유효한 값이어야 한다. 예: 할인율 0% 이하/100% 초과 불가
- 유효 기간은 시작일이 종료일보다 늦을 수 없다
- 제외 조건과 적용 조건이 정책 안에서 모순되면 안 된다
- 활성화된 정책은 임의로 핵심 조건을 바꿀 수 없거나, 변경 시 새 버전으로 발행해야 한다
- 제외 패턴은 정책의 일부이며, 외부에서 리스트를 직접 수정하지 않고 정책 행위로 추가/삭제되어야 한다

두 번째 애그리거트 후보는 `IssuedCoupon` 또는 `CustomerCoupon`입니다.

`IssuedCoupon`이 보호해야 할 불변식:
- 한 번 사용된 쿠폰은 다시 사용할 수 없다
- 만료된 쿠폰은 사용할 수 없다
- 발급 대상 고객이 아닌 고객은 사용할 수 없다
- 사용 취소가 허용된다면, 취소 가능한 상태에서만 취소된다

**중요한 경계 판단**
`ExclusionPattern`은 애그리거트 루트라기보다 `CouponPolicy` 내부의 값 객체 또는 하위 엔티티에 가깝습니다. 독립적인 생명주기보다 “정책을 구성하는 규칙”에 가까우므로, 우선은 `CouponPolicy`가 소유하게 두는 편이 맞습니다.

쿠폰 적용 판단은 보통 `CouponPolicy.canApplyTo(orderSnapshot, customerSnapshot)` 같은 정책 행위나 `CouponApplicability` 도메인 서비스로 둘 수 있습니다. 다만 주문, 결제, 상품, 재고는 쿠폰 정책 애그리거트 안에 넣지 않고 ID나 스냅샷으로 참조해야 합니다.

Serena: 호출 가능한 Serena 도구가 없어 사용하지 못했고, 디렉터리 구조는 `rg`/`find`로 확인했습니다.
