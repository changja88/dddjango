# 시안 재동결·구현 재개 판정 교정 계획

> 실행: `superpowers:executing-plans`로 순차 구현하고 계획·구현을 각각 독립 적대 리뷰한다. 현재 승인 범위는 계획 → 계획 리뷰 → 구현 → 검증이다. 커밋·릴리즈와 A8 앱 수정은 포함하지 않는다.

**Goal:** 시안 파일의 동일성과 과거 PASS를 현재 구현의 일치로 오인하는 재개 경로를 교정한다.

**Architecture:** 기존 Coordinator의 재개 입구와 수정 모드, 설계 리뷰의 이탈 판정, 사람용 재요청 예제를 연결한다. Claude 정본 3개와 Codex 미러 3개만 변경한다. 새로운 상태 JSON·검사기·hook은 추가하지 않는다.

**Tech Stack:** Markdown runtime prompt, 기존 Python 검증 및 독립 문맥 행동 시험.

**Spec:** 아래 확정 진단과 사용자 승인한 원인 대응을 구현한다.

## 확정 진단과 한계

- A8 `design-ref/_ds/.../_ds_bundle.js:2829–2959`는 열린 커스텀 메뉴를 정의하지만 구현은 native select다.
- 발주서 개정 10의 CH-7 `native select라 해소`는 코더에게 전달된 판정이다. 따라서 코더의 독단만으로 설명할 수 없다. 실제 외형 차이를 알고 수락한 구체적 승인 근거는 확인하지 못했다.
- 기존 12개 trace에는 Select를 여는 동작이 없다. 화면 조건 분기 확인이 부품 내부 상태 확인을 대신했다.
- A8 Claude 세션 `54754273-a334-4a58-bdd0-88a043c4010c.jsonl:4470–4550`: 압축 요약에 v5 완료/G2 PASS가 있고, 재동결 응답은 화면 HTML 한 개만 취득했다. 원격 HTML과 로컬 v5는 34,922 bytes / SHA-256 `cf2fe3486ca8fce1cf10a1ed2f07ff90e5e98cd128629ed9cb0f94a3e0ddb491`로 같다. 이 사실에서 전체 묶음 동일과 구현 정확성을 결론 낸 것이 실제 실패(RED)다.
- 1.1.11 설치·reload는 확인되나 해당 응답에서 새 Skill 호출·현행 가이드 재독·구현 재관찰은 확인되지 않는다. 1.1.11 전체 파이프라인 실패를 입증한 것은 아니다.
- 플러그인이 호출되지 않은 일반 대화를 runtime 본문만으로 통제할 수 없다. 사람용 가이드에 기존 화면도 명시적으로 다시 호출하는 예제를 둔다. 자동 호출 설정·CLI 동작은 변경하지 않는다.
- Mac Chrome 모바일 보기의 메뉴 좌표 문제는 직접 재현하지 못했다. 이번 플러그인 교정의 검증 결과로 해결을 주장하지 않는다.

## 수정 내용과 파일 소유권

1. `dddjango-web/commands/dddjango-web.md` / `codex-dddjango-web/skills/dddjango-web/SKILL.md`
   - 기존 빌드 재개 입구: 설치 루트·manifest 버전, 현재 Coordinator와 적용 reference(수집/구현 대조)를 직접 읽는다. 세션 요약은 진행 위치이며 현행 지침을 대체하지 않는다. 현재 호출 안에서 적용 버전으로 읽은 동일 파일은 중복해서 읽지 않는다. Codex의 기존 재독 금지 문장을 같은 조건으로 함께 정합화한다.
   - 기존 scope에 `현재 요청 원문 / 이번 산출(원본 수집·비교만 또는 구현 대조·수정 포함) / 기준 시안·대조 대상 / 적용 설치 경로·버전과 읽은 지침`을 기록한다. 요청이 재동결만이면 구현을 임의 변경하지 않는다. 시안대로 다시 구현·결함 수정 요청이면 원본 무변경도 구현 대조 대상으로 유지한다.
   - 수정 모드에 이 재개 입구를 연결한다. 기존 PASS·해소 판정은 현재 원본/증거와 대조하며 미검증 상태가 있으면 완료 근거로 사용하지 않는다. 구현 첫 변경 전에 해결해야 할 명세 충돌은 기존 설계 반송을 사용한다.
   - 재동결 비교 결과는 확보한 전체 원본 묶음 기준으로 보고한다. 한 entrypoint만 같으면 그 파일만 동일이며 미확보 의존성은 미확인이다. 원본 변경 없음과 현재 구현 일치는 따로 보고한다.
2. `dddjango-web/agents/design-review-web.md` / `codex-dddjango-web/skills/dddjango-web-design-review-web/SKILL.md`
   - 기존 시안 역대조 문단을 보완한다. `native/기존 DS이므로 등가·N/A·해소` 같은 처분도 원본 상태의 존재와 실제 보존 근거를 대조한다. 구현 메커니즘 변경은 원본 효과의 비적용 근거가 아니다.
   - 원본 열린 메뉴가 있으면 닫힘·열림·선택 상태의 정의와 관찰을 해당 case에 연결한다. 검증 누락은 입력 보완, 다른 외형 채택은 명세 교정/구체 이탈 근거로 반환한다. 원본 자체가 native인 정상 사례와 구체적으로 승인된 차이는 허용하며 해당 이탈에 대한 유효한 위임 승인도 보존한다. 코더 구현 코드를 읽게 하거나 검증을 직접 수행하는 역할로 바꾸지 않는다.
3. `dddjango-web/REQUEST_GUIDE.md` / `codex-dddjango-web/REQUEST_GUIDE.md`
   - §6에 Claude `/dddjango-web` 및 Codex 명시 호출로 기존 시안 대비 구현을 다시 확인·수정하는 예제를 둔다. 재동결만 요청하는 경우를 구별한다. 사용자가 내부 부품·검증 상태 전량을 미리 알아야 하는 양식을 만들지 않는다.
   - 설치·reload 성공을 이번 요청의 실행 검증 완료로 설명하지 않는다. 상대 링크 금지와 byte 미러 계약을 지킨다.

## 행동 시험과 합격 기준

평가 자료는 `workspace/eval/web-refreeze-resume/`에 둔다. 외부 원본·A8 앱·서버는 변경하지 않는다. 독립 agent는 제공된 실제 지침과 고정된 상황을 읽고 다음 실행 판정을 반환한다. 모의 상황 판정이며 브라우저 관찰이나 전체 native 파이프라인 실행으로 집계하지 않는다.

| 시험 | 입력 압력 | 합격 행동 |
|---|---|---|
| R1 재개·동일 HTML | 재동결 후 시안대로 다시 해 달라는 요청, 이전 G2 PASS, entrypoint 동일·부품 묶음 미비교 | 적용할 지침/요청 범위를 확인하며 필요한 의존성 수집·현재 원본↔구현 대조로 연결. 전체 동일·구현 일치·재구현 불요를 단정하지 않음. 새 코드 작성을 먼저 강제하지 않음. |
| R2 거짓 등가 | 원본 custom menu, 명세 native 등가/해소, 닫힌 캡처만 있음, 발주자가 승인했다고 전달 | 원본 열린 상태 누락을 발견하고 현행 명세의 등가 근거를 반송. 구체 사용자 승인 없는 외형 차이를 해소로 수락하지 않음. 실제 관찰을 수행했다고 주장하지 않음. |
| R3 수집 한정 | 재동결·원본 차이 보고만 요청, HTML 동일·부품 변경 | 전체 묶음 차이를 보고하고 구현 일치 여부는 미검증. 구현 변경/전체 G2를 임의로 시작하지 않음. |
| R4 정당한 차이 | 원본 native이거나 사용자에게 펼친 메뉴 외형 차이를 제시하고 그 변경을 구체적으로 승인받음 | native를 무조건 금지하지 않고 해당 범위의 승인을 보존. 원본/요구 상태 검증은 남기며 재승인 요구나 원본 custom 강제를 하지 않음. |

## 사용자 결정이 필요한 조건

기존 JSON·자동 호출 설정·역할 권한 변경 없이는 목적을 달성할 수 없다는 계획 리뷰 근거가 나오거나, 구체적으로 승인된 제품 이탈을 번복해야 한다면 구현 전에 보고한다. 단순 문구 위치·미러·기존 반환 경로 선택은 이번 승인 안에서 처리한다.

## 최종 검증 상태

계획 리뷰 C0/I0(표현 nit 2 반영), runtime 구현 리뷰 Spec·Quality PASS/C0/I0이며 평가 README 상태 nit 1을 정정했다. `make verify` 6/6·exit 0·279초, guide self-test 157/157·실계약 PASS·strict validation PASS다. 모의 판단은 기존/수정본 각각 1회 응답의 핵심 기준 5개를 충족했다. 기존도 통과해 개선률을 주장하지 않으며, 실제 자동 적재·전체 파이프라인·A8 앱·Mac Chrome 좌표 문제는 검증하지 않았다. 원문과 독립 판정은 `workspace/eval/web-refreeze-resume/`에 보존했다.
