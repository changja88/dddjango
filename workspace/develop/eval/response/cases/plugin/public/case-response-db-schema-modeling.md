회의실 예약 기능의 RDB 스키마를 설계하려고 해.

요구사항:
- 한 회사 안에 여러 지점과 회의실이 있고, 회의실별 운영 시간과 수용 인원이 달라.
- 사용자는 회의실을 예약할 수 있고, 같은 회의실의 예약 시간이 겹치면 안 돼.
- 취소된 예약은 감사 목적으로 남기되, 같은 시간대 재예약은 가능해야 해.
- 자주 보는 화면은 `회사 + 지점 + 날짜`별 예약 목록과 `사용자별 예정 예약` 목록이야.

개념 ERD, logical schema, key 선택, cardinality/optionality, 정규화 판단, DB 제약조건과 index 후보를 중심으로 답해줘. Django migration 파일이나 API 계약은 작성하지 말고 DB 설계 판단만 정리해줘.
