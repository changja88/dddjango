1리팩토링 막힘 — 표준 안에서 정리할 길이 없음8개

사용자가 짚은 일(2026-11-20): 2.42.0 으로도 리팩토링을 빚 없이 끝낼 수 없다. 비동기 서버 BC 의 리팩토링 실행은 2.42.0 으로 시작(G0)을 지나 설계(G1)까지 갔다. 그러나 감사가 고르게 한 위반 가운데 다섯은 표준 안에서 정리할 길이 없어 이번 실행에서 뺐다. 넷은 한 규칙이 고치라 하는데 그 고칠 자리를 다른 규칙이 막는 꼴이다. 하나는 시험 규칙이 허용하는 시험 파일 나누기를 동작 보존 장치가 받지 못하는 꼴이다. G0 는 이 가운데 셋(F4-190 · 192 · 193)을 «규칙 둘이 반대 방향» 으로 알고도 사용자에게 «정리» 를 고르게 했고, G1 에서 «불가» 로 다시 올라왔다. 같은 실행의 구현(0T · 0C 창)에서 넷이 더 나왔다(F4-195 ~ 198) — 셋은 동작 보존 장치와 문서 검사기가 옮김 · 이름 바꾸기 · 상수를 읽지 못한 것, 하나는 보류해 둔 포트 자료 규칙 충돌이다.

  • F4-190 · 192로그인 필요를 401 로 낼 승인된 길이 모자라다(401 헤더 · 인증 뒤에 알게 된 인증 실패) — 방향 정함: 401 은 Ninja 가 내고 WWW-Authenticate 는 붙이지 않음(한계로 인정) · 인증 뒤 실패도 Ninja 401 · 로그인 필요 403 은 위반그대로
  • F4-191스트리밍(text/event-stream) 응답의 설명서 규칙이 없어 JSON 용 «이름 + 판별 키» 규칙이 걸린다 — 방향 정함: OpenAPI 3.2 표준대로 스트리밍 설명서 규칙을 새로 두고(oneOf + event 고정값 · 판별 키 요구 안 함) JSON 용 규칙은 JSON 에만그대로
  • F4-193중복 금지 규칙(«모아라»)과 유스케이스 공유 금지(«모을 자리 없음»)가 부딪혀 두 유스케이스의 같은 흐름을 정리할 수 없다 — 방향 정함: 유스케이스 독립성 유지(서로 공유하지 않음 · 비슷한 흐름도 각자 안 · 업무 판정은 도메인 한 곳 · 중복 금지는 유스케이스 사이 흐름에 걸지 않음)그대로
  • F4-194동작 보존 장치가 시험 케이스를 이름 · 내용 그대로 다른 파일로 옮기는 시험 파일 나누기를 삭제 · 추가로 잡는다 — 방향 정함: 장치는 그대로 두고 G1 승인 «케이스 옮김» 행(개명 행과 같은 꼴)을 더한다그대로
  • F4-195동작 보존 장치가 단언이 든 시험 도움 함수를 한 곳(conftest.py)으로 모으는 옮김을 삭제 · 추가로 잡는다 — F4-194 와 같은 장치 · 같이 고칠 수 있음그대로
  • F4-196동작 보존 장치가 본문이 서로 같은 예외 클래스 여럿의 이름 바꾸기를 짝짓지 못해, 이름만 바꾼 시험 쪽 파일을 붉게 잡는다그대로
  • F4-35 · 133 · 188 · 197포트 자료에 도메인 값 객체 · enum 을 쓰는 것을 규칙(R-0589)은 허용하고 검사기(#228)는 막는다 — 보류에서 다시 엶(보류 조건 «새 사례가 쌓이면 다시 연다» · 이번엔 리팩토링을 막음)그대로
