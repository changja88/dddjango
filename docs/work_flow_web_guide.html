AGENT 01 · PHASE 1

화면 설계자

design-architect-web

입력: G0 범위, 동결 시안·에셋·API 계약.

산출: design-spec.md. UI 동작 계약에 요구 근거, 담당 기술, JS/HTMX 파일, root·대상, 서버 요청·swap 경계, 임시 상태·자원, 키보드·실패·정리, 검증 행위를 확정합니다. JS가 필요 없으면 이유를 남깁니다. 리뷰 노트와 설계 반송을 반영하는 유일한 명세 작성자입니다.

설계 리뷰어

design-review-web

AGENT 03 · PHASE 2

산출: web/ 코드와 실제 렌더·브라우저 증거. Python·HTML·HTMX·CSS와 필요한 JS를 함께 구현합니다. 설계 결정을 바꿔야 하면 Coordinator에 반송합니다.

AGENT 04 · PHASE 2

규율 감수자

discipline-reviewer-web

입력: 코드, 승인 명세, 감사 범위, 브라우저·시안 대조 증거.

산출: 감수 리포트. 새 JS 스킬로 초기화·정리·UI 상태·키보드 동작의 구현 의미와 증거를 대조합니다. 직접 수정하지 않으며, 코드 수정은 구현자에게 돌아갑니다.

규율 감수자는 필요하면 Phase 1에서 명세 단순성만 경량 점검합니다. 이때는 아직 없는 코드나 브라우저 증거를 요구하지 않습니다.

한 구현자가 다루되, 기술의 책임은 분리합니다

기술맡는 일기준과 경계
Python · DjangoAPI 계약 소비, form·표시 상태 준비, 서버 HTML 렌더링architecture-web + implementation-ui. 비즈니스 판정은 백엔드 서버가 소유합니다.
HTML의미 있는 문서·폼·접근성 구조와 서버가 준비한 상태 표시implementation-ui. 표시 판정이나 별도의 비즈니스 계산을 복제하지 않습니다.
HTMX서버 요청, 서버가 렌더한 HTML의 부분 교체architecture-web + implementation-ui. 폴링·SSE·WebSocket 등 실시간 통신 채택은 별도 결정입니다.
CSS시안의 색·간격·서체·레이아웃·반응형·시각 전환implementation-ui. 동결 시안·토큰·에셋과 실제 렌더를 대조합니다.
JavaScript포커스, 토글, 파일 미리보기, 브라우저 API, 임시 UI 상태implementation-javascript. 승인된 UI 동작만 구현하며 권한·금액·저장 판정, 별도 업무 API 호출, SPA 상태 계층을 만들지 않습니다. native HTML/CSS로 충분하면 JS 파일이 없습니다.

파일 기준: web/static/js/<기능>.js — UI 기능 하나당 파일 하나입니다. 한 기능의 초기화·이벤트·정리 함수는 같은 파일에 둡니다. 웹 표준 트리의 css/·js/·htmx/·images/ 네 폴더 골격을 따릅니다. 검증된 폰트·다운로드 파일이 필요할 때만 fonts/·files/를 생성합니다.

HTMX 포함 경계: static/htmx/<기능>.html은 snake_case·평면으로 기능당 한 선언 조각을 두고, 페이지/section에서 {% include "static/htmx/<기능>.html" %}로 렌더합니다. 기존 TEMPLATES DIRS의 web 루트를 사용하며 새 finder·middleware·템플릿 엔진을 만들지 않습니다. 공개 static 원문에 비밀·사용자별 렌더 결과를 저장하지 않습니다. 데이터·권한·CSRF·fragment 응답은 view/section이 소유하며 static URL은 업무 fragment endpoint가 아닙니다.

실행 위치: 기능 JS는 snake_case·평면 파일을 base 공통 로드 또는 페이지의 범용 script block에서 외부 static 참조로 한 번만 로드합니다. classic은 defer, 기존 module 방식도 허용하며 async로 순서를 깨지 않습니다. fragment 실행 script와 inline JS·on*·hx-on·js:·hx-trigger 조건식은 금지합니다. 데이터는 json_script 또는 escape된 data 속성으로 전달하고 실행 소스에 보간하지 않습니다.

고정 라이브러리: 신규 core는 static/htmx/htmx.min.js 한 파일입니다. 기존 static/js/htmx.min.js·htmx.js는 브라운필드 설치로만 소비하며 이중 설치·조용한 이동/업그레이드는 금지합니다. core 누락 시 공식 2.0.10 고정 파일을 설치하고 버전·출처를 기록합니다. static/js/motion.js는 러너 채택 시 조건 설치하는 byte 고정 예약 이름으로, 기능 JS로 덮어쓰지 않습니다.

모션 명세의 ui-js는 static/js/<기능>.js :: [data-<root>] 좌표와 근거·실제 동작 증거를 연결합니다. 백스톱은 경로·실행 채널·판형과 파일/root 존재를 확인합니다. 기능 일대일의 의미, 업무 로직 부재, JS 내부 모션 전수성은 독립 감수와 실제 동작 검증의 몫입니다. static_only도 필요한 로컬 UI JS를 허용합니다.

01 · 설계

서버와 UI를 구분

설계자는 업로드 처리·검증은 서버, 선택 파일의 로컬 미리보기는 JS로 명세합니다. 설계 리뷰어가 경계를 검토하고 사용자가 G1을 승인합니다.

02 · 구현

기존 구현자가 JS 작성

구현자는 HTML·CSS를 구현하고, JS 스킬을 읽어 file_preview.js를 작성합니다. 임시 URL·이벤트·정리도 같은 UI 기능 안에서 관리합니다.

03 · 브라우저 확인

재사용·교체 상황 확인

재선택, 초기화 중복, 여러 미리보기의 상태 격리, HTMX 교체 후 새 UI 연결과 이전 자원 정리, 키보드·포커스를 확인합니다.

04 · 감수·인수

같은 JS 기준으로 감수

규율 감수자가 코드와 증거를 독립 대조합니다. Coordinator는 개정된 백스톱을 실행하고, G2에 실제 결과와 미검증 항목을 제시합니다.

코드가 명세를 어긴 경우

감수·브라우저 확인·백스톱 발견 → Coordinator → coder-web 수정 → 영향을 받은 확인·감수·검사 재실행.

명세의 기술 결정이 바뀌어야 하는 경우

구현자가 사유 보고 → Coordinator → design-architect-web 수정 → 관련 설계 재검토·G1 재확인 → 계약·슬라이스를 맞춘 뒤 구현 재개.

읽어 확인한 기준: dddjango-web/commands/dddjango-web.md, dddjango-web/agents/*.md의 역할·입출력·skills: 목록, 웹 표준 트리. JS 스킬 직접 주입과 실행 경계는 현재 소스에 반영된 계약입니다.
