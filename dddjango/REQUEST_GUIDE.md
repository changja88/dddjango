# dddjango 작업 요청 가이드

설치된 플러그인 루트의 이 `REQUEST_GUIDE.md`가 해당 runtime에 대한 권위 있는 가이드 사본입니다.
manifest의 homepage는 최신 온라인 가이드(latest-online)를 발견하는 경로이며, 설치 버전의 정본을
대신하지 않습니다. 이 문서는 Claude Code와 Codex 양쪽에서 사용할 수 있습니다.

## 1. 언제 쓰는가

`dddjango`는 기존 Django 프로젝트의 한 기능을 업무 요구 정리 → DDD 설계 → TDD 구현으로
진행하는 플러그인입니다. 주문 취소, 사용 한도 변경, 외부 정산 결과 반영처럼 원하는 행동과
결과가 있는 기능에 사용합니다. 신규 기능도 기존 프로젝트 안에서 시작합니다.

시안 재현 중심의 웹 화면 작업은 `dddjango-web`에 요청하세요. Django admin이나 기존 업무
기능에 포함된 화면 변경은 `dddjango`가 담당하는 경우도 있습니다. 구분이 어려우면 현재 화면과
원하는 변화를 알려 주세요. 플러그인이 기존 코드를 조사해 담당 범위를 안내합니다.

새 프로젝트 구성이나 서비스 전체의 전면 재설계는 이 가이드의 범위 밖입니다.

## 2. 바로 시작

Claude Code에서는 `/dddjango`로 시작합니다.

```text
/dddjango 기존 Django 프로젝트에 회원이 배송 시작 전 주문을 취소할 수 있게 해 줘.
```

Codex에서는 사용할 플러그인을 자연어로 지정합니다.

```text
dddjango를 사용해 기존 Django 프로젝트에 회원이 배송 시작 전 주문을 취소할 수 있게 해 줘.
```

조금 더 정해 둔 내용이 있다면 아래 네 묶음 중 아는 내용만 보태세요. 모두 채울 필요는 없습니다.

```text
dddjango를 사용해 기존 Django 프로젝트에서 <기능과 원하는 변화>를 구현해 줘.
대표 성공 결과: <어떤 행동 뒤에 무엇이 보이거나 어떤 상태가 되어야 하는지>
이미 정한 핵심 규칙과 실패 결과: <반드시 지킬 조건, 실패할 때 보일 결과와 남아야 할 상태>
범위: <유지할 기존 동작 / 이번에 바꿀 부분 / 제외할 부분>
```

한 기능과 원하는 변화만으로 시작할 수 있습니다. 규칙을 아직 정하지 못했거나 자료 위치를
몰라도 괜찮습니다. 플러그인이 프로젝트에서 확인할 수 있는 내용을 먼저 조사한 뒤, 사용자가
결정해야 하는 결과를 질문합니다.

Claude Code에서는 템플릿 첫 문장의 `dddjango를 사용해`를 `/dddjango`로 바꾸면 됩니다.

## 3. 알려 주면 좋은 제품 정보

이번 기능의 결과에 영향을 주고 이미 정한 내용이 있을 때만 보충하세요. 사용자·행위자나 목적도
그에 따라 허용되는 행동이나 결과가 달라질 때 알려 주면 됩니다.

- 성공 전후에 바뀌는 업무 상태와 항상 지켜야 하는 규칙
- 금액·수량·기간의 경계에서 허용하거나 거절할 결과
- 실패할 때 사용자에게 보일 결과와 바뀌지 않아야 할 주문·재고·결제 등의 상태
- 중복 요청·재시도·동시 실행이 생겼을 때 기대하는 결과
- 외부 알림·결제 등이 완료돼야 하는 시점과 실패 뒤 허용되는 업무 상태
- 기존 사용자나 연동 시스템이 계속 이용할 동작과 의도적으로 바꿀 동작

예를 들어 “사용 가능한 포인트가 1,000점이면 1,000점 사용까지 허용하고, 1,001점 사용은
거절하며 잔액과 사용 내역은 그대로여야 해”처럼 허용 범위와 실패 뒤 상태를 함께 설명할 수 있습니다.
해당하지 않거나 아직 정하지 못한 항목을 채울 필요는 없습니다.

다음은 동시 구매와 알림까지 기대 결과가 정해진 요청의 예시입니다.

```text
dddjango를 사용해 기존 Django 프로젝트의 재고 예약 기능을 만들어 줘.
남은 재고와 같은 수량까지 예약할 수 있고, 성공하면 예약한 수량만큼 판매 가능한 재고가 줄어야 해.
재고가 1개일 때 두 주문이 동시에 예약하면 한 주문만 성공하고 재고는 0이 되어야 해.
같은 예약 요청이 다시 도착해도 예약이 추가로 생기거나 재고가 더 줄어들면 안 돼.
재고 부족이면 사용자에게 예약 실패를 알리고, 예약과 재고 변경이 남으면 안 돼.
예약 성공은 즉시 보여 주고, 알림은 1분 이내 전달하면 돼. 알림 전달에 실패해도 예약은 유지해 줘.
기존 재고 조회 응답은 유지하고, 결제와 배송 기능은 이번 범위에서 제외해 줘.
```

## 4. 플러그인이 하는 일

플러그인은 관련 코드·문서·기존 테스트를 찾아 현재 동작을 조사합니다. 자료 사이에 다른 해석이
있으면 확인한 내용을 정리하고, 원하는 제품 결과를 선택해야 하는 부분을 질문합니다.

업무 규칙에 맞는 DDD 구조를 설계하며 업무 영역의 경계(BC), aggregate·repository 배치와
API·DB 구현 방법을 정합니다. 사용할 agent·skill, 테스트 구조와 필요한 수량, TDD 구현과
검증 절차도 플러그인이 판단합니다. 진행에 필요한 질문과 승인은 플러그인이 안내합니다.

## 5. 알고 있는 자료가 있으면 함께 주기

자료가 있으면 위치만 알려 줘도 됩니다. 자료 없이 시작할 수 있으며, 요청 전에 찾아서 분석하거나
정리할 필요는 없습니다.

- 관련 코드·제품 문서·기존 테스트 경로. 예를 들어 `apps/orders/`, `docs/orders.md`, `tests/orders/`
- OpenAPI, 요청·응답 예시, 연동 시스템을 설명하는 자료
- 경계 사례·동시 실행·외부 연동의 실제 상황을 보여 주는 문서나 샘플
- 외부 자료의 접근 조건 등 이미 알고 있는 사실

실제로 정해진 환경 제약이 있으면 그 이유와 지켜야 할 결과를 함께 알려 주세요.

## 6. 수정하거나 이전 작업 이어가기

이전 작업을 이어간다는 사실과 바꿀 결과, 유지할 동작을 말하면 됩니다. 세션 밖에서 바뀐 사실을
알고 있다면 함께 알려 주세요.

```text
dddjango를 사용해 이전 주문 취소 작업을 이어서 수정해 줘.
이제 결제 완료 후에도 배송 시작 전이면 취소할 수 있어야 해.
배송 시작 후 취소 거절과 기존 주문 조회 응답은 유지해 줘.
대화가 끝난 뒤 환불 서비스가 새 버전으로 바뀌었어.
```

이전 작업이나 새 자료의 위치를 알면 덧붙일 수 있습니다. 플러그인이 기존 기록과 현재 상태를
확인해 이어갈 작업과 필요한 질문·승인을 안내합니다.

동작을 유지하면서 코드 품질만 개선하고 싶다면, 대상 기능과 현재 불편한 점을 알려 주세요.

```text
dddjango를 사용해 주문 취소의 현재 동작은 유지하면서,
규칙 하나를 수정할 때 여러 곳을 고쳐야 하는 불편을 줄여 줘.
```

## 7. 완료 보고 읽기

구현한 업무 사례, 실제로 실행한 검증, 남은 미확정이나 제한을 확인하세요. 원하는 성공·실패 결과와
보존할 동작에 차이가 있으면 그 결과를 알려 주세요. 자동 검사 통과는 확인한 사례와 범위에 대한
결과이며, 모든 가능한 결함이 없음을 보장하지는 않습니다.
